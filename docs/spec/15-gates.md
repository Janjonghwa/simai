# 15. 검증 게이트와 시나리오 데이터셋

G0\~G9를 통과하면 MVP 완성이다. 수치는 판단용 초기 목표이며 안전 인증 기준이 아니다. 모든 게이트는 실패 시 바꿀 것을 미리 정해 둔다. 15.1 은 시연 합격 게이트이고, 그 밖의 “0건/100%”·측정·기록 항목은 회귀 시험으로 부록 D 에 둔다.

## 15.1 MVP 게이트 (시연 합격)

**PPE 시연용 활성화 예외(Lead 이원준 승인, 2026-11-09, S15P31A101-556).** G9·G6-R9·G6-R11 미통과 상태에서 시연·준비 검증을 위해 R9·R11 v1 을 시드에 넣어 활성화한다(8.10). 아래 합격 기준·측정 분모·미달 시 조치는 그대로이며, 이 승인은 게이트 합격이나 제품 성능 검증이 아니다. CAUTION·작업 기준 요구·UNKNOWN 유지·LIVE 외 실제 알림 금지는 유지한다. 실행 중 Tier 0 의 -548 포함 판 확인 → 서버 배포 조율 → 새 묶음 APPLIED → 워치 연결·장비별 발생·착용 해소를 확인한다. 예외 종료·오경보·부하 문제로 비활성 복구할 때는 시드 제외만으로 DB 행이 비활성화되지 않으므로 적용 기간 종료와 새 묶음 적용까지 한다(`docs/design/ppe-demo-activation.md`).

G3 는 위 세 행과 부록 D.4 항목으로 판정하고, 항목별 결과·근거는 `docs/design/g3-report.md` 에 모은다. 담당을 나눈 항목(Tier 0 몫과 노트북·EC2 몫)은 두 몫이 모두 PASS 여야 그 항목이 PASS 다.

G6 경보율은 위 항목과 별도로 전체 경보율을 함께 기록하고, 상한은 ISA-18.2 의 운영자 1인당 10분에 1건 수준을 참고로 본다. G6는 규칙별로 판정한다(G6-R1 등). G6-R6·R7은 부록 D 의 해당 G3 항목과 같은 측정으로 판정한다.

**측정 방법.**

- **최소 표본.** 실패가 0건이면 실패율의 95% 상한은 약 3/n 이다. 그래서 R1 98% 는 진입 150회 이상, R2·R3 95% 는 60회 이상에서 판정한다. 오경보 “시간당 1회 이하”는 정상 영상 3시간 이상에서 0건이어야 말할 수 있다(R4 의 2시간당 1회는 6시간 이상).
- **종단 지연(glass-to-alarm).** 카메라가 보는 LED 와 노트북의 소리·화면을 240fps 휴대폰 한 화면으로 함께 촬영해, LED 가 켜진 프레임부터 소리·화면이 나온 프레임까지를 잰다.
- **카메라 간 촬영 시각 차이.** 4대가 함께 보는 LED ms 카운터 판으로 잰다. 휴대폰 화면 시계는 주사율 때문에 해상도가 8\~16ms 에 그치므로 쓰지 않는다. “보간 후 잔여 오차 p95 20ms” 는 측정·기록 항목이고(부록 D), 실제 영향은 G2 위치·추적 결과로 판정한다.
- **틀어짐 재현(약 1°).** 카메라에 레이저 포인터를 붙이고 5m 떨어진 벽의 점이 약 8.7cm 움직이도록 돌린다(부록 D).
- **G2 ID 정답.** ID 정답 주석은 구현자가 아닌 팀원이 단다. 주석 분량(구간 수·시간)은 확인 필요다.
- **G7 사람 평가.** 평가는 구현자가 아닌 사람이 한다. 평가자 수는 G7 착수 전에 정한다(확인 필요). 표본 구성·채점 기준표 초안·평가자 운영·판정 규칙은 `docs/design/g7-eval.md`(S15P31A101-35)와 `docs/design/tbm-legal-graph.md`(S15P31A101-415, 보고서 인용 조항 존재 100% 코드 4단계 검증 및 인용 적절성 사람 평가 80% 이상 표본 준비)에 있다.
- **G7 측정.** 제품과 같은 질문으로 잰다: 분석 워커 처리기와 같은 프롬프트·응답 형식과 같은 입력 규칙(프레임 촬영 시각 순, 이벤트 시점 뒤 프레임 제외, 얼굴 처리를 마친 프레임만, 5.4)을 쓰고, 형식 오류·잘림은 처리기처럼 한 번 다시 묻는다. 평가 도구의 지연은 얼굴 처리부터 근거까지(다시 묻기 포함)이고, 제품 조건(동시 4·Tier 0 동시)의 p95 는 통합 시험 결과로 낸다. 다시 물어도 형식이 어긋나거나 잘린 답, 얼굴 처리를 마친 프레임이 없어 답이 없는 표본은 근거-상태 일치의 분모에서 빼고 따로 세며, 100건은 채점한 표본 기준이다. 정답 데이터(SIM·시나리오 골든)·시험 입력 녹화나 자리 표시 프롬프트로 만든 답으로는 판정하지 않는다.

정확도 게이트의 절대 오차 항목(G1 카메라 높이, G2 실측 격자, G4 실측 대비)은 개발 교실에서 한 번 줄자·레이저로 재서 판정한다. 시연 현장은 실측 없이 운영하며 현장 수치를 게이트 합격으로 주장하지 않는다.

G5의 “한 카메라 제외 재투영”은 3대로 삼각측량한 관절을 4번째 카메라에 투영해 그 카메라의 실제 keypoint와 비교하는 방식으로, 모션캡처 장비 없이 관측 일관성을 잰다. 실제 3D 위치의 정답은 아니므로, 위치 정확도는 G2의 실측 XYZ로 따로 판정한다. G5 발-지지면 오차의 목표값(5cm)을 발목 자체 높이를 뺀 값으로 읽어야 하는지는 확인 필요다.

## 15.3 시나리오 데이터셋

4대 동기화 녹화를 한 번에 촬영해 모든 게이트 비교에 재사용한다. 녹화 세션마다 `recording_manifest`(파일·해시·프레임 수·시각 범위·카메라 설정·보정 버전·동의 범위·보관 기한·저장 위치, `contracts/data/`)를 남기고, 영상은 녹화 보관 위치의 `recordings/<session_id>/`에 둔다(Network Volume 폐기 뒤의 보관 위치와 `storage.uri` 형식은 19.1 미결). 저장소에는 영상 없이 manifest 사본(`docs/data/sessions/<session_id>.json`)만 커밋한다(설명은 `docs/data/recording-manifest.md`).

- 시간 동기화: 네 카메라가 함께 보는 위치의 LED ms 카운터 판, 종단 지연용 LED + 240fps 휴대폰 촬영
- 보정·현장 세팅: 깨끗한 배경 20~30초 누적 + 실측 정물(로비 스툴 0.425 m, 안전봉·라바콘 등) 2~3개 배치(보정 최적화의 걷기 보정은 폐지) + 보정 발행 뒤 1인 30~60초 보행 「카메라 확인」(4.3)
- 위치 정답: 1m 격자 기반 20곳 이상(중앙, 가장자리, 책상 뒤, 카메라 근처·바로 아래)에 지점당 3회 서기, 키를 아는 사람
- 추적: 두 사람 교차, 나란히 걷기, 서서 작업, 책상 뒤 이동
- 실패: 카메라 1대 가리기·전원 차단, 노트북 네트워크 차단
- 위험: 테이프 구역 진입(150회 이상)·경계 머물기, 40cm 단상(고소·가장자리, 60회 이상), 매트 위 눕기(낙상), 빠르게 앉기·물건 줍기(오경보용), 정상 활동 3시간 이상(오경보 측정용)
- PPE: 안전모·조끼 착용·미착용, 착탈 전환, 손에 든 안전모·의자와 책상의 조끼(함정), 머리 가림, 사람 겹침, 작업 중 안전모 미착용(R9, 60회 이상)·작업 중 조끼 미착용(R11, 60회 이상)·착용 상태로 머물기(오경보용), 위에서 내려다보는 교실 카메라 각도. 학습에 쓴 사람·시간·합성 계열과 나눈 사람 승인 정답으로 평가한다
- 장비 대체·워치: 확장(부록 C)

**준비물:** 줄자, 레이저 거리계, 레이저 포인터(틀어짐 재현), 바닥 테이프, 40cm 단상, 매트, LED ms 카운터 판, 240fps 촬영 휴대폰, 실측 정물(안전봉·라바콘 등).

## 15.4 모델 학습과 비교 실험

학습 전에 기본 성능과 ID 오류가 나는 조건을 먼저 잰다. 학습 순서는 YOLO26x-pose 미세조정(COCO 17관절 + 발 6점 = 23점, A1) → (G2 ID 유지 실패 시에만) ReID 이고, YOLO26x PPE 검출(5.5)은 별도 학습 GPU 에서 이와 나란히 진행한다(무학습 기준선 YOLOE-26 을 같은 평가로 먼저 잼). BEV 기반 추적 학습은 연구 참고로만 둔다. 모두 사전학습 가중치에서 시작하며 처음부터 학습하지 않는다.

**데이터.** 4대 카메라 영상에서 조건이 다른 프레임 500\~1,500장을 초기 가안으로 주석화한다. 필요 수량이 아니라 시작 규모이며, 장수보다 상황 다양성(걷기, 앉기, 물건 줍기, 교차, 책상 뒤 이동, 비슷한 옷, 조명·거리 차이, 천장 모서리 카메라의 근처·바로 아래 시점)이 중요하다.

- 관절마다 VISIBLE / OCCLUDED / UNLABELED를 구분하고, 보이지 않는 발 위치를 임의로 찍지 않는다.
- 학습·검증·시험은 프레임 무작위가 아니라 촬영 세션·날짜·가구 배치·참가자 단위로 나누고, 일부 조건은 최종 평가 전용으로 남긴다.
- 주석 부담은 무거운 포즈 모델(ViTPose, Sapiens)로 자동 주석을 만든 뒤 사람이 고치는 방식으로 줄인다.
- 발 6점(좌우 엄지발가락·새끼발가락·발뒤꿈치)은 COCO-WholeBody(연구·비상업)의 발 주석 형식을 따른다. 23점 모델의 발 점은 ContactEstimator(5.2)의 근거가 된다.
- 공개 다시점 데이터(CMU Panoptic 등)는 보조로만 쓰고 현장 데이터와 분리해 평가한다.

**비교 실험.**

| 실험 | 구성 | 확인할 것 |
|---|---|---|
| A0 기준선 | YOLO26x-pose(E2E) + 카메라별 TrackTrack + 기하 융합 | 현재 성능, 밀집 장면 재현율 기록 |
| A1 관절 개선 | 23점 미세조정 YOLO26x-pose + 같은 추적 | 2D 관절·발 점·World XYZ 정확도 |
| A2 ID 개선(G2 ID 실패 시에만) | A1 + 선택적 ReID·궤적 매칭 | ID 전환, IDF1, HOTA |
| A3 연구 참고 | TrackTacular, MVTrajecter, BEV 추적 학습 | 실험하지 않음. 문헌 참고 |

포즈 효과는 관절별 정확도·미검출률·G2 World XYZ 오차로, 추적 효과는 IDF1·HOTA·ID 전환·분열·오병합으로 판단한다. 모든 구성에서 4대 합산 처리량과 capture_to_risk 지연을 함께 본다. 채택 순서는 2D 관절 정확도 → G2 World XYZ 정확도 → IDF1·HOTA → 4대 지연이며, G2 World XYZ가 개선되지 않으면 2D 점수만 올랐다는 이유로 새 모델을 채택하지 않는다. 지연은 6.6 목표 안이어야 한다.
