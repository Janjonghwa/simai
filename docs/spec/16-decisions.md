# 16. 결정 기록

검토 후 제외·교체·보류한 항목과 이유다. 같은 논의를 반복하지 않고, “왜 이건 안 썼나”에 답하기 위해 남긴다. 영역별로 묶었고, 뒤에 뒤집힌 결정은 지우지 않고 “대체됨”으로 표시한다. 괄호 안 버전은 결정한 판이다.

|---|---|---|

| MVP·시연 아바타 | 기본·폴백은 캡슐/막대(InstancedMesh)(v1.3), 시연 범위는 EXP-02 MHR 리깅 메시·포즈 스트림(v1.3 수정 29) | 시연 범위에서 `/topic/avatar` 로 MHR SkinnedMesh 를 구동하고, 스트림 지연·끊김·ID 불확실·보정 불일치·자산 미준비(13.2 5조건) 때는 Tier 0 골격 캡슐 아바타로 즉시 돌아간다 |
| 외형 텍스처 생성형 복원(SiTH·FISHuman) | 제외(v1.3, v1.3 수정 29 재확인) | 3m 높이 카메라에서 얼굴이 30\~50px라 물리적으로 보이지 않는 면과 얼굴을 지어내게 된다. 관측과 추정을 구분하는 원칙과 충돌 |

| 재식별(Re-ID) | 전신 임베딩을 기하 게이트 뒤 보조 비용으로만 허용, Tier 0 위치·ID 정본 덮어쓰기 금지, 도입은 10/30 이후 G2 측정 뒤(v1.3 수정 29, 사용자 결정 2026-10-23). 이전의 “재식별 금지”는 대체됨 | 얼굴 재식별은 하지 않고, 전신 외형 임베딩도 기하 게이트를 통과한 후보 사이의 보조 비용으로만 써서 Tier 0 기하 정본을 덮지 않는다. 지금 범위가 아니며 10/30 이후 G2 ID 유지율 측정 뒤 도입 여부를 정한다(19.1) |
| YOLO26 계열 통일 | 채택(v1.2) | pose·분류·seg를 한 프레임워크로 학습·내보내기·추론. 라이선스 AGPL-3.0(교육 프로젝트, 네트워크 서비스 배포 시 소스 공개 의무 유의) |
| Tier 0 검출 모델 크기 | YOLO26x-pose(v1.2 r4) | 운영 GPU H100 80GB 에서 x·1280·4대 동시 38 ms 로 충분하고 크기별 정확도는 공식 벤치마크로 확인됨. 노트북 6GB 측정으로 크기를 고르지 않는다. s 기준선 안은 폐기 |
| NMS 경로 vs NMS-free 비교 | E2E(NMS-free) 기본(v1.3). 이전의 “잠정 NMS + G0 비교” 결정은 대체됨 | 공식 COCO 지표 E2E 71.6, NMS 71.7 로 같다. 비교 실험 없이 E2E 를 쓰고 밀집 장면 재현율은 A0 녹화에서 기록만 |
| 발 keypoint 확보 | YOLO26x-pose 를 COCO 17 + 발 6점(23점)으로 미세조정(v1.3). RTMO·RTMPose Halpe-26 비교군은 대체됨 | Tier 0 단일 추론을 유지하면서 ContactEstimator 에 발뒤꿈치·발끝 근거를 준다. 발 주석은 COCO-WholeBody(연구·비상업) |

| PPE 분류 우선 | 검출 우선으로 변경(v1.2 r2) | 분류로는 안전모가 머리에 쓰였는지 손에 들렸는지 구분하기 어려움. 검출로 위치 관계를 판단 |

| 사고 구간 요약 | M3, `incident_summary` 작업, 관리자 요청(v1.3 수정 13) | 최소 리플레이·VLM 근거와 같은 단계. 상향 의견을 내지 않고 보고서와 같은 우선순위 |
| VLM 입력 얼굴 흐림 주체 | 분석 워커, VLM 호출 직전(v1.3 수정 13) | 클립은 흐림 없이 저장되므로 프레임·클립을 한곳에서 처리하고 Tier 0 실시간 경로에 부하를 더하지 않는다. Tier 0 업로드 전 흐림은 이득이 작아 버림 |
| 상향 의견 적용 | 관리자 승인 → I1 `event_escalate` → Tier 0 UPDATED 전이(v1.3 수정 13) | LIVE 생명주기 정본은 Tier 0 다. EC2 가 등급을 직접 바꾸면 저널·현장 경보와 어긋난다 |
