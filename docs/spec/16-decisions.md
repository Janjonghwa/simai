# 16. 결정 기록

검토 후 제외·교체·보류한 항목과 이유다. 같은 논의를 반복하지 않고, “왜 이건 안 썼나”에 답하기 위해 남긴다. 영역별로 묶었고, 뒤에 뒤집힌 결정은 지우지 않고 “대체됨”으로 표시한다. 괄호 안 버전은 결정한 판이다.

| Cross-view 쌍 기하 오차 관절별 잡음 가중 | V1a(`1/KEYPOINT_NOISE_SCALE` 정규화 가중 평균·가중 중앙값) 채택, V1b(배율 직접 나눔)·V2(경계 병합)·V3(한 카메라 제외 투표) 기각·보류(v1.3 수정 39) | 픽셀 문턱(20 px·12 px)과 완전 연결·경계 보류 원칙을 그대로 두면서 하체·말단 흔들림으로 인한 쌍 기각만 줄여 4대 융합률을 +5.7%p(10/28)·+6.4%p(10/29 새 보정 holdout) 높이고 오병합 지표(D-G2-04·VIEW_SPLIT·0.5m 튐·D-G2-06)는 0건, 다중클러스터 ID 전환은 30~38% 감소(5.2). | 2.5D Homography 단독 | 3D로 확장 | 높이를 표현 못 해 떨어짐 시나리오를 다룰 수 없음 |

| 영상 I0 경로 | Direct TCP + Tier 0 TLS 종료 + 기기 토큰(v1.2 r4), 막힌 망(SSAFY 망)은 EC2 SSH 로컬 포워드 경유 + Pod 공개 포트 Direct TCP, 443 프록시는 최후 예비(v1.3 수정 44, S15P31A101-392) | 카메라별 연결로 한 카메라 지연이 다른 카메라를 막지 않음. SSAFY 망에서는 노트북→EC2(짧은 구간, 약 5 ms)만 SSH 하나를 같이 쓰고 EC2→Pod(약 41 ms)는 포워드된 연결마다 별도 Direct TCP 로 나가며 TLS 는 Tier 0 가 직접 종료한다. Pod 까지 단일 SSH 터널로 묶지 않고, Pod SSH(`ssh -J simai-ec2`)는 개발·운영 접속용으로만 쓴다 |
| Pod 접속 주소 | Tier 0 엔드포인트 등록 → 노트북은 EC2 에서 조회(v1.3) | RunPod 는 Pod 재설정 때 외부 포트 매핑이 바뀐다(3.12) |
| TLS 서버 확인 | 공개키 고정(또는 팀 사설 CA), 검증 끄기 금지(v1.3) | 공개 IP 포트라 중간자 공격을 막아야 하고, Pod 주소가 바뀌어도 키는 저장 위치에 남는다(컨테이너 디스크면 인스턴스와 함께 사라지므로 새 지문을 다시 고정, 12.7) |
| I5 분석 작업 연결 | 분석 워커가 EC2 에서 작업을 가져감(v1.3). 이전의 “EC2 → RunPod REST + HMAC 콜백” 결정은 대체됨 | Pod 로 들어오는 포트·IP 제한·HMAC 콜백이 필요 없다. TLS + 토큰으로 충분 |
| 아바타 포즈 스트림 구간(I6) | 분석 워커 → EC2 별도 WebSocket(`wss://<ec2>/ws/worker/avatar`, 워커 토큰)과 I2 `/topic/avatar`(v1.3 수정 29, S15P31A101-249) | I1 `world_state` 에 섞으면 Tier 0 단일 TLS 송신 큐에서 경보·상태 전달이 밀리고 프로세스 분리가 깨지며, I5 작업 대여는 사람별 2\~5 Hz 스트림을 감당하지 못한다. 포즈는 축각 라디안 회전만 싣고 위치는 `/topic/world` 정본을 쓴다(12.2, 12.4) |
| 배포 단위 기준 폴더 구조(ai/tier0 등) | 기능별 패키지로 변경(v1.2 r4) | Risk Engine은 Tier 0와 EC2에, Tier 0 기능은 현장 프로파일에도 배포된다. 기능별 패키지를 두고 배포 단위(services/)는 조립만 한다(21.1) |
| 실험 리뷰 방식 | 구현자와 독립된 Reviewer(v1.2 r4) | 구현자의 자기평가로는 재현성·계약 위반을 놓친다. 사람 또는 독립 리뷰 에이전트가 공통 체크리스트로 검증한다. 작업 도구는 명세에서 정하지 않는다 |

| 항목 | 결정 | 이유 |
|---|---|---|
| UNKNOWN 경보 등급 하향 | 제외 | 불확실 ≠ 덜 위험. 등급 유지 + “확인 필요” |
| “추락 리스크 85%” 수치 | 제외 | 보정되지 않은 LLM 수치. 등급 + 근거 조항 |
| 발생 지속 조건·이벤트 재개 | 채택(v1.3) | 순간 오검출과 경계 깜빡임을 줄인다. 3프레임 중 2프레임 지연은 G6 예산 안. 깜빡임 목표는 “10초 안 재발생 0건”으로 바꿈 |
| 반장 PWA·Web Push·조치 티켓 | 폐기(v1.3, 2026-10-31 팀 결정, 세부는 사용자 결정 2026-11-03). MVP 현장 전달은 노트북 로컬 경보·관제 화면 경보와 관제 화면 확인(ACK). G8 은 촬영 → 관제 화면 원격 전달(p95 1.2초)로 다시 정의. ACK 채널 값 `FOREMAN_PWA`·계약 `risk_alert`·DB 의 push·`TICKET_PHOTO` 는 남겨 두고 별도 이슈에서 정리 | 반장 휴대폰 경로를 쓰지 않기로 했고, 서버에 발송기가 없어 남은 명세가 구현과 어긋났다. 계약·DB 정리는 메이저 변경이라 명세 정리와 나눈다 |
| 시험 경보·시험 이벤트 | 시험 알림 별도 경로(v1.3). 노트북 로컬 시험음만 둔다(시험 푸시는 반장 PWA 와 함께 폐기) | 시험이 RiskEvent 가 되면 LIVE 만 실제 알림 규칙과 충돌한다 |
| 확인 대상 sequence | 확인은 확인한 사람이 본 event_sequence 를 대상으로 기록(v1.3 수정 4) | 등급 상향 전 상태에 대한 늦은 확인이 상향된 경보 소리를 끄지 않게 한다. 상향·재개는 다시 울린다(3.10) |
| 노트북 → EC2 하트비트 | 추가(v1.2 r4) | EC2 가 Tier 0 정지와 원격 전달 단절을 구분해 관리자에게 현장 경보 동작 여부를 알림 |
| 관제 화면 실시간 영상 | 현장 노트북 로컬 미리보기(v1.3 수정 34)와 로그인한 관리자 전용 EC2 경유 원격 시청(보는 사람 있을 때만 전송·EC2 무저장, v1.3 수정 46, 사용자 결정 2026-11-02)을 허용한다. 이전의 ‘원격 관제 화면 실시간 영상 제외(v1.2 r4)’와 ‘관제 미리보기 영상은 EC2 를 거치지 않음(v1.3 수정 34)’은 대체됨 | C110 RTSP 동시 접속 2세션 한도는 그대로 지킨다(중계가 이미 받은 1세션 스트림을 추가 RTSP 접속·디코딩·재인코딩 없이 127.0.0.1 루프백과 EC2 수신 WebSocket 으로 나눠 넘긴다). 원격 시청은 보는 관리자가 있을 때만(`cctv_remote_control` `demand active: true`) 전송하고, EC2 는 저장 없이 메모리에서 중계하며 동시 5명·월 80 GB·10분 무입력·30분 연속 시청·탭 비가시 차단으로 대역과 비용을 묶는다([cctv-remote-view.md](../design/cctv-remote-view.md)) |
| 클라우드 푸시 워치 알림 | 제외 | 지연 보장 없음. 지속 연결 + ACK(부록 C) |
| 앱 없는 워치 알림 | 전용 앱으로 대체 | 움직임 대조·ACK 불가. 지급 전 휴대폰 알림 미러링은 반장 PWA 폐기로 없어졌다(부록 C) |
| 워치 GPS 위치 대조 | 제외 | 수 m 오차, 실내 불가. 1\~2m 거리의 사람을 구분 못 함 |

| TBM 계획 작업 위치 | Risk Engine 컨테이너가 작업면·구역에서 자동 생성(기본), 요청에 직접 줄 수도 있음. 결과에 REQUESTED·GENERATED 로 표시하고 EC2 가 `sim.*` 에 저장(v1.3 수정 21, 사용자 결정) | 명세 8.3 의 레이아웃에는 사람 위치가 없어 사람 대상 규칙이 항목을 내지 못한다. 화면에서 위치를 받게 하면 레이아웃 편집 작업이 늘어 버림. 생성 위치는 추정이라 출처를 구분한다 |
| 사고 구간 요약 | M3, `incident_summary` 작업, 관리자 요청(v1.3 수정 13) | 최소 리플레이·VLM 근거와 같은 단계. 상향 의견을 내지 않고 보고서와 같은 우선순위 |
| VLM 입력 얼굴 흐림 주체 | 분석 워커, VLM 호출 직전(v1.3 수정 13) | 클립은 흐림 없이 저장되므로 프레임·클립을 한곳에서 처리하고 Tier 0 실시간 경로에 부하를 더하지 않는다. Tier 0 업로드 전 흐림은 이득이 작아 버림 |
| 상향 의견 적용 | 관리자 승인 → I1 `event_escalate` → Tier 0 UPDATED 전이(v1.3 수정 13) | LIVE 생명주기 정본은 Tier 0 다. EC2 가 등급을 직접 바꾸면 저널·현장 경보와 어긋난다 |
