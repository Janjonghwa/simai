# 16. 결정 기록

검토 후 제외·교체·보류한 항목과 이유다. 같은 논의를 반복하지 않고, “왜 이건 안 썼나”에 답하기 위해 남긴다.

| 항목 | 결정 | 이유 |
|---|---|---|
| PEAR (SMPL-X·FLAME) | 제외 | 1인 crop 구조라 다인원에서 느리고 가림에 약함(P1 확인). 고유 기여인 표정은 3m 높이 카메라에서 얼굴 30\~50px라 관측 불가 |
| SAM 3D Body + PEAR 동시 사용 | 제외 | 같은 양을 두 번 추정해 병합 경계(손목·목) 불일치가 생김. 프레임당 추정기 하나 원칙 |
| LHM++ (Gaussian 아바타) | 비채택(메시형 EXP-02와 구분) | 261016 목표는 실사형 메시 아바타이지만 Gaussian 아바타 LHM++를 현재 선택하지 않음. MHR 메시를 기초로 연속 관측에서 외형을 갱신하는 별도 실험. 개인정보/가림/비용 이슈는 그대로 관리 |
| Multi-HMR 2 주력 | 기준선으로 유지 | SAM 3D Body와의 직접 비교 근거가 없음. G5에서 판정 |
| SAM 3D Body | EXP-02 선행 실험 후 확장 채택 판단 | 기존 MVP는 2D keypoint 삼각측량·3D 골격 유지. Fast SAM 3D Body는 MHR 메시/포즈 및 외형 고도화 가능성을 별도 검증해 채택, Tier 0 위치 정본은 변경하지 않음 |
| MoGe-3 정적 형상 주력 | 대조군으로 강등 | 실측 K·pose를 입력으로 쓰지 못하고 뷰별 스케일이 흔들림(PoC 0.94\~1.23) |
| MapAnything 외부 백엔드(VGGT-Ω 등) | 비교군 | 외부 wrapper가 알려진 pose를 소비한다는 보장이 없음. Native 우선 |
| Tier 0 검출 모델 크기 | YOLO26x-pose (수정 5) | 운영 GPU H100 80GB 에서 x·1280·4대 동시 38 ms 로 충분하고 크기별 정확도는 공식 벤치마크로 확인됨. 노트북 6GB 측정으로 크기를 고르지 않는다. s 기준선 안은 폐기 |
| GS-Pool·3DGS-U 온라인 감지 | 선택 단계로 | GS-Pool은 두 3DGS 비교용이라 매 프레임 감지에 비효율. 단순 차분이 기준선 |
| 무한 기둥 점유 | 제외 | 바닥 투영이 틀리고 방 밖까지 위험 영역 확장. 방 형상으로 제한한 볼륨 사용 |
| Visual Hull 무조건 외접 가정 | 제외 | 마스크 누락·가림·보정 오차에서 실제 물체를 잘라냄. 팽창 실루엣 + 일관성 검사로 대체 |
| 1.2m 기본 높이 임시 OBB | 제외 | 실제보다 작으면 과소평가. 크기를 모르면 OBB를 만들지 않음 |
| UNKNOWN 경보 등급 하향 | 제외 | 불확실 ≠ 덜 위험. 등급 유지 + “확인 필요” |
| VLM의 신호수 경보 제외 판단 | 제외 | AI에게 경보 하향 권한을 주게 됨. 구별 표식 규칙으로 대체 |
| “추락 리스크 85%” 수치 | 제외 | 보정되지 않은 LLM 수치. 등급 + 근거 조항 |
| RealSense D405 추가 | 제외 | 이상 거리 7\~50cm, baseline 18mm 패시브 스테레오라 3\~10m에서 무의미. RGB 1280×720로 PPE 해상도 부족 |
| 워치 GPS 위치 대조 | 제외 | 수 m 오차, 실내 불가. 1\~2m 거리의 사람을 구분 못 함 |
| 엣지 GPU 장비 구매 | 노트북으로 대체 | 구매하지 않음. v1.2부터 Tier 0도 RunPod에서 처리하고 노트북은 중계·현장 경보 단말 |
| 체커보드·마커 보정 | 대체 경로로 | 설치 자동화 요구. 사람 기반 자동 보정 + 사람 키·표준 사물 스케일(수정 6) |
| 삼각측량·융합의 외부 GPU 처리 | 제외 | v1.2에서 Tier 0 전체를 RunPod에 두면서 검출과 같은 서비스에서 처리(중간 왕복 없음) |
| 클라우드 푸시 워치 알림 | 제외 | 지연 보장 없음. 지속 연결 + ACK |
| 앱 없는 워치 알림 | 단계적 대체 | 움직임 대조·ACK 불가. 지급 전 PWA 미러링, 이후 전용 앱 |
| Unreal 실시간 렌더 | 빌드 도구로만 | 사람과 배경이 다른 렌더러면 가림 불일치. Three.js 단일 렌더러 |
| Unreal 수작업 후처리 | 고정 레시피로 | 수작업은 Scene 버전 갱신마다 반복되고 재현되지 않음 |
| 2.5D Homography 단독 | 3D로 확장 | 높이를 표현 못 해 떨어짐 시나리오를 다룰 수 없음 |
| Risk Engine EC2 단독 배치 | 교체(v1.1) | 인터넷 단절 시 판정이 멈춰 안전 경로 독립과 양립하지 않음. Python 라이브러리 하나를 Tier 0 서비스(LIVE, v1.2부터 RunPod)와 EC2 컨테이너(계획·리플레이)에 배포 |
| 노트북에 최소 규칙만 Python으로 중복 구현 | 제외(v1.1) | Java·Python 이중 구현은 판정이 어긋날 위험. 단일 코드 공통 배포로 대체 |
| 실패한 Visual Hull을 UNKNOWN 볼륨으로 재사용 | 제외(v1.1) | 잘린 부분이 돌아오지 않음. 제약을 완화해 더 큰 볼륨으로 재계산 |
| VLM의 직접 심각도 상향 | 제안으로 변경(v1.1) | 오해석 시 불필요한 강한 경보. proposed_severity로 기록 후 규칙·운영자 확인 |
| Tier 0 노트북(엣지) 배치 | 클라우드로 변경(v1.2) | 노트북 GPU 제약을 없애고 노트북을 중계·현장 경보로 단순화. 대신 인터넷·RunPod 의존, 상시 영상 업로드·비용·개인정보 부담을 수용(17장). 엣지 구성은 DeploymentProfile ’현장’으로 되돌릴 수 있게 유지 |
| 대형 VLM 도입 | 채택(v1.2) | 이벤트 클립 이해, 사고 요약, 보고서 등 용도가 많아 소형 모델로는 한계. 권한은 제안만 유지, 후보 2개(Qwen3-VL, Cosmos 3 Reasoner)는 G7로 선택 |
| YOLO26 계열 통일 | 채택(v1.2) | pose·분류·seg를 한 프레임워크로 학습·내보내기·추론. 라이선스 AGPL-3.0(교육 프로젝트, 네트워크 서비스 배포 시 소스 공개 의무 유의) |
| SAM 3D Body로 Tier 0 포즈 대체 | 제외 | 사람별 crop 처리라 4대 다인원 매 프레임 실시간에 맞지 않음. Tier 1 강화로 두고 YOLO26-pose keypoint를 프롬프트로 받음 |
| 낙상을 YOLO 클래스로 학습 | 제외 | 높이 정보 없이 2D 모양만 보게 되어 앉기·물건 줍기와 구분이 더 어려움. 3D 골격 규칙(R4) 유지 |
| PPE 분류 우선 | 검출 우선으로 변경(v1.2 r2) | 분류로는 안전모가 머리에 쓰였는지 손에 들렸는지 구분하기 어려움. 검출로 위치 관계를 판단 |
| 영상과 메타데이터 분리 채널(I0) | 같은 메시지에 헤더 + 프레임(v1.2 r2), 카메라별 연결(v1.2 r3) | 도착 시점 차이로 촬영 시각이 다른 프레임에 붙을 위험. 같은 메시지에 실어 결합을 구조적으로 보장 |
| DeepStream MV3DT 직접 도입 | 보류 | 기본 검출기 구성이 달라 YOLO26 Python 서비스에 그대로 붙지 않음. 원칙만 Python으로 구현, 성능상 필요할 때 재검토 |
| 발목을 접지점으로 사용 | 제외(v1.2 r2) | COCO 17관절에 발 접촉점이 없음. ContactEstimator로 분리 |
| RunPod 글로벌 볼륨(베타) | 제외(r4 수정 1) | 객체 저장소 기반이라 원자적 rename·파일 잠금이 없고 최종 일관성이다. 저널 계약(추가 전용 + fsync)과 맞지 않고, 물리적 저장 위치를 특정할 수 없어 동의서에 보관 위치를 적을 수 없다 |
| 여러 리전 동시 운영 | 제외(r4 수정 1, 4) | 크레딧 관리. 2026-10-16부터 개발·시연 모두 일본 리전 |
| 시연 리전 | 일본 AP-JP-1 H100(r4 수정 4) | 캐나다 개발 환경에서 종단 지연이 커서 개발부터 일본으로 옮김. 일본 GPU를 못 구하면 다른 등급 → 미국 순으로 대체 |
| Tailscale(노트북↔RunPod) | 제외(r4 수정 4) | SSAFY망에서 DERP 중계를 타 업로드 2.4 Mbps. SSH 직접 연결 기본, HTTPS 프록시 443 예비 |
| Tier 0와 분석 워커의 GPU Pod 분리 | 단일 GPU Pod로 변경(r4 수정 2) | 크레딧 관리. 프로세스 분리와 자원 상한, Tier 0 우선 규칙으로 격리하고 영향은 G0에서 잰다 |
| 실험 리뷰 방식 | 구현자와 독립된 Reviewer(r4 수정 2) | 구현자의 자기평가로는 재현성·계약 위반을 놓친다. 사람 또는 독립 리뷰 에이전트가 공통 체크리스트로 검증한다. 작업 도구는 명세에서 정하지 않는다 |
| 관측 기반 외형 갱신(EXP-02) | 실험(r4) | PEAR 제외 근거(3m 높이에서 얼굴 30\~50px로 표정 관측 불가)는 그대로 유효하며 표정·얼굴은 계속 범위 밖이다. 몸 전체 외형은 4시점의 누적 관측으로 개선될 수 있다는 가설을 EXP-02에서 검증한다. 개선이 없으면 포즈만 부분 채택하거나 HOLD |
| 배포 단위 기준 폴더 구조(ai/tier0 등) | 기능별 패키지로 변경(r4 수정 2) | Risk Engine은 Tier 0와 EC2에, Tier 0 기능은 현장 프로파일에도 배포된다. 기능별 패키지를 두고 배포 단위(services/)는 조립만 한다(21.1) |
| 영상 I0 경로 | Direct TCP + Tier 0 TLS 종료 + 기기 토큰(수정 6) | 카메라별 연결로 한 카메라 지연이 다른 카메라를 막지 않음. SSH 터널은 개발·운영 접속용 |
| 지연 초과 시 GPU 분리 | 제외(수정 6) | 단일 GPU Pod 유지. 분석 워커 축소로 대응 |
| 노트북 → EC2 하트비트 | 추가(수정 6) | EC2 가 Tier 0 정지와 원격 전달 단절을 구분해 반장·관리자에게 현장 경보 동작 여부를 알림 |
| 관제 화면 실시간 영상 | 제외(수정 6) | 영상은 EC2 를 거치지 않음. 설치·점검은 노트북 미리보기, 운영 확인은 상태 패널·이벤트 클립 |
| 실측 평면도(World 기준·스케일·G4 기준) | 제외(수정 6) | 시연 현장에서 미리 만들 수 없고, 메인 공간 표현은 MapAnything 디지털 트윈이다. 평면도는 정확도 목표 없는 BEV 보조 화면으로 바꾸고, 절대 정확도는 개발 교실 줄자 실측으로 판정 |
| 스케일 근거 | 실측 정물(시연용 안전봉·라바콘 등) 1순위(수정 6) | 시연 때 줄자를 펼치기 어렵다. 미리 잰 단단한 장비를 놓으면 현장 실측 없이 약 1% 스케일을 기대할 수 있다. 탐지 물체 통계는 같은 규격 편향이 평균으로 줄지 않아 보조로만 씀 |
| Local Tracker 기본값 | TrackTrack(수정 7) | 공식 벤치마크(MOT17·MOT20·DanceTrack)에서 ByteTrack 보다 좋고 Ultralytics 에 들어 있음. 비교 실험 없이 기본값으로, ByteTrack·BoT-SORT + ReID 는 설정 전환. 교실 ID 성능은 G2·A0 로 확인 |
