# 13. 뷰어

Three.js가 유일한 렌더러다. 배경·사람·구역·경보·PPE(확장 시 장비)가 같은 장면과 깊이 버퍼에 있어야 책상 뒤 사람의 가림이 맞기 때문이다. 뷰어는 경보 경로가 아니며, 뷰어가 멈춰도 경보는 계속된다.

## 13.1 장면 구성

| 요소 | 표현 |
|---|---|
| 정적 배경 | 현장 세팅 직후 구역을 그리는 단계에서는 **빠른 3D 미리보기 맵(`preview_scene`)**을 먼저 띄우고, 구역을 그리는 동안 뒤에서 `texrecon` 정밀 텍스처 굽기가 끝나면 정식 정적 3D glTF(MapAnything + Open3D TSDF + `texrecon` 디지털 트윈, 확장 시 Unreal에서 조명을 구운 glTF)로 매끄럽게 교체한다(4.3, 5.3). 사진 텍스처가 있는 배경 메시는 이중 조명·톤매핑 왜곡을 막기 위해 비조명 재질(`MeshBasicMaterial`, `SRGBColorSpace`, `toneMapped: false`, `DoubleSide`, 캔버스 `NoToneMapping`)로 그리고, 정합 미확인(`DIMMED`) 때는 알파 정렬이 깨지지 않게 불투명(깊이 가림 유지) 상태에서 명도(0.65)·채도(0.25)만 낮춘다(무텍스처 메시는 기존 반투명 0.35 + 법선 계산). 표면 출처 지도(`surface_source_map_urls`)가 있으면 최근접 샘플링으로 관측(`2`)·추정 평면(`3`)·보간(`1`)·미관측(`0`, 어둡게 + 사선 빗금)을 구분 표시하며, 선택 후처리(`N8AO` + `SMAA`, 기본 꺼짐)를 지원한다(`docs/design/viewer-background-quality.md`). 정적 3D 전에는 BEV 평면도 바닥 이미지. 2D 개요 화면은 BEV 평면도 |
| 사람 | 기본·폴백은 Tier 0 골격의 관절 사이를 잇는 캡슐/막대 아바타(InstancedMesh). 시연 범위(EXP-02)에서는 `/topic/avatar`(`avatar_frame`)로 받는 MHR 리깅 메시(Three.js SkinnedMesh)와 포즈 스트림을 점진 도입한다(1단계 MHR 리깅 메시 + 포즈 스트림·상하의 대표색, 2단계 관측 픽셀 UV 텍스처 누적, 3DGS 미사용). 사람의 존재·root 위치·접지·관측 상태·안전 판단 근거는 계속 `/topic/world`(Tier 0)가 정본이다 |
| 작업면·정적 객체 | 고소 작업면(`WORK_SURFACE`)은 화면에서 `HIGH`(주황) 위험구역과 같은 시각 스타일(반투명 주황 + 상판 가장자리 선·높이 라벨)로 그리되, 내부 데이터는 작업면 OBB 와 `top_height_m` 을 그대로 유지한다(R2·R3·접지 높이 근거 보존, 관리자가 편집 모드에서 그리면 작업면 OBB + 둘레 `HIGH` 구역 동시 생성, 7.5·8.2) |
| 구역 | 반투명 입체(다각형 + 높이 범위), 심각도 2종 색(`CRITICAL` 빨강, `HIGH` 주황 — 단순 표시용 "작업구역"과 구역 `CAUTION`·`INFO` 선택지는 두지 않으며, 이벤트 심각도 `CAUTION`·`INFO` 와는 별개, 7.2·8.2). 작업 중 카메라 회전·이동으로 시야(FOV)에서 벗어난 구역은 R7 감시 저하(`CAUTION`, 사선 빗금)로 표시한다(4.4) |
| 경보 | 대상 아바타 강조 + 이벤트 목록, 같은 사람의 여러 규칙은 한 묶음. 진행 중인 작업이 없을 때(관제 대기)나 현재 작업 대상 구역 밖에서 발생한 진입 경보도 100% 똑같이 울리고 **“작업 외 진입”** 배지를 함께 표시한다(경보는 작업 상태로 절대 숨기지 않음, 8.1) |
| 장비·불확실 점유 | 확장(부록 C) |

## 13.2 상태 표시 규칙

- 관측 상태: OBSERVED 실선 / PREDICTED 반투명 + 예측 궤적 / UNKNOWN 마지막 위치에 물음표 표식(아바타 제거하지 않음). 위치가 확실하지 않은 트랙(`PREDICTED`, 카메라 1대이고 접지점 미확인, `IDENTITY_UNCERTAIN` 등 R1 확실한 위치 조건 미충족, 7.1·8.2)은 이벤트·경보를 만드는 대신 3D 관제 화면의 사람 표시에만 “위치 불확실”을 흐리게 표시한다(뷰어 후속).
- 관절 가시성이 거짓인 관절은 흐리게 처리한다. 아바타는 접지가 확인되면 발을 ground_anchor_xyz에 맞추고 발아래 지지면(`ground_anchor_xyz`)에 방사형 접지 그림자(`GroundShadowLayer`)를 그리며, 접지가 미확인이면 그림자를 숨기고 pelvis_xyz 기준으로 배치하며 “접지 미확인”을 표시한다(5.2, `docs/design/viewer-background-quality.md`).
- MHR 메시 아바타 구동(`/topic/avatar`): 사람의 존재·위치·접지·관측 상태·ID 신뢰도는 `/topic/world` 만 따른다. root 위치는 지연 없이 `/topic/world` 최신 위치(접지 VALID 면 발을 `ground_anchor_xyz` 에 맞춤)를 쓰고, 관절 회전(축각 라디안, null 은 bind 회전)만 재생 지연 버퍼 D = 250 ms 로 두 표본 사이를 slerp 한다(외삽 금지, Three.js 좌표 변환은 어댑터 한 곳에서만 수행). 외형은 텍스처가 없으면 기본 재질(상·하의 대표색)과 아바타 전용 소형 PMREM 환경맵으로 그리고, `albedo.png`(`SRGBColorSpace`, `LinearFilter`)와 `surface_source.png`(`NoColorSpace`, `NearestFilter`, 밉맵 없음)가 있으면 사람·버전별로 두 장이 모두 준비될 때 깜빡임 없이 교체해 부호별로 표시한다: `2`(관측)·`1`(보간) 원본 색, `0`(미관측)은 같은 UV 섬·상하 부위(바인드 높이 0.88 m 경계)의 관측·보간 색으로 채워 그리고(부위에 관측이 없으면 인접 부위·같은 상하 관측 색의 중앙값, 그것도 없으면 기본 재질), `128`(얼굴 미관측)은 관측 얼굴(`EXCLUDED` 면 쓰지 않음) 또는 목 피부의 단색 평균(이목구비·무늬 없음, 없으면 기본 재질), `130`(얼굴 관측)은 `face_policy` 에 따라 `OBSERVED` 원본·`BLURRED` 얼굴 관측 텍셀 한정 3×3 가우시안+채도 완화·`EXCLUDED` 기본 재질로 그린다(20.3, `docs/design/avatar-pose-stream.md`). 채우기는 표시만이다: 사람 × `appearance_version` 마다 한 번 표시용 albedo 를 만들어 그 버전이 준비된 같은 갱신에서 바꾸고, `surface_source`·비율·계약·저장은 그대로라 관측 범위는 출처 지도로 본다(화면에서는 관측과 채운 면을 구분하지 않는다, 2026-11-15 사용자 결정, `docs/design/S15P31A101-742-avatar-fill-display.md`). 아래 5조건 중 하나라도 해당하면 그 사람은 즉시 캡슐 아바타로 되돌아가고, 해소되면 다음 포즈부터 다시 메시로 그린다(세부는 `docs/design/avatar-pose-stream.md`·`contracts/`).
  1. 새 포즈 수신이 0.5 s 넘게 끊김
  2. HMR 촬영 시각 지연(`world_state` 최신 시각과의 차)이 500 ms 초과(상태 표시줄에 데이터 연령과 함께 표시)
  3. 포즈의 `identity_revision` 이 트랙과 다르거나(단, 순수 병합 `pure_merge` 시에는 직전 메시·외형을 새 revision 으로 이어감, 5.6), 같은 revision 에서 `IDENTITY_UNCERTAIN` 이 `1.5 s`(`AVATAR_IDENTITY_HOLD_MS = 1500`) 넘게 이어짐(`docs/design/S15P31A101-661-merge-carryover.md`). 포즈 차수가 트랙 차수보다 작아도 순수 병합으로만 오른 차수 사슬의 시작 차수 이상이면 같은 사람의 포즈로 보고 끊김·늦음 기준을 1.5 s 늘려 마지막 자세로 둔다(분할·별칭 없는 상승은 캡슐, `docs/design/S15P31A101-743-avatar-appearance-continuity.md`)
  4. 포즈의 `calibration_version` 이 `world_state` 와 다름
  5. 아바타 자산이 없거나 내려받기·무결성·관절 수 검증 실패
- **사람·워치 운영 표시 이름, 3D 이름표 칸(`LabelCell`) 구조 및 표준 한국어 명칭(11.4-5, 12.4, 14장):**
  - 3D 관제 이름표는 `world_id`·`device_id` 원문 문자열 대신 **`[워치 상태 아이콘 칸 | 운영 표시 이름 칸 | 선택 PPE 상태 칸]`** 배열 렌더러로 그린다(워치 연결 시 하늘색 스마트워치 아이콘, 끊김 시 회색 아이콘+빨간 점, 미배정 시 아이콘 칸 생략, `docs/design/S15P31A101-658-person-name-label.md`). 표시 이름 해석 우선순위는 당일 관리자 수동 지정(`WORLD_MANUAL`) > 배정 워치 기기 표시 이름(`WATCH_DEVICE`, 현장 지속 권장) > 당일 자동 일련번호(`UNIDENTIFIED`, `"미확인 N"`)이며, 동명이인이 있을 때는 공간 위치가 없는 2D 텍스트 목록·경보 배너·워치 알림에만 짧은 식별자를 괄호로 덧붙이고 작업자 선택 시 우측 `PersonDetailPanel` 에서 이름 출처·동명이인 배지·배정 워치 기기 ID·현재 `World ID` 조회 및 관리자(`ADMIN`) 인라인 이름 변경·초기화를 제공한다.
  - 순수 병합(`aliases` 에 직전 `world_id` 포함, `split_from` 없음, 5.2)이 일어나면 뷰어의 선택·포커스 대상과 CCTV 인물 따라가기 대상이 생존 `world_id` 로 자동 승계되며, 상단 바의 추적 인원 수는 `TENTATIVE`·`LOST` 를 제외한 **`CONFIRMED` + `OCCLUDED` 트랙만** 집계한다(`docs/design/S15P31A101-661-merge-carryover.md`).
  - 카메라(`cam_A`~`cam_D` 및 `cam1`~`cam4` → `카메라 1`~`카메라 4`), 규칙(R1~R11), 위험 등급 명칭은 3D 뷰어·이벤트 카드·경보 배너·워치 알림 전반에서 한국어 표준 표시 이름(3.10·7.2)으로 통일하며, 병합 흡수 마감(`resolution.kind = "IDENTITY_MERGED"`, 6.4·12.4)된 이벤트는 운영자 종료와 구분해 `중복 추적 병합 정리`로 표시한다(`docs/design/S15P31A101-660-alert-camera-names.md`).
- “확인 필요” 이벤트는 이유(`confidence_reasons`, 7.1)와 불확실성 범위를 함께 보여준다.
- 데이터 연령(staleness), System Health, 그리고 **Tier 0 최근 5초 롤링 평균 처리 지연(`pipeline_lag_ms`, `> 600 ms` 시 강조, 미수신·모름이면 비움)**을 화면 상단 바와 카메라별 상태 카드에 표시한다(프레임 연령만으로 오탐을 내던 카메라 카드의 `'정지'` 배지는 두지 않음). EC2 연결(STOMP 하트비트)이 끊기면 연결 끊김을 표시한다.
- **관제 중 회전 자동 복구(`rotfix`)와 틀어짐 상태 표시(4.4, 4.5):**
  - 작업(LIVE 관제) 중 카메라가 살짝 돌아가 중심 고정 회전 자동 복구(`rotfix`)가 적용되면 카메라 중심과 World 좌표계가 바뀌지 않으므로 정적 3D 배경(Scene)을 제 색 그대로 유지하고 상태 표시줄에 보정 버전 갱신만 알린다.
  - 반면 카메라 위치가 옮겨졌거나 매칭이 깨질 만큼 크게 돌아가 자동 복구할 수 없을 때는 정합이 깨진 배경을 흐리게(`DIMMED`) 표시하고 시야에서 벗어난 위험구역을 R7 감시 저하(`CAUTION`, 빗금) 및 시스템 보정 상태(`DRIFTED`)로 알린다(관제 화면 상단을 가리던 고정 장애·재세팅 배너 띠는 제거, `docs/design/S15P31A101-652-session14-ops.md`).
- 현재 Scene 버전과 배경 자산 버전이 다르면 경고한다. 현장 세팅 중 백그라운드 `texrecon` 이 완료되거나 관리자가 새 Scene 버전을 활성화하면 서버 재기동 없이 `/topic/health`(`viewer_health.scene.mismatch`)에 반영되어 열린 뷰어가 새 배경 자산을 로드한다(`docs/design/scene-version-from-job.md`, `docs/design/site-setup-pipeline.md`).
- 교실 테스트베드와 시연에서는 현장 규칙 기준을 교실 시험 프로파일(`CLASSROOM_TEST`, 높이차 `0.35 m`, 7.4)로 고정해 화면에 `교실 시험 기준 · 0.35m` 안내를 표시하며, 관제 상단 바의 규칙 기준 전환 UI 는 두지 않는다(`docs/design/S15P31A101-669-rule-profile-classroom-fixed.md`).
- 워치 상태 아이콘과 “추적 인원 vs 활성 워치 수” 표시는 부록 C.6 을 함께 따른다.

## 13.3 PPE 표현 (MVP, M3)

- 뷰어는 같은 World ID·`identity_revision` 의 PPE 상태에만 미리 만든 모델을 붙인다: WORN 은 실물 표시, UNKNOWN 은 모델 없음, NOT_WORN 은 모델 없음 + 경고 표식. UNKNOWN 을 같은 형상의 반투명·외곽선으로 그리면 관제 거리에서 착용과 구분되지 않으므로 그리지 않는다(위치 UNKNOWN 의 물음표 표식과도 섞지 않는다). 크기는 3D 골격의 어깨 폭·몸통 길이·머리 크기로 맞추고, 좌표 변환은 뷰어 어댑터 한 곳에서만 한다(4.2).
- 근거가 만료되거나 EC2 연결이 끊기면 UNKNOWN 으로 보인다. 순수 병합(`pure_merge`, 5.5) 시에는 직전 ID 의 상태를 생존 ID·새 `identity_revision` 으로 이어받되, 분할이나 새 사람에게는 이전 ID 의 상태를 넘기지 않는다(`docs/design/S15P31A101-661-merge-carryover.md`). 착용이 아닐 때(미착용·모름) 3D 사람 이름표 오른쪽 텍스트 칸(13.2)에 장비별 상태를 글로 보이고, 모름에는 마지막 근거 시각(10초·1분 단위) 또는 EC2 연결 끊김을 붙인다. 둘 다 착용이면 글 없이 실물만 보인다.
- 사람 표현이 캡슐·골격·상시 HMR 아바타(EXP-02) 중 무엇이든 같은 규칙으로 붙인다. 안전모·조끼 모델은 골격 막대면 귀·어깨·골반 관절로 자리와 크기를 맞추고, 캡슐·아바타 메시 사람이면 캡슐 몸의 고정 자리에 둔다. 높이 모름 기둥에는 장비 없이 경고 표식만 둔다. 아바타 메시 머리 정밀 맞춤은 하지 않는다(`docs/design/ppe-viewer.md`).
- 상태는 `/topic/ppe`(`ppe_view`, 12.4)로 받는다.
- PPE 표시는 경보가 아니다. 경보는 R9(안전모)·R11(조끼) 이벤트로만 나간다(7.3).

## 13.4 화면

- **기본 진입 경로와 상단 내비게이션:** 관제 웹앱 루트(`/`)는 **작업 관리(`/work`, 예전 `/tbm` 호환 리다이렉트)**로 연결되며, 상단 메뉴 순서도 작업 관리 → 실시간 3D 관제(`/live`) → 지난 작업 다시 보기 순으로 현장 운영 흐름(작업 생성·세팅·구역·TBM → 관제 시작)을 따른다(8.3).
- **현장 세팅 화면 및 대기·카메라 확인·구역 검토 표시(`POST /api/setup-sessions`, `GET /api/setup-sessions/{id}`, `/zones`·`/seed`·`/complete`, `/retry`, `docs/design/site-setup-pipeline.md`):**
  - 작업을 시작하기 전 여는 화면이며, 보정 최적화 자체에는 걷기 단계가 없다. **세팅 1단계(카메라 연결·각도 확인)** 에서는 카메라 4대 실시간 미리보기와 함께 게이트웨이 별도 CPU 프로세스가 계산해 올린 **카메라 각도 헬퍼 결과(`GET /api/cameras/coverage-guides`, `coverage_guide` 1.0.0)** — 4대 연결 배지(`CONNECTED`·`DISCONNECTED`·`UNKNOWN`), 6쌍 매칭 등급(`ENOUGH`·`WEAK`·`LACK`·`UNKNOWN`), 카메라별 수신 상태(`OK`·`NO_VIDEO`·`STALE`) 및 회전 방향·크기 안내(`LEFT`·`RIGHT`·`UP`·`DOWN`·`NONE`, `SMALL`·`MORE`·`NONE`) — 와 카메라별 실측 높이 입력칸(**직전 세팅에서 입력한 높이 값이 자동으로 채워져 표시됨**, 처음이라 값이 없으면 빈칸·입력 필수), 필요 시 사각지대 보강용 보조 촬영 파일 업로드를 보여준다. 각도 헬퍼는 이 1단계 화면이 열려 있는 동안에만 계산되며, 세팅 시작을 막지 않는다(`DISCONNECTED` 나 헬퍼 미수신 상태여도 **“그대로 진행”** 가능하며, 헬퍼의 `"CONNECTED"` 는 시야 연결 안내일 뿐 `CALIBRATED` 보정 성공이 아니다). 1단계의 맵 방식 선택은 `새 맵 만들기(기본 · 약 13분)` / `이전 맵 재사용(약 1~2분)` 순서이고 재사용은 관리자가 고를 때만 쓴다(진행 중 세션의 요청 방식 복원은 유지, S15P31A101-762). 옆 쌍이 Stage A 기준에 못 미치거나 흔들리면(`stage_a_readiness`, 4.3 0단계) 「지금 할 일」·배경 촬영 창·「자세히 · 카메라 상태」에 경고와 방향 안내를 보이되 「시작」은 막지 않고, 기준 시점을 아는 카메라 칸에는 십자선·목표 점(ALIGNED 초록·NEAR 노랑)·「오른쪽으로 1.2° · 위로 0.4° 돌려 주세요」 같은 교정 문구와 「기준 사진 겹쳐 보기」(기본 끔, 50%)를 두며, 4칸 모두 초록이면 「기준 시점과 같음 — 이전 맵 재사용도 안전」, 모두 노랑 이상이면 「새 맵 세팅 시작해도 됨」을 카드 머리에 보인다(`aim_check`, 결과가 오래되면 각도·초록을 지움, `docs/design/S15P31A101-761-helper-stage-a-criteria.md`, `docs/design/S15P31A101-765-aim-reference-overlay.md`).
  - 관리자가 **“현장 세팅 시작”**을 누르면 **2단계 진행·검증 화면**으로 전환되어 단계별 상태, **시간 추정이 아닌 실제 하위 단계 완료 기준 단조 진행률(`progress_pct`)과 현재 단계 경과 시간(`초`·`분 초`)**, 카메라별 배경 수집률을 실시간으로 보여준다. 보정이 발행(`65%`)되면 **「카메라 확인」 카드**(1명이 작업 영역을 30~60초 걸어 다닐 때의 측정 진행률·카메라별 관측 배지·원인 안내)와 **6쌍 「쌍별 검증」 표**(홀드아웃 중앙값/p90 px, 사람 통과율, 통과·실패·확인 중 판정)가 함께 표시되며, **정밀 맵 완료와 카메라 확인 통과(`camera_check_passed = true`)가 모두 충족되어야** 다음(구역 검토·발행 및 세팅 완료) 버튼이 켜진다(`docs/design/S15P31A101-646-setup-camera-check.md`). 재생 시험 스위치로 걷기를 건너뛴 세션(`SKIPPED_REPLAY`, 4.3)은 걷기 창 없이 「재생 시험: 걷기 확인 생략」을 한 줄로 보인다.
  - **세팅 구역 확인·편집 단계**에서는 VLM 위험구역·작업면 초안(“AI 초안”)과 함께 이전 세팅에서 고정 좌표계로 이어받은 미확인 구역(`needs_review = true`, 새 맵은 「이전 구역 불러오기」를 눌렀을 때만 이어받음, 8.2. AI 초안과 같은 자리인 이어 온 구역은 한 행으로 짝지어 「이전 것 유지」·「AI 초안으로」 중 하나를 고르게 하고, 초안이 0건이면 직접 그리거나 이전 구역을 불러오라고 안내)을 **`변경 의심(CHANGE_SUSPECTED) → 모름(UNKNOWN) → 변화 없음(UNCHANGED)`** 순으로 정렬해 보여주며, **`UNCHANGED` 구역에만 일괄 확인 버튼**을 두고 `CHANGE_SUSPECTED` 구역에는 로컬 VLM 전후 비교 의견(`KEEP` 유지·`MODIFY` 범위 수정·`REMOVE` 해제 배지 및 한국어 한 줄 근거)과 전/후 고정 카메라 크롭 비교 모달을 띄운다(자동 변경 없음, `docs/design/S15P31A101-630-zone-height-change.md`, `docs/design/S15P31A101-631-zone-vlm-opinion.md`).
  - 배경 수집 미달, 인접 쌍 특징점 부족, 바닥 평면 검출 실패, 품질 게이트(`quality_gate`) 또는 카메라 확인(`camera_check`) 미달 시에는 구체적인 실패 원인과 현장 조치 안내 및 **“다시 시도”** 버튼을 표시하며, 통과하기 전에는 구역 발행과 작업 시작(LIVE)을 막는다. 보조 촬영 파일이 고정 카메라와 정합됐으나 품질 관문 등으로 맵에 쓰이지 않은 경우에는 `붙지 않음 · 화면과 맞췄지만 품질 기준에 걸려 넣지 않음`(`REGISTERED_NOT_USED`)으로 구분 표시한다(`docs/design/S15P31A101-652-session14-ops.md`).
- 실시간 관제(`/live`, 관리자 구역·작업면 편집 모드·새 물체 안내·수동 맵 재생성 버튼 포함): 3D 장면(빠른 미리보기 맵 → 정식 텍스처 Scene 자동 교체), 작업 세션 연동 바(`IN_PROGRESS` 작업이 없으면 “진행 중인 작업 없음 · 관제 대기” 및 현재 작업 이벤트 목록 비움, 작업 시작 시 해당 작업의 현장 세팅·구역·배치·담당 조 및 작업별 보호구 의무 상태 `WorkPpeStatus` 탑재, 비작업 중/구역 밖 위험 진입 시 정상 경보 + “작업 외 진입” 배지), 작업 중 새 물체 감지 시 추정 상자·“새 물체 감지 · 위험 검토 필요”(`CAUTION`) 안내(및 VLM 초안, 관리자가 클릭으로 장애물 등록·위험구역 발행 시 즉시 판정 반영, 추정 자체는 판정 미사용, 후속), 관리자 전용 수동 **“맵 재생성”** 버튼(`POST /api/scenes/regenerate` → I5 `scene_regenerate` 로 그때까지 쌓인 사람 지운 배경 기반 전체 재구성 후 새 `CANDIDATE` 활성화, 5.3·12.5·12.6, S15P31A101-427·-428), 이벤트 목록·상세(VLM 상향 제안 승인·거절 `EscalationControl` 포함, 5.4·12.6. 「최근 해소」는 관측 해소·운영자 종료·병합 흡수만 보이고 EC2 마감(6.4)은 빼며, 상태·타임라인 문구는 `작업 종료로 마감`·`GPU 세션 종료로 마감`·`Tier 0 기록 없음으로 마감`으로 관측 해소와 구분한다, `docs/design/S15P31A101-722-auto-close-open-events.md`), 사람 상세 패널(`PersonDetailPanel`, 13.2), 상태 표시줄. **별도의 구역 편집 페이지는 두지 않으며**, 이 화면 안에서 **`ADMIN` 편집 모드**로 위험구역(`CRITICAL` 빨강·`HIGH` 주황 2종; 안전모·조끼 착용 의무는 구역이 아니라 작업 단위로 지정, 8.2·8.10)과 고소 작업면(그리면 작업면 OBB + 둘레 `HIGH` 구역 동시 생성, 7.5·8.2)을 편집하고 `POST /api/zones/commit` 으로 저장·발행(`config_bundle` 발행이 곧 확정)한다(`docs/design/work-session-flow.md`).
- 작업 관리(`/work`, 구 TBM 페이지 승격, F-02): **세팅 → 구역 → TBM → 시작(관제) → 종료 → 마무리 → 서명**의 7단계 작업 생명주기를 관리한다. 작업(`work_unit`) 생성·수정 시 장비별 보호구 착용 의무(`안전모`·`조끼`, 기본 둘 다 체크, 8.10)를 설정하고, 현장 세팅(`/api/setup-sessions`)과 구역 발행(`/api/zones/commit`)이 끝나면 그 구역 위에서 개구부·비계·장비 가상 레이아웃(`/api/layouts`)과 TBM 보고서 초판(`/api/reports/tbm`)을 생성·조회하며, 작업 시작 전 확인 모달에서 안전모·조끼 착용 의무 체크박스를 최종 확인한 뒤 **“작업 시작”**(`POST /api/work-units/{id}/start`, `PLANNED` → `IN_PROGRESS`, `ppe_policy` 1.2.0 발행, `docs/design/S15P31A101-654-ppe-r3-demo.md`)과 **“작업 종료”**(`POST /api/work-units/{id}/end`, `IN_PROGRESS` → `DONE`, 실제 시작·종료 시각 기록)를 수행한다. 작업 종료 시 진행 구간·구역 LIVE 이벤트 요약 기반 “작업 마무리” 자동 채움(새 `report_version` 저장)과 참석자 전자서명(실명·손글씨 서버 전용 저장, 버전 잠금·`content_sha256`, `"공인 전자서명 아님, 내부 기록용 전자 서명"` 표기, 8.3·14장)을 제공한다. 지난 날 이벤트 로그는 관제 이벤트 카드와 같은 묶음 함수로 줄을 만들고(같은 위험 = 규칙·구역별 시각 순, 같은 사람이거나 앞 줄 끝에서 60초 안이면 한 줄, 지난 기록이라 살아 있는 사람 없음으로 묶어 트랙 번호만 바뀐 같은 초 경보는 「×n」 한 줄), 사람은 내부 트랙 ID 대신 `작업자 #0010`(여럿이면 「외 n명」, 원래 World ID 는 hover)으로 보인다. 줄 수가 사건 수이고 머리에 `사건 m (경보 n)` 을 쓴다. 달력 칸·월간 요약·종료 미팅도 같은 규칙으로 서버가 센 사건 수(작업 응답 `incident_counts{CRITICAL,HIGH}`, 사건 등급 = 든 경보 중 가장 높은 등급, `event_counts` 와 같은 범위)를 보이고 경보 기록 수는 hover·괄호로 곁들이며, 종료 미팅 문장 끝에는 서버가 「관제 카드 기준 사건: 위험 a건·경고 b건」 한 줄을 덧붙인다. 기록·이벤트는 바꾸지 않는 표시·읽기 집계다(7.4, `docs/design/S15P31A101-751-past-event-log-grouping.md`).
- 최소 리플레이·작업 다시 보기(M3): 시각 슬라이더로 `world_track_state`·`risk_event` 재생, 지난 작업(`DONE`) 구간 다시 보기(`/api/work-units`, 당시 작업의 보정·Scene·구역 계보 사용). 기본 조회 범위는 당일 전체가 아니라 **`actual_started_at ~ actual_ended_at`**(작업 시작 = 관제 시작, S15P31A101-679, 8.5)이며, 관제 종료 뒤 게이트웨이가 올린 카메라별 작업 구간 녹화 조각(`GET /api/videos`, 14일 보관, 5.1·11.5·12.6)이 있으면 타임라인 시계에 맞춰 S3 `<video>` 영상을 동기 재생하고 아직 올라오지 않았거나 만료된 구간은 3D 관제 모의 시점 폴백으로 표시한다(`docs/design/S15P31A101-668-recording-s3-playback.md`). 기록 없는 구간은 “데이터 없음”으로 표시하며, 이벤트 점프·재생 속도·버전 재현은 확장(부록 C)이다.
- 시스템 상태: 카메라·Tier 0·보정(현장 세팅 상태 및 회전 자동 복구 이력 포함)·지연·구성 묶음 동기화 상태 화면
- 시뮬레이션·What-if(확장, 부록 C): PLANNED·WHAT_IF 결과 표시. 실시간 화면과 시각적으로 구분한다.

## 13.5 성능 목표

\[MVP 캡슐 아바타\] 아바타 10명에서 30 FPS 이상(G5). 발 위치 정확도는 뷰어가 아니라 Tier 0 지표로 잰다: 지지 표면이 확인된 프레임에서 관측 발목 Z − 지지면 Z(G5). \[EXP-02 HMR(시연 범위)\] 동일 입력에서 별도 추론 지연·메시 갱신 빈도·VRAM·렌더링 FPS를 E-GATE-0~3 으로 검증하며(지연·끊김 시 캡슐 아바타 폴백, 13.2·20.6), 기본 G5 목표를 자동 변경하지 않는다.

## 13.6 비상 화면

Three.js 뷰어가 멈췄을 때를 대비해, World 상태만으로 그리는 가벼운 2D 평면 상태 화면을 둔다. BEV 평면도 2D 개요 화면(4.1)과 같은 컴포넌트로 만든다. 무거운 렌더러 장애가 상황 인식 장애가 되지 않게 하기 위함이다.
