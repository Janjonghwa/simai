# 부록 C. 확장 트랙

MVP 밖의 기능을 한 단락씩 요약한다. 확장 기능도 같은 World 좌표, Risk Engine, Spatial DB 를 재사용하고 불변 규칙(Tier 0 가 위치 정본, LIVE 만 실제 알림, AI 는 제안만 등)을 그대로 따른다. 착수할 때 해당 장에 설계를 다시 쓰고 게이트를 정한다. 원래 절에는 “이동(v1.3) → 부록 C”만 남겼다.

**확장 순서(초기안).** 1) C.1 리플레이 확장(로그가 이미 있어 비용 대비 효과가 가장 큼) 2) C.2 F-01 위험 동선 시뮬레이션 3) C.3 F-08 에이전틱 리포팅 4) C.4 F-03 What-if · F-04 배치 추천 5) C.5 F-07 공정 연계. PPE·워치·정적 공간 갱신·Unreal 은 별도 트랙이다.

## C.1 리플레이 확장 (구 8.5 일부)

최소 리플레이(M3, 8.5)에 더해, 시각 T 의 World 상태·골격, 그 시각에 유효했던 구역·규칙, COMMITTED Scene, 활성 이벤트를 그 시각에 적용돼 있던 구성 버전으로 불러와 재생한다. 재생 속도 조절과 이벤트 지점 점프를 둔다. 게이트: 과거 시각 재현이 기록과 100% 일치(구역·Scene 버전 포함).

## C.2 F-01 위험 동선 시뮬레이션 (구 8.6)

관리자가 “10\~12시 카트 A→B”처럼 시간 구간이 있는 계획 궤적을 입력하면, 궤적을 보간해 Risk Engine 을 PLANNED 출처로 실행하고 교차·이격거리 이내 접근 시점과 좌표를 “위험 예측 스팟”으로 표시한다. 장비는 등록 GLB + 반경 파라미터(`equipment_asset`)로 표현하고 뷰어에 반경을 표시한다. 실시간 화면과 시각적으로 구분하고 실제 알림으로 보내지 않는다. R8 장비 근접은 장비 방향(heading) 추정이 전제이며, 그 전에는 정지 장비를 R1 구역으로 등록해 대신한다.

## C.3 F-08 에이전틱 리포팅 (구 8.7)

고위험 이벤트에서 작업중지 명령서 초안, F-01 경로 계산으로 우회 동선, 해당 반장 전달을 준비한다. 명령서는 관리자 승인 후에만 발행한다(작업중지 결정 주체는 사람). VLM·LLM 도구 호출 권한은 문서 초안 생성·경로 계산 요청·알림 초안까지로 제한하고, 발송은 승인 흐름을 거친다. 운영자 질의응답(LLM 이 로그 조회 도구로 답함)도 이 트랙에 둔다.

## C.4 F-03 What-if · F-04 배치 추천 (구 8.8)

카메라 K·pose 와 정적 3D 로 책상·기둥 가림을 반영한 3D 가시성을 계산하는 공통 엔진을 쓴다. What-if 는 과거 로그나 계획에서 사람·장비·신호수 위치를 옮겨 사각지대와 위험을 재계산한다(WHAT_IF 출처). 배치 추천은 카메라 위치·각도, 신호수 위치, 안전 펜스 라인을 근거와 함께 제안한다. 커버리지 지표는 “모든 지점이 최소 2대에 보임”과 “최소 1대에서 안전모 32px 이상”이고, 법정 기준을 규칙으로 먼저 건 뒤 과거 아차사고 위치를 가중치로 반영한다. 확정 배치는 F-02 보고서에 근거와 함께 들어간다. 계획 모드 단독 평가 API(`/api/layouts/{id}/evaluate`)와 그 결과 조회(`GET /api/layouts/{id}/evaluations/{evaluationId}`, 비동기로 계산할 때만)도 이 트랙이다.

## C.5 F-07 공정 연계 (구 8.9)

공정표(오늘의 작업, 타설 후 경과일)를 구역 ID 로 연결해 VLM·LLM 입력에 넣고, 위험 가중(예: 양중 예정 구역의 낙하물 위험)을 규칙 파라미터로 반영한다. 공정 데이터 확보가 전제이며, 그 전에는 수동 입력한 오늘의 작업 메모를 구역 속성으로 쓴다.

## C.6 워치 알림 (구 10.2, 13.2 일부, 6.5 일부, I4)

갤럭시워치(Wear OS) 전용 최소 앱이 당사자에게 직접 진동 알림을 준다. 익명 World ID 와 워치는 움직임 대조(Tier 0 의 걸음·시작/멈춤 시점과 워치 가속도 비교, 가능하면 3D 손목 가속도의 0.5\~3 Hz 크기 신호 비교)로 몇 초 창의 점수표를 누적해 1:1 배정(헝가리안)한다. 채널 상태는 BOUND(연결·신뢰도 충분, 개인 진동 + 일반 경보) / UNBOUND(워치 없음·연결 미확정·신뢰도 부족·ID 병합/분열 의심, 반장 PWA·관리자 화면) / LOST(끊김, UNBOUND 와 같고 끊김을 관리자에게 알림)다. 전달은 클라우드 푸시가 아니라 워치 ↔ EC2 WebSocket 지속 연결(I4: 아래로 `watch_alert`·`heartbeat`, 위로 `ack`·`gait_features`, 기기별 토큰·wss)이고, 진동 후 ACK 가 없으면 현장 경보·관리자 알림으로 격상한다. 워치 알림은 진입 예측(R5) 시점에 나가야 하며, 진동 패턴으로 등급을 구분한다(주의: 짧게 두 번, 위험: 길게 연속). 뷰어는 아바타 위 채널 아이콘과 “추적 인원 vs 활성 워치 수”를 표시하고, 착용 의무가 있으면 “연결된 워치 없음”으로 표시한다(“미착용”으로 단정하지 않음). 워치 충격 감지는 카메라가 놓친 낙상의 추가 근거다. 워치 등록자 이름은 접근 제한된 별도 테이블에만 두고 관리자만 조회하며, 보고서에는 “워치 등록자 기준”으로 출처를 남긴다. 확장 DB 테이블: `channel_state`, `watch_feature`, `watch_binding`. GPS 는 쓰지 않고, 움직임 대조가 부족하면 UWB 를 고려한다.

| 측정 항목 | 초기 목표 |
|---|---|
| 올바른 연결 시간 비율 | 95% 이상 |
| ID 전환 후 연결 회복 | 10초 이내 |
| 위험 진입 → 진동 | p95 1.5초 이하 |
| 앱 켠 상태 배터리 | 8시간 이상 |

## C.7 PPE 판정 (5.5, 구 13.3, R9)

설계 기준은 5.5 에 있다. YOLO26 검출로 안전모·조끼·신호수 표식을 판정하고(WORN/NOT_WORN/UNKNOWN), R9 는 안전모 요구 구역에서 NOT_WORN 일 때 HIGH 다(UNKNOWN 은 등급 유지 + “확인 필요”). 뷰어는 상태 판정 결과에 따라 미리 만든 모델을 붙인다(WORN 실물 표시, UNKNOWN 반투명·외곽선, NOT_WORN 모델 없음 + 경고 표식, 크기는 3D 골격의 어깨 폭·몸통 길이·머리 크기로 맞춤). 확장 DB 테이블: `ppe_state`. PPE 프로세스를 함께 돌릴 때 capture_to_risk p95·p99 증가와 대기열 적체가 6.6 목표 안이어야 한다.

| 측정 항목 | 초기 목표 |
|---|---|
| 상태별 정밀도·재현율 | 90% 이상 |
| 함정 케이스(손에 든 안전모, 의자의 조끼) WORN 오판 | 0건 |
| 머리 가림 시 UNKNOWN | 정답으로 처리 |
| PPE 동시 실행 시 capture_to_risk p95·p99 | 6.6 목표 이내 |

## C.8 정적 공간 변화와 임시 형상 (구 6.3, 5.7, R10)

고정 카메라 배경 관측 → 단순 영상·깊이 차분(기준선) → 지속 변화 확인 → (선택) 3DGS 계열 후보 Scene → Scene 버전 검증·원자적 커밋으로 정적 공간을 갱신한다. 변화 구역은 3D 갱신을 기다리지 않고 보수적으로 판단한다: 새 장애물 후보는 임시 형상으로 즉시 반영, 사라진 것처럼 보이는 장애물은 제거 검증 전까지 유지, 조명·그림자 변화는 물리 장애물로 확정하지 않는다. 임시 형상은 팽창 실루엣 원뿔의 교집합 ∩ 방 형상(BEV 평면도의 방 외곽을 넉넉히 넓힘)으로 계산한다. 2대 이상 일관성 검사를 통과하면 Temporary Collider, 통과하지 못하면 실패한 Visual Hull 을 재사용하지 않고 가려진 카메라의 제약을 빼고 여유를 키워 다시 계산한 더 큰 Possible Occupancy Volume 을 UNKNOWN_OCCUPANCY 로 둔다. UNKNOWN_OCCUPANCY 가 TTL 안에 해소되지 않으면 재관측·재구성 우선순위를 올리고, 그래도 실패하면 구역을 UNKNOWN 으로 유지한 채 운영자 확인을 요청한다(TTL 은 불확실성을 없애는 타이머가 아니라 해결 절차를 격상하는 타이머). R10 은 UNKNOWN_OCCUPANCY 영역 근접이며 심각도는 원래 위험 기준 그대로다. 뷰어는 UNKNOWN_OCCUPANCY 볼륨을 점선 외곽으로 표시한다. 확장 DB 테이블: `region_state`.

## C.9 그 밖의 확장 후보

- **Track 체크포인트 복원·재관측 매칭:** 재시작 시 World Track(ID·별칭·마지막 위치·불확실성)을 체크포인트에서 복원해, 재관측된 사람을 복원 Track 과 같은 ID 로 잇는다(MVP 는 후보 표시와 이벤트 연결까지만 한다, 3.2). 복원 Track 은 OBSERVED 로 두지 않고, 체크포인트가 기준 시간(초기값 30초)보다 오래됐으면 복원하지 않는다.
- **Unreal 배경 빌드(5.8):** 고정 레시피로 조명을 구운 glTF 를 만든다. 렌더러는 Three.js 하나다.
- **EXP-01 텍스처 메시:** MVP 의 점군 → 단순 메시 glTF 를 텍스처 메시로 올린다.
- **실사형 메시 아바타:** EXP-02 채택 시 캡슐 아바타를 MHR 메시·관측 기반 외형으로 대체 표시(20.3).
- **모델 후보 묶음:** Cosmos3-Super(64B, 더 큰 GPU 가 있을 때), SOMA-X 바디 표현 변환, 3DGS 계열(3DGS-U·GS-Pool·GaussianUpdate·CL-Splats).
- **정적 공간 변화 VLM 의견:** VLM 이 Scene 변화에 의견을 붙인다(제안만).
- **장비 검출:** 장비 대체물(카트), 책상·의자, 방향 마커 검출 클래스.
