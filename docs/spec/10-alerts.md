# 10. 알림 채널

위험 판단은 카메라에 잡히는 모든 사람에게 같고, 달라지는 것은 전달 경로뿐이다. 반장 PWA는 MVP의 기본 원격 경로다. 노트북 로컬 경보·관제 화면 경보(3.10)를 대체하지 않는다. 당사자에게 직접 닿는 워치는 확장이다(부록 C).

## 10.1 반장 PWA

- 전달: EC2 → Web Push(VAPID). 알림 내용은 위험 등급, 구역, 위치, 근거 한 줄. 근거 한 줄은 Risk Engine 규칙 근거(규칙 이름과 측정값)로 바로 보낸다. VLM 근거는 나오면 이벤트 상세 화면에만 더하고 푸시를 다시 보내지 않는다.
- 푸시 설정: `Urgency: high`, 짧은 TTL, `Topic`은 `event_id`(같은 이벤트의 알림은 새 알림으로 대체)로 보낸다. 알림을 띄우지 않는 무음 푸시는 보내지 않는다(WebKit 은 알림 없는 푸시가 3번 쌓이면 구독을 지운다). iOS 18.4 이상에서는 Declarative Web Push 를 선택지로 둔다. 갤럭시 휴대폰은 Chrome 을 절전 예외에 넣는다(18.1).
- 수신 확인: Service Worker 가 푸시를 받으면 EC2 에 수신 확인을 보낸다(12.6). G8 의 전달 성공률과 지연은 이 기록을 근거로 한다.
- 연결 상태: PWA 는 EC2 와의 연결 상태(STOMP 하트비트)를 화면에 표시한다. 로그인은 긴 갱신 토큰을 써서 관제 중에 끊기지 않게 한다(14장).
- 시험 알림: `POST /api/push/test`로 보내는 시험 푸시는 RiskEvent 가 아니며 “시험”을 표시한다(3.10).
- 조치: 요청 → 확인 → 조치 중 → 완료, 완료 시 사진 업로드(8.4).
- 앱 없이 워치에 휴대폰 알림이 미러링되는 것은 구역 단위 경보 수준이며, 개인 알림으로 보지 않는다.
