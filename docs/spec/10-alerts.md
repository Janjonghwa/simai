# 10. 알림 채널

위험 판단은 카메라에 잡히는 모든 사람에게 같고, 달라지는 것은 전달 경로뿐이다. 반장 PWA는 MVP의 기본 경로, 워치는 당사자에게 직접 닿는 보조 경로다. 둘 다 현장 사이렌·관리자 경보를 대체하지 않는다.

## 10.1 반장 PWA

- 전달: EC2 → Web Push(VAPID). 알림 내용은 위험 등급, 구역, 위치, 근거 한 줄.
- 조치: 요청 → 확인 → 조치 중 → 완료, 완료 시 사진 업로드(8.4).
- 앱 없이 워치에 휴대폰 알림이 미러링되는 것은 구역 단위 경보 수준이며, 개인 알림으로 보지 않는다.

## 10.2 워치 (확장)

**기기.** 갤럭시워치(Wear OS). 최소 기능 전용 앱: 화면 거의 없음, 포그라운드 서비스, 지속 연결, 걸음 특징 계산, 등급별 진동 + 방향·한 단어 표시, ACK. 지급 전에는 PWA 미러링으로 시연한다.

**연결(신원 결합).** 카메라의 World ID는 익명이라 어떤 트랙이 어떤 워치를 찼는지 움직임 대조로 연결한다.

- 기본층(Tier 0 서비스, 항상 동작): Tier 0의 걸음·시작/멈춤 시점과 워치 가속도의 걸음 피크를 비교.
- 강화층(있을 때만): 3D 손목 궤적에서 계산한 가속도를 0.5\~3 Hz 대역의 방향 무관 크기 신호로 워치와 비교. `joint_visibility`가 참인 구간만 쓰고, 양 손목을 모두 계산해 찬 손을 자동 판별.
- 전체 워치 × 전체 트랙의 점수표를 몇 초 창으로 누적하고 1:1 배정(헝가리안)한다.
- 워치와 EC2 시계를 Wi-Fi로 맞추고 오차를 측정한다(위상 대조는 수십 ms 이내 필요).
- 출입 등록은 선택 기능이다. 진입 직후 근거가 쌓이기 전은 “연결 미확정”으로 UNBOUND 경로를 쓴다.
- GPS는 오차(수 m 이상)와 실내 불가로 쓰지 않는다. UWB는 움직임 대조가 부족할 때 고려한다.

**채널 상태.**

| 상태 | 의미 | 전달 경로 |
|---|---|---|
| BOUND | 워치 연결됨, 신뢰도 기준 이상 | 개인 진동 + 일반 경보 |
| UNBOUND | 워치 없음, 연결 미확정, 또는 신뢰도 부족·ID 병합/분열 의심 | 구역 경보, 반장 PWA, 관리자 화면 |
| LOST | 연결 중 신호 끊김 | UNBOUND와 같음 + 끊김 사실을 관리자에게 알림 |

**전달.** 클라우드 푸시가 아니라 워치 앱 ↔︎ EC2 지속 연결(WebSocket)을 쓴다. 워치는 진동 후 ACK를 보내고, 정해진 시간 안에 없으면 현장 경보·관리자 알림으로 격상한다(RiskEvent의 ACKNOWLEDGED와 연결). 워치 연결 상태는 System Health에 포함한다. Wear OS가 Wi-Fi를 끄고 블루투스로 돌리지 않도록 앱이 Wi-Fi 네트워크를 명시적으로 요청·유지한다. 가속도 원본은 보내지 않고 걸음 시각·팔 흔들림 크기 같은 특징만 보내며, 정밀 대조 시에만 짧은 구간 원본을 요청한다.

**예측 시점.** 걷는 속도 1.5 m/s에 처리 지연·전달·반응 시간을 합치면 1초 남짓이라, 워치 알림은 진입 전 예측(R5) 시점에 나가야 한다.

**표현.** 진동 패턴으로 등급 구분(주의: 짧게 두 번, 위험: 길게 연속). 히스테리시스·중복 억제를 그대로 적용한다.

**워치 미착용자.** 위험 판단에서 빠지지 않고 UNBOUND로 전달된다. 착용 의무 시 “연결된 워치 없음”으로 준수 항목 표시(“미착용”이라고 단정하지 않음). 관리자 화면에 “추적 인원 vs 활성 워치 수”를 표시한다.

**신원 주의.** 워치는 실제 착용자에게 연결된다. 워치 등록 이름을 보고서·근태에 쓸 때는 “워치 등록자 기준”으로 출처를 남긴다.

**낙상 보완.** 워치 가속도의 충격 감지는 카메라가 사람을 놓친 상황을 보완한다(카메라 UNKNOWN + 워치 충격 = 강한 사고 증거). 앱에서 받을 수 있는 센서 범위는 Samsung SDK로 확인한다.
