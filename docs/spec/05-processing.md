# 5. 처리 계층

실시간 경로는 Tier 0(검출·추적·keypoint·삼각측량·LIVE 판정)이며 RunPod Tier 0 서비스에서 관제 중 상시 동작한다. 나머지는 같은 GPU Pod 안의 분석 워커 프로세스에서 비동기로 처리하며, 3.2의 자원 규칙으로 Tier 0의 큐와 GPU 메모리를 침범하지 않는다.

**계층(Tier) 명칭.** simai는 처리를 지연 요구와 안전 판단 권한에 따라 Tier로 나눈다. 번호가 작을수록 실시간성과 안전 판단 권한이 높다.

| Tier | 이름 | 내용 | 실행 | 안전 판단 권한 |
|---|---|---|---|---|
| Tier 0 | 실시간 안전 경로 | 관측 → YOLO26-pose 검출·추적·2D keypoint → 카메라 간 연결 → 시간 보간·삼각측량 → World 상태 → LIVE 판정 | RunPod Tier 0 서비스, 실시간 | 있음. 위험 판단의 유일한 위치 근거 |
| Tier 1 | 3D 인체 강화 | SAM 3D Body 등 HMR로 빠진 관절·체형·손 보강 | RunPod 분석 워커, 비동기 | 없음. 표시·보조용(inferred), Tier 0 위치를 덮어쓰지 않음 |

구 Pipeline 문서의 Tier 2(LHM++·PEAR 기반 사실적 아바타)는 폐지했다(16장). EXP-02의 메시·외형 갱신은 Tier 1(안전 판단 권한 없음)의 시각화 확장으로 두고, 채택 여부는 20.6의 절차로 정한다. 정적 3D, VLM, PPE 워커는 Tier 번호 없이 각자의 주기로 도는 비동기 처리이며, 결과는 상태(Scene 버전, 근거 문장, PPEState)로만 위험 판단에 들어간다. 아래 표에서 5.1·5.2가 Tier 0, 5.6이 Tier 1이다.

| 계층 | 실행 위치 | 주기 | 단계 |
|---|---|---|---|
| 5.1 Tier 0 관측 | RunPod Tier 0 | 카메라당 12 FPS 이상 | MVP |
| 5.2 3D 골격·World 상태 | RunPod Tier 0 | 10 Hz | MVP |
| 5.3 정적 3D | RunPod 분석 워커 | 설치 시 1회 | MVP |
| 5.4 VLM | RunPod 분석 워커 | 이벤트 발생 시 | MVP |
| 5.5 PPE 검출 | RunPod Tier 0 | 1\~2 Hz | 확장 |
| 5.6 SAM 3D Body 강화·메시 아바타(EXP-02) | 분석 워커 프로세스 | 측정 후 결정(관절 보강 5\~15 Hz 목표) | 선행 실험·확장 |
| 5.7 정적 공간 갱신 | RunPod 분석 워커 | 저주기 | 확장 |
| 5.8 Unreal 배경 빌드 | 빌드 워커 | Scene 커밋 시 | 확장 |

## 5.1 Tier 0 관측

- 입력: 노트북이 중계한 카메라 4대 영상(RTSP over TCP)과 촬영 시각 메타데이터(3.9)
- 모델: YOLO26-pose 하나로 사람 검출과 COCO 17관절 2D keypoint를 한 번의 추론으로 낸다. **기준선은 YOLO26x-pose, TensorRT FP16, imgsz 1280**(수정 5). 운영 GPU(H100 80GB)에서 카메라 4대 동시 입력 38 ms(카메라당 약 26 FPS)로 목표를 넘고, 크기별 정확도는 공식 벤치마크와 COCO 측정 모두 x 가 가장 높다. 크기 비교를 다시 하지 않는다. NMS 경로는 잠정 NMS 사용(conf 0.25)이고 교실 밀집·가림 장면에서 NMS-free 와 다시 본다. RTMO는 가림 상황 비교군이고, 발 접지 판단이 부족하면 발 keypoint가 있는 RTMPose Halpe-26을 검토한다.
- 추적: 카메라별로 독립된 ByteTrack 상태(추적기 설정은 명시 지정). 추론 모델은 공유해 묶음 추론하되 ID 공간·시간 기록·추적 상태는 카메라마다 분리한다. 카메라 간 통합은 5.2의 추적 3계층이 맡는다
- 검출 클래스: 사람(MVP). 확장: 장비 대체물(카트), 책상·의자, 방향 마커
- 출력: 카메라별 `observation_2d`(bbox, 카메라 내 트랙 ID, keypoint 배열과 신뢰도)
- 2D keypoint는 카메라 간 연결, 삼각측량, PPE crop 위치, 자동 보정, 워치 움직임 대조, SAM 3D Body 프롬프트의 공통 입력이라 단일 실패점이다. 가림 시 신뢰도 동작을 G0·G2에서 검증하고 bbox와 트랙 이력을 독립 근거로 함께 쓴다. 마스크는 분석 워커의 YOLO26-seg를 쓰는 확장 단계부터 쓴다.

**입력 추상화.** Tier 0 서비스는 노트북 중계 스트림, 녹화 파일(시나리오 데이터셋), 시뮬레이터 출력을 같은 형식(카메라 ID + 촬영 시각 + 프레임)으로 받는다. 시뮬레이터는 2D keypoint 단계부터 바로 넣을 수도 있다. 장비 없이 개발하고 같은 데이터로 반복 검증하기 위한 장치다.

**프레임 최신성 정책.** 처리 속도가 입력(카메라당 25 fps)보다 낮아도 늘 최신 영상을 판정한다.

- 디코딩과 추론을 분리한다. 디코더는 프레임 의존성 때문에 모든 압축 프레임을 받지만(GPU 하드웨어 디코더), 추론은 카메라별 최신 디코딩 프레임만 고른다(latest-frame-wins).
- 카메라별 추론 대기열은 최대 1\~2장, 최대 대기 시간(queue_wait_ms 기준, 초기값 150ms)을 넘긴 프레임은 추론하지 않고 버린다.
- 정책상 건너뛴 프레임은 `SKIPPED_BY_POLICY`, 전송 중 사라진 프레임은 `NETWORK_LOSS`로 따로 기록한다. G0의 손실률에는 NETWORK_LOSS만 넣는다.
- 오래된 프레임을 뒤늦게 추론한 결과로 LIVE 상태를 갱신하지 않는다. 결과는 촬영 시각 기준으로 시간 모델(6.1)에 들어가고, 이미 반영된 최신 결과보다 오래되면 버린다.
- 카메라당 12 FPS는 평균값이므로, 최대 결과 간격과 촬영부터 추론 시점까지의 전체 경과 시간인 프레임 연령(`frame_age_ms`)을 함께 잰다.
- GPU가 포화되면 Tier 0 포즈 추론을 지키고 PPE 프레임부터 건너뛴다.

**이벤트 클립 링 버퍼.** Tier 0 서비스는 카메라별 최근 영상(예: 60초)을 압축 상태로 메모리에만 보관한다. CRITICAL·HIGH 이벤트가 나면 앞뒤 구간(예: 각 20초)을 잘라 객체 저장소에 올리고 `media_clip`에 기록한다. 그 외 영상은 덮어써져 사라진다.

## 5.2 3D 골격과 World 상태

- 카메라 간 연결: 바닥 투영 위치 + 다시점 기하 일관성으로 같은 사람을 묶고, 전체 1:1 배정으로 World ID를 유지한다(MV3DT 방식).
- 삼각측량: 2대 이상에서 보인 관절만 삼각측량한다. 1대 이하인 관절은 `joint_visibility = false`로 표시하고 지어내지 않는다.
- World 위치: 골반 관절의 삼각측량 결과를 우선 쓰고, 발 접지점이 보이면 함께 쓴다. 2대 이상 유효 관측이 없을 때 바닥 투영(발점)은 발의 접지 표면이 검증된 경우(바닥 또는 등록된 작업면)에만 쓴다. 지지 표면을 모르면 Z를 0으로 가정하지 않고 z_validity = UNAVAILABLE로 두며, 높이 규칙(R2·R3)은 “확인 필요”로 처리한다. 고소 위치였던 사람이 가려지면 마지막 유효 높이와 커지는 불확실성을 유지하고, 바닥 위치로 바꾸지 않는다. 바닥 투영은 일반적인 3D 관측 실패의 대안이 아니다.
- 출력: `world_track_state`(XYZ, 불확실성, 속도, 관측 상태, 시간 필드, 기여 카메라)와 `skeleton_3d`
- root 위치의 정본은 이 계층이다. HMR 모델 결과가 이 위치를 덮어쓰지 않는다.

**접지 추정(ContactEstimator).** YOLO26-pose의 COCO 17관절에는 발목까지만 있고 발뒤꿈치·발끝·접촉점이 없다. 그래서 발목 위치(`ankle_position`)를 접지점(`ground_contact_point`)으로 취급하지 않는다. ContactEstimator가 발목 높이와 정지 여부, 다시점 발목 Z, 등록된 작업면 높이를 근거로 접지 여부와 지지 표면을 추정하고, 근거가 부족하면 `support_surface = UNKNOWN`으로 둔다. 바닥 투영과 높이 규칙(R2·R3)은 이 결과를 쓴다. 발 세부 관절이 필요해지면 RTMPose Halpe-26을 비교한다.

**추적 3계층.** 하나의 Tier 0 서비스 안에서 중앙 집중형으로 동작한다.

| 계층 | 담당 | 구현 |
|---|---|---|
| Local Tracker | 같은 카메라 안에서 프레임 간 사람 연결 | 카메라별 독립 ByteTrack(기준선), 선택: BoT-SORT + ReID |
| Cross-view Association | 네 카메라의 트랙이 같은 사람인지 판단 | MV3DT 원칙의 Python 구현. 근거: World 위치(유효 접지·다시점 관절), 1\~2초 궤적·속도, 관절 재투영·에피폴라 오차, 필요 시 ReID, 가림·불확실성 |
| World Track Manager | 최종 World ID, XYZ, 속도, 가림·재관측 | World 칼만 필터, tracklet 이력, 늦은 재연결(late re-association), ID 교정 |

- 같은 카메라의 서로 다른 두 검출을 한 World ID에 동시에 묶지 않는다. World XY가 가깝다는 이유만으로 합치지 않는다.
- 매칭이 애매하면 합치지 않고 새 ID를 만들거나 `IDENTITY_UNCERTAIN`을 표시한다. 잘못 합친 ID보다 갈라진 ID가 덜 위험하다.
- Track 생명주기 TENTATIVE → CONFIRMED → OCCLUDED → LOST는 관리용 속성이며, 위험 판단용 관측 상태(OBSERVED/PREDICTED/UNKNOWN)와 별도다. ID 확신과 위치 확신도 별도로 관리한다.
- ReID는 보조 근거다. 비슷한 복장이 많으면 외형만으로 구분할 수 없으므로 기하와 궤적이 주 근거다.
- DeepStream MV3DT를 직접 붙이지 않고 원칙(공유 World 좌표, tracklet 연결, 가림 상태 관리, 늦은 재연결)을 Python으로 구현한다.
- Pod를 여러 개로 늘리면 World Association 상태가 나뉘므로, 확장 시 카메라·시간 단위 분할과 상태 소유권을 따로 설계한다.

**계산 순서.** 카메라 간 연결과 삼각측량, 접지 추정이 서로를 기다리지 않도록 순서를 고정한다.

1. 카메라별 Local Tracklet(2D keypoint, 공통 시각으로 시간 보간)
2. 연결 후보 생성: 에피폴라 오차, 시간, 기존 World Track 궤적, 임시 바닥 가설(발목을 바닥으로 투영한 근사)
3. 후보별 삼각측량과 검증: 재투영 오차, 시선각, 관절 일관성(관절 유효성 게이트)
4. ContactEstimator: 지지 표면과 접지 신뢰도
5. 최종 연결과 World Track 갱신

임시 바닥 가설은 후보 생성에만 쓰고 안전용 접지나 Z로 쓰지 않는다. 4단계에서 접지가 검증되지 않으면 `z_validity`와 `support_surface`를 UNKNOWN으로 둔다.

**ID 교정 기록.** World ID를 조용히 덮어쓰지 않는다. 병합·분할·교정마다 `identity_revision`을 올리고 별칭(alias)과 교정 이력을 남기며, 이벤트에는 발생 당시의 원본 World ID를 보존한다. ID 교정은 이력과 리플레이를 고칠 수 있지만 진행 중인 위험을 자동 해소하지 않는다.

**World 위치의 정의.** 사람의 위치는 하나의 `position`으로 뭉뚱그리지 않고 아래처럼 나눈다.

| 필드 | 의미 | 없을 때 |
|---|---|---|
| `pelvis_xyz` | 삼각측량한 골반 관절 위치 | 2대 이상 유효 관측이 없으면 비움 |
| `position_xy` | 구역 판정용 수평 위치. 기본은 골반 XY | 골반이 없으면 검증된 접지점 XY, 둘 다 없으면 예측값(PREDICTED) |
| `ground_anchor_xyz` | 검증된 지지 표면 위의 위치(ContactEstimator) | 접지 미확인이면 비움. Z=0으로 채우지 않음 |
| `support_surface_id`, `support_surface_validity` | 서 있는 면(바닥, 등록 작업면)과 그 유효성 | UNKNOWN |
| `head_z` | 삼각측량한 머리 높이 | 비움 |

- 높이 규칙(R2·R3)은 `ground_anchor_xyz`의 Z(서 있는 면 높이)를 쓰고, 없으면 “확인 필요”로 처리한다. 낙상(R4)은 `head_z` 변화를 쓴다.
- 구역 진입(R1)은 구역 유형에 따라 판정한다(8.2). GROUND_FOOTPRINT는 `position_xy`와 수평 불확실성으로, VOLUME_3D는 사람이 차지하는 높이 범위(서 있는 면 Z부터 VALID 관절 중 가장 높은 Z까지, 없으면 `head_z`까지)와 구역 높이 범위의 겹침을 3D 불확실성과 함께 본다.
- 아바타는 접지가 확인되면 발을 `ground_anchor_xyz`에 맞추고, 아니면 `pelvis_xyz` 기준으로 배치하며 “접지 미확인”을 표시한다(13.2).

**3D 관절 유효성 게이트.** 두 대에 보인다는 것과 그 관절의 Z가 안전 판단에 충분히 정확하다는 것은 다르다. 관절마다 아래 항목으로 VALID / UNCERTAIN / UNAVAILABLE을 정한다.

- 관측 카메라 수(시간 보간 후 유효한 카메라만)
- 재투영 잔차
- 두 시선 사이 각도(작으면 깊이·높이가 불안정)
- 시간 일관성(속도 상한, 뼈 길이 변화)
- 삼각측량 불확실성

위험 규칙은 VALID 관절만 확정 근거로 쓴다. UNCERTAIN이면 등급은 유지하고 “확인 필요”를 붙인다. `joint_visibility`는 이 게이트의 입력 중 하나이며, I1의 skeleton에 `validity`를 함께 싣는다.

## 5.3 정적 3D (설치 시 1회)

**261016 선행 검증 — EXP-01.** 기존 M3 정적 배경 산출물을 바꾸기 전에 MapAnything Native로 깊이/점군/카메라 정보 → 깊이 정합·표면 복원·glTF → World 스케일·정렬 비교를 하나의 대형 실험으로 검증한다. 비교군은 MoGe-3이고 G4 목표는 개발 교실 줄자 실측 대비 10cm다(수정 6). Experiment는 재현성·실패 사례·렌더링·VRAM 지표를 함께 제출한다.

- 안전 판단용 Operational Geometry 정본은 보정으로 확정한 바닥 평면과 관리자가 등록한 정적 객체(보수적 OBB)·위험 구역이다. 정적 3D·BEV 평면도의 벽은 보기용이다(수정 6).
- 사물(책상, 사물함)은 CALIBRATED 이후 MapAnything Native에 알려진 K·pose를 넣어 복원하고, glTF로 Three.js에 넣는다.
- MoGe-3는 G4 비교 대조군이다. MapAnything이 G4에서 실패하면 MoGe-3 + 바닥 평면 스케일 보정을 시험하고, 그래도 기준 미달이면 실측 도면 기반 단순 형상을 쓴다. 최종 대체 경로는 MoGe-3가 아니라 실측 도면이다.
- 안전 판단용 사물 형상은 보수적 OBB로 쓴다.

**촬영 조건.** 정적 3D용 프레임은 설치 시 교실을 비운 상태로 카메라마다 여러 장 확보한다. 빈 교실을 만들 수 없으면 사람 분할 마스크로 사람 영역을 빼고 여러 시점의 프레임을 합성한다. 사람이 찍힌 프레임을 그대로 쓰면 사람이 배경 형상에 섞인다.

**복원 후처리.** MapAnything 출력(점 지도·깊이)은 바로 배경 메시가 아니다. 뷰 간 깊이 정합 → 이상점 제거 → 표면 생성 → (필요 시) 텍스처 → 메시 단순화 → 평면도 벽과 비교한 World 좌표 검증 → glTF 순서로 만든다. 이 결과는 보기용 Visual Geometry다. 안전 판단용 Operational Geometry는 실측 평면도와 사물의 보수적 OBB로 만든다.

## 5.4 VLM

- 역할: 설명과 제안만 한다. 경보 판단 권한은 없다(원칙 6).
- 후보: Qwen3-VL(범용, 문서·한국어 출력에 강점)과 Cosmos 3 Reasoner(물리·영상 시간 추론에 강점, 이해용 Reasoner만 단독 실행). G7에서 같은 기준으로 비교해 하나를 고른다. 중간 크기(8B\~30B급)부터 시작하고 G7 미달 시 키운다. RunPod에서 vLLM의 OpenAI 호환 API로 서빙해 교체를 쉽게 한다.
- 용도: (1) R1\~R4 이벤트 근거 설명(빠른 경로: 이벤트 시점 프레임 + 직전 3\~5초 + 구조화 상태, G7의 5초 목표 대상), (2) 사고·아차사고 구간 요약(사후 경로: 이벤트 전후 20초 클립, ⑩ 리플레이), (3) TBM 보고서·일일 일지(규칙 계산 결과 + RAG), (4) 정적 공간 변화 의견(확장), (5) 공정 맥락 진단(⑦)과 운영자 질의응답(로그 조회 도구 사용).
- 맡기지 않는 일: PPE 판정·신호수 구별(YOLO26), 낙상 검출(3D 골격 규칙), 구역 판정(Risk Engine). 전용 모델과 규칙이 더 빠르고 수치로 검증되기 때문이다.
- 권한: 근거 설명과 상향 의견(proposed_severity) 제시만 가능하다. 이벤트 심각도는 규칙 결과로 유지하고, 상향은 검증된 규칙 조건이나 운영자 확인을 거쳐 적용한다. 하향·해소 불가.
- 보고서 인용은 RAG로 검색된 조항 ID만 허용하고 자동 검사한다.
- 큐: 이벤트 근거가 보고서보다 우선한다.

**VLM 입력 프레임.** VLM에 넣는 이벤트 클립·프레임은 얼굴 영역을 흐림 처리한 뒤 넣는다(기본값). 근거 판정에 얼굴은 필요 없고, 안전모가 보이도록 머리 윗부분은 남긴다.

## 5.5 PPE 워커 (확장)

- 모델: YOLO26 검출을 1순위(분류는 비교군)로 PPE 데이터에 미세조정한다. 검출이어야 안전모·조끼와 머리·몸통 keypoint의 위치 관계로 착용 여부를 판단할 수 있다. 클래스는 안전모, 안전모 없는 머리, 조끼, 신호수 표식(다른 색 조끼·완장). 공개 PPE 데이터셋으로 먼저 학습하고, 위에서 내려다보는 교실 카메라 각도의 시나리오 데이터로 추가 미세조정한다.
- 실행: RunPod Tier 0 Pod 안의 별도 프로세스(낮은 GPU 우선순위)에서 1\~2 Hz로, keypoint로 잡은 머리·몸통 부분을 **원본 해상도** 프레임에서 잘라 묶음으로 처리한다. 축소 영상에서는 안전모가 10픽셀 남짓이라 판정할 수 없다.
- 다시점 비대칭 규칙: 한 대라도 착용을 확실히 보면 WORN 근거, NOT_WORN은 머리가 선명히 보이는데 안전모가 없을 때만, 그 외 UNKNOWN.
- 사람과의 연결: 안전모는 머리 keypoint 영역, 조끼는 어깨\~골반 영역과 겹쳐야 착용. 손에 든 안전모, 의자에 걸린 조끼를 착용으로 세지 않는다.
- 상태 전환: WORN은 약 3초간 연속 판정 대부분이 착용일 때, NOT_WORN은 머리가 선명한 판정이 연속 미착용일 때. 근거가 약 10초 갱신되지 않으면 UNKNOWN.
- crop은 판정 직후 삭제하고 저장하지 않는다. 별도 프로세스는 오류만 격리할 뿐 GPU는 공유하므로, PPE에 GPU 메모리·대기열 길이·초당 추론 수 상한을 두고 GPU가 포화되면 PPE 프레임부터 건너뛴다.
- 3MP(가로 2304px)·가로 약 105°에서 교실 중앙 안전모는 약 36픽셀로 추정되어 기준선(32px)을 조금 넘는다(가로 1920px·98.8° 기준 약 32px에서 해상도·화각 비율로 환산, 화각 실측 후 다시 계산). 다만 약 1.1 Mbps의 강한 압축이 세부를 줄일 수 있다. PPE 트랙 시작 시 실제 스트림 품질로 정확도를 먼저 확인한다.
- 신호수 등 역할은 표식 클래스 검출로 규칙 기반 부여한다.

## 5.6 SAM 3D Body 강화 (확장 · EXP-02 선행 검증)

**261016 선행 검증 — EXP-02.** Fast SAM 3D Body로 MHR 메시·포즈를 복원해 인물별 동적 아바타를 구성하며, 카메라 연속 관측이 쌓일수록 실제 관측 기반 외형·텍스처를 개선하는 절차를 시험한다. 이는 기존 골격 강화에 더한 별도의 시각화 목표다. 마네킹/스켈레톤만으로 최종 실사형 외형 목표를 충족했다고 처리하지 않는다. 실사형 아바타는 MVP 자동 채택이 아니라 독립 품질·성능·개인정보 게이트를 거치는 확장 후보이다.

- 역할: 삼각측량에서 빠진 관절(책상 뒤 하체 등)을 채우고 체형·손을 더한다.
- 사용: Fast SAM 3D Body 변형, mask 프롬프트(분석 워커의 YOLO26-seg 마스크), keypoint 프롬프트는 몸통·고관절 같은 안정 관절만(손목·손 제외).
- 검출기·입력(수정 5): 사람 박스·손 영역은 Tier 0와 같은 YOLO26x-pose 로 잡는다. 기본 모드는 손 포함(full)이다(일본 H100 웹캠 라이브 e2e p50 450 ms, EXP-02 6.4). 카메라 K 는 보정(CalibrationProvider) 값을 쓰고, MoGe2 화각 추정은 E-GATE-0 공식 설정 재현에만 쓴다.
- 다시점 집계: 카메라당 최대 1개 제약 클러스터링 → 대표 포즈의 translation만 다시점 재투영 오차로 보정. 최종 root는 5.2를 따른다.
- 채택 기준: G5의 “한 카메라 제외 재투영 오차”와 “책상 뒤 하체 누락률”을 삼각측량 기준선보다 의미 있게 개선. Multi-HMR 2는 비교 기준선이다.
- 표현 계약: `Human3DState`의 canonical_motion(공통 관절)과 native_pose(MHR 원본)를 분리하고 SOMA-X를 변환 후보로 둔다.

**observed / inferred 구분.** Tier 0 삼각측량 관절은 observed, Tier 1 HMR이 채운 관절은 inferred로 표시한다(`joint_source`). 위험 규칙은 observed이면서 VALID인 관절만 확정 근거로 쓰고, inferred 관절은 표시·보조에만 쓴다. HMR 메시의 각 표면/텍스처에는 관측 근거·갱신 시점·미관측/보간 여부를 구분한다. World root 위치·접지 기준의 정본은 계속 5.2이다.

## 5.7 정적 공간 갱신 (확장)

흐름: 고정 카메라 배경 관측 → 단순 영상·깊이 차분(기준선) → 지속 변화 확인 → (선택) 3DGS-U 불확실성 평가 → GaussianUpdate 또는 CL-Splats로 후보 Scene → (선택) GS-Pool 객체 단위 비교 → Scene 버전 검증·원자적 커밋. 변화 중인 영역의 안전 판단은 6.3의 임시 형상 정책을 따른다.

## 5.8 Unreal 배경 빌드 (확장)

- Unreal은 배경 자산 빌드 도구다. 렌더러는 Three.js 하나다.
- MCP 에이전트는 빌드 레시피(Unreal Python 스크립트 또는 고정 툴 호출 순서)를 작성·수리만 하고, 파이프라인은 검토 후 고정한 레시피를 실행한다.
- 빌드: Scene 커밋 → 레시피 실행(import, 재질, 조명 굽기, LOD) → glTF 출력 → 격자점 왕복·bounding box 검증 → `scene_version` 태그. 실패 시 이전 자산 유지.
- 에디터 MCP는 루프백만 허용하고 툴 범위를 제한한다. Blender 헤드리스를 대안으로 비교한다.
