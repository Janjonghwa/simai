# 부록 E. 시연 시나리오 (초안 — 큰 틀 확정·세부 조정 중)

시연에서 보여줄 장면의 큰 틀(약 10분, 장면 0~8 아홉 개)과 실패 시 대체를 정한다. **이 장의 장면별 세부 시간·동작·대사는 초안(세부 조정 중)** 이며 11차 GPU 세션과 리허설 결과에 따라 계속 다듬는다. 당일 점검표와 시작 순서는 18.2 를 따른다.

## E.1 원칙과 무대 구성

- **무대·역할 구성.** 현장 세트(로비 세트: **높이 0.425 m** 단상 2개와 그 사이 개구부, 바닥 경고 테이프·추락주의 표지)에서 연기자 2명(**A·B**)이 움직이고, 심사위원은 발표장 화면으로 3D 관제 화면과 현장 중계(카메라·워치·노트북 경보)를 함께 본다.
  - **연기자 A (워치 착용)**: 바닥 기준 위치 비교(장면 2) · 개구부 가장자리 접근(장면 4, 워치 주의 약한 진동 → 위험 강한 진동) · 개구부 안 떨어짐(장면 5, 워치 「낙상 의심」 강한 진동).
  - **연기자 B (워치 착용)**: 단상 위 고소 위치 비교(장면 2) · 단상 하차 후 안전모·조끼 착탈과 손목 워치 PPE 경보 수신(장면 3) · 카메라 가림(장면 6). 워치는 A·B가 하나씩 차고 각자 본인 알림만 받는다(2026-11-13 결정, S15P31A101-681). **장면 3 끝에 B가 단상에서 완전히 내려가야 장면 4·5의 A 경보에 섞이지 않는다.**
- **라이브 시연 + REPLAY 대체.** 장면 2~6(이어서 약 6분)의 기본은 라이브로 하고, 라이브가 안 되면 11차 GPU 세션·리허설에서 같은 동작으로 통째로 찍어 둔 4대 동기화 녹화 세션을 REPLAY 출처로 재생한다(녹화 원본은 현장 노트북에만 두고 EC2 에는 두지 않음, 3.10·15.3). REPLAY 출처는 실제 알림 채널로 나가지 않으므로 워치·노트북 로컬 경보는 울리지 않고 관제 화면 경보만 보인다(2장 원칙 10, 3.10 점검·리허설). 이 차이를 발표에서 미리 말한다.
- **교실 테스트베드(`CLASSROOM_TEST` 고정, `rule_version 1001`) 명시와 단상 높이(0.425 m) 기준.** 장면 0 또는 장면 2 첫머리에서 **"교실 테스트베드(`CLASSROOM_TEST`, `rule_version 1001`), 고소 높이 기준 0.35 m(운영 2.0 m)"** 임을 한 줄로 명확히 고지한다(현장 DB `site.rule_profile` 기본값도 `CLASSROOM_TEST` 로 고정, 7.4, `docs/design/S15P31A101-669-rule-profile-classroom-fixed.md`). 시연에 쓰는 단상(로비 스툴, `lobby_stool_top`)의 실측 높이는 **0.425 m**(`docs/design/measured-object-scale.md`, S15P31A101-357, 2026-10-28 실측)로 교실 시험 프로파일 고소 기준(0.35 m)보다 **7.5 cm** 높다(접지 높이 추정 오차가 이 7.5 cm 여유를 넘지 않는지는 11차 GPU 세션에서 확인, 19.1). VLM 에게도 교실 사물(책상, 단상, 테이프)을 건설 현장 사물(비계, 개구부)로 바꿔 부르라고 지시하지 않고 보정 투영된 위험 구역·대상 인물 오버레이와 관측 사실만 설명하게 한다(5.4).
- **주장 범위.** 정확도 수치는 개발 교실 실측 결과(15.1)로만 말하고, 시연 현장 수치를 게이트 합격으로 말하지 않는다.
- **리허설 = 실행 1, 본 시연 = 실행 2.** 같은 날 같은 작업 안에서 「작업 시작 ~ 작업 종료」를 실행 1·2 로 반복한다. TBM·세팅은 하루 한 번이며(카메라가 그대로면 다시 하지 않음), 실행마다 시작·종료 시각·이벤트·녹화 구간·다시 보기가 따로 남는다. 리허설 기록을 지우는 작업 다시 열기(reopen)는 쓰지 않는다(2026-11-14 결정 방식 B, 구현 중 S15P31A101-696).

- **장면 2~6 연속 진행 및 대체**: 장면 2~6은 현장 연기자 A·B가 끊지 않고 이어서 약 6분 동안 수행한다. **반드시 「작업 시작」 뒤에** 한다(작업 시작 = 관제 시작, -679). 라이브 장애 시 같은 시나리오 녹화 세션을 REPLAY 로 재생하며, 재생할 때도 작업을 시작해 둬야 경보가 난다.
- **장면 8 → 7 순서**(2026-11-13 결정, S15P31A101-681): 웹에서 작업을 종료하면 게이트웨이가 종료 구간을 조회해 닫힌 녹화 조각을 S3 로 올리고(관제를 유지해도 됨) 장면 7에서 실제 카메라 영상을 3D 와 같은 시각으로 재생할 수 있다. 업로드 완료 표시를 기준으로 영상 재생으로 넘어가고, "종료 후 몇 초면 준비" 같은 약속은 하지 않는다(업로드 중에는 3D 다시 보기·이벤트 클립·VLM 근거부터).
- **B 단상 하차**: B는 장면 3 시작 전에 단상에서 완전히 내려가 R3 고소 경보와 보호구 경보가 섞이지 않게 하고, 장면 4·5의 A 경보에도 섞이지 않게 한다.

## E.4 리허설 항목

- 시연과 같은 사이트·GPU 등급·저장 위치로 한다(3.12). TensorRT 엔진 캐시와 GPU 인스턴스 기동 시간(시작 절차 포함)을 확인한다.
- 시연장 망(SSAFY 망)에서 기본 경로인 EC2(`simai.live:22`) SSH 경유 + Pod 공개 포트 Direct TCP(EC2 보안 그룹 인바운드 22 허용 확인 포함)를 10분 이상 연속 시험하고, LTE 테더링 업링크(두 번째 업링크)와 RunPod HTTPS 프록시(443 + wstunnel, 최후 예비)로 전환해 본다(3.12, 18.1). 리허설·시연 중에는 EC2 CPU 를 같이 쓰는 CI 빌드를 피한다.
- 엔드포인트 등록 → 노트북 접속, 노트북 재접속 후 현장 경보 재동기화(3.10)를 확인한다.
- 노트북 OS 설정(업데이트 중지, 집중 모드, 출력 오디오 장치 고정, 서비스 자동 기동)을 확인한다(18.1).
- **11차 GPU 세션 및 리허설 확인 항목**:
  - 현장 세팅 시작부터 구역 편집 가능(`READY_FOR_ZONES`)까지의 소요 시간이 목표(약 1분 30초) 안에 들어오는지와 백그라운드 `texrecon` 완성 시간을 실측한다(확인 필요).
  - 로비 스툴 단상(실측 높이 `0.425 m`) 위에서 접지 높이 추정 오차가 교실 프로파일 고소 기준(`0.35 m`)과의 여유(`7.5 cm`)를 넘지 않아 장면 2의 R3 고소 판정이 안정적으로 나는지 확인한다.
  - 장면 1 TBM 보고서 실제 생성 결과에서 인용된 법령 조문 번호로 발표 대본을 맞춘다.
  - 장면 2·4·5에서 연기자 A·B가 서거나 이동하는 단상·개구부 위치가 R1 확실한 위치 조건(관측 `OBSERVED` + 카메라 2대 이상 정합 또는 1대이면 검증된 접지점 확인, `VOLUME_3D` 구역은 높이 확인, 7.1·7.2)을 안정적으로 만족하는지 리허설에서 확인한다(확인 필요).
  - 장면 4의 R5(진입 예측) → R2(가장자리 1.0 m 이내) 순차 발생을 위한 A의 접근 속도와, 장면 5의 R4(낙상 의심 급하강) 인식을 위한 A의 하강 속도를 리허설에서 맞춰 고정한다(확인 필요).
  - 위험 이벤트를 만드는 장면 연습은 녹화한 뒤 REPLAY 로 돌리고(연결 점검·세팅 촬영은 LIVE 연결 + 시험 알림 경로, 3.10 점검·리허설), **11차 GPU 세션에서 장면 2~6 연속 연기를 4대 동기화로 통째로 녹화**해 현장 노트북에 예비 세션으로 보관하고 REPLAY 재생에서 실제 알림이 나가지 않는지 확인한다.
- PPE 장면 3은 실행 중 Tier 0 -548 포함 판, 서버 시드 R9·R11, 새 묶음 APPLIED, B 워치 BOUND·연결을 먼저 확인한다. 안전모·조끼를 따로 벗고 다시 입어 각 이벤트가 따로 발생·해소되는지, UNKNOWN 이 새 이벤트·자동 해소를 만들지 않는지 확인한다. 실패하면 이 장면을 R3 워치 경보로 대체하고 PPE 게이트 합격으로 발표하지 않는다. REPLAY 대체에서 실제 워치 진동은 울리지 않는다.
- T-60분 go/no-go 점검표(18.2)를 그대로 한 번 돌린다.
