# 2. 설계 원칙

모든 모듈 설계와 구현 판단은 아래 원칙을 따른다. 원칙과 충돌하는 구현은 결정 기록(16장)에 예외 사유를 남겨야 한다.

1. **단일 World.** 모든 관측은 하나의 Canonical Metric World(미터, Z-up)로 통합한다. 좌표계는 첫 CALIBRATED 때 교실의 바닥·벽으로 한 번 정하고 바꾸지 않으며, 카메라 보정은 그 안에서 정밀해질 뿐이다(4.1, 수정 6).
2. **Tier 0는 한 곳에서 끝낸다.** 관측부터 LIVE 위험 판정까지(Tier 0)는 RunPod Tier 0 서비스 한 곳에서 처리한다(3.2). 클라우드 장애는 숨기지 않는다. 노트북이 현장에서 “관제 중단”을 즉시 알리고 System Health는 UNSAFE_UNKNOWN이 된다. EC2만 끊기면 판정과 현장 경보는 계속되고 이벤트는 복구 후 재동기화된다. 엣지에서 독립 동작하는 구성은 DeploymentProfile의 “현장” 프로파일로 유지한다.
3. **검증된 정보만 안전 판단에.** 위험 판단에는 검증된 위치·형상·상태만 쓴다. HMR, 3D 재구성, VLM 결과는 보강·설명·시각화 계층이다.
4. **모르면 모른다.** 관측이 끊기면 PREDICTED를 거쳐 UNKNOWN이 된다. 사라진 사람은 “나갔다”가 아니라 “확인 불가”이고, 확인 불가인 경보는 자동 해소하지 않는다.
5. **불확실성은 보수적으로, 등급은 그대로.** 불확실한 위험은 등급을 낮추지 않고 “확인 필요”를 붙인다. 경보 피로는 히스테리시스·병합·억제로 다룬다.
6. **AI는 제안만 한다.** VLM은 근거를 설명하고 상향 의견(proposed_severity)을 낼 수 있지만, 이벤트 심각도를 직접 바꾸거나 경보를 끄지 못한다. 상향은 검증된 규칙 조건이나 운영자 확인을 거쳐 적용한다.
7. **판정 경로의 추정기 하나.** 같은 안전 판단량(사람 자세, 정적 형상)을 여러 모델로 동시에 추정해 임의로 합치지 않는다. 후보는 비교 실험으로 선정한다. HMR은 별도 비동기 시각화/보조 계층으로 실행하며 Tier 0의 관측값과 확정 위치를 덮어쓰지 않는다.
8. **관측과 추정을 구분한다.** PPE는 검출 상태에 따라 별도 모델/오버레이를 붙인다. 시각용 HMR 메시·텍스처는 관측된 영역과 보간·추정된 영역을 구분하며, 불확실한 외형을 실제 관측 사실처럼 표시하지 않는다. 이 결과를 LIVE 위험 규칙에 투입하지 않는다.
9. **덮어쓰지 않는다.** 시계열·이벤트는 추가만 하고, 구역·규칙·보정·Scene은 버전을 추가한다. 리플레이는 “그 시각에 시스템이 알던 것”을 재현한다.
10. **시뮬레이션은 실제 경보와 분리한다.** PLANNED·WHAT_IF·REPLAY 출처의 위험은 계산하되, 실제 알림 채널로는 절대 나가지 않는다(DB 제약으로 보장).
11. **설치 자동화.** 마커·체커보드·실측 평면도 없이 설치 후 사람의 움직임으로 자동 보정한다(수정 6).
12. **측정으로 결정한다.** 모든 모델·임계값 선택은 검증 게이트(15장)의 수치로 판정하고, 실패 시 대안이 미리 정해져 있다.
