# 17. 한계와 위험

교실 테스트베드의 결과는 실제 현장 성능을 보장하지 않는다. 알려진 한계는 아래와 같고, 대응을 함께 적는다.

| 한계·위험 | 영향 | 대응 |
|---|---|---|
| 3MP지만 강한 압축(약 1.1 Mbps)과 광각으로 PPE 여유가 적음(중앙 약 36px 추정) | PPE 오판 | 실제 스트림으로 G-PPE 측정, 부족 시 카메라 밀도·해상도 상향 |
| Wi-Fi 카메라 지연 흔들림, 시간 동기화 불확실 | 다시점 융합 오차 | G0 최우선 측정, 시간 오프셋 추정 |
| 2.4GHz 간섭·끊김 | 프레임 손실 | 전용 공유기, 손실률 감시 |
| 스탠드 거치 틀어짐 | 위치 오차 | 재투영 오차 감시, DRIFTED 자동 재보정 |
| 클라우드(EC2·RunPod) 의존 | 인터넷 단절 시 알림 불가 | 이중 하트비트, 현장 “관제 중단” 표시. 기본 배치는 클라우드 프로파일이며, 현장 독립성이 필요하면 현장 프로파일을 별도 실증 |
| 노트북 단일 장비 | 노트북 정지 시 위치 추적 중단 | EC2 측 감시로 즉시 UNSAFE_UNKNOWN |
| 사람 키 기반 스케일 편향 | 높이·Z·거리 오차(1\~5%) | 실측 정물(시연용 안전 장비)을 1순위 스케일 근거로 쓰고 사람 키·모델 메트릭과 교차 확인, 절대 오차는 개발 교실 실측으로 확인(수정 6) |
| 위에서 내려다보는 각도의 keypoint 품질 저하 | 카메라 바로 아래 영역 정확도 | 다른 카메라가 덮음, 신뢰도 가중 |
| VLM의 근거 오류·인용 날조 | 잘못된 설명 | 상향 전용 권한, 인용 자동 검사 |
| 교실과 현장의 차이(거리, 조명, 고소 높이, 장비) | 현장 성능 미검증 | 비목표로 명시. 현장 30m 거리에서 안전모 약 12px라 카메라 밀도·줌 필요 |
| 카메라보다 높은 작업자 | 화면 밖으로 빠짐 | 교실 40cm 단상은 문제없음. 현장 확장 시 카메라 높이 상향 |
| 인터넷·RunPod 단절 시 관제 정지 | 위치 추적과 위험 판정이 모두 멈춤(EC2만 끊기면 판정·현장 경보는 계속) | 노트북이 현장 ‘관제 중단’ 경보, System Health UNSAFE_UNKNOWN. 엣지 독립이 필요하면 DeploymentProfile ’현장’으로 전환 |
| 관제 화면 경보 의존 | 관제 화면을 아무도 보지 않거나 소리가 꺼지면 현장 경보 없음 | 확인될 때까지 소리 반복, 반장 PWA 병행, 시작 시 시험 경보 |
| iPhone PWA 알림 조건 | 홈 화면에 설치하지 않으면 알림을 받지 못함 | 설치 절차(18.1)에 포함, 시험 알림으로 확인 |
| 당사자 직접 경고 수단 없음(MVP) | 위험한 작업자 본인에게 닿는 채널이 없음 | 로컬 경보 소리, 확장 트랙의 워치 |
| 자동 보정의 실증 근거 없음 | Tapo C110 4대로 자동 보정이 되는지 PoC 전 | 독립 검증점 통과 전까지 PROVISIONAL, 대체 경로 준비 |
| 상시 영상 업로드·RunPod 상시 가동 | 대역폭(C110 실측 4대 약 4.5 Mbps, 10 Mbps 이상 확보, 3.5)·크레딧·개인정보 부담 | 관제 시간에만 가동, TLS 전송, 영상 비저장(링 버퍼만), 동의서 명시 |
| RunPod 데이터센터 거리 | 업로드·왕복 지연 증가로 현장 경보가 늦어짐 | 가까운 데이터센터 선택, G0에서 capture_to_site_alert 실측 |
| 클라우드 프로파일의 안전 주장 범위 | 지연 목표는 시험 목표일 뿐, 현장 안전 경보에 충분하다고 보장하지 않음 | 연구·교육 시연으로 한정. 현장 안전 독립성은 현장 프로파일 별도 실증 |
| COCO 17관절의 발 정보 부족 | 접지·지지 표면 판단이 부정확할 수 있음 | ContactEstimator, UNKNOWN 처리, 필요 시 RTMPose Halpe-26 비교 |
| Fast SAM 3D Body 외형 복원 한계 | 고정 카메라 가림/좁은 시점에서 외형이 추정에 과도하게 의존 | 관측/추정 영역 분리, 다중 시점 검증, 원형 기본 메시 폴백 |
| 공유 GPU에서 대형 EXP 동시 구동 | Tier 0 지연·OOM·CUDA 환경 충돌 위험 | 개발 시 직렬 큐, 프로세스·환경 격리와 운영 중 우선순위 제한, 지연 초과 시 분석 워커 축소. GPU Pod 는 하나로 유지(3.2, 수정 6) |
| 3D 인물 텍스처의 개인정보 | 외형을 통한 재식별/민감한 관측자료 축적 가능성 | 별도 동의·접근/저장·삭제 정책 승인 전 실인물 데이터 수집·학습 보류 |
| 시연 리전 GPU 가용성 불확실 | 시연 당일 GPU를 못 구하거나 등급이 바뀜 | 일본 리전 확정(수정 4), 대체 순서 사전 지정, GPU별 엔진 빌드 절차·설치 스크립트 준비, D-14 GPU 확보 확인 |
| 리전 이전 작업 | 누락·손상, 이전 직후 기동 실패 | 이전 목록·해시 비교, Docker 이미지 기반 기동 시험, 리허설은 이전 후 같은 환경에서 |
| 시연 리전에서 상위 GPU(H200 등) 사용 | 크레딧 소진 가속 | 관제 시간에만 가동, 리허설 횟수 계획, 비용 기록(20.5) |
| 노트북 GPU 대체 경로 미검증 | 장애 시 현장 프로파일로 못 넘어감 | 4070에서 4대 FPS·지연 측정 후 채택, 미채택이면 "관제 중단" 표시만 유지 |
| Tier 0와 분석 워커의 GPU 공유 | VLM 실행 중 Tier 0 지연 증가, 메모리 부족 | Tier 0 메모리 선확보, 지연 초과 시 분석 작업 중지, G0 동시 실행 측정 |
