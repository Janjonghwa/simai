# 17. 한계와 위험

교실 테스트베드의 결과는 실제 현장 성능을 보장하지 않는다. 알려진 한계는 아래와 같고, 대응을 함께 적는다.

| 한계·위험 | 영향 | 대응 |
|---|---|---|
| 3MP지만 강한 압축(약 1.1 Mbps)과 광각으로 PPE 여유가 적음(중앙 약 36px 추정) | PPE 오판 | 실제 스트림으로 부록 C PPE 게이트 측정, 부족 시 카메라 밀도·해상도 상향 |
| Wi-Fi 카메라 지연 흔들림, 시간 동기화 불확실 | 다시점 융합 오차 | G0 최우선 측정, 촬영 시각 추정(3.9), 시간 오프셋 추정 |
| 2.4GHz 간섭·끊김 | 프레임 손실 | 전용 공유기, 손실률 감시 |
| 스탠드 거치 틀어짐 | 위치 오차 | 재투영 오차 감시, DRIFTED 자동 재보정 |
| 클라우드(인터넷·RunPod·EC2) 의존 | 인터넷이나 RunPod 가 끊기면 위치 추적과 위험 판정이 모두 멈춤(EC2만 끊기면 판정·현장 경보는 계속) | 이중 하트비트, 노트북이 현장 ‘관제 중단’ 경보, System Health UNSAFE_UNKNOWN. 기본 배치는 클라우드 프로파일이며, 현장 독립성이 필요하면 DeploymentProfile ’현장’을 별도 실증 |
| EC2 자체 장애 | PWA·관제 화면 전달이 멈추고 그 구간 world_state 기록이 빔 | 판정·현장 경보는 유지, PWA·뷰어에 STOMP 하트비트로 연결 끊김 표시, 리플레이는 “데이터 없음”. 외부 가동 감시는 선택 |
| 노트북 단일 장비 | 노트북 정지 시 위치 추적 중단 | EC2 측 감시로 즉시 UNSAFE_UNKNOWN. 노트북 OS 설정(18.1)으로 업데이트·절전 중단 방지 |
| 사람 키 기반 스케일 편향 | 높이·Z·거리 오차(1\~5%) | 실측 정물(시연용 안전 장비)을 1순위 스케일 근거로 쓰고 사람 키·모델 메트릭과 교차 확인, 절대 오차는 개발 교실 실측으로 확인 |
| 위에서 내려다보는 각도의 keypoint 품질 저하 | 카메라 바로 아래 영역 정확도 | 다른 카메라가 덮음, 신뢰도 가중, 미세조정 데이터에 카메라 근처·바로 아래 시점 포함(15.4) |
| 2대만 보는 영역의 오연결 | 다른 사람 관절이 잘못 묶여 Z 가 틀림 | 에피폴라 경쟁 후보가 있으면 VALID 금지(5.2), G2 에서 오연결률 측정 |
| 발목 가림 | support_surface UNKNOWN 이 많아져 높이 규칙이 “확인 필요”로 몰림 | 발 6점 미세조정(15.4), G2 에서 UNKNOWN 비율 측정 |
| “확인 필요” 경보 몰림 | PREDICTED 불확실성 확대와 보수적 판정으로 알림 피로 | 발생 지속 조건·재개(6.4), G6 에서 몰림 정도와 전체 경보율 측정 |
| VLM의 근거 오류·인용 날조 | 잘못된 설명 | 상향 전용 권한, VLM 입력 사본에 위험 구역·대상 인물 오버레이 표시 및 교실 사물 명칭 변경 프롬프트 금지(5.4), 보고서는 법령 지식 그래프 허용 목록·코드 4단계 검증으로 인용 존재 100% 강제(v1.3 수정 49) |
| 외부 LLM API 사용 및 법령·지침 코퍼스 저작권 | 개인정보 국외 이전, 외부 서비스 장애, 외부 기술지침·사례 무단 재배포 위험 | EC2 Python 컨테이너에서 텍스트만 전송(영상·이미지·얼굴·실명 금지), SSAFY GMS 를 거쳐 OpenAI(국외)로 보냄, 기관(SSAFY) 허가 기준(11.5). 국가법령정보센터 Open API 법령을 먼저 적재하고 KOSHA GUIDE·중대재해 사이버안전박물관 재해사례는 재배포·API 이용 조건 확인 후 적재(5.4·11.3). LLM 장애는 보고서만 지연시키고 경보에는 영향 없음 |
| 교실과 현장의 차이(거리, 조명, 고소 높이, 장비) | 현장 성능 미검증 | 비목표로 명시. 현장 30m 거리에서 안전모 약 12px라 카메라 밀도·줌 필요 |
| 카메라보다 높은 작업자 | 화면 밖으로 빠짐 | 교실 40cm 단상은 문제없음. 현장 확장 시 카메라 높이 상향 |
| 노트북 로컬 경보 의존 | 노트북 소리가 꺼지거나 출력 장치가 바뀌면 현장 경보가 들리지 않음 | 확인될 때까지 소리 반복, 출력 오디오 장치 고정(18.1), 시작 시 시험음, 관제 화면 경보·반장 PWA 병행 |
| iPhone PWA 알림 조건 | 홈 화면에 설치하지 않으면 알림을 받지 못함 | 설치 절차(18.1)에 포함, 시험 푸시로 확인 |
| 당사자 직접 경고 수단 없음(MVP) | 위험한 작업자 본인에게 닿는 채널이 없음 | 로컬 경보 소리, 확장 트랙의 워치(부록 C) |
| 자동 보정의 실증 근거 없음 | Tapo C110 4대로 자동 보정이 되는지 PoC 전 | 독립 검증점 통과 전까지 PROVISIONAL, 걷기 재수행·정물 추가 배치(4.3) |
| 상시 영상 업로드·RunPod 상시 가동·원격 CCTV 시청 | 대역폭(C110 실측 4대 Tier 0 약 4.5 Mbps, LIVE 관제 중 원격 CCTV 시청 동시 활성 시 합산 약 9 Mbps, 10 Mbps 이상 확보, 3.3·3.5)·크레딧·EC2 송출 비용(시청자당 약 1.8 GB/h)·개인정보 부담 | RunPod 는 관제 시간에만 가동, 원격 CCTV 는 보는 관리자가 있을 때만 전송(`cctv_remote_control` `demand active`)하고 Tier 0 와 큐를 분리하며 동시 5명·월 80 GB(1분 단위 추가 전용 기록)·10분 무입력·30분 연속 시청·탭 비가시 차단 상한 적용(10차 GPU 세션에서 동시 전송 지연 실측 후 밀리면 관제 중 원격 시청 끄기 설정, v1.3 수정 46), TLS 전송, EC2 영상 무저장, 기관(SSAFY) 허가 기준(11.5) |
| RunPod 데이터센터 거리 | 업로드·왕복 지연 증가로 현장 경보가 늦어짐 | 가까운 데이터센터 선택, G0에서 capture_to_site_alert 실측 |
| Pod 재설정 시 공개 포트 변경 | 노트북이 Tier 0 에 접속하지 못함 | 엔드포인트 등록·조회(3.12) |
| 시연장 망(SSAFY 망)과 EC2 경유 | 시연장도 SSAFY 망이라 외부 임의 포트 Direct TCP 가 막혀 EC2(`simai.live:22`) SSH 경유 + Pod 공개 포트 Direct TCP 를 기본으로 씀. EC2 가 I0 경로에 들어가므로 EC2 호스트가 멈추면 현장 경보도 함께 멈추고(전에는 뷰어만. EC2 배포는 컨테이너만 재시작하므로 호스트 `sshd`·I0 중계는 끊기지 않음), EC2 CPU(`t3.xlarge` 4 vCPU, 버스트형)를 CI 와 같이 쓰며, 시연장 SSAFY 망 바깥 IP 가 다르면 EC2 보안 그룹 인바운드 22(팀 IP 대역만)에서 막힐 수 있음. 443 프록시는 요청당 약 0.58 s 지연 추가·100초마다 끊김 | 시연장 망에서 EC2 경유 경로(보안 그룹 인바운드 22 확인 포함) 10분 이상 연속 시험(NFR-35), LIVE·GPU 세션 중 CI 빌드 피하기, EC2·망 장애 시 LTE 테더링(두 번째 업링크)·443 프록시(최후 예비)로 전환(3.12, 18.1) |
| 클라우드 프로파일의 안전 주장 범위 | 지연 목표는 시험 목표일 뿐, 현장 안전 경보에 충분하다고 보장하지 않음 | 연구·교육 시연으로 한정. 현장 안전 독립성은 현장 프로파일 별도 실증 |
| Fast SAM 3D Body 외형 복원 한계 | 고정 카메라 가림/좁은 시점에서 외형이 추정에 과도하게 의존 | 관측/추정 영역 분리, 다중 시점 검증, 캡슐 아바타 폴백 |
| GPU 공유(Tier 0·분석 워커·대형 EXP) | VLM·EXP 실행 중 Tier 0 지연 증가, 메모리 부족, CUDA 환경 충돌 | Tier 0 메모리 선확보와 메모리 예산표(3.2), 지연 초과 시 분석 작업 중지·축소, 개발 시 직렬 큐, 프로세스·환경 격리, LIVE 관제 중 오프라인·배치 EXP 금지(시연 범위인 EXP-02 상시 아바타 스트림 루프는 분석 워커 상한 안에서 돌되 Tier 0 지연 감시 표시 파일로 지연 초과·모름 시 즉시 멈추고 뷰어는 0.5 s 뒤 캡슐로 복귀, 큐 대기 초과 소수는 넘기고 재개 10초, 3.2), G0 동시 실행 측정. GPU Pod 는 하나로 유지 |
| 3D 인물 텍스처·얼굴 표현 | 저해상도(30\~50px)에서 안 보이는 얼굴을 지어내거나 외형 자산이 무기한 남을 위험 | 촬영·활용은 기관(SSAFY) 허가 기준(참여자 별도 동의 조건 없음). 관측된 얼굴 픽셀은 그대로 쓸 수 있으나(`face_policy` 기본 OBSERVED, BLURRED·EXCLUDED 선택) 생성형 얼굴 복원·표정 추정은 금지하고, 얼굴 영역도 관측·미관측을 구분한다(`face_ratios`, 보간 없음). 자산은 관제 앱 인증으로만 조회하고 프로젝트 발표 후 30일 안 파기(11.5, 14) |
| 시연 GPU 사이트 미정·가용성 불확실 | 시연 당일 GPU를 못 구하거나 등급이 바뀜, 재시작에도 남는 저장 위치가 없으면 재시작 복구가 성립하지 않음 | 시연 사이트를 D-14 전에 정함(19.1), 최소 사양·시작 절차(`simai-bootstrap`)로 어느 GPU 에서든 같은 순서로 준비, GPU별 엔진 빌드 절차 준비, 시연 저장 위치에서 강제 종료 복구 시험(G3), D-14 GPU 확보 확인, 당일 아침 Pod 확보 후 유지(18.2) |
| 노트북 GPU 대체 경로 없음 | 인터넷·GPU 사이트 장애 때 현장 프로파일로 넘어가지 못함 | 대체 경로를 만들지 않기로 함(3.12). 장애 때는 "관제 중단" 표시와 EC2 UNSAFE_UNKNOWN 만 유지 |
| 노트북 보안 프로그램의 소켓 오류(Windows `WinError 10014`) | 노트북 앱 연결이 끊기거나 앱이 멈춤 | 호출 지점에서 짧게 다시 시도, 넘기면 기존 재접속, 모르면 관제 중단 표시(3.10). 원인(보안 프로그램 네트워크 필터)은 예외 전후 빈도로 확인 |
