# 18. 운영 절차

설치부터 종료, 장애 대응, 데이터 삭제 확인까지의 표준 절차다.

## 18.1 최초 설치

1. 교실 실측: 천장 높이, 카메라 위치, 전원·콘센트, 평면도 파일 작성(원점 모서리와 축 표시).
2. 네트워크 시험: 카메라 1대로 싸피 Wi-Fi 접속과 노트북 RTSP 수신 확인. 실패 시 공유기 구성(3.5).
3. 카메라 앱 설정: RTSP 계정, fps 25 고정, 워터마크·UPnP·경보·야간 전환·사생활 모드·자동 업데이트 끄기, 펌웨어 버전 기록.
4. 거치: 네 모서리, 2.6\~2.8m, 아래로 25\~28°, 무게 주머니.
5. 시간 동기화 시험(G0): ms 시계를 4대가 동시에 촬영.
6. 평면도 업로드 → 자동 보정 시작 → 한 명 1\~2분(부족하면 여러 명 5분 이상) 걷기 → 실측 검증점 3\~5곳에 서기 → CALIBRATED 확인. 기준 미달이면 그 자리에서 평면도 점 PnP, 그다음 ChArUco 보정으로 전환한다(설치 일정에 여유를 둔다).
7. 정적 3D 생성 요청 → Scene 커밋 확인.
8. 구역 등록, 시험 이벤트로 PWA 알림 확인.

**설치 보충.**

- 정적 3D 생성 전에 교실을 비우고 카메라별 프레임을 확보한다(5.3).
- 카메라 시각 기준을 노트북으로 지정하고, 4대 시각 차이를 상태 화면에서 확인한다(3.9).
- 반장 휴대폰: Android는 브라우저에서 알림을 허용한다. iPhone은 Safari에서 “홈 화면에 추가”로 PWA를 설치한 뒤 알림을 허용해야 Web Push를 받는다(iOS 16.4 이상). 설치 후 시험 알림으로 확인한다.
- 관제 화면 PC의 소리 출력을 켜고 시험 경보로 확인한다(3.10).

## 18.2 일상 시작·종료

- 시작: 노트북 서비스 기동(재부팅 시 자동 기동 설정) → EC2 상태 화면에서 카메라 4대 OK, CALIBRATED, NOMINAL 확인 → RunPod Tier 0는 관제 시작 전에 반드시 기동하고, 분석 워커는 필요할 때만 기동.
- 노트북 설정: 전원 연결 유지, 잠자기·덮개 닫힘 동작 해제, 인터넷 트래픽이 싸피 Wi-Fi로 나가는지 확인.
- 종료: 노트북 서비스 정지 → RunPod 정지(크레딧 절약) → 당일 이벤트·조치 미결 확인.

## 18.3 장애 대응

| 증상 | 확인 | 조치 |
|---|---|---|
| 현장 “관제 중단” | 노트북 인터넷 연결 | Wi-Fi 재연결, RunPod Tier 0·EC2 상태 확인 |
| “현장 장비 응답 없음” | 노트북 전원·서비스 | 재기동 |
| 카메라 1대 OFF | 카메라 전원·공유기 연결 | 재연결, 구역 감시 저하 해소 확인 |
| DRIFTED | 스탠드 충돌 여부 | 위치 복구 후 한 명 걷기로 재보정 |
| VLM 근거 지연 | RunPod 상태 | 분석 워커만 문제면 근거 없이 경보는 정상. Tier 0 Pod 문제면 관제 정지 상태이므로 즉시 재기동 |
| 시간 동기화 이탈 | health의 sync_offset | 카메라 재부팅, NTP 확인 |

## 18.4 데이터 삭제 확인

주 1회 객체 저장소 수명 주기 규칙과 DB 보관 정책이 동작했는지 확인하고(삭제 예정일 지난 클립 0건), 보존 표시된 항목의 사유를 검토한다. 참여자 삭제 요청은 해당 세션 데이터를 찾아 삭제하고 기록을 남긴다.
