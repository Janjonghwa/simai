# 8. 기능 명세

MVP는 F-05 → F-06 → 현장 전달(노트북 로컬 경보·관제 화면 경보, 3.10)의 실시간 루프와 F-02 사전 보고서, F-10 기록·최소 리플레이, F-11 PPE 판정으로 구성한다. 확장 기능은 같은 Risk Engine과 Spatial DB를 재사용하며 부록 C 에 요약한다. 기능 번호는 1.3 을 본다.

## 8.1 F-05 3D 위치 추적 (MVP)

- 5.1·5.2의 출력(World XYZ, 3D 골격, 관측 상태)을 10 Hz로 EC2에 보낸다.
- 위치 정확도는 “m 단위 근사 + 오차 범위 명시”로 표현한다. 밀리미터 정밀도를 주장하지 않는다.
- 고소 작업자는 Z로 직접 표현되어 R2·R3·R4의 입력이 된다.

## 8.2 F-06 입체 Geo-fencing (MVP)

- 관리자는 Three.js 뷰어에서 바닥 다각형을 그리고 최저·최고 높이를 지정해 입체 구역을 만든다(“개구부 위 2m 작업 공간”, “양중 하부 공간”).
- 구역 속성: 유형, 심각도, 유효 시작·종료 시각, 요구 조건(안전모·조끼. R9 경보는 안전모 요구만, 8.10).
- 수정은 덮어쓰지 않고 새 버전을 추가한다. 리플레이 확장은 그 시각에 유효했던 구역을 보여준다(부록 C).
- 판정은 Point-in-Prism + 불확실성 범위(7.1), R1·R5·R6 적용. 판정은 Risk Engine 이 하고 VLM 근거는 첨부만 한다.

**구역 판정 유형.** 구역마다 판정 유형을 지정한다.

| 유형 | 판정 | 쓰임 |
|---|---|---|
| GROUND_FOOTPRINT | position_xy + 수평 불확실성이 바닥 다각형에 걸리는지 | 바닥 출입 통제 구역, 장비 주차 구역 |
| VOLUME_3D | 사람이 차지하는 높이 범위(서 있는 면 Z \~ VALID 관절 중 가장 높은 Z, 없으면 head_z)와 구역 높이 범위가 겹치는지, 3D 불확실성 포함 | 개구부 위 작업 공간, 양중 하부 공간 |

VOLUME_3D 구역에서 XY는 다각형 안인데 Z(서 있는 면 또는 head_z)를 모르면 “진입하지 않았다”고 확정하지 않고, 이벤트를 만들되 “확인 필요”(`Z_UNKNOWN`)로 표시한다.

## 8.3 F-02 TBM 리스크 보고서 (MVP)

- **작업(`work_unit`) 단위 보고서와 레이아웃 연결.** TBM 보고서 단위는 TBM 작업(`work_unit`, `/api/work-units`) 하나에 보고서 1개(최신본 + 버전 이력)다. 각 작업(`work_unit`)에 그 작업이 쓰는 가상 레이아웃(`layout_plan`, `/api/layouts`, 개구부·가설 비계·장비 주차 구역)과 공종(`work_type`, 예: 고소·비계 작업, 개구부 주변 작업, 자재 반입·운반 등)을 연결한다(`work_unit.layout_id`, `work_unit.work_type`, v1.3 수정 49). 같은 작업의 보고서를 다시 만들 때는 덮어쓰지 않고 새 버전(`report_version`)을 추가한다.
- **계획 작업 위치.** 사람 대상 규칙(R1·R2·R3)은 사람이 서 있을 위치가 있어야 판정한다. 기본은 Risk Engine 컨테이너가 레이아웃의 작업면·구역에서 대표 위치를 자동으로 만들고, 관리자가 위치를 직접 줄 수도 있다(그때는 만들지 않는다). 요청에 위치가 없거나 빈 배열이면 ‘사람 없음’이 아니라 ‘컨테이너가 만든다’는 뜻이다. 판정에 쓴 위치는 결과에 출처(요청이 준 위치 REQUESTED, 만든 위치 GENERATED)와 함께 실리고, EC2(Spring)가 결과의 위치 목록을 위험 항목과 함께 `sim.*` 에 저장한다. 계획 위치는 World ID 가 아니다. 생성 규칙: 작업면마다 상판 가운데 1곳(가운데가 R2 발생 거리 밖일 만큼 넓은 면은 가장 긴 변 가운데에서 0.5 m 안쪽 1곳을 더함), 판정 시각에 유효한 개구부 구역(`zone_type` OPENING)마다 가장 긴 변 가운데에서 바깥 0.2 m 의 바닥 1곳(점유 반경 0.3 m 안이라 R1 이 판정한다). 그 밖의 구역 유형에는 만들지 않고, 머리 높이는 주지 않으며(VOLUME_3D 구역에서는 확인 필요 `Z_UNKNOWN`), 같은 레이아웃·판정 시각이면 같은 위치·같은 ID(`gen-<작업면·구역 ID>-<순번>`)다. 수치 근거는 `docs/design/risk-engine-container.md`.
- **평가한 위치 없음.** 만들 작업면·유효한 개구부가 없고 요청도 위치를 주지 않으면 결과의 위치 목록이 비고 위험 항목도 없다. 이것은 사람 대상 규칙을 판정할 위치가 없었다는 뜻이지 ‘위험 없음’이 아니다. 보고서·화면은 ‘평가한 작업 위치 없음’으로 보이고, 필요하면 관리자가 위치를 준다. 계약은 빈 위치 목록을 그 뜻으로 읽고, 선택 표시 `no_evaluated_positions` 로 명시할 수 있다(`risk_plan_result` 1.1.0, 컨테이너가 채우는 것은 19.1).
- Risk Engine이 PLANNED 출처로 규칙을 계산한다(수평 거리와 높이 차 포함). 위험 항목은 확률 대신 등급 + 근거로 표현한다(“추락 리스크 85%” 같은 수치는 쓰지 않는다).
- 계산 요청과 현장 이력 연계: 관리자가 `POST /api/reports/tbm`(작업 ID `workId` 지정, 하위 호환 `layoutId`)을 부르면 EC2 가 그 작업에 연결된 가상 레이아웃으로 Risk Engine Python 컨테이너(`deploy/risk-engine`)에 PLANNED 계산을 요청하고(결과는 `sim.*`), 해당 구역들의 최근 `risk_event` 발생 이력 요약(구역별 건수·최고 등급·대표 규칙, 폐지된 반장 조치 티켓은 제외) 및 개인정보가 아닌 공종(`work_type`)과 함께 같은 Python 컨테이너의 보고서 생성 경로(`POST /v1/report/generate`, 12.2)를 호출한다(GPU·Pod 불필요, I5 `tbm_report` 작업은 폐기 예정, v1.3 수정 49). 작업명·인원·반장/조 이름은 LLM 에 보내지 않고 서버가 보고서 머리말에만 붙인다(5.4). M3 에는 단독 평가 API 가 필요 없다(단독 평가는 부록 C.4).
- 법령 지식 그래프 검색과 4단계 생성·검증: EC2 Python 컨테이너가 PostgreSQL 법령 지식 그래프(`rag_node`·`rag_edge`, `Qwen/Qwen3-Embedding-0.6B` 1024차원)에서 규칙 태그·키워드(`pg_trgm`)·벡터(`pgvector`) 하이브리드 검색과 참조 엣지 1단계 확장으로 후보를 모으고(1단계), 허용 인용 ID 목록을 확정한 뒤(2단계), 외부 LLM(5.4, 텍스트만 전송)으로 초안 JSON 을 1회 작성하고(3단계), 코드 검증으로 허용 목록·본문 미허용 조문 번호·확률 표현·등급 불변성을 검사한다(4단계, 위반 시 최대 1회 재작성). 일일 일지도 같은 컨테이너 경로(`report_kind` DAILY, `POST /api/reports/daily`)로 만든다(`docs/design/tbm-legal-graph.md`).
- 출력과 관제 웹 `/tbm` 화면 흐름: 보고서(PDF 는 브라우저 인쇄로 만든다, 별도 내보내기 API 없음), 계산 근거 표, 인용된 법령·지침·사례의 관계 서브그래프(`subgraph`: `nodes[]`·`edges[]`) 및 4단계 실행 상태(`steps[]`: 단계별 건수·결과·소요 ms)를 작업별 최신 보고서와 버전 이력으로 조회한다(`GET /api/reports/tbm?workId={workId}`, `GET /api/reports/tbm/{reportId}`). 관제 웹앱 `/tbm` 화면은 작업 등록·수정(`/api/work-units`, `/api/layouts`)과 보고서 생성·조회(`/api/reports/tbm`)를 연결해 ① 왼쪽 패널의 **위험성 평가 표** ← PLANNED 판정 결과, ② **대책·법령 근거(새 칸)** ← 보고서 문단(`sections`)·인용(`citations`), ③ **법령 그래프 패널·단계 표시** ← `subgraph`·`steps`(시연 Scene 6), ④ 오른쪽 패널의 **A4 회의록** ← 위 값들과 작업 머리말로 자동 채움(고정 체크리스트 문구는 유지하고 사람이 편집 모달에서 수정 가능)으로 그린다. 기존 `tbmDemo.ts` 목 데이터는 API 실패 시 대체 화면으로만 쓴다(`docs/design/tbm-legal-graph.md`).

## 8.4 F-09 반장 PWA

폐기(v1.3). 반장 PWA·Web Push·조치 티켓·조치 사진을 두지 않는다(16장). MVP 에서 카메라에 잡힌 모든 사람의 위험은 노트북 로컬 경보와 관제 화면 경보로 전달하고 관제 화면에서 확인(ACK)한다(3.10). 개인 채널인 워치는 부록 C.

## 8.5 F-10 기록 (MVP) · 최소 리플레이 (M3)

- 최소 리플레이(M3): 시각 슬라이더로 시각 T를 고르면 그 시각의 `world_track_state`와 활성 `risk_event`를 불러와 Three.js에 재생한다. EC2 단절 등으로 기록이 없는 구간은 “데이터 없음”으로 표시하고 보간하지 않는다.

## 8.10 F-11 PPE 판정 (MVP, M3)

- 관제 화면에 World ID 별 안전모·조끼 상태(WORN·NOT_WORN·UNKNOWN)와 근거 시각을 보인다(13.3). 판정 방법은 5.5 를 본다.
- 구역 편집에서 안전모·조끼 요구 조건을 지정한다(8.2). 안전모 요구 구역에서 안전모 NOT_WORN 이면 R9(HIGH) 로 노트북 로컬 경보·관제 화면 경보를 낸다(7.2·7.3). 조끼는 표시만 한다.
- R9 경보는 G9·G6-R9 를 통과해야 켠다. 통과하지 못하면 판정·표시만 하고 R9 는 끈다(15.1).
- 신호수 표식·역할 예외는 확장이다(부록 C).
