# 4. 좌표·단위 규약과 캘리브레이션

World 좌표계는 첫 CALIBRATED 때 교실의 바닥·벽으로 한 번 정하고 바꾸지 않는다. 캘리브레이션은 마커·체커보드·실측 평면도 없이 교실 직선과 사람의 움직임으로 자동 수행하며, 결과는 버전으로 확정한다.

## 4.1 World 좌표계

- 단위: 미터. 오른손 좌표계, +Z 상방
- 원점: 첫 CALIBRATED 때 정한 교실 한 모서리의 바닥
- 축: X·Y는 원점에서 만나는 두 벽 방향이다. 4.3 1단계 MapAnything 초기 추정의 벽 형상·벽 소실점으로 정하며, COMMITTED Scene(5.3)과는 별개다. 바닥 Z = 0(사람 발 접지점으로 맞춘 바닥 평면)
- 위험 구역·장비·작업면·가상 레이아웃은 모두 이 좌표로 저장한다. 카메라 보정이 바뀌어도 영향을 받지 않는다.
- 좌표계를 정한 뒤 다시 정하면 “좌표계 이전”을 명시적 사건으로 기록하고 모든 데이터를 변환한다.

**BEV 평면도(보조 화면).** 전체 상황을 한눈에 보는 간략한 위에서 본 화면이다. 보정이 끝나면 카메라 4대의 바닥 영역과 정적 3D 를 위에서 본 화면으로 펴서 자동으로 만든다. 좌표·스케일의 기준이 아니고 정확도 목표도 없다. 안전 판단에는 쓰지 않으며, 구역을 그리거나 사람 위치를 2D 로 보여주는 데 쓴다. 비상 화면(13.6)도 같은 화면 컴포넌트를 쓴다. 메인 공간 표현은 MapAnything 정적 3D 디지털 트윈(5.3)이다.

## 4.2 경계별 변환 규칙

변환은 각 경계의 어댑터 한 곳에서만 수행한다. 다른 코드는 World 좌표만 다룬다.

| 대상 | 규약 | World (x, y, z) 로부터 |
|---|---|---|
| 카메라 좌표 | OpenCV: x 오른쪽, y 아래, z 앞 | 외부 파라미터 R, t |
| Three.js · glTF | 미터, 오른손, +Y 상방 | (x, z, −y) |
| Unreal | 센티미터, 왼손, +Z 상방 | (100x, −100y, 100z) |
| 시각 | UTC, int64 밀리초 | — |
| 각도 | 내부 라디안, 화면 표시만 도 | — |

각 어댑터에는 격자점 몇 개를 왕복 변환해 원래 값으로 돌아오는지 확인하는 단위 테스트를 둔다.

## 4.3 자동 캘리브레이션

설치 후 사람이 할 일은 실측 정물 세우기, 걷기, 한 번의 검증(4.4)뿐이다. 초기 보정은 교실에 한 명이 1\~2분 걷는 것으로 시작하고, 부족하면 여러 명이 걷는다. 여러 명이 걸으면 모두 보정에 쓰고, 카메라 간 오대응은 강건 손실과 이상치 제거로 거른다. 필요한 시간은 G1에서 확정한다.

1. **초기 추정:**
   - 내부 파라미터(무마커): 교실 영상(벽 모서리·문틀·책상 가장자리·천장선 같은 직선이 보이는 장면)으로 단일 이미지 내부 파라미터를 추정해 초점거리·왜곡 초기값을 얻는다. 기본 경로는 학습 모델 AnyCalib(ICCV 2025, `anycalib_dist` 가중치, `radial:2` = OpenCV [k1, k2], 주점도 추정)이고, 사용할 수 없으면(패키지·가중치 없음, 해시 불일치) GeoCalib(ECCV 2024, `distorted`·`radial`), 그것도 없으면 고전 기준(직선이 곧게 펴지는 방사 왜곡 + 직교 소실점 초점, 가중치·GPU 불필요) 순서로 내려간다. 광각·왜곡 영상으로 학습했고 코드·가중치가 Apache-2.0 이며 공식 벤치마크로 우열이 나와 있어 세 방법 비교 실험은 하지 않는다(라이선스는 부록 B). 백엔드가 돌았는데 실패하면 다른 방법 값으로 채우지 않고 비우며, 어떤 방법으로 나왔는지 기록에 남긴다. 고전 기준은 학습 결과의 직선성 확인에도 쓴다: 고전 기준이 찾은 교실 직선을 학습 결과로 펴서 곧지 않으면 그 결과를 비운다. 추정 입력은 몇십 초 동안 받은 프레임의 시간 중앙값 배경이며, 영상은 메모리에서만 처리하고 저장하지 않는다(11.5). 이 값은 초기값이고 C110 4대는 같은 렌즈이므로 한 대의 추정값을 나머지의 초기값으로 쓰고, 최종값은 3단계에서 카메라별로 다듬는다.
   - 4대 영상을 MapAnything 에 넣어 상대 자세, 바닥 평면, 중력 방향, 벽 형상을 추정한다.
2. **좌표계 고정:** 사람 발 접지점으로 바닥 평면(Z = 0)과 중력 방향을, 1단계 MapAnything 의 벽 형상·벽 소실점으로 축을, 방 모서리 하나로 원점을 정해 고정한다(어느 모서리·벽을 고르는 자동 규칙은 19.1). 스케일은 아래 우선순위로 정한다.
3. **정밀화:** 걷는 사람의 2D keypoint로 번들 조정을 수행한다(HumanCalib 원리를 따른 자체 구현). 바닥 평면은 발 접지점으로 재확인하고, 실측 정물을 제약으로 넣어 카메라별 내부 파라미터·왜곡 계수를 함께 다듬는다.
4. **검산:** 4.4 의 독립 검증(보정에 쓰지 않은 지점의 머리 높이·카메라 간 일관성)으로 확인한다. 차이가 크면 PROVISIONAL을 유지한다. CCVS 방식 카메라별 높이 검산(사람 몸이 수직이라는 가정으로 카메라 한 대의 높이를 따로 구함)은 보조 진단이다: CALIBRATED 기준(4.4)에 넣지 않고, 번들 조정 결과와 한도 넘게 어긋나거나 검산할 수 없으면 그 후보를 불확실(UNCERTAIN)로 표시해 새 보정 버전으로 제안하지 않는다(재보정 후보 거름).
5. **동결:** CALIBRATED가 되면 보정을 동결하고 이후에는 감시만 한다.

**번들 조정 구현 범위.** HumanCalib 의 원리(걷는 사람의 관절을 다시점 제약으로 쓰는 번들 조정, 뼈 길이 일정)를 따르되 코드는 쓰지 않고 자체 구현한다. HumanCalib 의 사람 선택과 3D lifting 초기화(기본 3D lifter 는 비상업 라이선스)는 쓰지 않는다: 받은 사람을 모두 쓰고, 초기 3D 는 1단계 초기 보정으로 삼각측량한 값이다. 내부 파라미터는 1단계 값을 초기값·사전 분포로 쓴다. 2D 입력은 따로 추론하지 않고 Tier 0 의 YOLO26x-pose keypoint 를 재사용한다. 키를 아는 사람의 실측 키와 실측 정물은 스케일 제약으로 넣고 서로 교차 확인한다. 퇴화(카메라 3대 미만, 접지점이 한 줄로 몰림, 영상 덮음 부족 등)나 이상치 비율이 크면 결과를 불확실로 표시하고 제안하지 않는다. 판정(CALIBRATED/PROVISIONAL)은 4.4 기준이 한다.

**스케일 근거 우선순위.** 실측 정물 \> 키를 아는 사람 \> 사람 키 통계(여러 사람이 지날수록 수렴) \> 표준 사물 크기(문, 책상) \> 모델 자체 추정(MapAnything 메트릭). 둘 이상을 교차 확인한다.

- **실측 정물:** 시연에 쓰는 안전 장비 중 단단하고 큰 것(안전봉, 라바콘, 바리케이드 등)의 치수를 미리 재서 정물 목록(이름·치수·측정일)으로 둔다. 설치 때 2\~3개를 방의 서로 다른 곳, 카메라 2대 이상에 보이는 위치에 세운다. 라바콘·안전봉은 COCO 클래스가 아니므로 YOLOE-26 으로 찾고, 정물마다 꼭대기·바닥 끝점을 정의해 2대 이상에서 삼각측량한 높이를 목록 치수와 맞춰 스케일을 정한다. 클수록, 서로 멀수록 정확하다(예상 약 1%, 미검증). 안전모는 작아서 보조로만 쓰고, 안전조끼처럼 형태가 변하는 것은 쓰지 않는다.
- **키를 아는 사람:** 보정 걷기를 키를 미리 잰 팀원이 해서 정물과 교차 확인한다(예상 1\~2%).
- 실측 정물이 없으면 스케일 정확도는 2\~5%에 머문다는 것을 보정 버전에 기록한다. 사용한 근거를 보정 버전에 기록한다.

**번들 조정 게이지 고정.** 재최적화마다 전체 장면이 회전·이동·축척되는 것을 막기 위해 바닥 Z = 0, 벽 방향 = 확정한 World 축, 스케일 = 확정한 스케일을 제약으로 건다.

**대체 경로.** 자동 보정이 G1 기준에 못 미치면 걷기를 다시 하거나(경로 안내, 4.5) 실측 정물을 더 배치한 뒤 다시 보정한다. 마커·체커보드 보정과 평면도 대응점 보정은 쓰지 않는다(16장).

## 4.4 보정 상태

| 상태 | 의미 | 운영 |
|---|---|---|
| UNCALIBRATED | 연결 직후, 추정 전 | 위치 기반 판단 불가, System Health UNSAFE_UNKNOWN |
| PROVISIONAL | AI 초기 추정 또는 기준 미달 | R1은 넓은 불확실성으로 동작, R2·R3·R4에 “확인 필요”(`PROVISIONAL_CALIB`, 7.1), DEGRADED |
| CALIBRATED | 기준 충족, 동결 | 정상 운영, NOMINAL |
| DRIFTED | 운영 중 재투영 오차 증가 또는 스트림 해상도·화각 변경 | DEGRADED, 자동 재보정 시작(원인 카메라를 가렸고 해상도·화각이 그대로일 때만, 아래 감시 규칙) |

**CALIBRATED 기준(초기값).** 재투영 오차 중앙값 2px·p95 5px 이하, 사람 관측이 걸을 수 있는 바닥(통로) 면적의 80% 이상을 덮음, 4대의 바닥 평면 차이 3cm 이하, 스케일 근거가 실측 정물(2개 이상, 서로 일치)이거나 사람 20명 이상의 키 통계이고, 다른 근거 하나와 교차 확인됨. 그리고 키를 아는 사람이 보정에 쓰지 않은 지점 3\~5곳에 섰을 때 머리 높이(`head_z`, 5.2 정의) 오차 최대 15cm, 카메라 쌍별 위치 불일치 최대 15cm 이내(설치 직후 빠른 검산. 표본이 적어 p95를 쓰지 않는다). 현장에서는 실측하지 않으므로 절대 위치 정확도는 개발 교실의 G1·G2 실측으로 판정한다. 재투영 오차는 모델과 관측이 맞는다는 뜻일 뿐 World 좌표가 정확하다는 뜻이 아니므로, 이 독립 검증을 통과하지 못하면 PROVISIONAL을 유지하고 대체 경로(걷기 재수행·정물 추가 배치, 4.3)로 간다.

**운영 중 틀어짐 감시(DRIFTED).** 지나가는 사람의 keypoint 로 카메라마다 그 카메라를 뺀 다른 카메라 쌍으로 삼각측량해 투영한 재투영 오차를 계속 재고, 최근 창의 중앙값이 기준선보다 일정 시간 이상 크게 유지되면 그 카메라를 DRIFTED 로 표시한다. 해상도·화각 변경은 지속 조건 없이 바로 DRIFTED 다. 모르면 비운다는 원칙(2장)을 감시에도 적용한다.

- **감시 근거 없음.** 사람이 없거나 신선한 표본이 모자라면 ‘감시 근거 없음’으로 보고하고 보정 상태를 바꾸지 않는다. 틀어졌다고도, CALIBRATED 가 유지됨을 확인했다고도 보고하지 않는다.
- **기준선.** 검증된 기준선은 그 보정을 만든 입력 관측(보정 걷기·재보정 관측)에서 같은 방식으로 잰 값뿐이다. 그 밖에는 감시를 시작한 뒤 배운 기준선을 쓰되 끝까지 ‘기준선 미확정’으로 보고한다(시간이 지나거나 재시작해도 검증된 것으로 바뀌지 않는다). 감시 시작 전에 이미 틀어진 카메라는 기준선과 무관한 절대 상한(초기값 8px)으로만 잡는다.
- **귀속.** 틀어진 카메라를 뺀 기준 쌍이 있을 때만 특정 카메라로 확정한다. 불일치가 지속되지만 어느 카메라인지 가리지 못하면(귀속 불확실) 보정이 틀어졌다는 근거로 DRIFTED 를 표시하되 자동 재보정은 시작하지 않고 운영자에게 알린다.
- **재보정 시작 조건.** 해상도·화각이 바뀐 카메라가 있으면 이전 내부 파라미터를 초기값으로 쓸 수 없으므로 번들 조정 재보정을 시작하지 않는다(내부 파라미터부터 다시 추정, 절차는 19.1). 재보정 결과는 4.5 대로 검증을 통과할 때만 새 버전이 된다.
- DATASET_GT·SIM·MODEL_ESTIMATE 보정은 현장 보정이 아니므로 DRIFTED 로 표시하지 않는다. SIM·정답 입력으로 잰 감지 시간·오경보 수는 상한이다(20.4).

## 4.5 보정 버전

- 후보 보정은 백그라운드에서 계산하고, 의미 있게 좋아졌고 검증을 통과할 때만 새 버전으로 원자적 전환한다.
- 모든 위치 계산 결과에 `calibration_version`을 붙인다.
- 정적 3D는 CALIBRATED 이후에만 생성하고, 생성에 쓴 보정 버전을 Scene 버전에 기록한다. 보정이 크게 바뀌면 해당 Scene을 재생성 대상으로 표시한다.
- 운영 중에는 지나가는 사람들의 keypoint로 재투영 오차를 계속 계산한다. 자동 보정 과정의 커버리지 계산으로 “카메라 3번이 너무 아래를 봄” 같은 설치 안내와 걷기 경로 안내를 띄운다.
