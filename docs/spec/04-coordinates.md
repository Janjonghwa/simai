# 4. 좌표·단위 규약과 캘리브레이션

작업이 바뀔 때마다 카메라 위치나 각도가 달라질 수 있으므로, 작업을 시작할 때 **현장 세팅 화면**에서 그 작업 전용 초기 세팅(배경 누적 → 무마커 내부 파라미터 → MapAnything 초기 자세·점구름 및 World 좌표계 자동 정의 → 배경 특징점 공동 번들 조정·실측 정물 검증 → 빠른 3D 미리보기 맵 및 VLM 위험 구역 초안 생성)을 새로 수행한다. 이전 작업의 보정값을 그대로 믿지 않으며, 현장 세팅이 끝나야 실시간 관제(LIVE)가 시작된다. World 좌표계는 세팅마다 복원된 점구름의 바닥·벽과 카메라 실측 높이로 자동 정의하며, 그 작업 안에서만 일관되면 된다. 과거 작업 기록은 당시 보정·Scene 버전 계보로 조회한다(`docs/design/site-setup-pipeline.md`).

## 4.1 World 좌표계

- 단위: 미터. 오른손 좌표계, +Z 상방
- 세팅별 자동 정의: 작업 시작 전 현장 세팅을 수행할 때마다 복원된 정적 점구름(MapAnything 초기 추정)과 카메라 실측 높이로 그 작업의 World 좌표계를 자동으로 잡는다. 매번 사람이 바닥 점을 찍는 수동 지정 절차는 두지 않는다.
- 바닥(Z = 0)과 +Z 축: 재구성된 점구름에서 바닥 평면을 RANSAC 으로 찾아 Z = 0 으로 두고, 카메라 중심들의 평균이 양의 높이(+Z)에 놓이도록 위쪽 수직 법선을 +Z 로 고정한다(4.3 2단계).
- 수평 축(+X, +Y): 바닥 평면 위로 투영한 점구름 외곽에서 **가장 긴 직선 경계 벽 방향**을 +X 로 두고, 방 안쪽(카메라 중심 평균 쪽)을 향하도록 Y = Z × X(오른손 직교 축)로 정한다(`axis_source`: `WALL_AND_FLOOR`, 서로 수직인 두 경계 벽이 잡히면 `WALLS`). 만약 개방된 공간이나 적치물 때문에 경계 벽 직선이 최소 기준 이상 잡히지 않으면 실패로 멈추지 않고 **카메라 배치 기반 대안(`CAMERA_LAYOUT`)**으로 자동 전환해 기준 카메라(`cam_A` → `cam_B` 또는 카메라 중심 주성분 수평 방향)로 +X, Y = Z × X 를 정한다. 어느 근거로 축을 정했는지(`world_axes_source`: `WALL_AND_FLOOR`, `WALLS`, `CAMERA_LAYOUT`)를 보정 버전에 기록한다.
- 원점: 바닥 평면(Z = 0) 위에서 경계 벽이 만나거나 바닥·벽 인라이어 분포의 하위 분위수가 놓이는 **방 모서리 근처 바닥 점**을 원점 (0, 0, 0)으로 잡아 작업 영역 좌표가 주로 양수(+X·+Y) 사분면에 놓이게 한다(열린 공간에서 벽 한 방향만 쓰거나 `CAMERA_LAYOUT` 대안을 쓸 때는 바닥 인라이어 분포의 모서리 분위수 또는 벽-바닥 교선 위 카메라 중심 투영점을 원점으로 기록).
- 작업 간 독립성과 계보 조회: 위험 구역·장비·작업면·가상 레이아웃은 해당 현장 세팅(`setup_session`)에서 확정한 World 좌표로 저장하며 그 세팅/작업 단위에 귀속된다. 한 작업 도중 카메라 중심을 고정한 미세 회전 자동 복구(4.3, 4.4)가 일어나도 World 좌표계와 정적 3D 배경은 그대로 유지된다. 다른 작업으로 넘어가 새로 현장 세팅을 하면 새 `calibration_version` 과 `scene_version` 이 발급되고, 과거 작업의 이벤트·리플레이·보고서는 당시 보정·Scene·구성 묶음 계보로 조회한다.

**BEV 평면도(보조 화면).** 뷰어가 받은 COMMITTED Scene GLB 를 브라우저에서 직교 투영하여 만든다. World 바닥 Z=0 위 1.6 m 를 넘는 부분을 자르고 북쪽(World +Y)을 위로 둔다. Scene 버전마다 한 번 만들며 다시 보기는 그 시각의 Scene 을 쓴다. 워커 `bev_floorplan` 작업과 `GET /api/floor-plans/current` 는 예약되어 사용하지 않는다(12.5·12.6). 좌표·스케일의 기준이나 안전 판단에는 쓰지 않는 표시용이며, 실패하면 기본 평면을 쓴다. 비상 화면(13.6)도 같은 화면 컴포넌트를 쓴다.

## 4.2 경계별 변환 규칙

변환은 각 경계의 어댑터 한 곳에서만 수행한다. 다른 코드는 World 좌표만 다룬다.

| 대상 | 규약 | World (x, y, z) 로부터 |
|---|---|---|
| 카메라 좌표 | OpenCV: x 오른쪽, y 아래, z 앞 | 외부 파라미터 R, t |
| Three.js · glTF | 미터, 오른손, +Y 상방 | (x, z, −y) |
| Unreal | 센티미터, 왼손, +Z 상방 | (100x, −100y, 100z) |
| 시각 | UTC, int64 밀리초 | — |
| 각도 | 내부 라디안, 화면 표시만 도 | — |

각 어댑터에는 격자점 몇 개를 왕복 변환해 원래 값으로 돌아오는지 확인하는 단위 테스트를 둔다.

## 4.3 자동 캘리브레이션 (현장 세팅 파이프라인)

작업 시작 전 **현장 세팅 화면**에서 관리자가 1단계 카메라 각도 헬퍼로 4대 시야 연결 상태를 확인하고 카메라별 실측 높이(직전 세팅 입력값이 자동으로 채워짐, 처음이면 빈칸)를 확인한 뒤 세팅 시작을 누르면, 사람이 방 안을 걸어 다니는 **걷기 보정 없이** 깨끗한 배경과 정적 기하 제약만으로 초기 보정·World 정의·미리보기 맵 생성을 자동 수행한다. 관리자가 세팅 시작을 누른 뒤 빠른 3D 미리보기 맵 위에서 위험 구역을 그릴 수 있을 때까지의 목표 시간은 **약 1분 30초 안쪽**(배경 누적 20~30초, 상주 MapAnything 수 초, 배경 특징점 번들 조정 10~20초, 빠른 미리보기 맵 약 10초 + VLM 위험 구역 초안 병렬 생성, 실제 소요 시간은 현장 측정으로 확인 필요)이다(`docs/design/site-setup-pipeline.md`). 맵 방식은 **새 맵 만들기가 기본**이고, 이전 맵 재사용(고른 완료 맵의 보정·카메라 높이·구역을 그대로 쓰고 카메라 시점만 확인)은 관리자가 고를 때만 쓴다. 카메라 각도가 바뀌어 있을 위험이 높기 때문이다(2026-11-16 사용자 결정, S15P31A101-762. 서버 REST 기본도 `NEW`).

0. **세팅 1단계 — 카메라 연결·각도 확인 헬퍼(`coverage_guide`, 세팅 시작 전 비차단 보조):**
   - **목표와 원칙:** 세팅 시작(`POST /api/setup-sessions`)을 누르기 전에 **지금 화면만으로**(이전 세팅 외부 자세 미사용, 렌즈 고유 내부값 `intrinsics_source: "STORED"` 또는 없을 때 공칭 화각 기본값 `"DEFAULT"`) 카메라 4대가 겹치는 시야를 통해 **하나의 연결 성분(`CONNECTED`)을 이루는지**만 최소 비용으로 확인하고, 부족한 카메라를 어느 쪽으로 돌릴지 안내한다. YOLO·VLM 은 쓰지 않으며, 세팅 화면이 열려 있는 동안에만 계산한다. 헬퍼 결과는 진행을 막지 않으며(`DISCONNECTED`·`UNKNOWN` 이어도 **"그대로 진행"** 가능), 헬퍼의 `"CONNECTED"` 는 시야 연결 안내일 뿐 보정 성공(`CALIBRATED`, 4.4)이 아니다.
   - **실행 위치와 경로(추가 RTSP 세션 0):** Tapo C110 의 동시 RTSP 2세션 한도(3.3)를 침범하지 않고 `torch` 추론이 영상 중계를 멈추지 않도록, 게이트웨이(노트북)의 **별도 CPU 프로세스**가 `gateway/relay` 의 로컬 미리보기 루프백 WebSocket(`127.0.0.1:47032`, `simai-cctv-preview/1`)에서 카메라별 최신 키프레임만 받아 계산한다. 결과(`contracts/messages/coverage_guide.schema.json` 1.0.0, 아래 Stage A 판정은 1.3.0·기준 시점 맞추기는 1.4.0)는 게이트웨이 → EC2 `POST /api/devices/coverage-guides`(기기 토큰) → 관제 앱 `GET /api/cameras/coverage-guides`(`latest`)로 전달한다.
   - **판정과 회전 방향 안내 규칙:** 가로 `1024 px` 리사이즈 영상에서 카메라당 ALIKED 최대 `1024`개 특징점을 뽑고 6쌍(`4C2`) 모두에 LightGlue 매칭 후 Essential RANSAC(기본 `2.0 px`, `DEFAULT` 내부값일 때는 완화) + `recoverPose` 양의 깊이를 통과한 인라이어 수(`inliers`)와 비율(`inlier_ratio = inliers / raw_matches`)을 구한다. 카메라 상태는 `OK` | `NO_VIDEO` | `STALE`(2초 넘게 프레임 미수신)이며, `NO_VIDEO`·`STALE` 카메라가 낀 쌍은 `grade: "UNKNOWN"`(수치·무게중심 `null`)으로 둔다. 정상 쌍은 `ENOUGH`(`inliers >= 30` 그리고 `inlier_ratio >= 0.10`), `WEAK`(`15 <= inliers < 30` 그리고 `inlier_ratio >= 0.10`), `LACK`(그 밖)으로 분류하고, `ENOUGH`·`WEAK` 간선으로 union-find 한 연결 성분이 1개면 `connectivity: "CONNECTED"`, `UNKNOWN` 카메라 때문에 판정할 수 없으면 `"UNKNOWN"`, 그 밖은 `"DISCONNECTED"` 로 판정한다. 약한·부족 쌍(`5 <= inliers < 30`)은 인라이어 정규화 `[0, 1]` 무게중심(`centroid_a`·`centroid_b`)이 가장자리로 치우친 쪽(`x > 0.65` → `RIGHT`, `x < 0.35` → `LEFT`, `y > 0.68` → `DOWN`, `y < 0.32` → `UP`, 가로 우선)으로 회전 방향과 크기(`WEAK` → `SMALL`, `LACK` → `MORE`, `reason_code: "WEAK_PAIR_EDGE_CLUSTER"`, 이미 `CONNECTED` 면 선택 보강 `"OPTIONAL_IMPROVE"`)를 안내하고, `inliers < 5` 면 무게중심을 비우고(`null`) `direction: "NONE"`, `magnitude: "NONE"`, `reason_code: "NO_OVERLAP_VISIBLE"` 을 낸다. 쌍 등급과 연결 상태는 **2회 연속 같을 때만** 바꿔 화면 깜빡임을 막는다(헬퍼 프로세스가 적용).
   - **옆 쌍 Stage A 판정·경고(`stage_a_readiness`):** `ENOUGH` 는 4대 연결 기준일 뿐 Stage A(3단계)가 쓰기에 충분하다는 뜻이 아니므로, Stage A 가 쓰는 옆 4쌍만 그 라운드 측정값으로 따로 판정한다(대각은 등급만 참고로 싣고 판정·경고하지 않는다). 인라이어 `≥ 60`, 비율 `≥ 0.10`, 두 영상 모두 4×4 격자에서 인라이어 2개 이상인 칸 `≥ 4` 를 최근 4라운드(약 10 s) 연속 채우면 `READY`, 창이 덜 찼으면 `CONFIRMING`, 흔들리면 `UNSTABLE`, 미달이면 `SHORT`(사유 `FEW_INLIERS`·`LOW_RATIO`·`CLUSTERED`), 그 라운드 영상이 없거나 오래되면 `UNKNOWN` 이다. `UNSTABLE`·`SHORT` 쌍은 「지금 할 일」과 배경 촬영 창에 경고와 방향 안내(인라이어 30 이상이어도 무게중심이 가장자리면 `SMALL`)를 보이되 시작을 막지 않는다(사용자 결정: 경고만). `READY` 는 Stage A 합격 보장이 아니다(초기 자세·높이 입력·배경 품질은 못 본다, `docs/design/S15P31A101-761-helper-stage-a-criteria.md`).
   - **기준 시점 맞추기(`aim_check`):** 쌍 판정은 한 대를 돌리면 두 쌍이 함께 바뀌어 맞추기가 수렴하지 않으므로, 카메라마다 그 현장의 가장 최근 CALIBRATED 세팅(완료 세션이고 카메라 확인 `PASSED`·기준선 보정 = 세션 보정, 4.4)의 그 카메라 사람 지운 배경 사진과 그 보정의 렌즈에 맞춘다. 외부 자세는 쓰지 않고 사진끼리 비교하며, 기준 렌즈(K·왜곡·`image_size`)는 그 보정 원문 `cameras[]` 에서 읽는다(형식이 틀린 카메라는 뺀다, S15P31A101-771). 헬퍼가 SIFT 대응·호모그래피 RANSAC·순수 회전 검사 뒤 광선 직교 Procrustes 로 회전을 구해 교정량(`pan_rad`·`tilt_rad`·`roll_rad`)과 목표 점을 싣고, 상태는 `ALIGNED`(초록, 재사용 가능: 광축 차 `≤ 0.25°`·기울기 `≤ 1.0°`)·`NEAR`(노랑, 새 맵 세팅엔 충분: 광축 `≤ 1.5°`·기울기 `≤ 3.0°`)·`MISALIGNED`·`UNKNOWN`(대응 부족·위치 이동 등, 각도 비움)이며, 서로 다른 키프레임 2라운드 연속일 때만 단계를 올리거나 내린다. 화면은 카메라 칸마다 십자선·목표 점·각도 문구를 그리고(기준을 아는 칸은 옆 쌍 방향 꺾쇠를 그리지 않음, 기준 사진 겹쳐 보기는 기본 끔), 4대 모두 초록이면 「이전 맵 재사용도 안전」을 한 줄로 알린다(기본 맵 방식은 바꾸지 않음). 가장 최근 CALIBRATED 세팅의 사진·렌즈가 없으면 더 오래된 세팅으로 내려가지 않고 비운다(`docs/design/S15P31A101-765-aim-reference-overlay.md`).

1. **깨끗한 배경 누적 및 초기 추정:**
   - **깨끗한 배경 누적(20~30초 목표):** 4대 카메라에서 사람 분할 마스크(YOLO26-seg + 팽창)를 뺀 픽셀별 시간 중앙값 배경(`CleanBackgroundAccumulator`, 5.3)을 모은다. 현장에 사람이 없으면 조기 수렴한다.
   - **내부 파라미터(무마커):** 깨끗한 배경 영상(벽 모서리·문틀·책상 가장자리·천장선 같은 직선이 보이는 장면)으로 단일 이미지 내부 파라미터를 추정해 초점거리·왜곡 초기값을 얻는다. 체커보드는 쓰지 않는다. 기본 경로는 학습 모델 AnyCalib(ICCV 2025, `anycalib_dist` 가중치, `radial:2` = OpenCV [k1, k2], 주점도 추정)이고, 사용할 수 없으면(패키지·가중치 없음, 해시 불일치) GeoCalib(ECCV 2024, `distorted`·`radial`), 그것도 없으면 고전 기준(직선이 곧게 펴지는 방사 왜곡 + 직교 소실점 초점, 가중치·GPU 불필요) 순서로 내려간다. 광각·왜곡 영상으로 학습했고 코드·가중치가 Apache-2.0 이며 공식 벤치마크로 우열이 나와 있어 세 방법 비교 실험은 하지 않는다(라이선스는 부록 B). 백엔드가 돌았는데 실패하면 다른 방법 값으로 채우지 않고 비우며, 어떤 방법으로 나왔는지 기록에 남긴다. 고전 기준은 학습 결과의 직선성 확인(`undistort_check`)에도 쓴다: 고전 기준이 찾은 교실 직선을 학습 결과로 펴서 곧지 않으면 그 결과를 비운다. C110 4대는 같은 렌즈이므로 4대 추정값(초점·왜곡, 추정했으면 주점)의 중앙값을 공통 값으로 공유한다(실패한 카메라와 편차가 한도를 넘는 카메라는 빼고, 과반이 맞지 않으면 공통값을 비운다).
   - **MapAnything 초기 자세·점구름(상주 모델, 수 초 목표):** 왜곡을 편 4대 배경 영상과 내부 파라미터 K 를 **메모리에 상주(warm)시켜 둔 MapAnything 모델**에 넣어 초기 카메라 외부 파라미터, 바닥·벽 점구름을 추론한다(세팅 때마다 가중치를 디스크에서 새로 읽는 지연을 없앤다).
2. **World 좌표계 자동 정의:** 1단계 MapAnything 점구름과 카메라 실측 높이로 바닥·축·원점·스케일을 정해 고정한다. 정하지 못하면 비우고(변환·보정 문서를 내지 않음) 임의 바닥을 지어내지 않는다. 세부 수학 규약은 `docs/design/world-frame-from-mapanything.md` 및 `docs/design/site-setup-pipeline.md` 에 있다.
   - **바닥(Z = 0)·중력:** 카메라 광선 아래쪽 후보 점구름에서 RANSAC 평면 피팅(`floor_ransac_dist_m = 0.04 m`)으로 가장 낮은 주 수평 평면을 바닥(Z = 0)으로 잡고, 카메라 중심들의 평균이 양의 방향(+Z)에 놓이도록 법선 부호를 정한다. 바닥 인라이어가 기준에 못 미치면 실패(`FLOOR_FIT_FAILED`)로 안내한다.
   - **수평 축(+X, +Y):** 바닥 위 높이 구간(0.3~2.2 m)의 벽 후보 점들을 바닥 평면에 정사영해 외곽 경계에서 **가장 긴 직선 경계 벽 방향**을 RANSAC 으로 찾아 +X 로 두고, 방 안쪽을 향하도록 Y = Z × X(오른손 직교 축, `WALL_AND_FLOOR` 또는 두 수직 벽 `WALLS`)로 둔다. 경계 벽 인라이어가 기준에 못 미치면 **카메라 배치 기반 대안(`CAMERA_LAYOUT`)**으로 전환해 기준 카메라 중심들을 잇는 수평 방향으로 +X, Y = Z × X 를 정한다.
   - **원점:** 바닥 평면(Z = 0) 위에서 경계 벽 교점 또는 바닥·벽 인라이어 분포의 모서리 분위수(방 모서리 근처 바닥)를 원점 (0, 0, 0)으로 둔다.
   - **스케일(`MEASURED_CAMERA_HEIGHT` 기본):** 관리자가 현장 세팅 화면에서 확인한 카메라별 바닥~렌즈 중심 실측 높이(직전 세팅 값이 기본으로 채워져 표시됨)와 재구성된 카메라 높이의 비의 중앙값으로 전체 절대 스케일을 정한다(아래 스케일 근거 우선순위 참조).
3. **정밀화 — 배경 특징점 공동 번들 조정(V2, 10~20초 목표):**
   - **인접 카메라 쌍 고리 매칭:** 11차 GPU 세션 및 V0(`S15P31A101-437`, 2026-11-03) 실측에서 마주 보는 대각 카메라 쌍(`A–C`, `B–D`)은 시점 차이가 약 170°에 달해 직접 매칭이 성립하지 않고(인라이어 7~12개), 3대 이상 카메라에 동시에 찍히는 배경 특징점 트랙도 사실상 없음(인라이어 기준 2개뿐)이 확인되었다. 따라서 Leave-One-Out PnP(V1)는 쓰지 않고, 시야가 겹치는 **인접 카메라 4쌍(`A–B`, `B–C`, `C–D`, `D–A`) 고리**에서 추출한 ALIKED + LightGlue 배경 특징점(Essential RANSAC 인라이어)만으로 **2-view 고리 공동 번들 조정(V2 Joint BA)**을 수행한다.
   - **공간 격자 층화 홀드아웃과 단계적 최적화:** 특정 쌍이나 구석에 특징점이 몰려 회전과 카메라 중심 이동이 서로 엉키는 현상을 막기 위해, 영상을 공간 격자로 나누어 인라이어의 **80%는 최적화용, 20%는 공간 층화 홀드아웃 검증용**으로 분리한다. 잔차에는 쌍별 가중을 두지 않고 Huber 손실만 쓰며, 쌍 몰림·기준 카메라 오차로 기하 거절되거나 홀드아웃이 품질 게이트에 못 미치면 기준 카메라를 바꿔 다시 푼다(4단계 Stage A 자동 재시도). 최적화는 **Stage A(카메라 중심을 초기 위치에 고정하고 회전·3D 점만 정렬) → Stage B(카메라 실측 높이·바닥 평면 Z=0 제약과 강한 초기 중심 사전 구속 아래 중심·회전 동시 미세 조정) → Stage C(홀드아웃 재투영 오차·에피폴라 일관성·높이 편차가 개선될 때만 완화 채택)** 순서로 진행한다.
   - **무보행 배경 보정 최적화와 사후 카메라 확인(걷기 다듬기 예외):** 보정 파라미터를 푸는 번들 조정(Stage A~C) 자체에는 걷기 절차나 사람 2D 관절 제약을 넣지 않고 인접 쌍 배경 특징점과 정적 기하 제약만으로 완결한다. 사람 관절(`YOLO26x-pose`)은 보정 발행 직후 실제 다중 카메라 매칭과 삼각측량이 성립하는지 독립 검산하고 LIVE 감시 기준선을 남기는 **5단계 「카메라 확인」**에 쓴다(2026-11-12 결정, 16장, `docs/design/S15P31A101-646-setup-camera-check.md`). 세팅 카메라 확인의 한 사람 걷기에 한해, 시간 분할 Holdout 검증을 통과할 때만 외부 파라미터 후단 다듬기에 쓴다(2026-11-16 결정, `docs/design/S15P31A101-760-walk-refine-extrinsics.md`): 배경 BA 는 옆 4쌍만 묶고 카메라 중심을 고정한 채 먼 벽에 회전을 맞추므로, 방 가운데 사람에서 대각 쌍이 어긋날 수 있다. 새 맵 세팅에서 카메라 확인 시도가 기하 실패(통과율·잔차·재투영)로 끝나면 그 시도의 걷기를 Fit 2.4 s → 완충 0.6 s → Holdout 1.4 s → 완충 0.6 s 블록으로 나눠, Fit 으로만 카메라 4대의 회전·중심(K·왜곡 고정, 사전 σ 중심 수평 8 cm·수직 2 cm·회전 4°)을 한 번 다듬고 바닥 Z=0·축은 배경 보정 그대로 둔다(맵 정렬도 처음 보정 기준). 새 맵 시도는 이 다듬기의 Holdout 몫까지 4대 동시 관측(80 시각)과 카메라별 LOO 표본을 모을 때까지 끝내지 않는다. Holdout 만으로 카메라 확인과 같은 판정(대각 포함 모든 쌍 통과, 4대 모두 LOO 표본 `≥ 20`·통과·기준선)과 물리 상한(중심 수평 `≤ 0.20 m`·수직 `≤ 0.06 m`, 입력 높이 대비 `≤ 10 cm`, 회전 `≤ 8°`)을 모두 만족하고 Holdout 최저 쌍 통과율이 오를 때만 새 `calibration_version` 으로 발행하며(덮어쓰지 않음, 계보는 세팅 시작 때 활성 보정), 그 Holdout 판정이 카메라 확인 결과와 기준선이 된다. 하나라도 어기면 새 문서를 내지 않고, 같은 시도를 이전 맵 재사용과 같은 기준(옆 쌍만 막고 대각은 참고, 카메라별 LOO 표본 대기)으로 다시 판정해 통과하면 배경 보정 그대로 통과로 두며(대각 미해결 기록을 남김), 그것도 통과하지 못하면 다시 걷기를 안내한다.
4. **보정 절대 품질 게이트(`quality_gate`) 검산 및 실패 시 재시도 안내:**
   - Stage A~C 직후 인접 쌍 홀드아웃(20%) 재투영 오차(쌍별 중앙값 `≤ 3.0 px`·p90 `≤ 6.0 px`; 최소 홀드아웃 트랙 `5`개 미만인 쌍은 즉시 실패 대신 5단계 「카메라 확인」에서 반드시 통과해야 하는 `NEEDS_CHECK` 필수 확인 쌍으로 지정), 4대 바닥 평면 일관성, 카메라 실측 높이 편차(절대 한도 `±10 cm`, 화면 허용 안내 `±5 cm`), 현장에 둔 **실측 정물(`measure-stools` 로비 스툴, 안전봉·라바콘 등)** 치수·삼각측량 오차로 독립 검증한다(`docs/design/S15P31A101-646-setup-camera-check.md`).
   - **Stage A 자동 재시도(기준 카메라만 바꿈):** Stage A 와 품질 게이트를 한 시도로 본다. 시간 안에 끝난 기하 거절(미수렴·점 투영 미수렴·학습 점 깊이 무효·쌍 악화)이거나 FAIL 사유가 모두 쌍 홀드아웃인 품질 게이트 실패면, 같은 배경 트랙·같은 MapAnything 초기값으로 **기준 카메라만 바꿔** 최대 2번 더 푼다(최대 3시도, 후보는 초기 자세 전체 트랙 재투영 중앙값이 작은 순, 첫 시도는 지금의 자동 선택과 같다). 특징 부족·배경 미완·바닥 실패·높이 사유·시작 자세 삼각측량 실패·Stage A 시간 상한 초과는 다시 풀지 않는다. 재시도에 들어가면 남은 시간(카메라 확인 600 s 와 맵 600 s, 재사용이면 30 s 를 뺀 몫)이 지금까지 가장 긴 시도보다 길 때만 다음 후보를 풀고, 통과한 시도 중 순위(판정, 최악·평균 쌍 비율 = max(홀드아웃 중앙값 ÷ 3.0 px, p90 ÷ 6.0 px))가 가장 좋은 것을 채택한다. 모두 실패하면 가장 나은 실패 시도의 사유로 지금과 같이 끝내고 메시지 끝에 자동 재시도 횟수를 붙인다. 시도별 요약은 워커 로그에만 남고 세션 스냅샷에는 채택(또는 보고) 시도 값만 싣는다(`docs/design/S15P31A101-764-stage-a-auto-retry.md`).
   - 배경 누적이 덜 되었거나(`BACKGROUND_INCOMPLETE`), 인접 쌍 특징점이 부족하거나(`INSUFFICIENT_FEATURES`), 바닥 평면 검출(`FLOOR_FIT_FAILED`)·품질 게이트 검증(`VALIDATION_REJECTED`)에 실패하면 잘못된 보정을 발행하지 않고 하트비트·세팅 세션에 `quality_gate` 상세 스냅샷을 남긴 뒤 대기 화면에 실패 원인과 조치 방법(예: 겹치는 영역에 물체 배치, 카메라 각도·높이 확인)을 표시하며 재시도(`POST /api/setup-sessions/{id}/retry`)를 안내한다.
5. **보정 발행·빠른 미리보기 맵·구역 초안·「카메라 확인」 및 동결:**
   - 품질 게이트를 통과하면 새 `calibration_version`(문서 상태는 PROVISIONAL, 진행률 `65%`)을 발행하고, **빠른 3D 미리보기 맵(`preview_scene`, `70~80%`)**·**VLM 위험 구역 초안 및 변경 의심 이관 구역 의견(`vlm_zone_draft`, 5.4·8.2)**·**1인 「카메라 확인」 검산(`camera_check`, `80~90%`)**을 병렬로 수행한 뒤 정밀 텍스처 입히기(`texrecon`, `90~100%`, 직전 정식 Scene 대비 이관 구역 높이 변화 판정 `zone_height_changes` 포함, 8.2)를 마친다. 세팅 진행률(`progress_pct`)은 시간 추정이 아니라 실제 하위 단계 완료 지점만 단조 증가(`0 → 5 → … → 100%`)로 보고한다(`docs/design/site-setup-pipeline.md`).
   - **CALIBRATED 올림:** 보정 문서는 동결이라 PROVISIONAL 로 발행한 채 두고, 그 보정의 카메라 확인이 실제로 `PASSED`(기준선 포함, `camera_check.calibration_version` = 기준선 보정 = 세션 보정)이면 EC2 가 구성 묶음 `components.calibration.verification` 에 근거를 싣고 Tier 0 가 같은 버전의 운영 상태를 CALIBRATED 로 올린다(전환 이력에 `STATE_CHANGED` 추가 → `calibration_update`, 문서·`content_hash` 불변, 운영 상태의 정본은 Tier 0 전환 이력). 이전 맵 재사용 세션은 원 세션의 근거를 이어받는다. DRIFTED 인 보정, `SKIPPED`·`SKIPPED_REPLAY`, 기준선 없는 `PASSED` 는 올리지 않는다. 근거는 묶음을 낼 때마다 다시 보므로 GPU 를 새로 켜도 연결 뒤 다시 받는 묶음으로 올라간다(`docs/design/S15P31A101-745-calibrated-state.md`).
   - **세팅 「카메라 확인」 단계(2026-11-12 결정, `docs/design/S15P31A101-646-setup-camera-check.md`):** 보정이 발행된 직후 현장 1명이 작업 영역을 30~60초(최대 120초 대기) 걸어 다니면 Tier 0 `CameraCheckTap` 이 최대 5 Hz 로 기록한 2D 관절(`views.jsonl`)을 분석 워커가 실제 `CrossViewAssociator` 와 LOO(Leave-One-Out) 재투영으로 검산한다. 합격(`PASSED`) 조건은 ① 관측 구간 `≥ 30 s`, ② 단일 인물 기준 쌍별 표본 `≥ 30`개·통과율 `≥ 0.75`·쌍 잔차 중앙값 `≤ 8.0 px`, ③ 판정 가능 쌍 `≥ 3`개 및 모든 카메라가 최소 1개 이상 통과 쌍 보유, ④ 4단계 `NEEDS_CHECK` 필수 확인 쌍 전원 통과, ⑤ 카메라마다 사람이 보인 시각 표본 `≥ 30`개(미달 시 `NOT_OBSERVED`) 및 카메라별 LOO 표본이 20개 이상 모였을 때 LOO 잔차 중앙값 `≤ 8.0 px` 이다. 합격하면 카메라별·쌍별 잔차 중앙값을 이미 등록된 보정 문서 대신 Pod 공유 상태 경로(`<state>/camera-check/baselines/<sha256(calibration_version)[:32]>.json`, `source = "SETUP_CAMERA_CHECK"` → `BackgroundDriftWatch` 의 `calibration_baselines.json` `verified_camera_ids`)와 EC2 `setup_session.camera_check.baseline` 에 영속화하여 LIVE 감시 기준선으로 쓰고, **합격(`PASSED`) 전에는 세팅 구역 저장·초안 시드·세팅 완료 요청을 서버가 `409 SETUP_CAMERA_CHECK_NOT_PASSED` 로 차단**한다(`SKIPPED` 는 개발 명시 플래그 `SIMAI_SITE_SETUP_SKIP_CAMERA_CHECK=1` 일 때만 허용).
   - **막는 쌍과 참고 쌍:** 이전 맵 재사용 세팅의 카메라 확인은 세팅 보정이 맞춘 쌍(품질 게이트의 옆 쌍)만 막고, 그 밖의 쌍(대각)은 같은 기준으로 재서 싣기만 하며 실패해도 막지 않는다(배경 BA 가 대각을 묶지 않아 보정을 다시 해도 대각만 번갈아 틀어졌다, S15P31A101-759). 대각이 잡던 한 카메라 틀어짐은 카메라별 LOO 가 잡으므로, 막는 쌍이 아직 실패하지 않았으면 모든 카메라의 LOO 표본이 20을 채울 때까지 끝내지 않고 최대 대기까지 못 채운 카메라는 통과로 두지 않고 표본 부족(`FEW_SAMPLES`)으로 다시 걷게 한다. 새 맵 세팅은 대각까지 막는 쌍으로 재고 3단계 걷기 다듬기를 따른다.
   - **재생 시험의 걷기 생략(`SKIPPED_REPLAY`):** EC2 시험 스위치 `SIMAI_REPLAY_TEST_SKIP_CAMERA_CHECK`(기본 꺼짐, 설정 파일로만)가 켜져 있고 살아 있는 노트북의 카메라 입력이 모두 녹화 파일(`FILE`)인 동안에만, 세팅 대여 하트비트 응답 `camera_check_skip` 으로 워커가 걷지 않고 `SKIPPED_REPLAY` 를 남긴다. 관문은 완료·구역 저장 시점에 같은 조건을 다시 보고(스위치를 끄거나 RTSP 로 돌아오면 다시 409), 이 세션은 기준선·재사용 후보·CALIBRATED 근거가 되지 않는다. 실제 카메라와 섞이거나 합성 영상·입력 종류 모름이면 건너뛰지 않는다(3.10, `docs/design/S15P31A101-736-replay-test-switch.md`).

**스케일 근거 우선순위.** 카메라 높이 실측(`MEASURED_CAMERA_HEIGHT`, 기본) ↔ 실측 정물(`KNOWN_OBJECT_SIZE`, 교차 검증 및 대안) > 모델 자체 추정(`MAPANYTHING_METRIC`, 과거 호환 스키마 값 `HUMAN_HEIGHT_PRIOR` 는 현장 세팅에서 쓰지 않음). 카메라 높이 실측을 기본으로 쓰고 현장에 실측 정물이 있으면 반드시 교차 확인한다.

- **카메라 높이 실측(기본 1순위, 이전 값 자동 채움):** 각 카메라 렌즈 중심에서 바닥(Z = 0)까지 줄자나 레이저 거리계로 잰 높이와 2단계 바닥 평면 기준 카메라 중심 높이의 비의 중앙값을 전체 스케일로 쓴다. 현장 세팅 화면에는 **직전 세팅에서 입력했던 카메라별 높이 값이 자동으로 채워져**(처음이라 값이 없는 카메라는 빈칸이며 입력해야 한다. 임의 기본값을 채우지 않는다) 나와, 삼각대 높이를 바꾸지 않았으면 그대로 확인만 누르면 된다. 카메라 간 높이 비율 편차가 한도를 넘으면 오입력·바닥 오검출 경고를 띄운다.
- **실측 정물(검증 및 대안):** 시연·현장에 쓰는 단단한 정물 목록(`measured_objects.json`: 안전봉·라바콘·바리케이드(YOLOE-26 검출), 팀 노트북 윗판 `0.355 × 0.255 m`, 로비 하늘색 스툴 윗면 `lobby_stool_top` `0.415 × 0.415 m`·높이 `0.425 m`, `measure-stools` HSV 사각형 네 모서리 삼각측량, S15P31A101-100·-357)을 2대 이상 카메라 시야에 두면 삼각측량 치수로 카메라 높이 스케일을 교차 검증하고, 카메라 높이를 재지 못했을 때 대안 스케일 근거로 쓴다(`docs/design/measured-object-scale.md`). 안전모는 보조로만 쓰고 형태가 변하는 조끼는 쓰지 않는다.
- **모델 자체 추정(최후 대안):** 카메라 실측 높이와 실측 정물이 모두 없을 때만 쓰며, 스케일 정확도가 2~5% 수준에 머문다는 경고를 보정 버전에 기록한다. 사용한 스케일 근거(`scale_source`)는 보정 버전에 항상 기록한다.

**번들 조정 게이지 고정.** 최적화 도중 전체 장면이 임의로 회전·이동·축척되는 것을 막기 위해 기준 카메라(초기 자세 재투영이 가장 작은 카메라, Stage A 재시도 때는 다음 후보) 위치·수평 방향 기준, 바닥 Z = 0, 카메라 실측 높이 스케일을 제약으로 건다. 마커·체커보드 보정과 평면도 수동 대응점 보정, 수동 바닥 점 클릭, 보정용 걷기 절차는 쓰지 않는다(16장).

## 4.4 보정 상태와 작업 중 자동 회전 복구

| 상태 | 의미 | 운영 |
|---|---|---|
| UNCALIBRATED | 연결 직후, 현장 세팅 전 | 위치 기반 판단 불가, 작업 시작(LIVE) 불가, System Health UNSAFE_UNKNOWN. 방어적으로 판정이 나오더라도 R1은 이미 열린 이벤트의 유지·해소 판정에만 넓은 불확실성(보정 여유 0.3m, 7.1)을 적용하고, R2·R3·R4에 “확인 필요”(`PROVISIONAL_CALIB`)를 붙인다 |
| PROVISIONAL | 초기 추정만 완료되었거나 독립 검증 기준 미달 | R1은 이미 열린 이벤트의 유지·해소 판정에만 넓은 불확실성(보정 여유 0.3m, 7.1)을 적용(신규 발생은 확실한 위치가 구역 안일 때만), R2·R3·R4에 “확인 필요”(`PROVISIONAL_CALIB`, 7.1), DEGRADED |
| CALIBRATED | 현장 세팅 검증 충족, 동결 | 정상 운영, NOMINAL |
| DRIFTED | 작업(LIVE 관제) 중 카메라 회전·이동 감지 또는 스트림 해상도·화각 변경 | R1은 이미 열린 이벤트의 유지·해소 판정에만 넓은 불확실성(PROVISIONAL 과 같게), R2·R3·R4에 “확인 필요”(`PROVISIONAL_CALIB`, PROVISIONAL 과 같게), DEGRADED. **미세 회전이면 중심 고정 회전 자동 복구(`rotfix`) 실행, 위치 이동이나 큰 회전이면 자동 반영하지 않고 “현장 세팅 다시 하기” 알림 + 시야 이탈 구역 R7 감시 저하(`CAUTION`) 표시** |

**보정 상태와 “확인 필요”.** `PROVISIONAL_CALIB` 는 판정 위치를 만든 보정이 CALIBRATED 가 아니라는 뜻이다(PROVISIONAL·DRIFTED, 그리고 UNCALIBRATED 에서 판정이 나온 경우 방어적으로). 붙는 규칙은 R2·R3·R4 이고, 등급·발생·해소는 바꾸지 않는다(7.3). 규칙은 활성 보정 상태를 판정 문맥으로 받는다(3.2). 카메라로 잰 위치가 아닌 PLANNED 계획 위치에는 보정 상태가 적용되지 않아 붙지 않는다. 보정 상태를 알 수 없으면 CALIBRATED 로 보지 않는다. R1 은 “확인 필요”를 붙이지 않으며, 신규 발생은 보정 상태와 상관없이 확실한 위치(점 기준)가 구역 안일 때만 내고 불확실성 범위나 보정 여유로 넓혀 발생시키지 않는다(7.1, 7.2). 대신 같은 상태(CALIBRATED 가 아닌 상태)에서 이미 열린 R1 이벤트의 유지·해소 판정에는 불확실성 범위를 보정 여유(초기값 0.3m)만큼 넓혀 해소를 늦춘다(7.1). 등급은 바꾸지 않으며, PLANNED 는 넓히지 않는다.

**CALIBRATED 기준과 세팅 완료 게이트.** CALIBRATED(운영 상태, 문서는 PROVISIONAL 로 발행하고 카메라 확인 근거로 올린다, 4.3 5단계)는 인접 쌍 배경 특징점 홀드아웃(20%) 재투영 오차(절대 상한 쌍별 중앙값 `≤ 3.0 px`·p90 `≤ 6.0 px`, 이상 목표 중앙값 `2 px`·p95 `5 px`), 4대 바닥 평면 차이 `≤ 3 cm`, 카메라 실측 높이 편차(절대 한도 `±10 cm`, 화면 안내 `±5 cm`), 실측 정물이 있을 때의 정물 치수 교차 확인을 통과해야 하며(4.3 4단계 `quality_gate`), 이어서 보정 발행 직후 1인 30~60초 보행 **「카메라 확인」(`camera_check = PASSED`, 4.3 5단계)**까지 통과해야 구역 확정과 현장 세팅 완료가 허용된다(2026-11-12 결정, `docs/design/S15P31A101-646-setup-camera-check.md`). 현장에서는 별도 격자 실측을 하지 않으므로 절대 위치 정확도는 개발 교실의 G1·G2 실측으로 판정한다. 이 검증을 통과하지 못하면 세팅 화면에서 원인을 안내하고 재시도 경로(4.3 4단계)로 간다.

**작업(LIVE 관제) 중 틀어짐 감시와 자동 회전 복구(`rotfix`).** 작업 중 누군가 삼각대를 건드려 카메라가 돌아가거나 옮겨질 수 있다(11차 GPU 세션에서 확인된 10/30 이후 `cam_C` 13.2° 물리적 회전 사례). 관제 중 사람 관절로 후보 보정을 계산해 교체하는 경로(`live_candidate`, `live_calibration`, `LiveCandidateCalibrationRunner`)는 두지 않으며, LIVE 중 **보정 갱신(교체)**은 오직 사람을 지운 롤링 깨끗한 배경(`CleanBackgroundAccumulator`)과 세팅 완료 시점의 기준 배경·인접 카메라 쌍 배경 에피폴라 잔차만 비교하는 **배경 기반 자동 회전 복구(`rotfix`) 단일 경로**로만 수행한다. 다만 배경 누적 수렴 전 흔들림·충격을 빠르게 감지하기 위해 **사람 관절 LOO 재투영 감시(`ReprojectionMonitor`)는 배경 비교와 함께 두되 세팅 「카메라 확인」 기준선이 있을 때만 융합 제외에 사용**한다(2026-11-12 결정, 기존 ‘관절 재투영 감시 전면 제거’ 대체, 16장, `docs/design/site-setup-pipeline.md` 7절, `docs/design/camera-fall-drift-detection.md`, `docs/design/S15P31A101-646-setup-camera-check.md`):

1. **배경 비교 + 세팅 기준선 조건부 관절 재투영 감시:**
   - **정적 배경 상시 감시:** 특정 카메라에서 세팅 기준 배경 대비 롤링 깨끗한 배경의 특징점 이동이나 인접 쌍 배경 에피폴라/재투영 오차 상승이 지속되면 틀어짐 의심(DRIFTED)으로 감지한다. 해상도·화각 변경은 즉시 DRIFTED 다. 현장에 사람이 없거나 1~2대 카메라에만 보여도 정적 배경 비교가 상시 동작한다.
   - **세팅 기준선 조건부 재투영 제외·자동 복귀(`ReprojectionMonitor`):** 같은 Pod 의 세팅 「카메라 확인」 검증 기준선(`<state>/camera-check/baselines/<sha256(calibration_version)[:32]>.json`, `source == "SETUP_CAMERA_CHECK"`)이 확인된 카메라(`verified_camera_ids`)에 대해서만, 카메라별 LOO 관절 재투영 창 중앙값이 `max(기준선 × 2.5, 기준선 + 5.0 px)` 이상으로 치솟은 카메라를 실시간 삼각측량 융합에서 제외(`REPROJECTION`)하여 다른 정상 카메라 쌍의 위치 추정을 보호한다. 기준선이 없는 옛 보정에서는 `suspect_cameras` 와 `DRIFTED` 상태만 올리고 카메라는 융합에서 빼지 않는다. `REPROJECTION` 사유로 제외된 카메라는 15초 주기 배경 비교에서 최근 3회 연속 회전량이 `< 0.5°` 로 정상이 확인되면 일시 오탐으로 보아 융합에 자동 복귀시킨다(보정당 최대 2회 복귀, 그 이상 반복 시 재세팅 안내 유지).
2. **순수 미세 회전 자동 복구(`rotfix`, 카메라 중심 고정):**
   - 왜곡 보정 좌표계에서 세팅 당시 기준 배경과 최근 롤링 깨끗한 배경 사이의 특징점(SIFT 또는 ALIKED+LightGlue) 대응이 **단일 순수 회전 호모그래피 $H_i = K_i \Delta R_i K_i^{-1}$** 로 설명되고, 카메라 중심 $C_i$ 를 고정한 채 회전 $R_i$ 만 보정했을 때 인접 카메라 쌍의 2-view 재투영 오차가 유의미하게 개선되면 중심 고정 회전 복구 후보로 인정한다(11차 GPU 세션에서 이 방식으로 3-view 5,078개·4-view 192개 클러스터 복구 실증). 순수 회전 추정량이 `≤ 1.5°` 미소 각도이고 인접 쌍 재투영 개선만 불충족일 때는 위치 이동이 아니므로 재세팅 요청을 띄우지 않고 `NO_EVIDENCE` 로 둔다.
   - **안전 게이트 재사용(`CandidateConfirmation` + `SwapProbation`):** 일시적 가림이나 조명 변화를 걸러내기 위해 **연속 2회 주기 확인**을 거친 뒤 새 `calibration_version` 으로 원자적 교체하고, **교체 후 60초 감시(`SwapProbation`)** 동안 배경 호모그래피·인접 쌍 배경 에피폴라 잔차가 악화되면 즉시 직전 `calibration_version` 으로 자동 롤백한다(`ai/gpu_tier0/calibration_safety.py`).
   - **정적 3D 배경(Scene) 유지:** 카메라 중심 $C_i$ 와 World 좌표계가 전혀 바뀌지 않았으므로 정적 3D 배경(`scene_version`)을 다시 만들 필요가 없으며 기존 Scene 을 그대로 유지한다.
3. **위치 이동 또는 큰 회전 시 자동 반영 금지 및 “현장 세팅 다시 하기” 알림:**
   - 삼각대 위치가 옮겨져 시차(parallax)가 발생하면 순수 회전 호모그래피 인라이어 비율이 떨어지고 잔차가 커지며, 카메라가 너무 크게 돌아가면 기준 배경·인접 카메라와의 매칭 자체가 부족해진다.
   - 이 경우에는 **절대 자동으로 보정을 덮어쓰지 않고**, 관제 화면에 **“카메라 위치/각도가 크게 변경되었습니다 — 현장 세팅 다시 하기”** 경고를 띄워 관리자가 현장 세팅(`POST /api/setup-sessions`)을 다시 수행하도록 안내한다.
   - 미세 회전 자동 복구와 재세팅 요청을 가르는 구체적인 문턱값(호모그래피 인라이어 비율·잔차, 최소 매칭 수, 허용 회전 각도 상한 등)은 실제 카메라를 조금씩 돌려가며 재는 **통제된 회전 실험 후 확정**한다(19.1 미결, **확인 필요**).
4. **시야 이탈 구역의 감시 저하(R7) 표시:**
   - 회전 복구가 적용된 뒤에도 카메라 화각이 이동한 결과 기존에 발행된 위험 구역(`zone`)이 2대 이상 카메라 시야(FOV)에서 벗어났거나, 위치 이동/큰 회전으로 재세팅이 필요한 상태라면 해당 구역의 유효 관측 카메라 수를 즉시 재계산하여 **R7 감시 저하(`CAUTION`, 구역 빗금 표시)**를 발생시킨다.
5. DATASET_GT·SIM·MODEL_ESTIMATE 보정은 현장 보정이 아니므로 DRIFTED 로 표시하지 않는다.

## 4.5 보정 버전과 정적 Scene 계보

- 현장 세팅이 완료되거나 관제 중 중심 고정 회전 자동 복구(`rotfix`)가 2회 연속 확인을 통과하면 새 `calibration_version` 으로 원자적 전환한다.
- 모든 위치 계산 결과와 이벤트에 `calibration_version` 을 붙인다.
- 현장 세팅에서는 관리자가 구역을 바로 그릴 수 있도록 **빠른 3D 미리보기 맵(`preview_scene`)**을 먼저 내보내고, 관리자가 구역을 편집·발행하는 동안 백그라운드에서 정밀 텍스처 입히기(`texrecon`)를 마쳐 정식 `scene_version` 으로 매끄럽게 교체한다(5.3). 배경은 표시용이고 위치 정본은 Tier 0 라 판정에 영향이 없다.
- 한 작업 세션 안에서 중심 고정 회전 자동 복구(`rotfix`)가 일어나면 카메라 중심과 World 좌표계가 그대로이므로 현재 `scene_version` 과 위험 구역을 재생성 없이 그대로 쓴다. 반면 새 작업을 시작해 현장 세팅을 새로 수행하면 그 작업 전용 World·`calibration_version`·`scene_version`·구역 묶음이 새로 만들어지며, 과거 작업의 이벤트·리플레이·보고서는 그 작업에 기록된 당시 버전 계보로 조회한다.
- 세팅 시작 전 **세팅 1단계 화면**에서는 게이트웨이 별도 CPU 프로세스가 계산해 올린 카메라 각도 헬퍼 결과(`POST /api/devices/coverage-guides` → `GET /api/cameras/coverage-guides`, `contracts/messages/coverage_guide.schema.json` 1.0.0)로 4대 연결 여부(`CONNECTED`·`DISCONNECTED`·`UNKNOWN`), 6쌍 매칭 등급(`ENOUGH`·`WEAK`·`LACK`·`UNKNOWN`), 카메라별 회전 방향·크기 안내(`LEFT`·`RIGHT`·`UP`·`DOWN`·`NONE`, `SMALL`·`MORE`·`NONE`), 옆 쌍 Stage A 판정·경고(1.3.0), 카메라별 기준 시점 맞추기(1.4.0, 4.3 0단계)를 표시하고, 세팅 시작 뒤 대기 화면에서는 카메라별 배경 수집률·인접 쌍 매칭 수·바닥 검출 결과로 “`cam_C`–`cam_D` 겹치는 영역에 물체가 부족합니다” 또는 “카메라 각도가 바닥을 충분히 비추지 않습니다” 같은 현장 조치 안내를 띄운다.
