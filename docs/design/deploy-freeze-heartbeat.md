# S15P31A101-582 배포 동결과 하트비트

- 관련 명세: 12.5(I5 대여·만료), 3.12·18(운영). 동결은 `deploy/ec2/deploy.sh`, `freeze.sh`에서 공통 `deploy.lock`으로 직렬화한다. 동결 시작은 진행 중 배포를 기다리며, 이후 시작하는 배포는 입력을 비우고 사유·만료를 출력한 뒤 성공 종료한다. 만료 파일은 경고 후 무시한다. 동결 상태 파일 오류는 배포를 막는다.
- 서버 `JobMessages`의 유지 시간을 30초에서 180초로 늘리고 기존 하트비트 10초를 유지한다. 90초 장애, 최대 10초 재시도 대기 및 요청 시간 제한 여유를 고려했다. 30초를 유지하고 워커만 계속 실행하는 대안은 서버가 대여를 만료·재할당하여 중복 작업이 생기므로 버렸다. 계약의 30초는 기본안이며 필드나 의미는 바꾸지 않는다.
- 워커는 기존 지수 백오프(0.5초 시작, 2배, 30초 상한, 하트비트 주기로 추가 제한)를 사용한다. 전송 시간이 긴 실패 뒤에도 백오프를 기다린다. HTTP 404와 본문 없는 409는 상실로 처리하고 계약 REJECTED도 즉시 중단한다. 서버가 알려준 만료 시각이 지나면 중복 실행을 피하려고 중단한다. 실행 시간 상한과 LIVE 우선도 그대로다.
- 시험: `ai/tests/services/worker/test_client.py`, `test_runner.py`, 동결 셸 시험. 90초 시험은 가상 시계이며 실제 EC2 재시작 시험이 아니다.
- 남은 위험: 워커나 네트워크 장애 시 재할당이 최대 180초로 늦어진다. 배포 도중 동결을 요청하면 진행 중 배포는 막지 못한다. 90초 장애가 대여 만료 직전 시작되거나 작업 실행 상한이 먼저 도래하면 복구를 보장하지 않는다. 호스트 설치본 갱신과 배포 후 실제 환경 검증이 필요하다.
