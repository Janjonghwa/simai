## 실제 코드로 확인한 동작

### 구역 저장과 재전송

- `useZoneCommitMutation.send`: 보정/규칙/공개 주소 문제로 발행이 실패하면 서버가 저장도 롤백하므로 `publish: false`로 다시 저장한다. 이 경우 `useAcceptZoneDraft`는 저장 성공을 유지하면서 원인과 결과를 보인다. 서버 원문 오류는 노출하지 않는다.
- 현재 세션 구역 목록을 쓰는 경로(`saveToPlan`)는 수락 시 세션 목록만 저장하며 현장 전송 실패를 만들지 않는다. 세팅 완료 때 적용한다. 기존 직접 저장 경로의 실패 안내를 보완했으며 공용 구역 편집기의 문구는 범위 밖이라 고치지 않았다.
- `SetupCompletionService.complete`는 세션 구역과 보정을 적용한 뒤 구성 묶음을 발행한다. `WorkSessionService.start`도 `bundles.publishWith(...)` 안에서 작업을 시작한다. 따라서 완료·시작에서 다시 발행하지만 같은 보정/규칙/주소 오류가 남아 있으면 그 단계도 실패한다. 무조건 자동 복구된다고 안내하지 않는다.

### 걷기 쌍 진행과 재시도 제한

- 워커 `ai/src/simai_ai/calibration/camera_check.py`의 `_pair_view`와 `snapshot`은 `pairs[*].camera_ids`, `required`, `samples`, `verdict`와 `thresholds.min_pair_samples`를 보낸다. 서버는 세션 `camera_check`에 이를 싣고 프론트 스키마도 이미 읽는다. 추가 필드 불필요.
- 보정 오차 표의 옆 4쌍 제한을 걷기 표에 복사하지 않았다. 걷기는 서버가 보낸 모든 검사 쌍을 표시하고, 필수가 아닌 쌍은 「함께 보임 확인 대상 아님」으로 구분한다. 분모는 서버의 양수 유한 임계값을 우선하고, 이전 응답에 임계값이 없을 때만 기존 기본값 30을 쓴다. 숫자는 완료 비율이며 통과 판정을 대신하지 않는다.
- 쌍 정보가 없는 응답에는 「서버가 쌍별 진행을 아직 보내지 않았어요」와 겹치는 구간을 걷는 행동을 안내한다. 없는 쌍의 표본 수를 만들어 표시하지 않는다.
- `SetupService.startCameraCheck`는 COMPLETED/FAILED, 유효 대여 없음, 사용자 대기 상태가 아닌 경우를 거부한다. 맵 완료 뒤 무조건 「카메라 확인만 다시」를 연결하면 뒤늦게 409가 되므로 이유와 새 세팅 경로를 표시한다. 완료 후 같은 보정으로 걷기만 다시 여는 서버·워커 기능은 별도 후속 작업이다.

## 구현 위치와 시험

- `useValidationRejections.ts`, `setupFailures.ts`, `SetupPage.tsx`: 거부 이력과 직접 재시도. 화면에 머무는 동안의 마지막 두 종료 세션만 비교한다. 반복 폴링은 중복 계산하지 않고, 다른 원인·작업·완료는 연속 거부를 끊는다.
- `setupUx.ts`, `setupZonePlan.ts`, `SetupZoneReviewCard.tsx`: 표시 충돌 해소와 일괄 확인 제외, 발행 실패 안내, AI 기본 근거.
- `useBackgroundCapture.ts`, `backgroundCapture.ts`, `BackgroundCaptureModal.tsx`: 접수 전 대기 경과와 접수 후 촬영 카운트다운을 분리한다. 경과는 세션 시작 UTC ms부터 0.5초마다 갱신한다. 구형 응답은 배경 수집률이 0보다 큰 것도 촬영 시작 근거로 사용한다.
- `cameraCheck.ts`, `CameraCheckModal.tsx`: 쌍별 표본·임계값·부족 강조. `nextStep.ts`, `SetupCalibrateStep.tsx`: 맵 완료 뒤 행동.
- `cameraLabels.ts`, `setup.ts`, `ZoneOpinionView.tsx`, `SetupPanels.tsx`: 기존 번호 규칙으로 문장·사진 설명을 통일한다.
- 시험은 `front/apps/admin/src/__tests__/features/setup/`에 있다. `setupUx.test.ts`, `SetupUxViews.test.tsx`를 추가하고 기존 실패·페이지·패널·카메라·사진 시험을 갱신했다.

## 버린 대안과 남은 제약

- 첫 거부부터 물리적 재설치를 요구하는 안내와 재시도를 막는 방식은 버렸다. 같은 녹화가 다음 시도에 통과한 점검 근거와 맞지 않는다.
- AI 제안으로 높이 판정 원문을 바꾸거나 자동 확인하지 않는다. 충돌한 구역은 개별 확인 대상으로 남긴다.
- 연속 거부 이력은 현재 화면의 메모리다. 새로고침·다른 탭·화면 재진입 전의 시도는 서버가 이력을 주지 않아 횟수를 추정하지 않는다. 전역 연속 횟수가 필요하면 서버의 이전 시도 ID·거부 쌍 조회가 후속으로 필요하다.
- 네트워크·실제 GPU·실카메라 시험은 수행하지 않는다. 로컬 MSW와 가짜 시계 기반으로 검증한다. 브라우저 수동 시각 점검은 미실시다.
