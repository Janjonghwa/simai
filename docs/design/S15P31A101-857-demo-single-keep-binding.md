   `windowScore` 가 −0.5 를 내고, 누적 점수가 0.6 아래로 내려가자 `match()` 가 경쟁 없이 `MATCH_LOST` 로 풀었다.
2. **53 의 즉시 재결합과 MATCH_LOST**: 같은 대조 주기 끝의 `bindDemoSingleIfEligible` 이 1명 조건으로 6 ms 뒤 다시 `DEMO_SINGLE` 로 붙였다

3. **53→54 사이 10초 공백**: `bindDemoSingleIfEligible` 의 막음 `evidence != null && evidence < 0 → 잇지 않음`(-826, 붙였다 뗐다 진동 방지) 때문이다.
   점수는 근거를 낸 창에서만 감쇠·누적되고(서 있는 창은 NaN 이라 그대로 둠), 음수 점수가 다음 양수 창(걸음 일치 +0.2 등)이 들어와 0 이상이 될

## 정한 규칙

### 1. 시연 1명·워치 1개 동안 배정 유지 (`server/.../domain/watch/WatchMotionMatcher.java`)

- **유지**: 시연 스위치(`simai.watch.demo-device`)가 켜져 있고 최근 3초(`TRACK_STALE_MS`) 안에 보인 **확정 트랙(TENTATIVE 제외)이 정확히 1개**이며
  시연 워치의 대조 소유 배정(`MOTION_MATCH`·`DEMO_SINGLE`·임시 이어받기)이 그 트랙에 걸려 있으면, 경쟁 짝이 없고 ID 교정 직후가 아닌 한
  반대 근거로 `MATCH_LOST` 를 내지 않는다. 걸음이 맞으면 `DEMO_SINGLE` → `MOTION_MATCH` 승격, 임시 이어받기 확정은 그대로 한다.
- **2명 이상**: 확정 트랙이 2개 이상이 되면 위 유지를 하지 않고 기존 규칙(유지 문턱 `0.6`·임시 `0`, 경쟁 짝 `REPLACED`, -793 자리 이어받기, -826 갈아 끼우기)대로 걸음 대조가 판단한다.
- **바로 다시 붙기**: `bindDemoSingleIfEligible` 의 `evidence < 0` 막음을 뺐다. 1명인 동안은 반대 근거로 끊지 않으므로 그 막음이 막던 진동이 없고,
  2명 → 1명으로 돌아온 순간(또는 ID 교정 뒤 의심 3초가 지난 순간) 대조 주기(2초) 안에 다시 붙는다. 나머지 조건(5초 초과, 대상 트랙 배정 없음,
  시연 워치 기존 배정 ID 가 >10초 미관측)은 그대로다.
- **TENTATIVE 제외**: Tier 0 가 아직 확정하지 않은 잠깐의 유령 트랙 하나로 1명 조건이 깨지면 그 주기에 반대 근거로 끊긴다. 「확정 사람 1명」을
  `track_lifecycle != TENTATIVE` 로 센다(`Track.tentative`, 마지막 프레임 기준). 시연 1명 자동 배정 판정에도 같이 쓴다.
- **그대로 둔 것**: ID 교정(`IDENTITY_CHANGED`)·병합(`ID_MERGED`)·자리 이어받기(`HANDOFF`)·관리자 수동 배정·해제, I4 알림 매핑(`DEMO_SINGLE` → `MOTION_MATCH`), 계약.

### 2. 끊긴 동안 경보 이름 이어 쓰기 (`server/.../domain/watch/PersonDisplayNames.java` `historicalSnapshot`)

- **고른 지점**: 서버의 시각별 이름 구간 계산(`GET /api/people/display-names`, -835). 시각별 이름은 서버가 만든다(front `resolveHistoricalPersonName` 은
  받은 구간에서 찾기만 한다). 관제 카드(-851 `personNameMemory`·`withRememberedNames`)는 이미 「그 ID 의 마지막 실제 이름」을 쓰므로, 지난 기록 쪽만
  같은 결과를 내게 고치면 두 화면이 맞는다. front·계약·목업은 바꾸지 않는다.
- **규칙**: 시각 `t` 에 World ID W(그 시각까지의 병합·이어받기 계보 포함)에 이름이 없고(수동 이름·지금 배정 워치 이름 모두 없음),
  1. W 에 지금 배정이 없고(이름 없는 워치라도 지금 배정이 있으면 이어 쓰지 않음 = 「다음 배정까지」),
  2. W 의 가장 최근에 끝난 배정이 `MATCH_LOST`(대조가 잠깐 놓침)로 끝났으며,
  3. 그 끝 시각과 `t` 가 같은 작업 실행(`work_run_window` 한 행의 [시작, 종료)) 안이고,
  4. 그 사이 그 워치가 W 의 계보 밖 다른 World ID 에 배정되지 않았으면(다른 사람에게 옮겨 감),

  끝나기 직전 그 워치 이름을 `WATCH_DEVICE` 로 이어 쓴다. 이어 쓴 구간은 앞 구간과 이름·출처가 같아 한 구간으로 합쳐진다. 실행 종료 시각을 구간 분할점에 더했다.
- **이어 쓰지 않는 경우**: 관리자 해제(`RELEASED`)·ID 교정(`IDENTITY_CHANGED`)·교체(`REPLACED`)로 끝난 배정, 실행 밖, 워치가 다른 사람에게 옮겨 간 뒤.
  관리자·ID 교정은 「그 사람이 아니다」일 수 있어 모르면 비운다(규칙 2). 자리 이어받기·병합은 기존 계보 승계(-835)가 이미 이름을 잇는다.

## 버린 대안

1. **`DEMO_SINGLE` 의 유지 문턱만 더 낮추기(예: −1)**: 승격된 `MOTION_MATCH`(행 52)는 그대로 0.6 에서 끊기고, 점수가 계속 음수로 쌓이면 결국 끊긴다.
   「1명인 동안은 끊지 않는다」를 직접 두는 편이 리허설 흐름 전체(승격 포함)를 막는다.
2. **1명 동안 승격하지 않고 `DEMO_SINGLE` 로만 두기**: DB 이력에서 실제 걸음 일치를 구분하지 못하게 되고(-826 근거), 2명이 되는 순간 0 문턱으로
   더 쉽게 풀린다.
3. **`evidence < 0` 막음 유지**: 2명 → 1명으로 돌아왔을 때 양수 창이 올 때까지(서 있으면 영영) 다시 붙지 않는다. 10초 공백·54 뒤 미배정의 원인이다.
4. **front 에서 경보 시각 이름을 따로 계산(-835 API 를 관제 카드에도 쓰기)**: -851 이 버린 이유(카드마다 요청)와 같다. 관제 카드는 이미 기억 이름으로 맞다.
5. **이름 이어 쓰기를 날짜 끝까지**: 실행이 끝난 뒤 남은 트랙(정리·다음 리허설)에 앞 사람 이름이 붙는다. 실행 끝에서 멈춘다.
6. **모든 끝난 사유에서 이어 쓰기**: 관리자 해제·ID 교정 뒤에도 이름이 붙어, 관리자가 「아니다」라고 푼 사람에게 이름이 남는다.

## 남은 위험

- **시연 스위치 아래 1명은 걸음 근거를 무시한다.** 워치를 차지 않은 사람 1명만 화면에 있으면 반대 근거가 있어도 시연 워치가 그 사람에게 붙어 있다
  (-826 남은 위험과 같은 전제: 시연 스위치는 1인 시연 전용, 본 운영에서는 비운다).
- **유령 트랙이 CONFIRMED 로 올라오면** 그 순간은 2명이라 기존 규칙으로 끊길 수 있다. 다시 1명이 되면 대조 주기(2초) 안에 다시 붙는다(이력에 행이 늘고 워치에 UNBOUND·BOUND 알림이 한 번씩 간다).
- **2명 ↔ 1명이 번갈아 바뀌면** 붙였다 뗐다가 그 횟수만큼 난다(이전 `evidence < 0` 막음이 막던 경우). 사람 수가 실제로 바뀌는 때만이라 받아들였다.
- **관제 카드와 지난 기록이 다른 경우가 남는다.** 관제 카드(-851)는 실행·사유·옮겨 감과 상관없이 브라우저 세션 동안 그 ID 의 마지막 실제 이름을 쓴다.
  워치가 다른 사람에게 옮겨 간 뒤 W 에 새로 난 경보, 관리자 해제·ID 교정 뒤 경보, 실행 끝 뒤 경보는 관제 카드에는 이름이, 지난 기록에는 「작업자 #N」이 보인다.
  같은 ID 의 경보 대부분(배정 중·잠깐 끊긴 동안)은 같다. 맞추려면 관제 카드가 경보마다 그 시각 이름을 고정해야 한다(넘긴 일).
- **목업(`mocks/peopleNames.ts`)** 은 `MATCH_LOST`·실행 개념이 없어 이어 쓰기를 흉내 내지 않는다(목업 화면 결과는 그대로).
- **실 재생 검증 전이다.** 11-23 리허설 녹화 재생으로 진입·낙상 시각 배정 유지와 지난 작업 화면 이름을 확인해야 한다.
