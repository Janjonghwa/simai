# 아바타 외형 미관측 채움 표시 (S15P31A101-742)

18차 GPU 세션에서 실제 MHR 메시 아바타가 회색이 섞여 보였다. 원인은 뷰어 셰이더였다. 보간(`1`) 텍셀은 채도 45%·명도 85%로 낮췄고,
미관측(`0`)과 얼굴 미관측(`128`) 텍셀은 기본 재질 색(하의는 `0x5a6478` 청회색)으로 칠했다. 천장 2.4 m 카메라는 등과 다리 뒤를
거의 보지 못하므로 미관측 면적이 크다. 이 티켓은 뷰어 표시만 바꾼다. `surface_source` 데이터·계약·워커·서버는 그대로이고, 출처 기록도 그대로 남는다.

## 사용자 결정 (2026-11-15)

> 굳이 낮춘 색으로 갈 필요 없다. 원칙을 좀 고치더라도 최대한 보여 주기 좋은 쪽으로.

- 보간(`1`)은 텍스처 색을 그대로 쓴다(감쇠 없음).
- 미관측(`0`)은 회색 대신 같은 몸 부위의 관측·보간 색으로 자연스럽게 채운다.
- 얼굴 미관측(`128`)은 관측 얼굴(`130`)이나 목 피부의 단색 평균으로 채운다. 이목구비는 만들지 않는다(AGENTS 규칙 8).

## 채우는 방식

1. **언제.** `MeshBody` 의 재질 갱신 효과에서 `applyAvatarAppearanceToMaterials` 가 `appearance.displayAlbedo` 를 부른다.
   새 `appearance_version` 이 READY 가 된 같은 효과 안에서 채우고 uniform 을 바꾸므로, 채우지 않은 텍스처가 한 프레임도 보이지 않는다.
   같은 버전에서는 선택·색 변경으로 효과가 다시 돌아도 캐시된 텍스처를 그대로 쓴다. 원본 `albedoTexture` 는 셰이더에 묶이지 않아 GPU 에 올라가지 않는다.
2. **UV 부위 지도(메시에서 만듦).** 텍스처 해상도를 `factor = floor(max(w,h) / 256)` 로 나눈 격자(1024 → 256, 96 → 96)에
   메시 `TEXCOORD_0` 삼각형을 래스터화한다(glTF 상단 원점, `flipY=false`).
   - UV 섬: 삼각형으로 이어진 정점, 그리고 UV 좌표가 같은 정점(1e-5 반올림)을 한 섬으로 묶는다(union-find).
   - 부위 = 섬 × 상하. 삼각형 무게중심의 바인드 높이 `position.y` 가 `0.88 m`(`AVATAR_WAIST_REST_Y`, 셰이더의 상·하 기본색 경계) 이상이면 위다.
   - 인접: 같은 섬의 위·아래 부위, 그리고 바인드 위치가 같은 정점(0.1 mm 반올림, glTF 가 UV 이음매에서 정점을 가른 곳)을 가진 다른 섬.
   - 칸 중심을 덮지 못한 가장자리 칸은 이웃 부위로 한 칸 메운다.
   - 장면(공유 형상)과 격자 크기별로 `WeakMap` 에 한 번만 만든다. 관절(Joints) 재질 메시는 뺀다.
3. **격자 씨앗.** 몸 텍셀 중 관측(`2`)·보간(`1`)의 색을 격자 칸별로 평균한다. 얼굴 텍셀만 있는 칸은 몸 채우기에서 뺀다.
4. **같은 부위 안에서 번지기.** 씨앗에서 파면(wave) 단위로 4이웃을 넓혀 가고, 새 칸 색은 이전 파면까지 채워진 같은 부위 8이웃의 평균이다(반복 dilation).
   다른 섬·다른 상하 칸으로는 번지지 않는다. 그 뒤 번진 칸만 2회 완화한다(씨앗 고정)(`AVATAR_FILL_SMOOTH_PASSES`).
5. **남는 칸.** 번지기로 닿지 않은 칸(부위가 격자에서 끊긴 조각)은 그 부위 씨앗 색의 중앙값으로 채운다.
   부위에 관측이 하나도 없으면 인접 그래프를 넓이 우선으로 따라가 처음 만나는 관측 부위들(같은 상하를 먼저 고름)의 중앙값을 쓴다.
   거기도 없으면 같은 상하 전체 관측 색의 중앙값, 그것도 없으면 알파 0 으로 두어 셰이더가 지금의 기본색을 쓴다.
   중앙값은 채널별 256칸 히스토그램으로 구한다.
6. **아틀라스 빈칸.** UV 섬 밖 칸으로 2칸(`AVATAR_FILL_GUTTER_CELLS`, 1024 기준 8 텍셀) 더 번진다.
   `LinearFilter` 쌍선형 표본이 섬 가장자리에서 검정(워커가 미관측·빈칸에 넣는 RGB 0)과 섞여 어두운 이음매가 생기던 것도 함께 없어진다.
7. **원래 해상도로.** 관측·보간·얼굴 관측 텍셀은 원래 색에 알파 255 를 둔다. 미관측 몸 텍셀은 같은 부위 격자 칸끼리만 쌍선형 보간해 4×4 계단과 섬 사이 섞임을 막는다.
8. **셰이더.** `2`·`1` 은 텍스처 색, `130` 은 `face_policy` 처리 그대로, 그 밖은 `mix(기본색, tex.rgb, tex.a)` 다.
   알파는 선형(sRGB 변환은 RGB 에만 적용)이라 채운 곳과 못 채운 곳의 경계도 부드럽다.
9. **실패.** 채우기가 예외를 던지면 경고를 남기고, 관측·보간·얼굴 관측만 알파 255 로 둔 텍스처를 쓴다(미관측은 기본색). 원본을 그대로 쓰면 미관측이 검정으로 보이기 때문이다.

### 얼굴

- 얼굴 미관측(`128`, 얼굴 비트가 있는데 `130` 이 아닌 값)은 **단색** 하나로 채운다. 이목구비·무늬를 만들지 않는다.
- 색은 `face_policy` 가 EXCLUDED 가 아닐 때 관측 얼굴(`130`) 텍셀의 RGB 평균이다. EXCLUDED 이거나 `130` 이 없으면 목 피부를 쓴다.
  목 피부는 얼굴 칸에서 2칸(1024 기준 8 텍셀) 안에 있고 같은 UV 섬인 몸 관측 칸의 평균이다. 그것도 없으면 알파 0(기본색)이다.
- EXCLUDED 에서는 `130` 색을 단색 평균에도 쓰지 않는다(워커도 EXCLUDED 에서는 `130` 을 만들지 않는다).
- 몸 채우기의 씨앗에 얼굴 텍셀을 넣지 않아, 얼굴 색이 몸으로 번지지 않는다.
- 워커의 자동 얼굴 영역은 머리 전체다(`hmr-appearance-texture.md`). 그래서 뒷머리 미관측도 피부 단색이 된다.
  천장 카메라에서 관측 얼굴(`130`)은 정수리·머리카락이 많아 평균이 머리카락 쪽으로 어두워질 수 있다. 실자산에서 볼 항목이다.

### UV 부위 근거: 하드코딩 대신 메시에서 만든 이유

지시서는 MHR UV 배치로 상의·하의·팔·다리·신발 영역을 정하라고 했다(합성 fixture 의 v 경계 0.18·0.49 참고).
- 노트북에는 실제 MHR 자산(`mhr_model.pt`, 재배포 금지, GPU Pod 에만 있음)도, 실 세션의 `albedo.png` 도 없다. `simai-local` 전체와 세션 폴더를 찾아 확인했다.
  그래서 실제 MHR 아틀라스의 섬 좌표를 보고 고정 값을 정할 수 없었다.
- fixture 의 v 경계 0.18·0.49 는 `avatarFixture.ts` 가 그린 합성 그림의 경계다. MHR UV 가 아니다. fixture GLB 에는 UV 도 없어서 `ensureAvatarMeshUv` 가 앞·뒤 투영 UV 를 채운다.
- 뷰어는 텍스처를 칠할 메시(실제 MHR GLB 의 `TEXCOORD_0`, -88 `gltf_export.py` 가 MHR `texcoord_faces` 를 그대로 싣는다)를 이미 갖고 있다.
  섬은 그 UV 연결에서, 상하는 셰이더와 같은 바인드 높이 경계에서 나온다. MHR 버전이나 UV 가 바뀌어도 값을 고칠 필요가 없다.
  사람 몸 UV 는 보통 머리·몸통·팔·다리·손·발이 서로 다른 섬이라, 「섬 × 상하」가 지시서의 부위 구분(상의·하의·팔·다리·신발)과 거의 같다.
  섬 경계가 실제로 어떻게 나뉘는지는 실자산에서 확인한다(남은 위험).

| 항목 | 값 | 근거 |
|---|---|---|
| 채우기 격자 | 한 변 목표 256(1024 → 4×4 묶음) | 미관측은 원래 저주파로 채우는 곳이라 격자가 낮아도 된다. 1M 텍셀 번지기를 6.5만 칸으로 줄여 메인 스레드 시간을 수십 ms 로 맞춘다 |

| 상하 경계 | 바인드 높이 0.88 m | 셰이더 상·하 기본색 경계(`AVATAR_WAIST_REST_Y`)와 같게 해 채움과 기본색 폴백의 경계를 맞춘다 |

## 성능 (노트북 측정)

Windows 11 노트북, Node 26.12.1(vitest, V8 — Chrome 과 같은 엔진), 1024² albedo·출처 지도, dense 합성 리그(정점 21,168·삼각형 36,504, 실제 MHR 크기)의 부위 지도.
`avatarAppearanceFill.test.ts` 의 「성능」 시험을 세 번 돌렸다(한 번에 채우기 3회).

| 항목 | 측정 |
|---|---|
| 부위 지도(256², 메시 자산·격자당 한 번, 캐시) | 32.6 / 40.1 / 32.9 ms |
| 채우기 첫 호출(JIT 예열 전) | 79.4 / 115.6 / 90.7 ms |
| 채우기 예열 뒤 | 43.5 ~ 68.3 ms |
| 단계별(예열 뒤 한 번 표본) | 부호 읽기·씨앗 8~20 ms, 원래 해상도 옮기기 16~17 ms, 번지기·완화·중앙값 합 약 10 ms |

- 채우기는 사람 × `appearance_version` 마다 한 번이다. 워커 발행 간격은 관측 +2%p 또는 30초다(`hmr-appearance-texture.md`). 매 프레임 드는 비용은 없다.
- 페이지에서 처음 한 번은 약 0.1초 걸린다(부위 지도 + 채우기 첫 호출). 그 뒤로는 사람당 약 50 ms 다. 여러 사람이 같은 순간에 새 버전을 받으면 효과마다 이 비용이 차례로 든다.
- 시험 상한은 느린 CI 를 고려해 채우기 최소 250 ms, 부위 지도 500 ms 로 넉넉히 두었다. 위 표의 값은 시험 출력의 `[742 성능]` 줄에서 옮겼다.
- 원본 albedo 는 GPU 에 올리지 않고 표시용 하나만 올리므로 GPU 업로드 양은 그대로다. CPU 메모리는 사람당 4 MB(1024² RGBA)가 늘어난다.

## 규칙 7과의 차이

- AGENTS 규칙 7(관측과 추정을 구분한다)은 **데이터에서는 그대로 지킨다.** `surface_source.png`·`surface_ratios`·`face_ratios`·계약·워커·서버 저장은 바뀌지 않았다.
  관측·보간·미관측 출처는 자산에 남고, 위험 판정(Tier 0)에는 원래 외형을 쓰지 않는다(Tier 1 표시 전용).
- **화면에서는 관측과 추정의 구분이 더는 보이지 않는다.** 보간은 관측과 같은 색이고, 미관측은 관측 색으로 채워져 실제로 본 면처럼 보인다.
  채운 색은 같은 사람의 관측 픽셀에서 나온 것이며 새 옷 무늬나 형상을 만들지 않는다. 그래도 화면만 보고는 「이 면을 카메라가 봤다」고 말할 수 없다.
  관측 범위를 보려면 출처 지도(진단 폴더, `appearance_report` 비교 그림)를 본다. 화면에 구분을 되살리는 토글은 만들지 않았다(넘긴 일).
- 얼굴은 규칙 8 을 지킨다. 생성형 복원·이목구비 생성·표정 추정은 없다. 얼굴 미관측은 관측 픽셀 평균 단색 하나다.
  다만 20.3 의 「안 보인 얼굴 면은 기본 재질로 둔다」는 피부 단색으로 바뀌었다(아래 메모).

## 버린 대안

- **셰이더에서 실시간 채우기(이웃 표본 탐색).** 큰 미관측 면적은 수십~수백 텍셀을 찾아야 해서 프래그먼트 비용이 크고, 섬·부위 경계를 GPU 에서 알기 어렵다.
- **UV v 띠로 부위 하드코딩.** 실제 MHR 아틀라스를 확인할 수 없었고, fixture 경계는 합성 그림의 값이다. 메시에서 만드는 편이 자산이 바뀌어도 맞다.
- **전체 해상도 push-pull 피라미드.** 섬마다 마스크 피라미드를 돌리면 1024² 에서 수백 ms 가 든다. 256 격자의 파면 번지기 + 같은 부위 쌍선형으로 결과는 비슷하고 더 빠르다.
- **Web Worker 로 옮기기.** 메인 스레드를 막지 않는 가장 확실한 방법이지만, 버전 교체 때 깜빡임 없이 맞추려면 비동기 READY 단계와 메시 형상 전달이 필요하다. 예열 뒤 약 50 ms 라 이번에는 하지 않았다(넘긴 일).
- **워커(서버 쪽)에서 채운 PNG 보내기.** 출처 기록과 표시가 섞이고 워커·계약 변경이 필요해 범위 밖이다.

## 남은 위험

- 실제 MHR UV 섬 구성(몸통 앞·뒤가 한 섬인지, 손·발이 따로인지)을 실자산에서 아직 보지 않았다. 몸통 앞·뒤가 다른 섬이고 뒤가 전혀 안 보이면, 뒤판은 이음매로 붙은 앞판의 중앙값 단색이 된다.
- 바인드 자세에서 손이 허리(0.88 m) 아래로 내려가면 팔 섬의 손 쪽이 아래 부위가 된다. 그 부위에 관측이 없으면 인접(같은 섬의 위 부위)에서 팔 색을 빌려 와 큰 문제는 없을 것으로 보지만 확인이 필요하다.
- 얼굴 단색이 머리카락 섞인 평균이라 어둡거나, 머리 전체가 피부색이라 대머리처럼 보일 수 있다.
- 첫 호출이 0.1초 안팎이라 사람이 많은 장면에서 여러 사람의 새 버전이 겹치면 한 번 끊김이 느껴질 수 있다.
