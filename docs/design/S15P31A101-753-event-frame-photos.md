# 이벤트 프레임(사진) 표시: 관리자 이벤트 상세·관제 경보 카드 (S15P31A101-753)

CRITICAL R1~R4 이벤트 프레임(JPEG)은 Tier 0 가 S3 에 올리고 `event_frame_ready` 를 보내 EC2 가 받지만 VLM 근거 입력으로만 쓰였다.
관리자 화면과 조회 API 에 사진이 없어 「경보 순간 무슨 장면이었나」를 클립이 올라오기 전·클립이 없을 때 볼 수 없었다(-748 설계 6절 「명세와 다른 점」).

관련 명세: 5.4(VLM 근거 입력 프레임), 11.4(이벤트 프레임은 별도 테이블 없이 `analysis_job.input.frames`), 12.3(`event_frame_ready`), 12.6, 14(비공개 저장소·서명
주소), 16, AGENTS 규칙 8(관측 얼굴 픽셀 표시 가능, 기본 OBSERVED). 앞 문서: `S15P31A101-748-event-clip-upload.md`, `S15P31A101-731-live-alert-cards.md`,
`server-object-storage.md`. **계약(JSON Schema)·DB 마이그레이션 변경 없음**(`event_frame_ready` 1.1.0 그대로, 버전 묶음 번호를 쓰지 않는다).

## 1. 저장 위치와 API

| 항목 | 결정 | 근거 |
|---|---|---|
| 저장 위치 | 새 테이블을 만들지 않고 `analysis_job.input.frames`(작업 종류 `vlm_rationale`)에서 읽는다 | 명세 11.4 가 이미 이 자리를 정했다. `VlmRationaleIngestor` 가 프레임 주소·카메라·촬영 시각을 넣어 둔다 |
| API | `GET /api/events/{id}/frames`(관리자). 응답 `{event_id, frames:[{camera_id, capture_ms, timestamp_source, timestamp_uncertainty_ms, url, expires_at_ms}]}` | `GET /api/events/{id}/clips` 와 같은 틀(12.6 표에 없는 보조 경로) |
| 이벤트 상세 `GET /api/events/{id}` 에 싣지 않은 이유 | 상세는 반장·관리자가 부르고 자주 다시 받는다. 사진은 관리자 전용이고 서명 주소는 만료가 있어 따로 받는다 | 얼굴이 보일 수 있는 원본이라 클립과 같은 권한(관리자)으로 둔다 |
| 서명 | 요청마다 `ObjectStorage.signGet`(만료 5분, `downloadTtl`). 서명 주소는 저장·로그 금지 | 14장 |
| 안전 장치 | `frame_uri` 가 이 이벤트의 `event-frames/<event_id>/` 접두에 있는 객체만 서명한다(다른 이벤트·다른 버킷 주소는 건너뜀) | 작업 입력의 주소를 그대로 믿고 서명하지 않는다 |
| 정렬 | 촬영 시각, 같으면 카메라 | |
| 저장소 미설정 | 빈 목록(503 으로 화면을 깨지 않는다) | 개발 환경 |

`local_copy`(Pod 로컬 사본)·`face_policy`(VLM 입력용 BLURRED 복사본 표시)는 내보내지 않는다. 화면의 사진은 S3 원본 그대로다(규칙 8: 관측 얼굴 기본
OBSERVED. 생성·복원 없음).

`front/apps/admin/src/features/eventPhotos/`.

| 자리 | 동작 |
|---|---|
| 사건 상세 「이벤트 사진」 칸(「이벤트 클립」 칸 위) | LIVE CRITICAL 이벤트마다 카메라별 썸네일(카메라 이름·촬영 시각). 누르면 크게 보기(어두운 덮개, Esc·바깥·닫기). 사진이 하나도 없으면 칸 전체를 숨긴다(`data-photos` + `has-[...]`) |
| 관제 경보 카드 | 카드 머리를 눌러 선택한(펼친) 카드 아래에 작은 썸네일 줄. 사진이 없으면 아무것도 없다 |
| 서명 주소 만료 | 만료 30초 전에 목록을 다시 받는다. 사진이 깨지면(`img` 오류) 곧바로 다시 받는다. 사진이 아직 없으면 15초마다 다시 본다 |

## 3. 명세에 없어 정한 수치

| 항목 | 값 | 근거 |
|---|---|---|
| 썸네일 크기 | 상세 144 px 너비, 카드 96 px(16:9) | 카드는 3줄 높이를 크게 늘리지 않게 |

## 5. 잔여 위험·넘긴 일

1. **사진이 없는 CRITICAL 이벤트가 있다.** `VlmRationaleIngestor` 는 같은 사건 30 s 창(-723)·5 s 늦은 수신·이미 있는 작업이면 근거 작업을 만들지 않는다.
   그 이벤트는 `analysis_job.input.frames` 가 없어 사진이 없다(화면은 칸을 숨김). 모든 CRITICAL 이벤트에 사진을 보이려면 `event_frame_ready` 를
   받을 때 프레임을 따로 기록해야 하며 11.4 개정(+ Flyway)이 필요하다. 이 티켓은 명세대로 두었다.
2. `local_copy` 가 있는 프레임은 S3 업로드를 기다리지 않고 알려 객체가 잠시 없을 수 있다. 서명 GET 이 404 면 이미지가 깨져 15초·재시도로 다시 받는다.
3. 사건 묶음 카드의 사진은 대표 규칙의 이벤트 것만 보인다(묶인 다른 규칙 사진은 사건 상세에서).
4. 14일 보관 자동 삭제(`ClipPurgeScheduler`)는 클립 대상이다. 이벤트 프레임 객체의 삭제는 이 티켓 범위 밖이다(저장소 수명 규칙에 맡김).
