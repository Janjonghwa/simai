# S15P31A101-708 GPU 자동 정지(IDLE) 기준 시각을 준비 완료부터로

관련 명세: 3.12(GPU 사용 원칙), 3.2(Tier 0 우선). 앞 티켓: -702 자동 정지(`S15P31A101-702-gpu-provider-runpod.md`), -699 세션 단계·`tier0_link`.
계약 변경 없음(관리 REST 는 계약 밖), DB 변경 없음.

## 고친 버그(16차 GPU 세션)

22:58:07 켬 → (다른 버그로) 23:27:12 READY → 66초 뒤 `GPU 자동 정지(IDLE)`. 유휴 시작점에 켠 시각이 들어 있어 부팅 29분이 유휴로 세어졌다.
또 Tier 0 가 I1 에 붙어 관리자가 화면을 보고 있었는데도 실행(work_run)이 없어 유휴였다.

## 기준 시각 규칙(사용자 결정 2026-11-14)

- 준비 완료 = 그 세션의 첫 READY 보고 수신 시각(`gpu_session_event` PROGRESS·READY 의 min(received_at))과 그 세션 Tier 0 의 첫 I1 연결을
  본 시각 중 이른 쪽. 화면 점이 초록(CONNECTED)이 되는 조건과 같다.
- 유휴 시작점 = max(준비 완료, 마지막 실행 종료·세팅 세션 갱신·작업 대여 활동·녹화 업로드 서명(기존 `GpuActivity.lastUse`),
  Tier 0 가 지금 붙어 있으면 마지막 관리자 화면 조작). 시작점 + 설정의 자동 정지 분이 지나면 IDLE.
- 준비 완료 전(등록 전·WEIGHTS·ENGINE·TIER0·VLLM 이고 I1 없음)은 유휴로 세지 않는다. 켠 시각은 BOOT_TIMEOUT(등록 없음 25분)에만,
  FAILED 는 FAILED 단계 시각(20분)에만 쓴다. SESSION_ENDED·LIVE/세팅/업로드/작업 대여 보호는 그대로.
- 첫 I1 연결 시각은 DB 에 없어 메모리에 둔다(자동 정지 점검이 그 세션의 연결을 처음 본 시각, 1분 주기라 최대 1분 늦음 = 끄는 쪽에 보수적).
  재시작하면 비지만 READY 를 보고한 세션은 DB 의 READY 가 기준이 되고, 아니면 재시작 뒤 처음 본 시각이 기준이 된다(늦어지는 쪽).

## 관리자 화면 조작 신호

- front: 상단바 `GpuIndicator`(관리자 화면마다 있음)가 `useGpuPresence` 로, 관리자이고 GPU 가 꺼져 있지 않을 때, 화면이 보이는 동안
  (`document.visibilityState === 'visible'`) 누르기·키 입력(`pointerdown`·`keydown`, window capture) 뒤 최대 1분에 한 번
  `POST /api/gpu/presence`(204, 관리자만) 를 보낸다. 실패는 알리지 않는다(다음 입력 때 다시).
- server: `GpuPowerService.presence()` 가 마지막 시각만 메모리에 둔다. 서버가 뜰 때는 뜬 시각으로 둔다(재시작·배포 직후 신호가 아직 없다고
  바로 끄지 않게. 대가는 재시작 뒤 최대 N분 더 켜 둠). 단일 EC2 라 인스턴스 사이 공유는 필요 없다.

## N(조작이 사용으로 남는 시간)

설정의 자동 정지 분(기본 30분)과 같게 했다. 조작 시각을 시작점 후보에 넣는 것과 같아 규칙이 하나다("Tier 0 가 붙어 있으면 마지막 조작 뒤 N분,
아니면 마지막 사용 뒤 N분"). 0분(끔)이면 유휴 정지 자체가 없다. 따로 10분을 두면 관리자가 화면을 보며 생각하는 30분 사이 꺼질 수 있고 설정이
둘로 갈린다.

## 버린 대안

| 안 | 버린 까닭 |
|---|---|
| 관리자 API 요청 시각(기존 신호) | 상단바 상태 조회가 10초마다 와 화면을 띄워 두기만 해도(밤새) 사용으로 센다. 실제 조작과 구분이 안 된다 |
| STOMP 구독(관제 화면 열림) | 같은 까닭(열어 두기만 해도), 조작 여부를 모른다 |
| 마우스 이동·스크롤까지 신호로 | 화면 위를 지나가기만 해도 센다. 누르기·키가 가장 단순하고 의도가 분명하다 |
| 조작 시각을 DB 에(V78) | 1분에 한 번 쓰기가 생기고 재시작 때 보존할 가치가 작다(재시작 직후는 뜬 시각으로 보수적으로 본다) |
| 첫 I1 연결 시각을 I1Connection 에 기록 | tier0 패키지를 건드린다. 1분 정밀도로 충분하고 늦게 잡히는 쪽이 안전하다 |
| Tier 0 연결만으로 사용 중 | 아무도 보지 않는 밤에도 켜져 과금된다(사용자 결정: 연결 + 최근 조작) |

## 남은 위험

1. 준비 중에 멈춘 채 보고만 계속하는 부팅(FAILED 도 READY 도 아닌 상태가 끝없이)은 유휴로 끄지 않는다. -700 은 단계마다 시간 제한 뒤 FAILED
   또는 READY(vLLM 1800 s)로 넘어가고, 보고가 끊기면 G1 STALE → SESSION_ENDED 가 끈다.
2. 첫 I1 연결이 READY 보다 먼저인 세션은 재시작하면 기준이 재시작 뒤로 밀린다(더 오래 켜 둠, 과금 쪽 위험만).
3. 관리자 화면을 여러 탭으로 열어도 신호는 탭마다 최대 1분에 한 번이라 부하는 무시할 만하다.
