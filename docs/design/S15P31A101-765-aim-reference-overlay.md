## 문제(사용자, 2026-11-16)

1단계 각도 안내는 「캠2–캠3 오른쪽으로 조금」 같은 옆 쌍 기준 문장뿐이다. 다른 카메라와의 관계를 머리로 그려야 하고, 한 대를 움직이면 그 카메라가 낀
두 쌍의 판정이 함께 바뀌어(헬퍼 등급·-761 Stage A 판정 모두 쌍 단위) 맞추기가 수렴하지 않는다.

## 고른 방법: 카메라끼리가 아니라 카메라마다 「보정이 잘 됐던 날의 그 카메라 사진」에 맞춘다

- **기준(aim reference)** = 그 현장의 가장 최근 CALIBRATED 세팅의 카메라별 사람 지운 배경 사진과 그 보정의 K·왜곡·image_size.
  CALIBRATED 세팅 = 세션이 COMPLETED 이고(카메라 확인 직후 구역 확인·굽기 중이거나 FAILED 로 끝난 세션 제외) `setup_session.camera_check` 가 PASSED 이고 `camera_check.calibration_version` 과 `camera_check.baseline.calibration_version`
  이 세션 보정과 같은 세팅(-745 `ConfigBundleService.cameraCheckVerification` 과 같은 조건). SKIPPED·SKIPPED_REPLAY·기준선 없는 PASSED 는 기준이 아니다.
  사진은 -712 와 같은 `SceneCameraImageService`(그 세팅이 만든 Scene 의 굽기 입력 사진, Tier 0 사람 지운 배경 원본 JPEG)다. 새 저장·측정 경로가 없다.
- 각 카메라는 자기 기준 사진만 본다. 한 대를 돌려도 다른 카메라 표시는 바뀌지 않는다.
- 기준 사진과 같은 방향이면 그 세팅의 보정(외부 자세)이 지금도 맞을 가능성이 높으므로, 4대 모두 같으면 「이전 맵 재사용도 안전」을 한 줄로 알린다
  (기본 맵 방식은 바꾸지 않는다. -762 가 새 맵 기본).

## 판정 방법(`gateway/camera_helper/src/simai_camera_helper/aim_check.py`)

1. 매칭은 -712 `view_check` 그대로: 같은 분석 크기(긴 변 960 px) SIFT 1600점, 분석 해상도 K 로 점의 왜곡 제거, 상호 최근접 Lowe 0.75,
   호모그래피 RANSAC 3 px, 인라이어 비율 ≥ 0.6, K⁻¹HK 특이값 비 ≥ 0.98, 회전 재투영 p95 ≤ 3 px.
2. 같은 위치에서 회전만 바뀌었다고 보고, 호모그래피 인라이어의 광선(K⁻¹p, K⁻¹q 정규화)으로 q ≈ R p 인 R 을 직교 Procrustes(Kabsch, SVD 직교화)로 구한다.
   K⁻¹HK 를 직교화한 R(-712)도 같은 값을 주지만, 호모그래피는 8자유도라 작은 각도에서 원근 항이 섞인다. 회전 3자유도 최소제곱이 0.25° 판정에 더 곧다.
3. 분해: R = R_y(pan)·R_x(tilt)·R_z(roll)(표준 오른손 축 회전, OpenCV 카메라 축 x 오른쪽·y 아래·z 앞). R 은 기준 광선 → 지금 광선이고
   R = R_wc_now⁻¹ · R_wc_ref 이므로 지금 카메라를 자기 축 기준으로 R 만큼 돌리면 기준 방향이 된다. 그래서 각도는 **교정량**이다.

| 값 | 부호 | 뜻 |
|---|---|---|
| `pan_rad` | + 오른쪽 | 기준 광축 R·e_z 가 지금 영상 오른쪽(+x)에 있다 → 카메라를 오른쪽으로 |
| `tilt_rad` | + 위 | 기준 광축이 위(−y)에 있다 → 위로 |
| `roll_rad` | + 시계 방향 | 카메라 뒤에서 렌즈 방향으로 볼 때 시계 방향으로 기울인다(카메라 x 축이 아래로) |
| `target_point`/`target_px` | — | 기준 원본 영상 중심((w−1)/2, (h−1)/2)을 왜곡 제거 → R 로 돌림 → 렌즈 왜곡 적용한 지금 원본 영상 위치. 이 점을 가운데 십자선에 오게 돌리면 된다 |
| `arrow_rad` | 0 오른쪽, +π/2 아래 | 가운데 → 목표 점, 목표 점이 영상 밖이면 (fx·tan pan, −fy·tan tilt) 방향 |

   목표 점은 정규화 좌표가 영상 테두리의 왜곡 제거 범위(+10%) 밖이거나 투영이 영상 밖이면 null 이다(왜곡 다항식이 영상 밖에서 안으로 접히는 것을 막는다).
4. 상태(목적별 두 단계, 후속 지시 2026-11-16): ALIGNED(초록, 기준과 같음 = 재사용 가능: 광축 차 √(pan²+tilt²) ≤ 0.25° 그리고 |roll| ≤ 1.0°) ·
   NEAR(노랑, 새 맵 세팅엔 충분: 광축 ≤ 1.5° 그리고 |roll| ≤ 3.0°) · MISALIGNED · UNKNOWN(NO_REFERENCE·NO_VIDEO·STALE·NO_TEXTURE·FEW_MATCHES(대응 < 40)·
   NOT_ROTATION(인라이어 < 0.6, 특이값 비·잔차 미달: 위치 이동·다른 장면, 돌려서 맞출 수 없음)·STREAM_MISMATCH·ERROR). UNKNOWN 은 각도·목표 점·화살표 null(규칙 2).
5. 깜박임 방지(헬퍼 한 곳, `AimHysteresis`): 단계 MISALIGNED < NEAR < ALIGNED 는 그 카메라의 서로 다른 키프레임 **2라운드 연속 충족**일 때만 오르고
   (두 라운드가 함께 충족한 단계까지), **2라운드 연속 미충족**일 때만 내린다(두 라운드 중 높은 단계까지). 처음과 UNKNOWN 뒤에는 가장 낮은 단계에서 다시 센다.
   같은 키프레임은 다시 세지 않는다. 각도·목표 점·화살표는 이번 라운드 측정값 그대로이고, 단계가 ALIGNED 면 화살표를 싣지 않는다.
   화면은 헬퍼가 보낸 단계만 그린다(다시 계산하지 않는다). 계약 `hysteresis_rounds`(2)로 화면·로그가 규칙을 안다.

| 값 | 정한 값 | 근거 |
|---|---|---|
| 광축 차 `max_aim_rad` | 0.25° | -694 섭동표(잡음 바닥 보정에서 카메라 하나를 돌린 걷기 확인): pan 0.25° 는 그 카메라 LOO 6.7~9.4 px 로 잡음 바닥 5.9~8.7 px 와 겹치고 쌍 잔차 3.3~5.3 px(관제 연결 경계 8 px 의 절반쯤)·골반 이동 1 cm. pan 0.5° 는 LOO 9.0~12.0 px 로 세팅 LOO 상한 12 px 에 닿고, tilt 0.5° 는 10.5~13.7 px 로 넘는다. 상한의 절반(0.25°)이면 그 세팅 보정을 그대로 써도 걷기 확인을 통과하는 쪽에 여유가 있다. 합(|pan|+|tilt|)이 아닌 크기로 본다: 광축이 어긋난 각도 그 자체라 방향에 무관하다 |

| 히스테리시스 | 2라운드 | -540·-712 의 2회 연속 확인과 같은 수. 라운드 약 3 s(GPU)라 오르내림은 약 6 s 안. 측정 잡음(0.001°)보다 사람·조명으로 대응이 바뀌는 라운드 하나의 튐을 막는다 |

-712 의 SAME(제자리 3 px = 분석 해상도에서 약 0.4°, 회전 10° 이하)은 「재사용 보정이 다시 맞춰 줄 만한가」라 이것보다 훨씬 느슨하다. 걷기 확인 LOO 와

## 게이트웨이 비용(측정, 이 노트북 CPU, OpenCV 4스레드, 2304×1296 4대)

| 라운드 구성 | 중앙값 |
|---|---:|
| 재사용 시점 확인만(후보 1개, 기준 사진 받은 뒤) | 350 ms |
| 재사용 시점 확인 + 기준 시점 맞추기(같은 맵, SIFT·기준 특징 공유) | 438 ms(+88 ms, 카메라당 매칭·적합 약 22 ms) |
| 기준 시점 맞추기만(공유 없음) | 349 ms |

공유가 없으면 지금 키프레임 SIFT 4장을 다시 뽑아 +350 ms 가 됐을 것이다. 공유 단위는 (카메라, 키프레임 시각, 분석 크기)이고 렌즈마다 다른 왜곡 제거만
따로 한다(`RoundFeatures`). 기준 맵이 재사용 후보와 같으면 기준 사진·특징도 재사용 시점 확인이 받은 것을 빌려 쓴다(받기·SIFT 0회). 헬퍼 라운드는
GPU 매칭 약 2 s(CPU 16~24 s)라 +0.1 s 는 라운드 간격 안이다. 현장 로그 `aim … <ms> shared_sift=<n>` 으로 실측을 남긴다.

## 화면(`front/apps/admin/src/features/setup/{aimCheck.ts,AimOverlay.tsx,SetupPanels.tsx,useAimReferenceImages.ts}`)

- 1단계 카메라 칸(2×2)마다: 가운데 십자선, 목표 점(동그라미, ALIGNED 초록·NEAR 노랑), 가운데 → 목표 점 화살표(광축이 재사용 허용 오차 밖이고 단계가 ALIGNED 가 아닐 때),
  아래 왼쪽에 「오른쪽으로 1.2° · 위로 0.4° 돌려 주세요」/「새 맵 세팅엔 충분 · 재사용하려면 오른쪽으로 0.4°」/「기준과 같음 (재사용 가능)」/모름 사유.
  칸 테두리 ALIGNED 초록(`ok`), NEAR 노랑(`delay`, 위험 등급색과 겹치지 않는 토큰).
- 기준 시점을 아는 칸(UNKNOWN 이 아님)은 옆 쌍 꺾쇠(-761·-446 `CameraCue`)를 그리지 않는다(한 칸에 두 기준의 화살표가 서로 다른 쪽을 가리키지 않게).
  모르는 칸은 기존 꺾쇠를 그대로 둔다. 「지금 할 일」 카드·배경 촬영 창의 -761 경고는 바꾸지 않는다.
- 카드 머리에 「기준 사진 겹쳐 보기」 단추(기준 사진이 있을 때만). **기본 끔**: 50% 로 겹치면 지금 영상의 대비가 절반이 되어 사람·가림·영상 끊김을
  보기 어렵고, 기준 사진에는 그날의 물건 배치가 남아 있어 처음 보는 사람에게는 두 장면이 섞여 혼란스럽다. 방향은 십자선·목표 점·각도로 이미 알 수
  있으므로, 겹쳐 보기는 마지막 미세 조정(이중선이 겹치는지 눈으로 확인)에 켠다. 50% 는 두 장면이 같은 무게로 보여 어긋남이 이중선으로 드러나는 값.
- 4칸 모두 초록이면 카드 머리에 「기준 시점과 같음 — 이전 맵 재사용도 안전」, 4칸 모두 노랑 이상(모두 초록은 아님)이면 「새 맵 세팅 시작해도 됨」.
- 결과가 오래되면(헬퍼 끊김·STALE) 각도·초록은 지우고(지금 것이 아닌 근거로 초록을 보이지 않는다) 겹쳐 보기는 둔다.
- 사진 주소는 뷰어 VDT 의 `GET /api/scenes/{scene}/camera-images` 와 같은 질의 키·다시 받기 규칙을 쓴다. 영상 칸(미리보기 연결)을 다시 만들지 않으려고
  주소 받기는 기준이 있을 때만 그리는 별도 칸(`AimReferenceProbe`)에서 한다.

## 버린 대안

- **카메라끼리(옆 쌍) 판정을 더 정교하게**: 쌍 판정은 본질적으로 두 카메라가 함께 움직여 상호 영향이 남는다(문제 그대로).
- **현재 관제 맵 사진을 기준으로**: 관제 맵은 미리보기·재사용으로 바뀌고 걷기 확인을 통과했다는 보장이 없다. 「보정이 잘 됐던 세팅」 = 걷기 확인 PASSED 가 기준이어야 한다.
- **가장 최근 세팅의 사진이 없으면 더 오래된 CALIBRATED 세팅으로**: 그 사이 카메라를 옮겼다면 옛 시점에 맞추라고 안내하게 된다. 모르면 비운다.
- **K⁻¹HK 직교화 R 그대로(-712)**: 쓸 수 있으나 0.25° 경계에서는 회전만 맞추는 최소제곱이 덜 흔들린다. 호모그래피는 인라이어 고르기와 「순수 회전인가」 검사에만 쓴다.
- **도(°)로 계약에 싣기**: 규칙 3(각도는 라디안) 위반. 화면이 바꾼다.
- **히스테리시스를 화면에서**: 화면은 결과를 10 s 마다가 아니라 받을 때마다 그리지만 라운드(키프레임)를 모른다. 같은 결과를 두 번 받으면 두 라운드로 셀 수 있어 헬퍼 한 곳에서만 한다.
- **한 단계(0.25°)만**: 손으로 0.25° 안에 맞추기는 어렵다(후속 지시). 새 맵 세팅에는 겹침만 같으면 되므로 목적별로 나눴다.
- **노랑을 화각 비율 대신 고정 도로**: 화각이 다른 현장에서는 열 폭(도)이 달라진다. 지금은 로비 광각(f ≈ 0.42 W)만 근거로 1.5° 를 두었고, 화각이 좁은 렌즈(f ≈ 0.8 W)면 바깥 열이 약 12° 라 1.5° 가 열의 12% 쯤으로 여전히 띠 안이다. 현장이 늘면 `f`·열 폭에서 계산하도록 바꿀 수 있다(잔여 위험).
- **겹쳐 보기 기본 켬**: 위 화면 절 근거.
- **기준 시점이 같으면 재사용을 기본으로 바꾸기**: 사용자 결정(-762 새 맵 기본) 범위 밖. 한 줄 안내만.

## 잔여 위험

- **위치 이동은 각도로 맞출 수 없다**: 삼각대를 옮기면 NOT_ROTATION(UNKNOWN, 「돌려서는 맞출 수 없음」)이다. 5 cm 이하 이동은 순수 회전 검사(3 px)를 지나
  각도만 보일 수 있다(-712 와 같은 한계, -694 표에서 수평 5 cm 는 pan 0.25°~0.5° 수준 피해).
- **기준 사진의 그날 배치**: 사람 지운 배경이라도 그날 놓인 물건(라바콘·가방)은 남는다. 많이 바뀌면 대응이 줄어 FEW_MATCHES 가 될 수 있다(모름, 막지 않음).
- **조명·혼잡**: 밤낮 조명 차이·많은 사람으로 대응이 40 아래면 UNKNOWN. 경계(0.25°·1.5°) 근처 깜박임은 2라운드 히스테리시스로 줄였지만, 단계가 바뀌는 데 약 2라운드(GPU 6 s, CPU 30~50 s) 늦다.
- **노랑 근거는 로비 광각 기준**: 1.5°·3° 는 f ≈ 0.42 W 와 옆 쌍 겹침이 한 열이라는 -761 관찰에서 정했다. 겹침이 한 열보다 좁은 쌍(-761 C–D 처럼 구석 몰림)은 1.5° 로도 칸 수가 바뀔 수 있다. 노랑은 「-761 판정이 기준 때와 비슷」이지 READY 보장이 아니다(-761 경고는 그대로 보인다).
- **같은 보정의 렌즈를 쓴다**: 카메라를 바꿔 끼우거나 줌을 바꾸면 K 가 달라 각도가 틀린다(대개 STREAM_MISMATCH·NOT_ROTATION 으로 드러난다).
- **ALIGNED 가 Stage A·걷기 확인 합격 보장은 아니다**: 세팅을 다시 하면 새 배경·새 보정이다. 4대 ALIGNED 는 「그 세팅 보정을 재사용해도 같은 방향」이라는 뜻이다.
- **헬퍼 라운드 간격**: GPU 약 3 s, CPU 16~24 s 마다 갱신이라 CPU 모드에서는 돌린 뒤 결과가 늦게 보인다.
- 기준 맵을 뷰어에서 다른 사람이 지금 보고 있으면 같은 질의 키를 나눠 쓴다(같은 주소라 문제는 없다).
