# S15P31A101-660 알림 규칙·카메라 표시 이름

## 범위와 근거

- `.agy/inst.md`의 Owner 지시를 적용한다. 관련 명세는 §7.2 규칙 목록·§7.3 알림 채널, §8.1·8.3 관제·TBM·§8.4 폐기된 Web Push다.
- 명세의 기존 R1·R2·R3·R5·R6·R7·R9·R11 제목과 이번 표시 이름은 다르다. 사용자 지시의 표시 이름을 적용하며 규칙 의미·ID·버전·등급·발생·해소·알림 채널은 바꾸지 않는다. R8 `장비 근접`, R10 `불확실 점유 근접`은 §7.2 그대로다.
- 사람 표시와 `contracts/`는 변경하지 않는다. `server/CONVENTION.md`는 이 체크아웃에 없다.

## 사전과 연결

- 프런트: `front/apps/admin/src/lib/ruleNames.ts`. 이벤트 카드·배너·상세·이력은 기존 이벤트 포맷 입구를 통해 쓴다. TBM 평가 문장·등급, 세팅 권장 등급, 구역 편집 등급, 워치 격상 안내도 같은 사전을 쓴다.
- 서버: `domain/rule/RuleCatalog.java`, `SeverityNames.java`. 규칙 조회·TBM 종료 미팅 대체 문장·자동 워치 알림을 연결한다. 수동 워치 문구는 운영자가 입력한 내용을 유지한다. `NotificationQueue`는 호출자가 주는 summary를 저장하는 큐이며 현재 Web Push는 폐기되어 별도 규칙 이름 사전이나 생성기를 추가하지 않는다.
- AI: `ai/src/simai_ai/risk/names.py`. 현장 경보 summary·종료 미팅·TBM 양식 태그·TBM/일일 일지 프롬프트에서 함께 쓴다. risk가 report를 참조하지 않도록 표준 라이브러리만 쓰는 risk 하위에 둔다.
- 현장 단말: `gateway/site_alert/.../display.py`는 수신 summary를 그대로 사용하고 등급을 위험·경고·주의·안내로 표시한다.
- 워치 I4 `word`는 앞뒤 공백 없이 8자까지다. 이를 넘는 R2·R6·R10만 서버 사전의 `watchWord`에서 `추락 위험`·`시야 끊김`·`점유 근접`으로 줄인다. 계약을 늘려 전체 이름을 보내는 대안은 채택하지 않았다.

## 카메라 번호

- 매핑은 `lib/cameraNames.ts`, 화면 훅은 `hooks/useCameraNames.ts`다. 기존 세팅 coverage 목록 순서가 최우선이다. 아직 세팅 목록을 받지 않았다면 중계 hello의 설정 순서, 마지막 health의 전체 카메라 순서, 전체 보정 카메라 ID 정렬 순으로 사용한다. 그마저 없으면 제공된 기록 목록의 ID 정렬을 쓴다.
- 선택·장애로 현재 보이는 항목만 다시 번호 매기지 않는다. 세션 시작·초기화 때 이전 현장 목록을 비운다. ID를 모르면 번호를 지어내지 않고 `카메라`로 표시한다.
- CCTV 본 화면·모의 화면·떠 있는 창·분할 탭·상태 칸, 3D 마커, 세팅의 카메라·쌍 이름, 이벤트 클립, 작업 다시 보기 영상에 적용한다. 원래 ID는 영상 연결·API·선택 키로 유지하고 표시 이름 옆 title 및 상세 진단에서 확인한다.
- 상태 전용 헬퍼 `features/system/health.ts`의 id는 화면 렌더링이 아닌 내부 식별자다. 이 헬퍼를 쓰는 실제 상태 패널은 현재 src에 없다. 현재 카메라 상태 표시인 CCTV StateTile에 공통 이름을 적용했다.

## 검증과 남은 위험

- 시험 결과·명령·Lead 실행 목록은 `.agy/notes.md`에 기록한다. 번호 시험은 설정 순서 우선, 부분 목록·연결 종료 후 유지, ID 정렬 대체, 새 세션 초기화를 검사한다.
- Spring/DB 통합시험은 Lead 실행이 필요하다. 독립 Java 사전 컴파일·11개 워치 문구의 길이는 로컬에서 확인한다.
- 이전 보고서·저장된 알림 문장은 소급 변경하지 않는다. 생성형 TBM 본문의 용어는 공통 사전을 프롬프트에 제공하지만 실 LLM 출력까지 이번 로컬 시험으로 보장하지는 않는다.
- 과거 현장의 전체 카메라 목록·순서가 전혀 없는 기록은 당시 번호를 복구할 근거가 없다. 현재 가능한 ID 정렬 대체를 사용하며 과거 번호의 영구 보존이 필요하면 별도 계약·기록 설계가 필요하다. 이번 계약 변경은 없다.
- 긴 한국어 카메라 쌍 이름의 실제 브라우저 배치와 워치 원형 화면의 줄바꿈은 기기 확인이 남는다.
