# EC2 워치 ↔ 사람 움직임 대조 배정

S15P31A101-340. 명세 부록 C.6(움직임 대조·헝가리안 1:1·채널 상태), FR-43(워치-사람 연결: 기본층 걸음 시점, 강화층 3D 손목 가속도),
FR-44(BOUND·UNBOUND·LOST), 11.2(`channel_state`·`watch_feature`), 11.3(`watch_binding`). 계약 I4 `gait_features` 1.0.0(-334, 워치 쪽 -339),
I1 `world_state`(트랙 `velocity`·`pelvis_xyz`·`skeleton`·`identity_revision`·`aliases`·`split_from`). 수동 배정·발송은
[`server-watch-alert.md`](server-watch-alert.md)(-338), 연결은 [`server-watch-link.md`](server-watch-link.md)(-336).

**실험 성격이다.** 목표(올바른 연결 시간 비율 95%, ID 전환 뒤 회복 10초)는 3명 동시 녹화로 재야 하고, 이 이슈는 흉내 낸 신호로만 확인했다(아래 "남은 일").

- 코드: `server/.../domain/watch/` — `WatchMotionMatcher`(입력·점수표·배정·채널 상태), `MotionMatch`(대역 통과·2차 차분·밀어 본 상관·헝가리안),
  `GaitFeaturesReceived`(WatchHub 가 계약 검사 뒤 냄), `WatchBindings.bindByMotion`·`unbindMotion`
- 표: V39 `watch_feature`·`channel_state`(hypertable), `watch_binding.unbind_reason` 에 `MATCH_LOST`·`IDENTITY_CHANGED`
- 시험: `MotionMatchTest`(계산), `WatchMotionMatchIntegrationTest`(세 사람·세 워치)

## 흐름

1. **World 쪽**: `world_state`(10 Hz)를 저장한 뒤 나오는 `WorldStateStored` 마다 트랙별로 손목(COCO17·HALPE26 의 9·10번)·골반 높이(Z)와
   수평 속력을 20초 쌓는다. 손목은 삼각측량(`joint_source` observed)이고 `validity` 가 VALID·UNCERTAIN 인 것만 쓴다.
2. **워치 쪽**: `gait_features`(4초 창, 2초마다)를 계약 검사한 뒤 `watch_feature` 에 남기고 창으로 쌓는다. 창 시각은
   `clock_offset_ms`(워치 − EC2)로 EC2 시각으로 바꾼다. 모르면 받은 시각을 창 끝으로 본다.
3. **창 점수**(2초마다, 트랙 표본이 창 끝을 덮으면): 트랙마다 −1~1.
   - 워치가 걷는 중(최대 주파수 있음, RMS ≥ 0.8): 워치 0.5~3 Hz 크기 신호와 트랙 연직 가속도(높이의 2차 차분을 같은 대역으로 거름)의
     상관, ±0.5초 밀어 본 최댓값. 손목 둘과 골반(0.8 배) 중 가장 높은 값(강화층).
   - 비교할 관절이 없으면 걷기 일치(속력 ≥ 0.3 m/s) +0.2, 불일치 −0.5(기본층).
   - 워치가 멈춰 있으면(최대 주파수 없음) 트랙이 걸을 때만 −0.5. 서 있는 사람끼리는 구분할 근거가 없어 점수를 내지 않는다.
4. **점수표**: 워치 × World ID 누적 점수 S ← 0.7·S + 창 점수(약 7초를 기억). 이번 창에 근거를 못 낸 칸(서 있음·가림·손에 들고 만짐)은
   줄이지 않고 그대로 둔다. 반대 근거가 아니기 때문이다. 같은 창을 다시 받으면(재전송) 넣지 않는다.
5. **배정**: 연결된 워치(수동 배정 없음) × 최근 3초 안에 보인 트랙(수동 배정 없음, ID 교정 직후 아님)으로 헝가리안 1:1.
   뽑힌 짝은 S ≥ 1.2 이고 같은 행·열의 경쟁 짝보다 0.4 이상 앞설 때만 `MOTION_MATCH` 로 잇는다(`score` = S / 3.33).
   이미 이은 짝은 같은 짝이 다시 뽑히거나, 경쟁 짝이 없고 S ≥ 0.6(또는 아직 그 짝의 점수가 없음)이면 둔다. 아니면 `MATCH_LOST` 로 푼다.
6. **ID 교정**: `identity_revision` 이 오르거나(분할도 보통 이것으로 잡힌다), `aliases` 에 아는 ID 가 오거나(병합), 처음 보는 ID 에 `split_from` 이 있으면(보강)
   그 World ID 의 점수와 대조 배정을 지우고(`IDENTITY_CHANGED`) 3초 동안 잇지 않는다.
7. **채널 상태**: 보이는 World ID(10초 안)마다 BOUND(배정·워치 연결)·LOST(배정·워치 끊김)·UNBOUND(그 밖)를 매기고, 바뀐 때만
   `channel_state` 에 한 행. 사라진 ID(10초 넘게 안 보임·병합)는 UNBOUND 행으로 마감한다. 두 표는 30일 보존.

## 명세가 비워 둔 곳에서 정한 것

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 비교 신호 | 워치 `band_magnitude`(\|a\| 대역 통과) ↔ 트랙 손목·골반 **연직** 가속도 | 걸을 때 a ≪ g 라 \|g + a\| − g ≈ 연직 성분. 수평 성분까지 크기를 내면 중력 방향을 모르는 워치 값과 맞지 않는다 |
| 대역 통과 | 2초 이동 평균을 빼고 [¼, ½, ¼] 평활(10 Hz) | 0.5 Hz 아래(자세)·3 Hz 위(관절 떨림)를 줄이는 가벼운 근사. 상관은 크기에 무관 |
| 시간 맞춤 | ±0.5초(5 표본) 밀어 본 최댓값 | 워치 시계 차이 추정 오차·Tier 0 관측 지연·하트비트 왕복 |
| 관절 | 손목 둘(COCO17·HALPE26 9·10), 골반은 0.8 배 | 손목이 C.6 강화층. 골반은 걸음마다 오르내려 손목이 가려도 리듬을 준다. HMR 추정(inferred)은 꾸민 움직임이라 쓰지 않는다 |
| 걷는 창 | 워치: 최대 주파수 있고 RMS ≥ 0.8. 트랙: 속력 ≥ 0.3 m/s | -339 실기기(걷는 창 RMS ≥ 0.8). 손에 들고 만지는 창(RMS 0.2~0.8)은 근거로 쓰지 않는다 |
| 누적 | 감쇠 0.7(창 2초 → 약 7초) | C.6 "몇 초 창의 점수표". 길면 ID 전환 뒤 회복(10초 목표)이 늦다 |
| 잇는 문턱 | S ≥ 1.2, 경쟁 짝보다 0.4 앞섬 | 상관 0.7 이 세 창(약 6초) 이어지면 넘는다. 리듬이 같은 두 사람은 구별할 수 없어 잇지 않는다 |
| 유지 문턱 | S ≥ 0.6 이고 경쟁 없음. 그 짝의 점수가 아직 없으면(서버 재시작 직후) 트랙이 보이는 동안 둔다 | 문턱 근처에서 배정이 깜빡이지 않게. 재시작마다 모두 UNBOUND 가 되지 않게 |
| ID 교정 | 점수·대조 배정 지움, 3초 잇지 않음 | C.6 "ID 병합/분열 의심은 UNBOUND". 3초 + 다시 쌓는 6초 ≈ 회복 10초 목표 안 |
| 수동 배정 | 관리자 `MANUAL` 이 걸린 워치·World ID 는 대조가 건드리지 않음(덮어쓰기) | 이슈 '수동은 관리자 덮어쓰기로만 남길지 결정': 시연·오판 바로잡기에 남긴다. 풀면 대조가 다시 맡는다 |
| 트랙 사라짐 | 3초 안 보이면 배정 후보에서 빠지고, 10초 안 보이면 대조 배정을 푼다(`MATCH_LOST`) | 잠깐 가려진 사람의 배정을 바로 풀지 않는다 |
| 채널 상태 기록 | 바뀐 때만 한 행, 확신도 = 배정 `score` | 10 Hz 마다 쓰면 hypertable 이 커진다. -342 화면은 최신 행을 읽는다 |
| '지금' | 마지막으로 받은 `world_state` 의 `t_latest_global`. 벽시계보다 10분 넘게 앞선 것은 버림 | 워치 창·트랙 표본이 같은 World 시각 축에 있어야 비교할 수 있다. Tier 0 와 EC2 시계는 같은 UTC(NTP)라고 본다. 최댓값으로 두면 잘못된 시각 하나에 '지금'이 묶여 대조가 멈춘다(전체 빌드에서 다른 시험의 시각으로 겪음) |
| 스레드 | 입력·대조·DB 쓰기 모두 `watch-match` 한 스레드. 쌓인 world_state 가 50개(5초)를 넘으면 새 것을 버린다. 작업 예외는 잡아 로그를 남기고 주기는 계속 돈다 | I1 수신 스레드와 워치 WebSocket 스레드를 붙잡지 않고, 점수표에 잠금이 필요 없다. 예외 하나로 주기 작업이 조용히 멈추지 않게 |
| 받는 창 | 창 끝 > 시작, 길이 10초 이하만. 트랙 표본이 창 끝을 덮을 때까지 기다리되 벽시계로 창 끝 + 5초가 지나면 있는 표본으로 낸다 | 스키마가 막지 않는 값(-339 스키마 밖 규칙). 긴 창은 배열 할당으로 스레드를 멈출 수 있다 |

## 시험

- `MotionMatchTest`: 헝가리안(탐욕과 다른 최적, 직사각형 양쪽, 빈 행렬), 밀어 본 상관(0.3초 시차 흡수, 다른 주기는 낮음, 평평·겹침 부족 NaN),
  대역 통과(상수 → 0), 2차 차분(t² → 2, NaN 이웃)
- `WatchMotionMatchIntegrationTest`(실제 포트 WebSocket 시험 워치 셋, 계약 `gait_features`):
  - 걸음 주기 1.6·1.9·2.2 Hz 세 사람 → 세 워치가 맞는 사람에게 `MOTION_MATCH`, `channel_state` BOUND, `watch_feature` 21행
  - 그 뒤 0번 사람 `identity_revision` 증가 → `IDENTITY_CHANGED` 로 풀리고 UNBOUND, 나머지 둘은 그대로
  - 수동 배정(0번 워치 → 1번 사람, 틀린 짝)은 대조가 바꾸지 않고, 그 사람에게 맞는 1번 워치도 잇지 않으며, 2번은 이어진다
  - 서 있는 워치(최대 주파수 없음)는 잇지 않고 UNBOUND
- 시험을 쓰다 본 것: 앞 시험의 같은 리듬 사람이 같은 World 시각에 남아 있으면 점수가 거의 같아(2.93 대 2.84) 차이 문턱에 걸려 잇지 않았다.
  구별할 수 없는 두 사람을 잇지 않는 의도대로다. 시험은 시험마다 World 시각을 60초씩 띄운다.

## 남은 일

- **판정 기록(이슈 완료 조건)**: 3명 동시 녹화(워치 3대 + Tier 0 world_state)로 올바른 연결 시간 비율·ID 전환 뒤 회복 시간을 재고
  채택/보류/기각을 적는다(목표 95%·10초). 지금 문턱(1.2·0.4·0.7)은 흉내 낸 신호로 정한 초깃값이다.
- 실제 Tier 0 손목 관절의 유효 비율과 잡음: 가림이 잦으면 골반·기본층에 기대게 된다. 녹화로 확인.
- 걸음 시점(`step_times_ms`)·시작/멈춤(`motion_transitions`)을 트랙 쪽 시점과 직접 맞추는 기본층은 넣지 않았다. 지금 기본층은 걷기 일치만 본다.
  녹화에서 강화층이 모자라면 더한다.
- 관제 화면의 대조·수동 구분 표시와 채널 상태 아이콘은 -342.
- 리뷰에서 남긴 것:
  - 창 점수가 상관 최댓값(신호 3개 × 시차 11개)이라 무관한 두 걷는 사람도 0.6~0.8 이 나올 수 있다. 녹화로 무관한 짝의 점수 분포를 재고 문턱(1.2·0.4)을 정한다.
  - world_state 가 멈추면 '지금'이 멈춰 상태가 마지막 값(BOUND 등)으로 굳는다. Tier 0 끊김은 System Health 가 따로 알린다.
  - 수동 배정 API 와 대조가 같은 워치를 거의 같은 순간에 잇으면 관리자 쪽이 409 를 받는다(다시 누르면 된다).
  - 서버 재시작 동안 일어난 병합·분할은 놓친다(Tier 0 재시작이면 ID 가 모두 새로 나와 영향이 작다). 병합·분할된 ID 의 수동 배정은 관리자 몫이라 그대로 둔다.
  - 10초 넘게 가려진 사람은 대조 배정이 풀린다(같은 ID 로 다시 보이면 근거를 다시 쌓는다).
- `gait_features` 의 시계 차이(`clock_offset_ms`)로 워치 ACK 시각을 EC2 시각으로 바꿔 진동 지연을 재는 것은 -341.
