## 근거로 쓴 값(서버가 이미 준다)

- 미확인 경보: 관제와 같은 이벤트 목록 캐시(`useLiveEvents`: REST 목록 + `/topic/events`)의 `acks`·`lifecycle`·`severity`·`delivery`. 실제 알림(LIVE)의 HIGH 이상, 감사 전용(AUDIT_ONLY)은 뺀다. 작업 시작 시각 이후, 종료 뒤 요약은 마지막 실행의 종료 시각까지.
  - 열려 있는 경보: 지금 경보 단계에서 확인한 사람이 없으면 미확인(`acknowledgedAt`, 등급이 오르거나 재개돼 새 단계가 열리면 앞선 확인은 세지 않는다).
  - 해소된 경보: 확인한 기록이 한 번도 없으면 미확인. 해소된 이벤트는 확인할 수 없어(`EVENT_RESOLVED`) 종료 확인 창의 수(`open`)에는 넣지 않고 종료 뒤 요약(`unconfirmed`)에만 넣는다. 종료 확인 창의 수는 「종료하면 확인하지 못한 채 닫히는 것」이다(`WORK_ENDED` 마감, -722).
- 꺼진 이유: 보고서의 `status`(AI 초안)·`wrap_up_status`(종료 미팅). 서버는 둘 중 하나가 GENERATING 이면 제출을 409 로 거절한다.
- GPU 켜짐: `GET /api/gpu/sessions/current` 의 `launch`·`session` → 기존 `isGpuOn`. 관리자만 받는다.
- TBM 작성 시각: 첫 작성 저장 때의 브라우저 시계. 서버는 빈 양식을 만들 때 `info.date_time_ms` 를 그 시각(작업 생성)으로 넣고(`TbmForm.blank`) 이후 덮지 않는다.

## 명세에 없어 정한 수치·규칙

- 아래 여백 128px: 하단 메뉴 위쪽 끝 84px(높이 70 + 바닥 14) + 본문 아래 여백 14px 를 빼고 50px 여유. 화면을 직접 띄워 겹침을 재현하지는 못했다(아래 한계).
- 「꺼진 이유」 글 최대 폭 320px(넘으면 줄임표, 마우스를 올리면 전체).
- TBM 일시를 「작업내용을 처음 고르는 저장」으로 정한 것: 사람이 TBM 을 쓰는 첫 행동이 작업내용 고르기뿐이기 때문이다(나머지는 초안이 채운다).

## 버린 대안

- 종료 확인 창에서 열린 미확인 경보가 있으면 종료 단추를 막기: 「뒤늦게 막지 않기」와 어긋나고, 종료를 못 해 요금이 계속 나가는 쪽이 더 나쁘다. 알리기만 한다.
- 확인 창에 「관제에서 확인」 단추(라우터 이동): 작업 종료 단계 시험이 라우터 없이 도는 구조이고, 취소 뒤 하단 메뉴로 관제에 가는 길이 이미 있다. 문구로만 안내했다.
- 종료 뒤 GPU 를 자동으로 끄기: 한 번 더 실행·다른 사람의 사용 여부를 화면이 모른다. 요금이 멈추는 이유와 끄는 단추만 준다(GPU 표시=실제).
- TBM 일시 문제를 서버(`TbmForm.blank`)에서 고치기: 정답에 가깝지만 서버·계약 변경이고 이 티켓은 front 몫이다. front 에서 저장 시점에 바꾸고, 서버 고침은 아래 「넘긴 일」에 둔다.
- 세팅 실패 카드의 GPU 판단을 카드 안에서 하기(`useGpuStatus` 직접 호출): 카드 시험이 QueryClient 없이 돈다. 판단은 `SetupPage` 가 하고 카드에는 `onTurnOnGpu` 만 넘긴다.
- 하단 메뉴를 본문 높이에 포함(`dockOverlay` 끄기)해 겹침을 없애기: /cctv·/work 가 같이 쓰는 레이아웃 약속(한 화면에 넣기)을 깨고 -735 와 겹친다.

## 한계·잔여 위험

- 이벤트 목록은 관제 캐시라 해소된 이벤트는 최근 50건(`MAX_RESOLVED`)만 남는다. 종료 뒤 요약의 「위험 경보 n건」은 작업 중 경보가 아주 많으면 적게 보일 수 있다. 서버가 작업별 경보 수를 주면 그 값으로 바꾼다.
- 경보 수는 이벤트(카드) 단위다. -731 이 같은 위험을 한 카드(n회)로 묶으면 관제 화면의 수와 달라질 수 있어, 그 정의가 정해지면 `alarmCountsOf` 를 맞춘다.
- TBM 일시: 이미 작업내용을 고른 옛 보고서는 서버가 넣은 작업 생성 시각이 그대로 남는다(다시 저장해도 안 바뀜).
- 아래 여백은 jsdom 시험이 겹침을 재지 못해 시험하지 않았고(클래스 값만), 실제 겹침 해소는 화면으로 확인해야 한다.
