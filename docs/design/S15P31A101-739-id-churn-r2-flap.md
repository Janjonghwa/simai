# S15P31A101-739 같은 사람 R2 반복 발생과 World ID 중복 (18차 재생)

18차 GPU 세션(2026-11-15, H100, 14차 녹화를 사이드카 촬영 시각으로 재생, -721 적용 뒤)에서 사람 2~3명인데 R2(CRITICAL)가
첫 구간에서는 같은 ID 로 RESOLVED → RAISED 를 반복하고, 혼잡 구간에서는 분당 3건꼴로 매번 다른 World ID 로 열렸다. 로그와 EC2 DB 로
원인을 (a) World ID 가 새로 생기는 경로와 (b) 같은 사람 재발생으로 나누고, 위치 정본을 덮지 않고(규칙 1) 모르면 비우는(규칙 2)
범위에서 둘 다 줄였다. R2 의 등급·발생 조건·해소 조건은 바꾸지 않았다.

자료(저장소 밖, 읽기만): 2번째 Pod `tier0.log`(추적 계측 30s, ID 교정, R4 진단), EC2 DB `risk_event`·`risk_event_update`·
`world_track_state`(10 Hz 트랙 상태: 관측 상태·생명주기·접지점·z_validity·카메라)·`skeleton_3d`(관절 XYZ·유효성)·`config_bundle_file`
(cfg-78 작업면), `timeline.txt`. 분석·재생 스크립트는 저장소에 넣지 않았다. 영상은 열지 않았다.

**Re-ID 는 꺼져 있었다.** 17·18차 모두 `tier0.log` 첫머리 "Re-ID 비활성화(기존 기하 추적으로 동작): FileNotFoundError: COPE 외부

### (b) 같은 사람 재발생: 바닥 접지 유지가 한 시각 발목 오차로 끊긴다

`world_track_state` 로 R2 발생 순간의 상태를 보면 첫 구간 17건 모두 CONFIRMED·OBSERVED·접지점 없음(Z_UNKNOWN)이고, 골반 높이는
0.73~0.85 m(멀리 있는 바닥 보행자 0.86 m 와 같음, 단상 위 사람은 1.17~1.20 m)다. **바닥 위 사람**이다. 단상(0.40 m 작업면) footprint
0.5 m 안에서는 track-tick 의 95 %(613/643), 1 m 안 86 %가 접지 모름이었다(멀리서도 45 %).

`skeleton_3d` 의 VALID 디딤발(낮은 발목) 높이는 바닥 보행자 기준 중앙 0.091 m(가정 0.08 m 와 맞음)지만 퍼짐이 커서 p10 0.017 m,
p90 0.169 m 이고 **12 %가 0.02 m 미만**(바닥 띠 0.08 ± (0.04 + 2σz) 의 아래쪽)이다. ContactEstimator 는 유지 중인 표면보다 디딤발이
낮으면 '표면을 떠났다'(HOLD_CONTRADICTED)로 유지를 끊는다. 단상 위 사람이 내려올 때를 위한 규칙인데 바닥에도 똑같이 걸려, 1초에
한 번꼴로 바닥 유지가 끊겼다. 다시 잡으려면 접촉 확인 2번(디딤발 정지 또는 두 발목 같은 띠)이 이어져야 하는데 걷는 동안·단상에
발이 가려진 동안은 드물어 접지 모름이 길게 이어졌고, 그동안 7.2 정책대로 범위가 단상 footprint 에 걸치면 R2·R3 가 열렸다. 접지점이
다시 잡히면 판정이 끊겨 3 s 뒤 해소, 다음 끊김이 10 s 넘게 뒤면 새 이벤트다(재발생 간격 10.6~26 s).

`world_track_state` + `skeleton_3d` 를 지금 ContactEstimator 에 그대로 다시 넣는 재생(관절 σz 는 DB 에 없어 0.005/0.01/0.02 m 로
가정)으로 확인했다. 재생의 접지 판정은 녹화와 맞고(단상 1 m 안 접지 모름 81 % vs 녹화 86 %, σz 0.01), 같은 근사 lifecycle(R2 발생
범위·3프레임 중 2·3 s 해소·10 s 재개)로 센 R2 발생 시각은 혼잡 구간에서 DB 와 거의 일치한다(0058 18:08, 0060 18:13, 0035 18:04 등).
재생에서 끊김 사유는 HOLD_CONTRADICTED 가 대부분이고 HOLD_EXPIRED·IDENTITY_REVISED 는 작다.

### (a) 새 ID: 2+2 시점 분할이 1초 넘게 이어지면 소유 이력 창이 지나 새 ID

- 첫 구간 새 ID 30개(분당 3.0, 그중 병합 흡수 12), 혼잡 43개(분당 4.3, 흡수 32). 분리 끔도 32·40개(흡수 10·30).
- 혼잡의 중복 ID 는 한 사람(단상 위, 골반 1.2 m)을 카메라 묶음 {C,D} 와 {A,B} 가 따로 본 2+2 분할이다(예: 0035 cam_C·D, 0058 cam_A·B,
  골반 0.15 m 차, 2.3 s 뒤 병합). 병합은 대부분 로컬 이력 병합(`revision.merge`)이고 그림자 능동 병합은 적다.
- **병합된 중복 ID 84개 중 46개(55 %)가 생존 Track 이 그 카메라들을 마지막으로 가진 뒤 0.9~1.6 s 에 처음 나타났다(중앙 1.15 s).**
  단상 위 사람(0035·0033)의 중복은 거의 모두 1.00~1.14 s 다. 분할 나머지 억제는 '로컬 키 하나 이상이 최근 1000 ms 안에 그 Track 에
  속했다'를 요구하는데, 억제한 나머지는 소유권을 합치지 않으므로(5.2) 분할이 이어지는 동안 그 키의 소유 시각이 갱신되지 않는다.
  분할이 1 s 를 넘기면 창이 지나 그림자 판정(한 점 재투영 20 px)에 맡겨지고, 두 묶음이 기하로 맞지 않아 갈라진 경우라 그림자도
  통과하지 못해 새 TENTATIVE 가 생긴다. 새 Track 은 접지 이력이 없어 접지 모름이고 단상 범위에 걸치므로 생기자마자(0~170 ms)
  R2·R3(·R1) 가 열렸다. 혼잡 R2 중복 37건 중 29건(78 %)이 이 시각 형태다.
- 나머지(0.9 s 미만 9개, 1.6 s 초과 29개)는 로컬 트래커가 새 로컬 ID 를 낸 경우 등 다른 경로다(이력 근거 없음).
- 단상 위 사람의 두 묶음이 0.15~0.2 m 어긋나는 것 자체는 보정(PROVISIONAL)이 단상 높이에서 덜 맞는 것으로 보인다. 녹화 바닥
  보행자(0047)가 등록 작업면 ws-3f52bd2b footprint 안을 골반 0.8 m 로 지나간 시각이 있어 작업면 등록 위치가 실제 단상과 어긋났을
  가능성도 있다(확인하지 않음, 넘긴 일).

## 수정

| 위치 | 바꾼 것 |
|---|---|
| `ai/src/simai_ai/contact/estimator.py` | 바닥 유지에서 디딤발이 바닥 띠보다 **낮은** 것은 반증으로 보지 않는다(`ANKLE_BELOW_FLOOR_BAND`). 접촉 근거로도 쓰지 않아 유지 시각을 갱신하지 않고 `hold_max_ms`(3 s)는 그대로다. 작업면 유지의 띠 아래(내려옴)·바닥 유지의 띠 위(올라섬)·다른 표면 높이 발목은 지금처럼 그 시각에 끊는다 |
| `ai/src/simai_ai/tracking/world_track.py` | 분할 나머지·시점 분할 그림자로 억제한 클러스터의 로컬 키를 근거 Track 의 억제 이력(`suppressed_keys`, 마지막 억제 시각)으로 남기고, 다음 시각 분할 나머지 판단의 최근 소유 이력에 같은 창(`split_suppression_owner_ttl_ms` 1000 ms)으로 넣는다(`split_suppression_chain`, 기본 켬). 소유권(`keys`)·위치·관절은 합치지 않고, 늦은 재연결·병합 근거·비용 보너스에는 쓰지 않는다. 진짜 주인의 최근 키가 있으면 그쪽이 우선이다. 30초 계측에 `new_track.suppression_chained` 를 더했다 |

새 수치 없음. 바닥 예외는 '바닥보다 낮은 면은 없다'는 기하 사실이고, 억제 이력은 기존 창 1000 ms 를 그대로 쓴다(이력이 1 s 넘게
끊기면 지금처럼 만료).

규칙 대조: 접지점 Z 를 지어내지 않는다(띠 아래 발목은 근거로 쓰지 않고 유지 상한 그대로, 유지는 surface_source inferred·z_validity
UNCERTAIN 이라 R2 는 HELD + PREDICTED 로 본다). Tier 0 위치·ID 정본을 다른 출처로 덮지 않는다(억제는 새 ID 를 안 만드는 것이고 측정은
합치지 않음). R2·R3 의 발생·해소·등급 논리, -725 보류 조건, 6.4 재개 10 s 는 그대로다.

## 버린 대안

- **발목 반증을 2번 이어져야 끊기(연속 반증).** 재생에서 첫 구간 이득은 바닥 예외와 같았고, 0035 가 단상에 올라선 장면에서 첫
  반증 뒤 발목이 가려져(VALID 없음) 두 번째 반증이 오지 않아 바닥 유지가 `hold_max_ms` 까지 남아 **R2 가 1.6 s 늦게** 났다(골반은 0.79 →
  1.19 m 로 올랐지만 확인 때 골반 높이가 없어 골반 반증도 걸리지 않았다). 안전 쪽 손해라 버렸다.
- **골반 높이로 유지 연장.** 골반 0.8 m(바닥)와 1.2 m(단상)로 갈리긴 하지만 5.2 는 접지 근거를 VALID 발목으로 한정한다.
- **재개 창 10 s 늘리기 / R2 해소 늦추기.** 재발생 간격 10.6~26 s 라 효과가 불확실하고 6.4·7.2 수치 변경이다. 원인(접지 끊김)을
  고치면 해소 자체가 정상 관측 해소라 바꿀 이유가 없다.
- **중복 의심 Track 의 R2 새 발생 보류(생존 Track 이 같은 규칙 활성 이벤트를 가질 때).** 혼잡 R2 의 60 %를 막지만 R2 발생 조건을 바꾸는
  일이고 -716 버린 대안·-723 결정 요청 1 과 같은 쟁점(진짜 두 번째 사람)이라 하지 않았다(Lead 결정 요청).
- **분할 나머지 억제 창(1000 ms) 늘리기.** 분할이 멈춘 뒤에도 옛 키를 오래 붙잡아 로컬 ID 전환된 다른 사람을 막을 수 있다. 억제
  이력은 '이어서 억제돼 온' 동안만 창을 이어 가서 끊기면 지금과 같다.
- **새 Track 에 근처 Track 의 접지 이력 물려주기.** 위치만으로 잇는 일이라 5.2 와 부딪힌다.

## 잔여 위험

1. **억제 이력의 누락 위험.** 한 사람의 나머지로 억제돼 온 로컬 키를 로컬 트래커가 0.6 m 안의 다른 사람에게 넘기고, 그 사람이 주인과
   카메라가 하나도 겹치지 않으며 같은 카메라가 둘을 따로 보지 못하면, 이전에는 1 s 뒤 새 ID 가 났지만 이제는 억제가 이어진다. 같은

   그 이벤트는 해소 확인을 하지 않는다(안전 쪽).
2. **바닥 예외는 '바닥 아래 면'이 없다는 전제다.** 개구부(바닥 구멍)·계단 아래는 등록 형식이 없어 원래도 다루지 않는다.
3. 혼잡 (a) 의 나머지 22 %(다른 경로)와 단상 높이에서 두 카메라 묶음이 어긋나는 원인(보정·작업면 등록)은 남는다.
4. σz 를 DB 에서 알 수 없어 재생 수치는 가정 범위(0.005~0.02 m)로 냈다.

## 다음 세션에서 잴 것 (라이브·정렬 재생, Re-ID 켠 상태와 끈 상태 각각)

Re-ID 를 켠 상태로 다시 잰다(S3 GPU 캐시에 COPE 묶음을 올린 뒤 `tier0.log` 첫머리에 Re-ID 비활성화 줄이 없는지 먼저 확인).
비교 기준은 이 문서의 18차 표다.

1. **분당 새 ID**: 30초 줄 `새 ID` 합 / 분, 그중 `ID 교정` 으로 흡수된 수. 18차 첫 구간 3.0·혼잡 4.3(흡수 12·32).
2. **R2 재발생 수**: 창마다 R2 RAISED 를 (a) `IDENTITY_MERGED` 흡수, (b) 같은 ID 재발생, 첫 발생, 재개로 나눈 표(위 SQL 분류). 18차 첫
   구간 (b) 13건·재개 10, 혼잡 (a) 20·17건.
3. 30초 줄 `new_track.suppression_chained`·`split_remainder_suppressed`·`suppressed_disjoint_shadow`·`new_track.created`, 그리고 병합
   중복 ID 의 '생존 Track 이 카메라를 잃은 뒤 첫 관측까지' 분포(0.9~1.6 s 몰림이 사라졌는지).
4. 단상 1 m 안 track-tick 의 접지 모름 비율(`world_track_state` 접지점 없음), R4 진단 `height_unknown` 비율. 18차 86 %·약 14 %.
5. 실제 단상 장면: 올라선 시각 → R2·R3 RAISED 지연(이번 변경으로 늘지 않아야 함).
