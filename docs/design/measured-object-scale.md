# 실측 정물 목록과 노트북 윗판 축척 근거 설계

S15P31A101-100(1단계: 목록 + 노트북 윗판). 기획서 §4.3(스케일 근거 우선순위: 실측 정물 1순위, 2단계 좌표계 고정), §4.4(CALIBRATED 스케일 주 근거), §20.4(출처·상한) 기준이다.
코드는 `ai/src/simai_ai/calibration/world_frame/measured_objects.py`(목록·검출·재기·묶기), 실행 도구는 `world_frame.cli measure-objects`, 목록 파일은 `ai/src/simai_ai/calibration/data/measured_objects.json`, 시험은 `ai/tests/calibration/world_frame/test_measured_objects.py` 에 있다.
World 고정·축척 선택(`choose_scale`)은 `docs/design/world-frame-from-mapanything.md`(-102·-277)를 그대로 쓴다. 이 티켓은 그 `fix --scale-evidence` 에 넣을 MEASURED_OBJECT 근거를 만든다.

## 왜

-277 로 새 교실 w1 이 입력 없이 World 고정(WALL_AND_FLOOR)되지만 축척은 MODEL_ESTIMATE(1.0)다. 임시 카메라 높이 2.70 m 로 넣으면 1.317(모델 단위가 약 24% 작음, 추정)이라 근거가 필요하다. 라바콘·안전봉은 배송 중이고, 사용자가 팀 노트북 윗판(덮개 판 전체, 액정 아님)을 실측했다: **가로 35.5 cm × 세로 25.5 cm**(2026-10-23, Jira -100 댓글). 팀 노트북은 같은 기종이라 교실 여러 곳·카메라 4대에 동시에 보인다. 작아서 단독 근거로는 약하다(댓글, 라바콘과 함께 쓴다).

## 흐름

| 단계 | 도구 | 출력 |
|---|---|---|
| 1 | `world_frame.cli measure-objects --run-dir <MapAnything 결과> --prepared <같은 입력 폴더> --weights-dir <가중치 폴더> [--catalog <목록>] [--object <id>] [--debug-dir <진단 그림 폴더>] --out <근거.json>` (extras calibration·detection) | `simai.scale_evidence` 0.1.0: `estimates`(근거를 냈을 때만), 정물별 검출·측정(두 방법)·버림 사유별 개수·묶음·삼각측량·이 배율로 본 카메라 높이 |
| 2 | `world_frame.cli fix … --scale-evidence <근거.json>` | `simai.world_alignment`(스케일 근거 MEASURED_OBJECT 또는 다음 근거) |

- 근거 파일은 `{"estimates": [{"basis": "MEASURED_OBJECT", "scale", "sample_count", "label": 정물 id}], "input_provenance", "cameras_json_sha256", …}` 다. 배율 = 목록 길이 / MapAnything 길이라 그 MapAnything 실행에서만 뜻이 있다. `fix` 는 근거 파일의 `cameras_json_sha256` 이 이번 실행과 다르면 입력 오류(종료 2)로 거절한다(이 필드가 없는 예전 근거 파일은 그대로 받는다).
- `input_provenance` 는 입력 폴더(`prepared.json`)의 출처(교실 사진 FILE)를 그대로 싣는다. `fix` 가 다른 입력과 같은 규칙으로 합친다(SIM 이면 결과 상한).
- 근거를 못 내면 `estimates` 가 비고 사유가 `objects[].reason` 에 남는다(종료 3). 그 파일을 `fix` 에 넣어도 근거 없이 다음 우선순위(카메라 높이 실측, 없으면 MODEL_ESTIMATE)로 간다.
- `--debug-dir` 는 카메라마다 `det_<정물>_<카메라>.jpg`(검출 윤곽: 채택 초록·버림 빨강, 번호·배율 또는 버림 사유·점구름 방법 결과, 원본 윗변 끝점)를 쓴다. 사람이 찍힌 그림이라 커밋하지 않는 곳에 둔다.
- 기본 출력은 `ai/experiments/recordings/world-frame/scale-evidence-<UTC>.json`(.gitignore), 있으면 덮어쓰지 않는다.
- **입력 폴더만 바꿔 다시 돌리기.** 입력은 `prepare` 출력 폴더 형식(`simai.mapanything_inputs`) 그대로다. 빈 교실 사진(사람 없음)으로 `prepare` → GPU 세션 MapAnything(`--mode prepared`) → 같은 두 명령을 돌리면 된다(사람 마스크가 비어도 동작).

## 목록 파일 (`simai.measured_objects` 0.1.0)

**위치.** 패키지 데이터 `ai/src/simai_ai/calibration/data/measured_objects.json`. 실행 도구가 기본으로 읽고 설치 패키지(uv_build)에 함께 들어간다(선례 `simai_ai/rag/data/*.json`). `docs/data/` 는 공개 데이터·녹화의 출처·라이선스·해시 manifest 자리라 코드가 읽는 설정과 맞지 않고, `ai/config/` 는 없다. 3단계 번들 조정의 정물 제약(명세 4.3)도 같은 목록을 읽게 `world_frame` 밖 `calibration/data/` 에 둔다. 다른 목록은 `--catalog` 로 준다.

| 필드 | 뜻 |
|---|---|
| `id` | 정물 식별자. 근거의 `label`(정물 하나 = 근거 하나) |
| `name`, `dimensions_m` | 이름, 치수(m, 기록용) |
| `edges[]` | 기준으로 쓰는 변: `name`, `length_m`(0 < x ≤ 10), `condition`(쓰는 조건) |
| `measured` | `date`·`by`·`method`(필수), `source` |
| `detector` | 찾는 방법. `kind` 가 `DETECTORS` 에 있어야 한다. 노트북: `ULTRALYTICS_SEG`, `yolo26x-seg.pt`(sha256 확인), COCO `classes [63]`(laptop), `conf 0.5`, `imgsz 1280` |
| `measurement` | 재는 방법. `kind` 가 `MEASURERS` 에 있어야 한다. 노트북: `LAPTOP_LID`, `open_edge`, `closed_edges [긴 변, 짧은 변]`, `length_method`(근거로 낼 방법, 기본 `IMAGE_EDGE`), 그리고 `LidConfig` 키로 아래 한도를 정물별로 바꿀 수 있다(모르는 키는 거절) |
| `aggregation` | `min_samples`(독립 표본 하한), `agreement_tolerance`(표본이 중앙값에서 벗어날 수 있는 비율, 0 < x < 0.5), `max_outlier_fraction`(뺄 수 있는 표본 비율, 0 ≤ x < 0.5) |
| `pending[]`, `cross_checks[]` | 아직 없는 정물(라바콘·안전봉 배송 중), 기록만 하는 교차 확인 값(노트북–가장 가까운 카메라 거치대 수평 160 cm: 어느 노트북인지 자동으로 가리지 못해 이번에는 쓰지 않음) |

`load_catalog`·`parse_catalog` 가 형식을 검사한다(형식 이름, id 겹침, 변 길이, 잰 날짜·사람·방법, detector·measurement kind, closed_edges 순서, length_method, 묶음 값 범위).

## 노트북 윗판 재기 (`LAPTOP_LID`)

**공통 단계(두 방법 모두).**

1. **검출.** 펴진(prepare) 그림(2304×1296)에서 YOLO seg laptop 마스크. 마스크가 그림 경계에 닿으면 버린다(TRUNCATED).
2. **모델 해상도로.** `inputs.mask_to_model_res(…, min_fraction=0.5)`: 사람 마스크와 같은 crop·resize(map-anything `crop_resize_if_necessary`)로 옮기되 덮인 면적 0.5 이상 픽셀만(픽셀 중심이 마스크 안). 그 픽셀의 MapAnything 점을 쓴다. 사람 마스크·신뢰도 하위 10% 거르기는 하지 않는다(사람 마스크 15 px 팽창과 경계 픽셀의 낮은 신뢰도가 덮개 끝을 깎는다).
3. **정리.** 점 30개 미만이면 버림. 점 중앙값에서 0.45(덮개 대각선 0.44 m) 넘게 먼 점은 배경 번짐으로 빼고, 30% 넘게 빠지면 섞인 마스크라 버림(MIXED_SURFACES). 바닥은 `fix_world_frame` 과 같은 점 고르기·난수·`find_floor` 로 찾는다(같은 실행이면 같은 평면).
4. **연/닫힘.** 바닥 기준 높이의 2~98 백분위 폭 ≤ 0.05 → 닫힌 덮개, ≥ 0.10 → 연 덮개, 사이 → 버림(AMBIGUOUS_OPENING).
5. **연 덮개 공통 검사.** 98 백분위 높이에서 0.03 안의 띠(덮개 윗변 근처)를 바닥에 내려 주성분 방향 = 윗변 방향. 띠 끝점(모델 그림에 투영)이 그림 경계 2 px 안이면 TRUNCATED, 끝점 바로 바깥 1~3 px(변 방향, 수직 ±1)에 0.05 넘게 더 가까운 표면이 있으면 END_OCCLUDED(손·컵·앞사람). **바닥 판(자판)**: 높이 폭 아래 1/3 의 점이 윗변과 수직인 수평 방향으로 윗변 길이의 25% 넘게 펼쳐져야 한다(아니면 BASE_NOT_SEEN: 세운 화면만 있는 모니터·덮개 뒷면만 보이는 노트북). **덮개 비율**: 가로(채택한 길이) / 덮개 높이(덮개 평면 2 cm 안 점의 경첩 쪽 2 백분위)가 목록 비(1.392)에서 50% 넘게 벗어나면 NOT_LAPTOP_SHAPE.
6. **닫힌 덮개.** 윗면 띠(98 백분위 − 0.015)만 쓴다. 판 법선과 바닥의 각 > 10° 이거나 평면 rms > 긴 변의 5% 면 NOT_FLAT. 변 방향은 두 축 백분위 폭의 곱이 가장 작은 직교 축(0.5° 간격). 가로/세로 비가 1.392 에서 10% 넘게 벗어나면 ASPECT_MISMATCH. 배율은 두 변 배율의 평균. 점구름 방법만 잰다(아래).

**길이 두 방법(`length_method` 로 근거를 고르고 다른 하나는 비교용으로 함께 기록).**

- **IMAGE_EDGE(기본, 연 덮개만).** 원본(펴진) 그림 마스크의 바깥 윤곽(`cv2.findContours`, 원본 px)을 덮개 평면(띠 높이 위쪽 절반 점의 평면)에 되투영한다(광선 = 원본 px → 모델 px → MapAnything K·자세, 점구름과 같은 규약). 평면 위 (윗변 방향 u, 덮개 위아래 w) 좌표에서 점구름 띠 둘레 ±0.12 안의 윤곽 중 위쪽 끝(w 99 백분위)에서 0.03 안을 첫 후보로 직선을 맞추고, 후보 전체에서 직선 거리 3 px(원본 px 를 그 자리 3D 길이로 바꿈) 안을 다시 골라 맞춘다(띠 방향이 실제 윗변과 조금 틀어져도 윗변 전체를 잡는다). 그중 윤곽 순서로 가장 긴 연속 토막(간격 10 점까지 이음)의 양 끝이 윗변 끝점이고, 길이 = 두 끝의 거리 + 원본 1 px(윤곽 픽셀은 경계 안쪽 픽셀이라 양 끝 반 칸씩). 버림: 광선과 평면의 각 < 10°(IMG_GRAZING), 윤곽 직선 없음(IMG_EDGE_NOT_FOUND), 인라이어 수 / 화면 길이 < 0.6(IMG_EDGE_NOT_STRAIGHT), 화면 길이 < 50 px(IMG_EDGE_TOO_SHORT), 윤곽 길이 < 점구름 띠 길이의 0.85(IMG_EDGE_PARTIAL: 윗변 일부만 잡음), 끝점이 그림 경계 8 px 안(TRUNCATED), **끝점 3 px 안에 사람 마스크(END_ON_PERSON, 덮개 다른 곳이 사람에 가까운 것만으로는 버리지 않는다)**. 사람 마스크는 `prepare` 의 팽창 마스크를 같은 크기(dilate_px)로 깎아 원래 윤곽에 가깝게 되돌려 쓴다.
  - **다시점 삼각측량.** 같은 노트북(아래 묶기)이 두 카메라 이상에서 채택되면 끝점 짝을 덮개 평면 교점의 3D 거리로 맞추고 각 끝점의 광선들을 최소제곱으로 만나게 한다. 끝점과 각 광선의 거리 ≤ 0.03, 광선 사이 각 ≥ 5° 면 그 길이(+ 원본 1 px)를 묶음 값으로 먼저 쓴다(TRIANGULATED, 깊이와 무관하고 카메라 자세만 쓴다). 아니면 한 대 값들의 중앙값(SINGLE_VIEW_MEDIAN)이고 이유(RAYS_DISAGREE·NARROW_ANGLE·NOT_ENOUGH_VIEWS)를 남긴다.
  - 닫힌 덮개는 이 방법으로 재지 않는다(IMG_CLOSED_LID): 비스듬한 카메라에는 판 옆면(두께)이 보여 가까운 쪽 윤곽이 옆면 아래 모서리다. 윗면 평면에 되투영하면 두 변이 두께 × 기울기만큼 길어진다(합성 −5~−8%). 판 두께를 목록에 재 두면 바로잡을 수 있다.
- **POINT_CLOUD(비교용).** 띠 좌표의 α = 2% 백분위 폭 ÷ (1 − 2α) + 끝 픽셀 위상 몫: 변을 가로지르는 줄이 r 개이고 끝 위상이 줄마다 고르게 다르면 가장 바깥 픽셀 중심이 끝에서 평균 1/(r+1) 칸 안쪽이라 양 끝 2/(r+1) 칸을 더한다(r = 점 수 / 화면 길이, 한 칸의 3D 길이 = 길이 / 화면 길이). 점구름 방법만 버리는 사유: 띠 끝점 너머 k·k+1 px(k = 화면 길이 15%, 최소 3)가 아직 노트북 마스크(EDGE_INCOMPLETE: 깊이 번짐으로 띠가 변 일부만 잡음), 띠의 수직 폭(5~95 백분위) > 길이의 25%(EDGE_NOT_STRAIGHT), 화면 길이 < 15 모델 px(EDGE_TOO_SHORT_PX).

**묶기·근거.** 어느 방법이든 배율을 낸 측정을 3D 위치(띠 가운데·판 가운데)로 0.20 안이면 같은 노트북으로 묶는다(단일 연결: 다시점과 한 카메라의 겹친 검출). 방법마다 묶음 값(삼각측량 또는 한 대 값 중앙값) = 독립 표본 하나다. 묶음 값의 중앙값에서 7% 넘게 벗어난 표본은 다른 기종·오검출로 보고 빼되, 뺀 비율이 34% 를 넘거나 남은 표본이 3개 미만이거나 남은 표본끼리 7% 넘게 어긋나면 근거를 내지 않는다(SPREAD·TOO_FEW_SAMPLES). 근거 = 남은 표본 중앙값, `sample_count` = 남은 표본 수. 퍼짐(최대 편차), 견고한 σ(1.4826·MAD), 중앙값 표준오차(1.2533 σ / √n), 방법마다 그 중앙값으로 본 카메라 높이를 기록한다.

## 정한 수치와 근거

명세에 없는 값이다. 길이는 MapAnything 단위(ma, 모델 추정 m), px 는 모델 해상도, 원본 px 는 펴진 그림.

| 값 | 정한 값 | 근거 |
|---|---|---|
| 검출 conf | 0.5 (사람 마스크는 0.25) | 축척 근거에는 놓침보다 오검출(모니터·태블릿)이 해롭다. w1 에서 conf 0.26·0.31·0.44 검출이 모니터·세운 태블릿이었다 |
| 마스크 덮임 | 0.5 | 픽셀 중심 규약과 같아 끝 위상 몫 계산의 전제와 맞는다 |
| 점 하한 30, 띠 점 하한 8 | — | 띠 끝 백분위(2%)가 점 하나 이상을 버리고 직선을 볼 수 있는 최소 |
| 정리 반경 0.45, 뺀 비율 30% | — | 덮개 대각선 0.44 m. 배경 번짐이 이보다 많으면 마스크가 다른 물체와 섞임 |
| 닫힘 ≤ 0.05, 열림 ≥ 0.10 | — | 닫힌 판 두께 1~2 cm + 깊이 잡음. 연 덮개 높이 = 0.255·sin(연 각도): 0.10 은 약 23° 열림 |

### 퍼짐 기준: 기존 2% 대신 정물별 7%

- 기존 `measured_object_agreement` 2%(정물 예상 정확도 약 1%)는 **서로 다른 정물끼리**(라바콘 대 안전봉) 배율 일치 기준이고 `choose_scale`·CALIBRATED 판정이 쓴다. 이 티켓은 바꾸지 않는다.
- 같은 정물(노트북 여러 대) 안의 퍼짐은 측정 한 번의 오차가 정한다. 518 에서 한 대 σ ≈ 2.7%(점구름 하한 15 px)·3.2%(원본 하한 67 px) 이고 표본이 3~10개면 최대 편차가 2σ 를 쉽게 넘으므로 2% 로는 늘 거부된다. 7% ≈ 2.6σ 로 정했다. 표본이 n 개면 근거 오차는 중앙값 표준오차 약 1.25 σ / √n(3개 2%, 8개 1.2%)이다.
- 다른 기종(교실의 다른 노트북, 가로 30~36 cm)은 배율이 1~15% 다르다. 7% 넘게 벗어난 것은 빼되 34%(셋 중 하나)까지만 뺀다. 과반이 다른 기종이면 근거를 내지 않는다. 남은 표본끼리도 7% 안이어야 한다.
- 정물 id 하나가 근거 하나라 노트북 여러 대는 `choose_scale` 에서 정물 하나로 센다. CALIBRATED 주 근거(서로 다른 정물 2개 이상 일치, 4.4)는 노트북만으로 채워지지 않는다(댓글의 "단독 근거로 약함"과 같다). 라바콘이 오면 정물끼리 2% 기준이 노트북 근거와 라바콘 근거를 비교한다.

### 2. 카메라 높이 + 정물 공동 최소제곱 축척·바닥 오프셋 추정

초기 보정 좌표계의 전역 축척 배율 $s$ 와 바닥 $Z$ 영점 오프셋 $\delta z_{\text{floor}}$ 를 다음 선형 최소제곱으로 동시에 푼다:

$$\min_{s,\,\delta z_{\text{floor}}} \sum_{i=1}^{N_{\text{cam}}} w_{\text{cam}}\left(z_i^{(0)} s - \delta z_{\text{floor}} - h_i^{\text{meas}}\right)^2 + \sum_{m \in \mathcal{M}_{\text{prop}}} w_m \left(L_m^{(0)} s - L_m^{\text{ref}}\right)^2$$
