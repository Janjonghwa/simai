# S15P31A101-731 관제 경보 카드 묶음·수 정의·재생 중 표시

17차 UX 점검(2026-11-15, 14차 녹화 재생)에서 관제 화면이 1~2명인데 같은 「추락 위험(가장자리)」 카드가 12장 떴고(트랙 번호가 바뀔 때마다
새 이벤트, 사라진 번호의 이벤트도 해소 근거가 없어 진행 중으로 남음), 같은 시각에 「사건 12건」·「54건」·「경보 96건」이 제각각이었다.
이 티켓은 **기록·이벤트·판정은 그대로 두고 화면만** 고친다(AGENTS 규칙 1·6). 위험 판정·알림 경로는 바꾸지 않는다.

관련 명세: 7.4(이벤트 병합: 한 사람에게 걸린 여러 규칙은 화면에서 한 묶음), 3.10(관제 화면 경보), 13.4(이벤트 패널), 12.4(viewer_health).
관련 설계: -722(EC2 마감), -723(현장 단말 같은 사람 묶음), -724(재생 중 실제 알림 끔). 계약 묶음 v7.59.0(viewer_health 1.6.0). DB 마이그레이션 없음.

## 1. 결정

### 1.1 같은 위험 경보를 한 카드로(화면 묶음)

- 카드의 기본은 지금처럼 **한 사람(World ID)의 묶음**(7.4)이다. 그 위에 **같은 위험(대표 규칙)·같은 구역** 묶음을 시각 순으로 잇는다.
  - 이어 붙이는 조건: 같은 사람이 이미 든 묶음이거나(시각 무관), 앞 묶음의 마지막 갱신에서 `CARD_MERGE_GAP_MS`(60초) 안에 시작했다.
  - 카드는 「N회」(카드 대표 위험의 발생 수, 해소 뒤 재개 포함)를 보이고, 올려 보면 묶은 까닭(트랙 번호 m개)을 알린다.
  - 진행 중 카드는 묶인 진행 중 경보 전부를 칩·점멸·경과에 반영한다(확인 대기 경보가 카드에서 사라지지 않게). 대표 규칙·선택·상세·3D 초점은
    대표 묶음 것이다.
- **실제 두 번째 사람을 숨기지 않는 조건**(필수):
  1. **지금 살아 있는(LOST 가 아닌 트랙, 병합으로 흡수된 이전 ID 포함) 서로 다른 두 사람은 한 카드에 넣지 않는다.** 진행 중이든 해소든 같다.
     카드 대표는 살아 있는 사람이다(없으면 가장 최근에 난 묶음). 살아 있는 사람마다 자기 카드가 하나씩 남는다.
  2. 살아 있는 사람을 모르면(World 를 아직 못 받음) 모두 살아 있는 것으로 보아 **서로 다른 사람은 묶지 않는다**.
  3. 구역 대상(사람 없는) 진행 중 묶음은 묶지 않는다. 위험(규칙)이나 구역이 다르면 묶지 않는다.
  4. 확정 전(TENTATIVE) 트랙도 실제 사람일 수 있어 살아 있는 쪽에 센다.
- 해소 카드(「최근 해소」)도 같은 규칙으로 묶는다(전에는 같은 사람·규칙·구역만). 해소 카드의 두 사람이 과거에 동시에 있었는지는 알 수 없으므로
  지금 둘 다 살아 있을 때만 막는다. 이력 표시일 뿐이고 기록은 작업 관리 다시 보기에 그대로 있다(잔여 위험 1).
- 7.4 와의 관계: 명세의 「같은 사람·같은 규칙은 하나의 이벤트」는 Tier 0 이벤트 병합이고 그대로다. 이 묶음은 그 위의 **화면 표시**이며 ID 가
  갈라진 같은 사람을 한 카드로 보이게 할 뿐 Tier 0 위치·ID 정본을 덮지 않는다(규칙 1, 8). 명세 13.4 에 적을 사안(6절).
- 사람 표기: 서버 자동 번호 이름 `미확인 205` 는 화면에서 `작업자 #205`(확인 상태 배지 「미확인」과 같은 말이라 헷갈렸다). 이름 목록이 없을 때의
  짧은 표시(전에는 `0722` 4자리)는 `작업자 #0722`. 서버 값·저장은 바꾸지 않는다(`personDisplay.workerLabel`, 3D 이름표·카드·배너가 같은 어댑터).
- 확인 상태는 카드 머리줄의 칩 하나(미확인·확인 시각·해소)다. 경보 배너의 「+N」은 「확인 대기 외 N건」으로 바꿨다.

### 1.2 수 정의 통일

| 화면 | 이름 | 정의 |
|---|---|---|
| 관제 이벤트 패널 머리줄 | **진행 중 n건** | 지금 진행 중인 사건 카드 수(1.1 묶음 뒤, 지난 관제 제외). 전에는 「사건」 |
| 작업 관리 · 작업 종료 단계 | **경보 기록 n건 · 위험 a · 경고 b** | 지금 실행에서 난 LIVE 위험·경고 이벤트 한 건 한 건. 구역 작업이면 그 구역만. 전에는 「사건」 |
| 종료 미팅(서버 문장) | 경보: 총 n건(위험 a, 경고 b, 주의 c) | 작업 구간 LIVE 이벤트(주의·안내 포함). 위험·경고 수는 위 경보 기록과 같은 정의 |

- 「사건」은 지금 진행 중인 카드, 「경보」는 기록 한 건 한 건으로 이름을 갈랐다. 머리줄 수에 올려 보면 이 구분을 설명한다.
- 작업자 수(머리줄): 지금 추적 중인 사람(확정·가려짐 트랙). hover 에 「같은 사람이 잠깐 두 번호로 잡히면 많게 보일 수 있음」.
- 작업 진행 화면의 경보 기록 줄은 시각·종류(규칙 이름)·구역·등급이고, **같은 초·같은 대상(사람, 없으면 구역)** 의 경보는 한 줄로 합친다
  (예: 추락 위험(가장자리) · 고소 작업면 위, 등급은 높은 쪽). 머리줄 수는 합치기 전 건수다.
- 종료 미팅 문장(서버·AI)은 바꾸지 않았다. 다중 실행이면 종료 미팅은 작업 전체, 작업 진행 카드는 지금 실행이라 수가 다를 수 있다(카드 제목이
  이번 실행 기준임을 hover 로 알림).

### 1.3 「모두 지우기」 → 「목록에서 숨기기」

- 이 단추는 이 브라우저의 목록·배너·경보음에서만 숨기고 확인(ACK)을 남기지 않는다(기존 동작 그대로). 이름을 「목록에서 숨기기」로 바꾸고 hover 에
  확인 처리가 아님을 적었다.
- 미확인 경보가 있으면 확인 창을 먼저 띄운다: 「확인(ACK) 처리가 아닙니다. 미확인 경보 n건이 … 사라지지만 확인 기록은 남지 않습니다」. 미확인
  경보가 없으면 바로 숨긴다(흐름을 막지 않음).

### 1.4 「최근 해소」는 지금 실행만

- -722 확인: EC2 마감(`WORK_ENDED`·`SESSION_ENDED`·`NOT_IN_SNAPSHOT`)은 화면(`resolvedGroups`)에서 이미 빠지고, 서버는 마감 커밋 뒤
  `/topic/events` 로 해소된 모습을 보낸다(`OrphanEventSweeper.closeGateway`). 하지만 17차 12:58 의 4건은 -722 전 손으로 닫은
  `OPERATOR_CLOSED`(actor `lead-cleanup`)였고, 평소 작업 종료는 살아 있는 Tier 0 가 종료 묶음 tick 에 **관측 해소**로 닫는다(-679
  `stand_down`, EC2 마감 아님). 둘 다 EC2 마감 제외로는 빠지지 않는다.
- 그래서 「최근 해소」는 **지금 실행이 시작된 뒤 난 이벤트만** 남긴다(실행 시작 = 진행 중 실행의 `started_at`, 옛 서버는 `actual_started_at`).
  진행 중 작업이 없으면(작업 전·대기) 「최근 해소」를 비운다. 작업 목록을 아직 못 받았으면 거르지 않는다. 진행 중 경보는 실행과 무관하게 보인다.
- 꼬리표 「작업 외 진입」은 이유별로 나눴다: 진행 중 작업이 없을 때 「작업 시간 외」, 작업 중이지만 작업 구역 밖이면 「작업 구역 밖」(hover 설명).

### 1.5 재생 중 표시(-724 남은 일 2의 표시 부분)

- 계약 `viewer_health` 1.6.0 `payload.laptop.test_input`(선택 boolean). EC2 `ViewerHealthService` 가 `HealthState.testInputActive()`
  (마지막 하트비트 60초 안 노트북 중 하나라도 `cameras[].source_kind` 가 FILE·SYNTHETIC)로 채운다. -724 워치 진동 차단과 같은 판정이라 화면의
  「실제 알림 꺼짐」이 실제와 같다.
- 화면: 관제 작업 세션 바의 단계 배지 옆에 「녹화 재생 중 · 실제 알림 꺼짐」, 작업 관리의 관제 적용 상태 맨 위 줄도 같은 문구(「현장 적용됨 · 경보
  켜짐」 대신). 칸이 없으면(이전 EC2) 모르는 것이라 표시하지 않는다.

### 1.6 작업 전 표시 정리

- 진행 중 실행이 없으면 머리줄 사람 수를 「미리보기 · 사람 n명」으로 적는다(hover: 경보 꺼짐).
- 「작업 시작 전 이벤트 n건 + 작업 관리로」 줄은 「이번 실행 전 이벤트 n건은 목록에서 뺐습니다」 한 줄로 바꾸고, 뺀 것이 없으면 그리지 않는다.
  「작업 관리로」 단추는 작업 세션 바(작업 중)·대기 안내(작업 전) 한 곳에만 남는다.
- 보호구 배지·작업 전 확인 창은 -730 몫이라 건드리지 않았다.

## 4. 버린 대안

- **서버/Tier 0 에서 이벤트 병합**: 기록을 바꾸거나 Tier 0 ID 정본을 덮는다(규칙 1·6). ID 안정화는 Tier 0 몫이다(-725·-661 계열).
- **시간만으로 묶기(살아 있음 무시)**: 같은 가장자리에 실제로 두 사람이 있으면 한 카드로 숨는다. 명세의 「실제 두 번째 사람」 위험.
- **해소 카드는 활성 구간이 겹치면 묶지 않기**: 번호가 바뀐 옛 이벤트는 해소 근거가 없어 오래 열려 있어 거의 모든 경우가 겹친다(효과 없음).
- **「모두 지우기」를 ACK 일괄 처리로 바꾸기**: 확인은 사람이 본 sequence 마다 남기는 기록이다(3.10). 화면 정리와 섞지 않는다.
- **종료 미팅 문장을 「경보 기록」으로 바꾸기**: AI 생성 문장·사실 계약(tbm_form_ending) 변경이 필요하고, 이미 「경보」라 이름이 맞는다.
- **재생 여부를 이벤트 `source` 로**: I1 LIVE 계약 의미 변경(-724 남은 일 1, Lead 결정).

## 5. 잔여 위험

1. 해소 카드는 지금 둘 다 살아 있을 때만 서로 다른 사람을 막는다. 과거에 동시에 있었던 두 사람이 이미 사라졌다면 「최근 해소」에서 「2회」 한 카드로
   보인다(이력 표시, 기록은 그대로).
2. 묶인 카드의 상세·확인은 대표 묶음(살아 있는 사람)만 연다. 사라진 번호의 미확인 경보는 배너(「확인 대기 외 n건」)로 하나씩 확인해야 한다.
3. 관리자 화면 경보음은 재생 중에도 울린다(-724 남은 일 2 의 소리 부분, 아래 넘긴 일).
4. 화면과 EC2 를 함께 배포하지 않으면: 옛 화면 + 새 EC2 는 `laptop` 의 모르는 칸 때문에 health 를 버린다(화면 먼저 배포).

## 6. 명세 갱신 필요(명세 정리 MR 에 넘김)

- 12.4: viewer_health 1.6.0 `laptop.test_input`.
