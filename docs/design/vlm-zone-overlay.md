# VLM 위험 구역 오버레이 (S15P31A101-420)

명세 5.4·8.2, `.agy/ref/tbm-legal-graph.md` 6장. EC2는 기존 `structured_state`에 이벤트 시점 보정 버전, 유효 구역의 다각형·높이, 해당 World Track의 실제 접지점을 담는다. GROUND_FOOTPRINT는 명세상 바닥 다각형이므로 Z=0, VOLUME_3D는 z_min이 있을 때만 쓴다. 워커는 같은 Pod의 버전별 보정 사본을 저장소 head의 문서 해시로 검증한다. 없거나 버전·해상도가 맞지 않으면 투영하지 않는다. 계약의 열린 `structured_state`를 사용하므로 스키마 변경은 없다.

얼굴 처리에 성공한 프레임의 메모리 사본에서 World→카메라 변환 후 깊이 1cm 평면으로 클리핑하고 OpenCV 보정 모델(핀홀·어안·무왜곡)로 투영한다. 화면 경계로 자른 구역은 빨간색 30% 채움과 외곽선, 확인된 대상 접지점은 노란 원과 `target`으로 표시한다. 전달된 대상 상자는 노란 사각형을 사용한다. 범례는 ASCII로 표시한다. 스위치 `SIMAI_VLM_OVERLAY=0`으로 끈다. 원본 저장과 판정에는 영향을 주지 않는다.

버린 대안: 활성 보정을 무조건 사용하거나 접지점 미상을 Z=0으로 채우면 다른 시점·높이의 잘못된 표시가 생긴다. 이미지에 없는 사물을 다른 이름으로 부르게 하는 프롬프트도 사용하지 않는다.

남은 위험: 과거 프레임에도 이벤트 시점 위치를 쓰므로 이동한 대상과 어긋날 수 있다. 현재 프레임 계약에는 대상별 2D 상자가 없으며 접지점이 없으면 대상 표시는 생략된다. 구역 정보가 없는 이벤트나 로컬 보정 사본이 없는 워커에서는 구역 표시도 생략된다. 투영 정밀도와 5초 지연 예산은 실제 카메라/GPU에서 별도 검증해야 한다. `incident_summary`는 이 티켓의 `vlm_rationale` 입력 범위 밖이다.
