# S15P31A101-654 작업 상태 배지·현장 규칙 기준·보호구 기본 필수·PPE 판정 완화

관련 명세: 5.5(PPE 상태 전환), 7.2(R2·R3 높이 프로파일, R9·R11), 7.4(규칙 버전·교실 시험 +1000), 8.10(작업 기준 안전모 요구), 11.1(`config_bundle.rule_profile`), 12.3, 부록 E(교실 테스트베드 고지). 근거: 14차 GPU 세션(2026-11-12 로비) `RESULTS.md` #5·#6 조사.

## 14차에서 확인한 원인

- 묶음 cfg-66~69 는 1초 안에 Tier 0 에 적용됐다(전달 문제 아님).
- R9·R11: 「작업 시작」을 누르지 않고 관제만 봐서 `ppe_policy` 가 `work_id=null`·NOT_REQUIRED 였다. 관제는 작업과 무관하게 돌아 시작된 줄 알았다.
- R3: 묶음 규칙이 운영(R3 v1, 2.0 m)이라 0.40~0.66 m 작업면에서 나지 않았다. 교실 시험(v1001, 0.35 m)은 `POST /api/config-bundles {"rule_profile"}` 로만 켜지고 화면 표시가 없었다.
- PPE 미착용 확정은 6칸 모두 B_NOT_WORN 이어야 해, 프레임 드롭으로 빈 칸(B_EMPTY) 하나만 끼어도 확정되지 않았다.

## 정한 수치와 근거

- 빈 칸 허용 1칸: 6칸(3 s) 중 1칸(0.5 s) 드롭은 14차 아바타 부하에서 흔했다. 2칸 이상은 근거 부족으로 본다. 착용·충돌·모호 근거는 그대로 막아 오탐 방지 성격을 유지하고, 마지막 칸은 미착용이어야 해 `last_evidence_at`·근거가 늘 실제 미착용 칸을 가리킨다.
- 관제 기준 표시 높이: 명세 7.2(운영 2.0 m, 교실 시험 0.35 m). 화면은 묶음의 `rule_profile` 만 받고 높이는 표에서 읽는다(규칙 판 값과 다르면 함께 고친다).

## 버린 대안

- 이전 묶음 상속 유지 + 화면 표시만: 세팅 완료·작업 시작 묶음이 무엇을 잇는지 운영자가 알 수 없고, 한 번 운영 묶음이 끼면 교실 시험이 풀린다(14차). 현장 설정 하나로 고정했다.
- 계약을 바꾸지 않고 끈 작업을 `work_id=null` 로 싣기: 작업 ID 를 지어내 빼는 셈이라 버렸다.
- PPE 창을 5칸으로 줄이기: 착용 쪽 규칙(5/6)과 비대칭이 커지고 모호 칸도 함께 느슨해진다.

## 명세와 다른 점(명세 정리 MR 에 넘김)

- 5.5: "NOT_WORN 은 6칸 모두 선명한 미착용" → 빈 칸 1칸 허용, 마지막 칸 미착용.
- 8.10·7.2 R9·R11: "진행 중 작업이 있으면 REQUIRED" → 작업마다 끌 수 있고 기본 REQUIRED(사용자 결정 2026-11-12).
- 11.1 `config_bundle.rule_profile`: "다음 발행의 기본값" → 현장 설정 `site.rule_profile` 이 발행 기준, 묶음 칸은 기록.

## 잔여 위험

- 배포 순서: 1.1.0 Tier 0 는 작업 중 NOT_REQUIRED 문서(보호구를 끈 작업)를 거부한다(묶음 거부, 이전 묶음 유지). 끈 작업을 시작하기 전에 Tier 0 를 이 판으로 올린다. 기본값(둘 다 필수)만 쓰면 이전 Tier 0 도 받는다.
- 기준을 작업 중에 바꾸면 바로 새 묶음이 나가 판정 기준이 바뀐다(막지 않음). 시연 전 세팅 단계에서 고른다.
- 빈 칸 허용으로 드롭이 잦은 장면에서 미착용 확정이 0.5 s 빨라지고 근거가 1칸 줄 수 있다. REPLAY(`live-20261112-135633`)로 오탐을 확인할 것.
- 같은 계약 판 번호(v7.38.0)·V61 을 동시 진행 이슈가 쓰면 머지 직전에 다시 고른다.
