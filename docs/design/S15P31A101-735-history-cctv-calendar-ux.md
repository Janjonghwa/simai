# S15P31A101-735 지난 날짜 다시보기·CCTV·작업 달력 UX 개선

## 1. 배경 및 목표

2026-11-15 전 화면 UX 감사(`findings.md`)에서 확인된 **지난 날짜 다시보기(`/work?date=지난날짜`)**, **CCTV(`/cctv`)**, **작업 달력(`/work`)** 세 영역의 안내 모순과 레이아웃 겹침 문제를 해결한다.

- 다른 티켓(`-730`~`-734`)과의 충돌을 막기 위해 `features/work/past`, `features/work/calendar`, `features/history`, `features/cctv` 내부에서만 변경한다.
- 모든 상태 문구는 **무엇이 / 왜 / 어떻게** 원칙을 따르며, 화면의 다른 영역과 모순되는 안내를 제거한다.

## 2. 항목별 변경 전/후 화면 문구 및 설계

### 2.1 지난 날짜 다시보기 (`/work?date=지난날짜`)

#### (1) 오래된 작업의 영상 업로드 상태 및 본문 모순 해결
- **원인**:
  - 서버(`VideoService`)는 작업 종료 후 14일 이내 구간에서 현장 노트북 게이트웨이가 `recording_upload_progress`를 한 번도 보고하지 않은 작업(`!reported`)에 대해 `status: 'WAITING', expected_segments: null`을 반환한다.
  - 기존 `useReplaySegments`는 작업 종료 시점(`range.to`)과 무관하게 `WAITING`을 무조건 `'영상 업로드 중 · 3D 기록 먼저 보기'`로 표시하고 10초마다 재조회했으며, `ReplayStage`는 3D 기록이 비어 있는 상태(`isEmptyReplay`)에서도 `'3D 기록 먼저 보기'` 문구를 그대로 노출했다.
- **해결**:
  - 작업 종료 시각(`range.to`)으로부터 업로드 폴링 허용 시간(`VIDEO_POLL_MS * VIDEO_POLL_LIMIT = 10분`)이 지났는데도 여전히 보고 없는 `WAITING`이면 종료된 상태(terminal)로 판정해 폴링을 멈추고 녹화 없음 사유를 표시한다.
  - 폴링 한도(10분 / 60회) 동안 `UPLOADING`이 끝나지 않으면 시간 초과 안내로 바꾼다.
  - `ReplayStage`는 `index !== null && isEmptyReplay(index)`일 때 상단 영상 문구에서 `' · 3D 기록 먼저 보기'` / `' 3D 기록을 먼저 볼 수 있습니다.'`를 제거해 본문과 모순되지 않게 한다.

| 상황 | 변경 전 문구 | 변경 후 문구 |
| --- | --- | --- |
| 종료 후 10분 이상 경과 + 업로드 보고 없음(`WAITING`) | `영상 업로드 중 · 3D 기록 먼저 보기` | `이 작업 구간에 업로드된 녹화 영상이 없습니다(현장 노트북 미연결 또는 녹화 없음).` |
| 업로드 폴링 10분(60회) 초과 시 | `영상 업로드 중 · 3D 기록 먼저 보기` | `영상 업로드가 시간 안에 끝나지 않았습니다. 현장 노트북 연결을 확인하고 다시 확인해 주세요.` |
| `FAILED` (`failed_segments > 0`) | `영상 업로드에 실패했거나 진행 보고가 끊겼습니다. 3D 기록을 먼저 볼 수 있습니다.` | `영상 업로드에 실패했습니다(전송 실패 조각 발생). 3D 기록을 먼저 볼 수 있습니다.` (3D 기록이 비었으면 뒷문장 생략) |
| `COMPLETED`이나 재생할 조각이 0개 | `녹화 영상을 확인 중입니다. 3D 기록을 먼저 볼 수 있습니다.` | `영상 업로드는 완료되었으나 이 작업 구간에 재생할 영상이 없습니다.` |
| 종료 후 10분 이상 경과 + 업로드 행·조각 모두 없음 | `녹화 영상을 확인 중입니다. 3D 기록을 먼저 볼 수 있습니다.` | `이 작업 구간에 녹화된 영상이 없습니다(업로드 기록 없음).` |

#### (2) 0초(시작=종료·1초 미만) 작업 및 빈 기록 사유 표시
- **원인**:
  - 시작 직후 바로 종료된 작업(`15:26:14`~`15:26:14`)이나 3D 기록이 전혀 없는 실행에서 `15:26`–`15:26`의 비활성 타임라인(`0.5× 1× 2× 4×`)과 단순 `데이터 없음`만 표시되어 왜 재생할 수 없는지 알 수 없었다.
- **해결**:
  - `pastDay.ts`에 `isZeroSpanWork`, `ZERO_SPAN_REASON`, `emptyReplayReason`을 추가하고 `PastDayPage`와 `ReplayStage`에서 비활성 0초 타임라인·빈 화면 대신 구체적 사유를 표시한다.

| 상황 | 변경 전 화면 | 변경 후 화면 문구 |
| --- | --- | --- |
| 시작 = 종료 (`actual_ended_at <= actual_started_at`) | `아직 다시 볼 구간이 없습니다.` + 빈 CCTV 영역 | `작업이 시작 직후 바로 종료되어(0초) 저장된 기록이 없습니다.` |
| 구간 길이 1초 미만 (`to - from < 1000`) + 빈 기록 | 비활성 타임라인(`15:26`–`15:26`) + `데이터 없음` | `작업이 시작 직후 바로 종료되어(1초 미만) 저장된 기록이 없습니다.` (타임라인 대신 사유 안내 표시) |
| 구간 전체가 `gaps`인 빈 기록 | 비활성 타임라인 + `데이터 없음` | `작업 구간 동안 관제 데이터를 받지 못해 저장된 3D 기록이 없습니다.` |
| 관제는 연결되었으나 감지된 사람·사건이 없는 빈 기록 | 비활성 타임라인 + `잡힌 작업자가 없습니다.` | `작업 시간 동안 감지된 작업자와 위험 이벤트가 없습니다.` |

#### (3) 옛 종료 미팅의 영문 등급 enum 한국어 변환
- **원인**:
  - 이전 버전에서 생성되어 DB에 저장된 TBM 보고서의 `form.review.ending` 문장에 `CRITICAL`, `HIGH`, `CAUTION`, `INFO` 영문 enum이 그대로 포함되어 있었다.
- **해결**:

| 구분 | 문구 예시 |
| --- | --- |

### 2.2 CCTV (`/cctv`)

#### (1) 중계 끊김 안내에 행동 유도 한 줄 추가
- **원인**:
  - 로컬 미리보기 끊김 시 `중계 끊김` 두 글자만 노출되거나, 원격 `waiting_source`에서 `현장 노트북 영상 중계가 서버에 연결되지 않았습니다. 연결되면 바로 보입니다`만 표시되어 사용자가 무엇을 해야 하는지 알기 어려웠다.
- **해결**:
  - `cctv.ts`에 `disconnectAction(link)`를 추가하여 `MockWithStatus`에서 `중계 끊김` 옆에 행동 유도 문구를 함께 표시하고, `remoteNotice`(`waiting_source`)에도 행동 유도 문구를 추가했다.

| 상태 | 변경 전 문구 | 변경 후 문구 |
| --- | --- | --- |
| 로컬·원격 소켓 끊김 (`unavailable`) | `중계 끊김` | `중계 끊김` + `현장 노트북에서 중계 프로그램을 켜세요. 연결되면 바로 보입니다.` |
| 브라우저 미지원 (`unsupported`) | `중계 끊김` | `중계 끊김` + `영상 디코딩(WebCodecs)을 지원하는 Chrome·Edge 브라우저에서 여세요.` |
| 원격 게이트웨이 대기 (`waiting_source`) | `현장 노트북 영상 중계가 서버에 연결되지 않았습니다. 연결되면 바로 보입니다` | `현장 노트북 영상 중계가 서버에 연결되지 않았습니다. 현장 노트북에서 중계 프로그램을 켜세요(연결되면 바로 보입니다)` |

#### (2) 경보 배너(`AlarmBanner`)와 CCTV 상단 카메라 이름·지연 배지 겹침 방지
- **원인**:
  - `AppLayout`의 `<Notices>`(`AlarmBanner`)는 `top-[72px]`에 절대 위치로 뜨며, 높이(`h + 20px`)를 루트 CSS 변수 `--notices-h`로 기록한다. 그러나 `CctvPage`는 제목(`PageTitle`)이 `sr-only`라 본문 첫 줄에 4분할 격자가 바로 시작되어, 경보 배너가 카메라 1의 우측 상단 판정 지연 배지와 카메라 2의 좌측 상단 카메라 이름 배지를 가렸다.
- **해결**:
  - `CctvPage` 루트 컨테이너에 `pt-(--notices-h,0px) transition-[padding] duration-150`을 적용해 평상시(`--notices-h: 0px`)에는 레이아웃 변화가 없고, 경보 배너가 떴을 때만 배너 높이만큼 CCTV 격자를 아래로 내려 가림을 방지한다.

### 2.3 작업 달력 (`/work`)

#### (1) 날짜 칸 점 색깔·`✓` 아이콘 의미 호버 범례 추가
- **원인**:
  - 지난 날짜 칸의 `✓`(`CheckCircle2`) 아이콘과 빨간 점(`bg-sev-critical`)·주황 점(`bg-sev-high`) + 숫자 표시에 텍스트 라벨이 없어 처음 보는 사용자가 의미를 바로 알기 어려웠다.
- **해결**:
  - `CalendarCell`의 완료 아이콘(`작업 완료(종료·제출)`), 빨간 점(`위험 경보 N건`), 주황 점(`경고 경보 N건`)에 호버 `title`을 부여했다.
  - `WorkCalendar` 머리줄(`월간 요약` 옆)에 `표시 범례` 버튼(`CalendarLegend`)을 추가해 마우스 호버 또는 키보드 포커스 시 `✓ 작업 완료`, `빨간 점 + 숫자: 위험 경보 건수`, `주황 점 + 숫자: 경고 경보 건수` 툴팁을 표시한다.

#### (2) 상단 바 GPU 툴팁과 월간 요약 겹침 방지
- **원인**:
  - 상단 바 우측의 `GpuIndicator`에 마우스를 올리면 아래로 열리는 상태 툴팁이 `WorkCalendar` 머리줄 우측 끝(`ml-auto`)에 배치된 `월간 요약`(`작업 N일 · 위험 N건 · 경고 N건`)을 덮었다.
- **해결**:
  - `WorkCalendar` 머리줄의 요약·범례 영역에서 `ml-auto`를 제거해 좌측 `오늘` 버튼 바로 오른쪽에 배치함으로써, 상단 바 우측 `GpuIndicator` 아래 영역을 비워 호버 툴팁과 겹치지 않게 했다.

## 3. 기각한 대안

1. **`AppLayout.tsx` 또는 `GpuIndicator.tsx` 직접 수정**:
   - `AppLayout`에서 모든 페이지의 `<main>`을 `--notices-h`만큼 밀거나 `GpuIndicator`의 툴팁 방향을 바꾸는 대안은 다른 티켓(`-733` GPU 패널·툴팁, `-730`/`-731` 실시간 관제)과 파일 충돌을 일으키고 다른 화면의 레이아웃에 부작용을 줄 수 있어 기각했다.
2. **달력 칸 내부에 `위험`·`경고`·`완료` 글자를 상시 노출**:
   - 35~42개 날짜 칸마다 글자를 반복하면 시각적 복잡도가 급증하고 이전 티켓(`-677` 간소화)의 의도를 해치므로, 머리줄 호버 범례(`표시 범례`)와 칸 요소별 `title` 툴팁 조합으로 해결했다.
3. **`features/work/report/paperTables.tsx` 수정으로 종료 미팅 enum 변환**:
   - 작업 종료·보고서 영역(`-734`)과의 병합 충돌 가능성을 원천 차단하기 위해 `features/work/past/`(`pastDay.ts`, `PastReportPanel.tsx`)에서 쿼리 캐시를 정규화하는 방식을 택했다.
