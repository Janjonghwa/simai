# S15P31A101-651 구역 편집 편의와 구역 이름 규칙

관련 명세: 5.3(위험구역·작업면 등록), 8.2(VLM 구역 초안은 제안만), 요구사항 FR-15·FR-16(구역 편집). 근거: 14차 로비 GPU 세션(2026-11-12) 결과 9번과 구성 묶음 cfg-67·68.

## 문제

- 관제 화면에서 구역 크기·위치를 고치기 불편하다. AI 초안(PCA OBB)은 거의 항상 yaw ≠ 0 이라 수락한 뒤 3D 손잡이가 뜨지 않는다(`surfaceBoxEditable` 은 yaw≈0 만 허용). 손잡이가 떠도 면 화살표 여섯이 상자 가운데 이동 구와 한 점에 겹친다. 저장할 때마다 편집 모드가 꺼진다.
- 이름이 `구역 1·2`, `작업대 상판`(7개)처럼 겹쳐 드롭다운·경보에서 구역을 가릴 수 없다.
- 같은 새 구역이 2.3 s 간격으로 두 번 만들어졌다. cfg-67(z-34b517eb + ws-ebd2c8ec)과 cfg-68(z-5450bf6b + ws-234b16c3)이 모양·작업면이 같다. 첫 추가가 끝나면 편집 모드가 꺼지고, 다시 열면 같은 기본 상자(기존 구역 경계의 가운데)로 새 양식이 열려 한 번 더 추가된 것으로 본다(이름이 `구역 1`·`구역 2` 였던 것과도 맞다).

## 한 일

1. **AI 초안 축 정렬**(`ai/src/simai_ai/vlm/zone_draft.py` `_fit_obb_2d`, `ZoneGeometryConfig.axis_snap_max_deg = 10`): 주축이 World 축(0·±90°)에서 10° 안이면 yaw 0 으로 두고 World 축 기준 경계 상자를 잰다. 수락 쪽(`front/.../setup/draftZone.ts`)도 같은 10° 로 옛 초안(작업면 obb, 작업면 없는 초안의 네 변)을 축 정렬로 맞춘다. 이미 수락한 구역은 맞추기 전 다각형으로도 알아본다(`acceptedByZones`).
2. **화살표 위치**(`viewer3d/editing/BoxEditHandles.tsx`): 화살표를 각 면의 바깥 가운데에 놓는다. 손잡이마다 `ScreenSized` 묶음(`box-edit-at:<손잡이>`)이 화면 크기를 맞춘다. 면 가운데는 상자 가운데를 지나는 끌기 축 위라 `boxEditDrag` 는 그대로다. 뷰어 `CONTRACT.md`·`CHANGELOG.md` 갱신.
3. **관제 편집 이어 가기**: `MonitorPage` 가 `onCommitted` 를 넘기지 않아 저장·추가 뒤에도 「편집 끝내기」 전까지 편집 모드가 남는다(추가하면 만든 구역이 골라진다). `ZoneSizeCard` 가 손잡이와 같은 상자의 가로(World X)·세로(World Y)·높이를 숫자로 고친다(`resizeBox`: 가로·세로는 가운데 기준, 높이는 바닥 기준, 교실 범위에서 자름, 최소 0.2 m·0.05 m 는 손잡이와 같다). 작업면이 붙었으면 높이는 작업면 카드의 상판 높이 칸이 맡는다.
4. **이름 규칙**(`zoneEditModel.ts`): 자동 이름은 `종류 + 구분자`. 고소작업면(작업면이 붙은 구역)은 A·B…(Z 다음은 27·28…), 개구부·바닥 단부·위험구역은 1·2…. 새 구역 기본 이름(`nextZoneName`)과 AI 초안 수락(`uniqueZoneName`)은 활성 구역과 겹치지 않는 가장 작은 구분자를 고른다. 사람이 고친 이름은 바꾸지 않고, 다른 활성 구역과 같으면 양식·목록 이름 바꾸기가 「같은 이름의 구역이 있습니다.」로 막는다(이름을 고쳤을 때만 본다. 예전에 겹친 채 저장된 구역의 다른 칸 저장은 막지 않는다). AI 초안(`unique_draft_names`)은 'AI 의견 없음' 초안을 늘 `고소작업면 A`·`개구부 1`·`바닥 단부 1` 로, VLM 이름은 한 번의 초안 안에서 겹칠 때만 구분자를 붙인다.
5. **두 번 제출 막기**(`useZoneCommitMutation`): 같은 QueryClient 에서 저장이 진행 중이면 다음 저장은 보내지 않고 `CommitInFlightError` 를 던진다. 편집 패널·세팅 초안 수락·목록 이름 바꾸기는 알림 없이 무시한다. 단추별 `useExclusiveRun` 은 그대로 둔다.

## 명세에 없어 정한 값

| 값 | 정한 것 | 근거 |
|---|---|---|
| 축 정렬 기준 | \|yaw − 가까운 축\| < 10° | 14차 작업대가 81.9°(축에서 8.1°). 점구름 PCA 흔들림은 수 도이고, 실제로 비스듬히 놓은 물체는 보통 15° 이상이라 남는다. 30° 상판은 회전을 유지(시험) |
| 축 정렬 크기 | 기운 상자를 덮는 축 정렬 상자 | AI 는 점의 World 축 경계를, 수락 쪽은 OBB 네 꼭짓점의 경계를 잰다. 조금 커지지만 위험 구역이 실제 물체를 빠뜨리지 않는다 |
| 구분자 | 고소작업면 A~Z, 그 밖 1~ | 사용자 결정 예시(고소작업면 A·B, 개구부 1, 위험구역 1) |

## 버린 대안

- 회전 작업면 손잡이(OBB 지역 축 끌기): 이번 범위 아님(사용자 결정 빠른 안). 대각선으로 놓인 작업대는 여전히 높이 칸만 고친다.
- 서버 이름 중복 검사: 예전에 겹친 이름으로 저장된 구역과 TBM 레이아웃 경로가 깨질 수 있어 하지 않았다. 화면이 막는다.
- 같은 본문 저장을 잠깐 동안 거르는 시간창: 다시 열어 같은 기본 상자로 추가하는 경우는 편집 모드 유지로 사라지고, 진행 중 막기로 충분하다.

## 잔여 위험

- 축 정렬은 World +X·+Y 가 방 벽과 나란하다고 본다(세팅 World 정렬). 벽과 비스듬한 World 에서는 맞추면 오히려 틀어질 수 있다.
- 서버는 이름 겹침을 막지 않는다. 다른 클라이언트(API 직접 호출)는 겹친 이름을 저장할 수 있다.
- 두 번 제출 막기는 한 브라우저 탭 안에서만이다. 두 관리자·두 탭은 서버 409 외에는 막지 않는다.
- 같은 작업대가 여러 후보로 쪼개지는 문제(점구름 병합)는 이 티켓 밖이다. 이름은 이제 겹치지 않지만 후보 수는 그대로다.
