# S15P31A101-860 낙상(R4) 워치 진동은 같은 사람 묶음에 묶이지 않고 바로

2026-11-23 리허설 운영 `watch_alert` 기록에서 R4(낙상, CRITICAL) 워치 알림이 늘 같은 사람의 R1(진입, CRITICAL) 알림이 지워질 때까지
기다렸다가 울렸다(14:00 run 14초 늦음, 15:34 run 3초 늦음, 14:13·16:43 run 은 안 울림).
원인은 -723 의 같은 사람 묶음(`WatchAlertService.send()` INSERT 의 두 번째 `NOT EXISTS`)이다: R1 CRITICAL 이 열려 있으니 같은 등급 R4 는 하위로 묶였다.

관련: -723 설계(`S15P31A101-723-alert-subsumption.md`), 명세 7.3(채널별 중복 억제 허용), 7.4(병합), 부록 C.6(워치).

## 결정 (사용자 결정 2026-11-23)

- 보내려는 이벤트의 규칙이 R4 면 같은 사람 묶음을 건너뛴다. 사람이 쓰러진 것은 가장 급하고 워치 글자도 「낙상 의심」으로 달라 따로 울릴 값이 있다.
- 같은 이벤트·워치 중복 방지(첫 번째 `NOT EXISTS`)는 그대로다. 같은 R4 를 재발행·요약 갱신·재동기화로 다시 받아도 진동은 한 번.
- R4 는 묶는 쪽으로는 계속 참여한다. R4 가 열려 있으면 같은 사람의 R1·R5 등 같거나 낮은 등급은 -723 그대로 묶인다.
- 규칙 ID 는 `WatchAlertService.IMMEDIATE_RULE`(= `RuleCatalog.R4`) 한 곳에 둔다. SQL 은 `(CAST(:immediate AS boolean) OR NOT EXISTS ...)`.

`alert`(I1 수신)·`clearIfResolved`(해소 뒤 `resync`)·`resync`(연결·배정) 모두 `send()` 한 곳을 지나므로 세 경로가 같은 규칙을 따른다.

## 버린 대안

- R4 에만 등급을 올려 묶음을 피하기: 등급은 Tier 0 정본이라 서버가 바꾸면 안 된다(AGENTS 규칙 1).
- 규칙별 우선순위 표(R4 > R2 > R1 …)로 묶음 판정 일반화: 지금 요구는 R4 하나이고 표를 정할 근거(현장 결정)가 없다.

## 시험

`WatchAlertIntegrationTest`: R1 열린 동안 R4 즉시(재발행·재동기화는 한 번), 재동기화 경로로도 R4 즉시, R4 열린 동안 R5 묶임, R1 열린 동안 R5 묶임.

## 잔여 위험

- 같은 사람에게 서로 다른 R4 이벤트가 동시에 열리면(ID 갈라짐 등) 각각 울린다. R4 는 드물고 급해서 받아들인다.
- 노트북 현장 소리(Tier 0 `SoundLadder`)·관제 화면 소리(`front/.../alarmPolicy.ts`)의 같은 사람 묶음은 이 티켓에서 바꾸지 않았다(워치만).
