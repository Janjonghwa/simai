# 아바타 외형 좌우 대칭 채움 (S15P31A101-790)

천장 카메라는 한쪽 팔·다리 면 전체를 못 보는 일이 많다. -742·-755 채움은 미관측 텍셀을 같은 부위(UV 섬 × 허리 위아래) 관측 색으로 번지고,
부위에 관측이 없으면 인접 부위 색을 빌린다. 그래서 안 보인 팔이 몸통 색으로 칠해지는 등 어색했다. 작업복·조끼는 대부분 좌우 대칭이므로,
미관측 몸 텍셀은 몸 좌우 반대편 같은 자리가 관측이면 그 색을 먼저 쓴다. 이 티켓은 뷰어 표시만 바꾼다.
`surface_source` 데이터·계약·워커·서버는 그대로다(-742 사용자 결정 "원칙을 좀 고치더라도 최대한 보여 주기 좋은 쪽으로", 표시만).

## 방식

### 대응표 (메시당 한 번)

1. **정점 묶기.** 표면 형상(UV 있음, 관절 재질 제외)의 바인드 자세 `POSITION` 을 0.1 mm 반올림으로 묶는다. glTF 가 UV 이음매에서 가른 정점이 하나가 된다(-742 이음매 판정과 같은 규칙).
2. **좌우 축과 대칭면.** 위 축은 glTF Y-up 의 y 이고(기존 부위 지도·셰이더와 같은 가정), 좌우 축은 x·z 중 반전했을 때 **다른** 정점과 짝이 더 많이 맞는 쪽이다.
   대칭면 위 정점이 자기 자신과 맞는 것은 세지 않는다(납작한 형상이 깊이 축 반전으로 전부 자기 짝이 되는 것을 막는다).
   x 짝이 90% 이상이면 z 는 재지 않는다. 대칭면 위치는 그 축의 경계 상자 가운데다. 실제 MHR 은 x 축, 대칭면 x = 0 이다.
3. **정점 짝.** 반전한 위치를 같은 0.1 mm 키로 먼저 찾고, 없으면 공간 해시로 허용 거리(`AVATAR_MIRROR_MAX_DIST_M` 1 cm) 안 가장 가까운 묶음을 찾는다. 없으면 짝 없음.
   다른 정점과의 짝이 묶음의 절반(`AVATAR_MIRROR_MIN_MATCH_RATIO`) 미만이면 대칭 메시가 아니라고 보고 대응표를 만들지 않는다(null → 기존 채움).
4. **삼각형 대응.** 세 정점의 짝으로 이루어진 삼각형(묶음 번호 세 개가 같은 삼각형)을 찾는다. 그 삼각형의 정점 UV 로 무게중심 좌표를 옮긴다.
   무게중심 좌표는 텍셀 좌표의 1차 함수이므로 삼각형마다 아핀 대응이다. 짝 삼각형이 없거나 자기 자신이면 대응 없음.
   무게중심의 좌우 좌표가 대칭면에서 `AVATAR_MIRROR_CENTER_BAND_M`(1 cm) 안인 삼각형(중앙선 위)은 자기 근처와 대응하므로 쓰지 않는다.
5. **텍셀 표.** 텍스처 해상도(1024²)에서 삼각형 UV(glTF 상단 원점, `flipY=false`)를 텍셀 중심으로 래스터화해 `텍셀 → 대칭 텍셀` 번호표(`Int32Array`, -1 은 없음)를 만든다.
   대칭 텍셀이 자기 자신이면 적지 않는다. 장면(공유 형상)·텍스처 크기별로 `WeakMap` 에 한 번만 만들고, 만들다 예외가 나면 경고를 남기고 null 을 캐시한다.

텍셀 단위로 둔 이유: 조끼 반사띠·주머니 테두리처럼 폭이 수 텍셀인 무늬를 4×4 격자로 옮기면 흐려진다. 표는 메시당 4 MB 이고 채우기에서는 텍셀마다 배열 한 번 읽는다.

### 채우기 순서

1. 관측·보간·얼굴 관측 텍셀(빈 픽셀 아님)은 원래 색 그대로다(바뀌지 않음).
2. **대칭(1b 단계, 새로 더함).** 미관측·빈 픽셀 몸 텍셀은 대칭 텍셀이 (빈 픽셀이 아닌) 관측·보간 몸 텍셀이면 그 RGB 를 그대로 쓴다(알파 255).
   대칭 텍셀이 얼굴·미관측·빈 픽셀이거나 이미 대칭으로 채운 텍셀이면 쓰지 않는다(연쇄 없음).
3. 남은 칸은 -742/-755 채움 그대로다(같은 부위 번지기·부위 중앙값·인접 부위·같은 상하, 섬 밖 8칸 번짐, 원래 해상도 쌍선형).
4. 얼굴(+128 영역)은 대칭 복사를 받지도 주지도 않는다. 얼굴 미관측은 관측 얼굴·목 피부 단색, 빈 얼굴 관측은 이웃 관측 얼굴 평균 그대로다(이목구비 생성 없음).

### 대칭 색을 번지기 씨앗으로 쓰는가: 쓴다 (`AVATAR_FILL_MIRROR_SEEDS = true`)

- 대응표가 닿지 않는 텍셀이 대칭으로 채운 영역 사이에 남는다. 섬 가장자리 텍셀(텍셀 중심이 삼각형 밖), 중앙선 띠, 반대편도 미관측인 곳이다.
  씨앗으로 쓰지 않으면 이 텍셀은 같은 부위의 **다른 관측** 색, 부위에 관측이 없으면 **인접 부위**(몸통) 색으로 채워져,
  대칭으로 채운 팔 위에 몸통 색 점·줄이 섞인다. 이 티켓이 고치려는 어색함이 그대로 남는다.
- 씨앗으로 쓰면 그 부위에 관측이 없어도 대칭 색이 씨앗이 되어 인접 부위에서 빌리지 않는다. 실자산 v2 에서 빌린 부위가 1 → 0 이 되었다(아래).
- 씨앗은 관측 씨앗과 따로 모아 격자 칸 평균에 더한다. 목 피부(얼굴 미관측 단색이 `130` 없을 때 쓰는 색)는 관측 씨앗만 쓴다.
- 대칭 색도 같은 사람의 관측 픽셀이라 새 색을 만들지 않는다. 대칭 텍셀은 원래 해상도 색을 그대로 쓰고, 씨앗은 남은 칸에만 영향을 준다.

### 실패와 끄기

- 대응표를 만들다 실패하면 `avatarUvMirrorMapForScene` 이 경고(`좌우 대칭 대응표 실패`)를 남기고 null → 기존 채움만.
- 대칭을 넣은 채우기가 예외를 던지면 `buildAvatarDisplayAlbedo` 가 경고(`좌우 대칭 채우기 실패, 대칭 없이 채움`)를 남기고 대칭 없이 다시 채운다. 그것도 실패하면 지금처럼 관측만 남기는 마스크다.
- 대응표 크기가 albedo 와 다르면 대칭 없이 채운다.
- 끄기: `AVATAR_FILL_MIRROR_ENABLED = false`(대응표를 만들지 않음), 씨앗만 끄기는 `AVATAR_FILL_MIRROR_SEEDS = false`. 시연 범위라 둘 다 기본 켬이다.

## 버린 대안

- **격자(256²) 단위 대응.** 부위 지도와 같은 격자라 간단하지만 폭 수 텍셀 무늬(반사띠)가 4×4 평균으로 흐려진다. 텍셀 표는 메시당 4 MB·수십 ms 한 번이라 감당할 만하다.
- **텍셀마다 3D 최근접 표면점 찾기.** 반전한 3D 점에서 가장 가까운 삼각형을 찾으면 비대칭 위상에도 맞지만 1M 텍셀 질의가 무겁다. MHR 은 위상까지 대칭이라(삼각형 95.5% 짝) 삼각형 아핀 대응이 정확하고 빠르다.
- **MHR UV 배치를 보고 좌우 섬 위치 하드코딩.** 자산·UV 가 바뀌면 틀린다. 메시에서 계산한다.
- **대칭 색을 씨앗으로 쓰지 않기.** 위 「씨앗」 절. 대칭으로 채운 면 사이에 인접 부위 색 점이 남는다.
- **대칭 텍셀을 쌍선형으로 표본.** 대칭 텍셀 하나를 그대로 쓰면 충분하다(왕복 오차 0 텍셀). 섬 가장자리에서 다른 섬·빈칸 색이 섞일 위험만 늘어난다.
- **얼굴 좌우 대칭.** 얼굴 영역은 머리 전체(+128)이고, 단색 규칙(-742)과 이목구비 생성 금지(규칙 8)를 지키려고 빼었다.
- **워커에서 대칭 채운 PNG 보내기.** 출처 기록과 표시가 섞이고 워커·계약 변경이 필요해 범위 밖이다.

## 잔여 위험

- **한쪽에만 있는 것의 복사.** 가슴 한쪽 로고·이름표·글씨, 한쪽 주머니·무전기·공구 벨트가 반대편에 거울상(글씨는 좌우 반전)으로 생길 수 있다. 끄려면 `AVATAR_FILL_MIRROR_ENABLED`.
- **관측 쪽 오염의 전파.** 관측 쪽에 남은 0 섞인 어두운 관측·다른 시각 크롭 픽셀(-755 잔여)이 반대편으로도 복사된다. 손·손가락처럼 관측이 삼각형 조각으로 흩어진 곳은 반대편도 조각 무늬가 된다.
- **조명 차이.** 한쪽은 창가, 다른 쪽은 그늘이었다면 밝기가 다른 색이 그대로 옮겨진다(채널 이득 맞춤은 워커가 카메라 사이에만 한다).
- **비대칭 체형 메시.** 정점 짝이 50% 미만이면 대응표 없이 기존 채움이다. 50~100% 사이 부분 비대칭은 1 cm 안 짝만 쓴다.
- **첫 표시 비용.** 사람마다 처음 한 번 대응표 35~80 ms 가 메인 스레드에 더해진다. 여러 사람이 같은 순간 처음 보이면 한 번 끊길 수 있다(Web Worker 는 -742 부터 넘긴 일).
- **실렌더 미확인.** 표시 albedo 그림까지 확인했고, 실제 MHR 메시에 입힌 렌더(Blender·관제 화면)는 Lead 가 비교한다.
