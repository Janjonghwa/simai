# S15P31A101-691 세팅 화면 정리: 영상 · 배지 하나 · 지금 할 일 하나

관련 명세: 8.1(설치·보정 화면 흐름), 13.4(세팅 화면), 4.3(세팅 파이프라인), 4.4(틀어짐 감시·재세팅 요구). 앞 문서
`S15P31A101-686`(배경 촬영 창), `-687`(카메라 확인 걷기 창), `-689`(맵 방식·reuse-check), `-690`(높이 확인 창), `-692`(관제 단계 배지),
`-696`(작업 실행·보고서 제출). front 표시·구성만 바꿨다. 서버·워커·계약·완료 판정(`isSceneMapComplete`·`canCompleteSetup`·'다음'
켜짐 조건)은 그대로다(-688 범위).

## 문제(15차, 사용자 지적 2026-11-13~14)

- "디자인이 난잡하다": 1단계 오른쪽에 카메라 연결 표(수신 배지 + 안내 문장)·겹침 경고·높이 입력, 왼쪽에 영상 4칸 + 가운데 2D 겹침 지도,
  2단계 오른쪽에 5단계 막대(단계마다 %·경과 시간)·대기 이유·카메라별 배경 % · 높이 표 · 쌍별 px 표가 한꺼번에 보였다.
- 모순: 카메라 칸에 「정상」 배지(수신 상태)와 "왼쪽으로 더 돌려 주세요"(각도 안내)가 같이 떴다. `setup.ts` 가 응답에 없는 카메라를
  `item?.status ?? 'OK'` 로 정상으로 미뤘다.
- 2단계 85% 에서 왼쪽 카메라 영상이 3D 미리보기로 저절로 바뀌어 영상을 더 볼 수 없었다.
- 보정·생성의 '다음' 이 맵 보강 창을 먼저 띄워 구역 단계로 가는 데 단추를 두 번 눌러야 했다.
- 꺼진 단추의 이유가 마우스를 올려야 보이는 title 에만 있었다.

## 원칙

화면에는 카메라 영상 + 카메라마다 배지 하나 + 오른쪽 「지금 할 일」 하나 + 주 단추 하나. 진단 수치는 관리자용 「자세히」(닫힘)로.
비활성 단추는 이유를 본문에, 실패는 "무엇이 / 어떻게" 두 줄.

## 카메라 배지(`features/setup/cameraBadge.ts`)

| 순서 | 배지 | 근거 | 조건 |
|---|---|---|---|
| 1 | 연결 끊김 | 각도 안내 `latest.cameras[].status` | 수신 근거가 지금 것이고 OK 가 아님(NO_VIDEO·STALE) |
| 2 | 직전 보정과 달라짐 | `GET /api/setup-sessions/reuse-check` 의 `changed_cameras`(camera_status CHANGED 또는 blocked_reason CAMERA_CHANGED) | 그 카메라가 목록에 있음. 근거는 -540 관제 회전 감시 재세팅 요구(TIER0_DRIFT)와 직전 재사용 거부(LAST_SETUP_REJECTED) |
| — | 확인 중 | — | 위 둘이 아니고, 수신 근거가 없거나(응답 없음·EMPTY·조회 실패·서버 stale·브라우저에서 오래됨·그 카메라 항목 없음) 연결 판정 계산 실패(connectivity UNKNOWN) |
| 3 | 겹침 부족 | 각도 안내 `pairs`(옆 쌍 LACK) | 이 카메라가 낀 옆 쌍이 LACK |
| 4 | 각도 확인 필요 | 각도 안내 `guides`(화면에 보일 안내, `visibleGuides`) | 이 카메라에 안내가 있음 |
| 5 | 준비됨 | — | 그 밖 |

- 「직전 보정과 달라짐」은 각도 안내와 따로 받은 근거라, 각도 안내가 오래돼도(확인 중이어도) 보인다. 「연결 끊김」은 지금 결과일 때만
  말한다(오래된 끊김은 모른다).
- 오래됨 판정: 서버가 응답마다 `stale`(받은 지 `stale_after_ms` 기본 10 s 넘음)을 준다. 화면은 조회를 쉬는 동안(보정·생성 단계, 조회 실패)
  받아 둔 응답이 계속 남으므로, 받은 시각(`dataUpdatedAt`) + `stale_after_ms` − `age_ms` 가 지나면 만료로 본다(`useCoverageExpired`, 만료
  시각에 한 번만 다시 그림). 새 수치는 만들지 않았다(서버 기준 10 s 그대로, 없으면 같은 10 s).
- viewer_health `re_setup` 을 화면이 직접 구독하지 않은 이유: reuse-check 가 같은 값(Tier 0 연결 중일 때의 re_setup)을 이미 판정에 쓰고
  1단계에서 10 s 마다 다시 받는다. 두 근거를 따로 읽으면 같은 사실을 두 길로 보여 어긋날 수 있다.
- 배지는 1단계에만 단다. 보정·생성 중에는 각도 안내 조회를 멈추므로(게이트웨이가 관리자 조회가 있을 때만 계산한다, 세팅 중 노트북 부하를
  늘리지 않는 기존 결정) 배지 근거가 없다. 그때 「확인 중」 4개를 13분 동안 띄우는 것은 잡음이라 배지 없이 영상만 보인다.
- 수신 상태 라벨(`statusLabel` 정상·영상 없음·끊김)은 계산은 남기되 화면에 보이지 않는다. 2D 지도 카메라 이름표도 배지 글을 쓴다.

## 바꾼 화면(전 → 후)

### 1단계 카메라 연결 관리

| 전 | 후 |
|---|---|
| 왼쪽: 영상 4칸이 가운데 2D 겹침 지도 양옆에, 칸 이름표에 「카메라 3 · 영상 없음」 + 영상 상태 | 왼쪽: 영상 4칸 2×2(교실 모서리 위치대로), 칸 이름표에 카메라 이름 + 배지 하나, 영상이 안 올 때만 영상 상태 |
| 오른쪽: 맵 방식 · 「카메라 연결 · 방향 안내」 표(수신 배지·안내 문장) · 겹침 부족 경고 · 높이 입력 | 오른쪽: 「지금 할 일」 · 맵 방식 · 높이 입력 · 「자세히 · 카메라 상태」(닫힘) |

「지금 할 일」(`step1NextStep`): '다음' 을 막는 것(요청 중 → 높이 칸 비었음·틀림 → 재사용 확인 중)이 먼저, 그다음 배지 순서(끊김 →
달라짐 → 겹침 부족 → 각도)로 가장 급한 하나, 근거가 없으면 「카메라 상태를 확인하고 있어요 / 확인이 끝나지 않아도 「다음」으로 시작할 수
있어요」, 다 좋으면 「카메라 4대가 준비됐어요 / 「다음」을 누르면 카메라 앞을 비우고 배경을 찍어요」. 카메라 문제는 진행을 막지 않는다
(기존 규칙, 겹침 부족은 시작 전에 확인창이 한 번 더 묻는다).

### 2단계 보정·생성

| 전 | 후 |
|---|---|
| 왼쪽: 85% 전 카메라 영상, 뒤에는 3D 미리보기로 저절로 바뀜 | 왼쪽: 「카메라 영상」(기본, 끝까지) · 「3D 미리보기」(미리보기 맵이 생기면 켜짐) 탭 |
| 오른쪽: 5단계 막대(단계 %·경과)·대기 이유(대기 시간·덧붙임)·카메라별 배경 % · 실패·멈춤 안내 · 「자세히 · 카메라 높이」 · 쌍별 검증 표 | 오른쪽: 「지금 할 일」(+ 전체 진행 막대 하나) · 실패 안내 · 「자세히 · 진행 단계」 · 「자세히 · 카메라 높이」 · 「자세히 · 카메라 쌍 검증」 · 「자세히 · 맵 보강」 |

「지금 할 일」(`calibrateNextStep`): 실패면 없음(실패 안내 두 줄이 대신) → 조회 실패 → 서버 대기 이유(제목·할 일) → 높이 확인 창 → 걷기
창 → 맵이 다 됐으면 「3D 맵이 준비됐어요 / 「다음」을 눌러 위험 구역을 확인하세요」(카메라 확인 미통과면 그 이유) → 단계별 한 줄(배경 찍는
중 / 보정 중 / 「3D 맵을 만들고 있어요 / 다 만들면 「다음」이 켜집니다 · 약 n분 남음」).

### 맵 보강 촬영

'다음' 이 더는 보강 창을 띄우지 않고 바로 구역 단계로 간다. 보강은 「자세히 · 맵 보강」의 「맵 보강 촬영」 단추에서만 연다(미리보기 맵이
있을 때, `supplementVisible`). 창의 「건너뛰기」·「다음」은 창만 닫는다: 미리보기 맵은 맵 완성(정밀 3D 맵) 전에도 있으므로 창에서 구역
단계로 보내면 '다음' 의 맵 완성 관문을 건너뛴다.

### 완료 요약 · 빈 구역 확인

- 「세팅 완료」 카드: 개수 한 줄(`구역 적용: 새로 n · 고침 n · 유지 n · 보관 n`) 대신 줄마다 사용 맵(이전 맵 재사용 / 새 맵 · 정밀 3D 맵 /
  새 맵 · 미리보기 맵), 카메라 확인(카메라 4대 모두 통과 / n/4대), 위험 구역 n개, 저장 결과(관제 구역에 적용 · 새로·고침·그대로·보관 중 0 이
  아닌 것). 모르는 값(카메라 확인 결과 없음, 다른 화면에서 완료해 적용 결과 없음)은 줄을 뺀다.
- 구역 목록이 비었을 때 완료 확인창: 보관될 지금 관제 구역 수와 이름(앞 3개 + 외 n개)과 「위험 구역 없이 관제합니다」. 관제 구역을 받아 둔
  캐시가 없으면 예전 문구 그대로(개수를 지어내지 않음).

## 「자세히」로 접은 것

- 1단계: 카메라별 배지 + 각도 안내 문장(「각도 양호」 포함), 연결 요약(「4대 모두 연결 · n초 전 확인」·갈림), 겹침 부족 경고, 위에서 본 겹침

- 2단계: 5단계 막대와 단계별 %·진행 중 경과 시간·전체 % · 경과 시간, 대기 이유의 대기 시간·마지막 연결·덧붙임, 카메라별 배경 수집 %,

## 버린 대안

- **2단계에서도 각도 안내를 계속 받아 배지를 달기**: 게이트웨이 계산을 세팅 내내 켜게 되고(노트북 부하), 보정 중 카메라를 돌릴 일도 없다.
- **viewer_health `re_setup` 을 직접 구독**: reuse-check 와 같은 근거를 두 길로 보인다(위).
- **맵 보강 창에서 「다음」으로 구역 단계로**: 맵 완성 관문을 건너뛴다(-688 이 다룰 완료 조건과 엇갈린다).
- **단계 표(카메라 연결 관리·보정·생성·구역)까지 접기**: 지금 몇 번째인지는 사용자 정보라 남겼다.
- **완료 뒤 요약 화면에 머무르기(날짜 화면 안)**: 완료하면 날짜 화면이 바로 작업 전 확인으로 넘긴다. 단추 한 번을 더 두는 흐름 변경은 이
  티켓 범위(표시·구성) 밖이라 카드만 풍부하게 했다.

## 잔여 위험

- 배지는 1단계에서만 보인다. 보정·생성 중 카메라가 끊기면 영상 칸이 흐려지고 영상 상태 글(중계 끊김 등)만 보인다(카메라 자체 끊김과
  화면 중계 끊김을 가르지 못함).
- reuse-check 는 1단계에서 10 s, 각도 안내는 2.5 s 주기라 카메라를 건드린 직후 「직전 보정과 달라짐」이 최대 10 s(+ Tier 0 감시 2회 확인)
  늦다.
- 빈 구역 확인 글의 관제 구역 수는 앱 틀이 받아 둔 캐시와 `readZones`(형식이 틀린 구역 제외) 기준이다.
- 화면 배치(2×2·탭·자세히)는 jsdom 시험으로 구조만 확인했고 실제 화면 크기·가독성은 16차 현장에서 본다.
