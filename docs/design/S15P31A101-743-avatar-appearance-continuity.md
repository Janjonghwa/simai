# S15P31A101-743 World ID 가 바뀌어도 아바타 외형 이어 쌓기

관련 명세: 3.2·20.3·20.4(EXP-02 아바타 외형 누적·교정 직후 누적 멈춤), 5.2(World Track 재연결·병합·분할, 도달 거리 게이트), 13.2(뷰어 사람 표시). 선행: -661(`S15P31A101-661-merge-carryover.md`, 순수 병합 판정·자산 유지·짧은 불확실 메시 유지). 계약 변경 없음(`world_state`·`avatar_asset`·`avatar_frame` 의 기존 필드만 읽고 쓴다).

## 문제

18차 혼잡 구간에서 같은 사람이 새 World ID 로 자주 바뀌었다. 아바타 외형은 World ID 마다 처음부터 쌓으므로 ID 가 바뀔 때마다 회색(미관측)이 많은 상태로 돌아갔다. -661 이후에도 남은 빈틈:

1. 순수 병합: 남는 ID 의 표본·자산은 잇지만 흡수 ID 가 쌓은 외형은 버렸다.
2. LOST 뒤 같은 ID 로 다시 이어져도(Tier 0 늦은 재연결) 아바타 루프는 상태를 지운 뒤라 처음부터 다시 구웠다.
3. 근거가 모자라 새 ID 가 생기면 외형도 처음부터였다.
4. 체형을 다시 구워(첫 메시 5 프레임 → 고정 체형 30 프레임) 외형 누적기를 다시 등록하면 그동안 쌓은 텍셀을 버렸다.
5. 병합하면 포즈 차수 ≠ 트랙 차수라 뷰어가 곧바로 캡슐로 돌아갔다.

## 규칙 1·8 과의 관계 (표시 전용, 신원 판단 아님)

- World ID·위치·접지·위험 판정은 늘 Tier 0 값이다. 이 티켓은 그 값을 읽기만 하고 바꾸지 않는다(규칙 1). 이어받기 결과는 아바타 워커 안의 "어떤 누적에서 외형을 시작할지"에만 쓰이고 `world_state`·RiskEvent·PPE 로 가지 않는다.
- 외형 색·임베딩으로 같은 사람인지 정하지 않는다(재식별 아님, 규칙 8). 판정 입력은 `world_state` 의 위치·시각·키(머리 높이 − 접지 높이)뿐이다. 같은 ID 로 잇거나 합치는 결정은 Tier 0(`aliases`, 같은 `world_id` 재등장)가 한 것을 따른다.
- 얼굴: 이어받는 텍셀은 다른 ID 에서 실제로 관측한 픽셀이다(생성·복원 없음). `face_policy` 는 그대로다.

## 1. 순수 병합 외형 합치기

판정은 -661 의 `identity_carry.pure_merge_absorbed` 그대로다. 흡수 ID 는 같은 `world_state` 에서 트랙이 빠지므로 아바타 루프가 빠질 때 상태를 잠시 들고 있다가(아래 '소실 기록') 병합을 본 순간 꺼낸다.

- 외형(`AppearanceAccumulator.absorb(inherit=False)`): 두 쪽 모두 본 관측인 텍셀은 품질 가중 평균(가중치 합 = 두 가중치 합), 한쪽만 관측한 텍셀은 그 값(합집합). 본 관측이 이어받은 값보다 먼저다. 합친 뒤 다음 발행 때 안정 프레임을 기다리지 않고 한 번 낸다(`carry_publish`). 새 버전은 지금 트랙 차수로 적는다(-661).
- 체형: 표본이 많은 쪽. 고정 체형(30 프레임)이 가장 많다. 남는 쪽이 이미 고정이면 그대로, 흡수 쪽만 고정이면 그 리그를 그대로 써서(다시 추정하지 않음) 남는 ID 경로로 GLB 를 새로 올린다. 둘 다 아직이면 표본 수가 많은 쪽 표본을 쓴다. 남는 쪽은 어차피 고정 체형 굽기가 남아 있으므로 버전이 하나 더 생기지 않는다(앞당겨질 뿐).

## 2. LOST 뒤 같은 ID 재연결

같은 `world_id` 가 소실 기록 안(빠진 뒤 20 s, S15P31A101-802 전에는 10 s)에 다시 나오면 그 상태(표본·자산·고정 체형·버전 이력)를 되살리고 외형 누적을 합친다. 자산은 같은 버전을 처음 내용 그대로 다시 알린다(빠질 때 송신기가 재알림 목록에서 놓았다. 같은 키 재알림은 계약이 허용). 빠지기 전 굽던 외형 결과는 세대를 올려 버린다(재입장 무효화 규칙). 차수가 바뀌어 돌아왔으면 지금처럼 순수 병합이면 잇고 아니면 처음부터다.

## 3. 새 World ID 외형 이어받기 (`hmr/appearance_carry.py`)

받는 쪽: 아바타 루프가 처음 본 World ID(분할로 갈라져 나간 ID 제외, 명세 20.3·-661). 주는 쪽: 보낸 아바타 자산이 있는 소실 기록(LOST 또는 `world_state` 에서 사라짐, 흡수됐는데 남는 쪽이 이 루프에 없어 합치지 못한 ID 포함). 모두 맞을 때만 이어받는다.

| 조건 | 값 | 근거 |
|---|---|---|
| 시간: 받는 쪽 처음 본 시각 − 주는 쪽 마지막 측정 시각 | −0.3 ~ 3.0 s | 3.0 s = World Track 짧은 재연결 창 `lost_after_ms`(가림이 LOST 가 되는 시간, 지시 초기값과 같음). −0.3 s = `tentative_max_gap_ms`: 옛 ID 의 마지막 측정과 새 ID 첫 측정이 몇 프레임 겹쳐 생기는 경우 |
| 거리: 처음 위치 ↔ 마지막 위치 | ≤ min(0.5 m + 2.0 m/s × 공백, 1.5 m) | World Track 도달 거리 게이트와 같은 식·값(`gate_base_m`, `max_speed_mps`(명세 6.1 속도 상한), `gate_max_m`). 시험이 기본값 일치를 확인 |
| 후보 수 | 받는 쪽에 닿는 주는 쪽 1, 그 주는 쪽에 닿는 받는 쪽 1 | 둘 이상이면 누구 외형인지 모른다 |
| 혼잡 | 주는 쪽 마지막 위치 1.5 m 안에 다른 살아 있는 사람(받는 쪽 제외)·다른 소실 ID 없음 | World Track `reconnect_crowd_radius_m` 과 같다(가까이 있던 두 사람의 로컬 트랙이 넘어갔을 수 있음) |
| 키 | 둘 다 알면 차이 ≤ 0.15 m | 키 = VALID `head_z` − `ground_anchor_xyz` Z, 트랙이 본 값의 최댓값(기립 키 근사). 한쪽이라도 모르면 이 조건은 보지 않는다(지어내지 않음). 0.15 m ≈ 머리 높이 삼각측량 잡음(수 cm)의 3배 + 자세 차이 여유. 웅크린 관측만 있으면 차이가 커져 거부(안전 쪽) |

- 판정 시점: 새 ID 는 옛 ID 가 아직 가림(살아 있음)일 때 생기는 일이 많고 옛 ID 는 3 s 뒤 LOST 가 된다. 그래서 받는 쪽을 처음 본 뒤 0.3 + 3.0 + 1 s(루프 주기 여유) 동안 기다렸다가 주는 쪽이 빠지는 회차에 정한다. 조건은 모두 처음 본 시각·위치와 마지막 측정 시각·위치로 계산하므로 판정이 늦어도 기준은 같다. 기한을 넘기면 `no_donor`.
- 이어받으면: 아직 자기 메시가 없으면 체형도 받는다(고정 리그는 그대로 써서 첫 프레임에 이 ID 경로로 GLB 를 올리고, 표본이면 받은 표본 + 자기 표본으로 안정 1 프레임 뒤 첫 메시). 외형은 자기 본 관측이 없는 텍셀만 채우고 `inherited` 표시를 둔다(`absorb(inherit=True)`). 표시된 텍셀은 이 ID 의 첫 관측이 평균 없이 덮고(색이 80 넘게 달라도 이상치로 거절하지 않음) 표시를 지운다. 받은 외형은 체형 메시가 생긴 뒤 안정 프레임을 기다리지 않고 한 번 발행하고, 새 관측 누적은 지금처럼 안정 30 프레임 뒤다.
- 기록: 워커 60초 요약 로그 `아바타 신원·외형 승계 identity_events=… carry=… appearance_carry=…`. `carry` 의 `carried`·`rejected_ambiguous_donor`·`rejected_ambiguous_receiver`·`rejected_crowd`·`rejected_height`·`rejected_split_child`·`no_donor`·`dropped_capacity`, `identity_events` 의 `merge_appearance`·`lost_restored`·`carry_inherited`. 외형 버전 확정 로그에 이어받은 텍셀 비율(`inherited=`)을 싣는다.

### 소실 기록

아바타 루프는 빠진 ID 의 포즈 루프 상태와 외형 누적 사본(배열 참조, 복사 없음)을 빠진 뒤 20 s(World Track 늦은 재연결 창 `reconnect_window_ms`, -802 에서 10 → 20 s) 동안 최대 16명 들고 있다. 1024² 텍스처 누적 하나가 약 17 MB(색 12 + 가중치 4 + 표시 1)라 최악 약 280 MB(RAM). 누적기는 빠진 사본이 같은 배열을 볼 수 있으므로 텍셀 배열을 제자리에서 고치지 않는다(초기화·합치기는 새 배열).

## 4. 체형 다시 굽기 뒤 누적 유지

외형 작업자는 체형 리그가 바뀌면 누적기를 다시 등록한다. MHR UV 는 체형과 무관하므로 같은 기준 차수·같은 UV 면 앞 누적 텍셀·발행 기록을 잇는다(`adopt`). 차수 초기화(분할 등)면 지금처럼 비운다. 첫 메시(5 프레임) 뒤 고정 체형(30 프레임)으로 다시 구울 때 버리던 텍셀도 남는다.

## 5. 캡슐 깜빡임

- 워커 포즈 송신: 병합 직후 남는 트랙은 일관성 확인 동안(약 1.3 s) `IDENTITY_UNCERTAIN` 이라 워커는 추론·포즈를 쉬고(명세 20.4, 바꾸지 않음), 풀리면 새 차수로 포즈를 보낸다. 자산은 병합 전 차수 그대로라도 된다(자산 차수 ≤ 포즈 차수).
- 뷰어(`avatarMeshPolicy.ts`): 데이터 Store 가 앞 프레임과 비교해 순수 병합으로만 오른 차수 사슬의 시작 차수(`WorldFrame.pureMergeBase`, 판정은 워커와 같은 규칙)를 붙인다. 포즈 차수가 트랙 차수보다 작아도 그 시작 차수 이상이면 같은 사람의 포즈로 보고, -661 의 짧은 불확실 유지처럼 끊김·늦음 기준을 1.5 s(`AVATAR_IDENTITY_HOLD_MS`) 늘려 마지막 자세로 둔다. 분할·별칭 없는 상승은 지금처럼 캡슐.
- 새 ID 이어받기는 뷰어가 받은 쪽·준 쪽을 알 수 없다(계약에 없음). 새 ID 의 첫 자산·포즈가 올 때까지는 캡슐이다. 받은 고정 체형으로 첫 프레임에 GLB 를 올려 그 시간을 줄였다(원래 안정 5 프레임). 텍스처는 GLB 자산 다음 외형 작업자 회차에 따로 나간다(잠깐 무늬 없는 메시). 뷰어가 이어받기를 알게 하려면 계약 변경이 필요해 하지 않았다(아래 '넘긴 일').
- 새 자산 버전을 받으면 뷰어는 내려받는 동안 `ASSET_LOADING` 캡슐이다(이전 메시 유지 안 함, `avatarMesh.ts`·`PersonLayer.tsx`). 병합 체형 승계는 원래 생길 고정 체형 버전을 앞당길 뿐 버전 수를 늘리지 않는다.

## 잘못 이어받을 때 영향

다른 사람의 옷 색·체형이 새 ID 아바타에 잠깐 보인다. 이어받은 텍셀은 그 ID 의 첫 관측이 덮으므로 보이는 면부터 곧 바뀌고, 안 보이는 면은 남는다. 위치·접지·인원·위험 판정·알림·PPE 는 Tier 0 값이라 영향이 없다. 표면 출처 지도에는 이어받은 텍셀도 관측(2)으로 적힌다(다른 ID 에서 관측한 픽셀, 계약에 '이어받음' 값이 없음).

## 지시와 다른 점

- 판정을 새 ID 를 처음 본 순간에 하지 않고 주는 쪽이 빠질 때까지(최대 4.3 s) 미룬다. 옛 ID 가 가림 상태로 3 s 살아 있는 동안 새 ID 가 생기므로 처음 본 순간에는 후보가 없다. 조건 수치는 처음 본 시각·위치 기준 그대로다.
- 같은 ID 늦은 재연결 되살리기(2)와 체형 다시 굽기 뒤 누적 유지(4)를 더했다. 둘 다 같은 증상(같은 사람인데 외형 처음부터)의 원인이었다.
- 분할로 갈라져 나간 ID 는 받는 쪽에서 뺐다(명세 20.3·-661).

## 명세와 다른 점 (명세 반영 요청)

- 20.3: "다른 사람의 외형이 같은 아바타에 섞이지 않게" 와 설계 'ID 교정 뒤 외형'의 "새 ID 는 물려받지 않는다" → "근거 부족으로 생긴 새 ID 는 사라진 ID 의 마지막 위치에서 갈 수 있는 거리·3 s 안이고 후보가 하나뿐이며 키가 맞을 때만 그 외형·체형으로 시작한다(표시 전용, 이어받은 텍셀은 새 관측이 덮음). 병합하면 흡수 ID 외형을 합친다. LOST 뒤 같은 ID 재연결은 상태를 잇는다" 로. 사용자 결정(2026-11-15).
- 13.2·20.4: 순수 병합 전 차수의 포즈는 1.5 s 유예 안에서 메시를 유지한다.

## 버린 대안

- **외형 색·임베딩 유사도로 주는 쪽 고르기**: 재식별이다(규칙 8, 19.1 미결). 기하·시간·키만 쓴다.
- **후보가 둘 이상이면 가장 가까운 쪽**: 혼잡에서 틀릴 확률이 높다. 거부하고 처음부터 쌓는다(모르면 비운다).
- **이어받은 텍셀도 평균**: 잘못 이어받은 색이 새 관측을 이상치로 거절해 다른 사람 옷 색이 오래 남는다. 첫 관측이 덮는다.
- **새 ID 의 첫 자산에 받은 텍스처를 함께 싣기**: 포즈 루프에서 PNG 두 장을 더 올려야 해 포즈 지연이 늘고, 외형 작업자와 누적 소유가 갈린다. 다음 외형 회차에 따로 낸다.
- **뷰어가 새 ID 에 옛 ID 메시를 그대로 쓰기**: 이어받기 관계를 알려 줄 필드가 없다(계약 변경).
- **Tier 0 에서 같은 ID 로 잇기**: Tier 0 정본 판단(-739 담당)이고 위험 판정에 영향이 있다. 이 티켓은 표시만 다룬다.

## 남은 위험

- 혼잡 조건(1.5 m 안 다른 사람)이 엄격해 18차 같은 붐비는 구간에서는 거부가 많을 수 있다. 다음 GPU 세션 거부 사유 분포로 조정한다.
- 판정 입력의 처음 위치는 아바타 루프가 처음 본 표본(≤5 Hz, 게이트로 건너뛴 회차 있음)이라 Tier 0 첫 측정보다 늦을 수 있다(공백이 커져 반경이 넓어지는 쪽).
- 같은 ID 재연결 되살리기는 Tier 0 의 같은 ID 판단을 그대로 믿는다. Tier 0 가 다른 사람을 같은 ID 로 이으면(오연결) 외형도 섞인다(이전에는 처음부터 쌓아 숨었다).
- 소실 사본은 외형 작업자가 그 순간 쓰는 배열을 참조한다. 진행 중이던 누적 한 회차가 사본에 빠질 수 있다(표시만 영향).
- 새 ID 가 받은 체형이 틀리면 고정 체형이라 그 ID 동안 바뀌지 않는다(차수 초기화 때만 다시 굽는다).

## 다음 GPU 세션 지표

같은 녹화를 이 MR 전후로 재생해 비교한다.

- 새 ID 당 관측 텍셀 비율: `외형 버전 확정 … observed= inherited=` 로그를 World ID 별로 모아 새 ID 첫 버전의 `observed` 평균(전/후), 그중 `inherited` 비율.
- 캡슐 깜빡임 횟수: 뷰어 메시 → 캡슐 전환 횟수·길이(`selectAvatarMeshStatus` 사유별, 특히 병합 직후 `IDENTITY`). 병합 직후 5 s 안 전환 수.
- 이어받기·거부 수: 60초 요약의 `carry`(`carried`·사유별 거부·`no_donor`)와 `identity_events`(`merge_appearance`·`lost_restored`·`carry_inherited`). 새 ID 수 대비 `carried` 비율.
- 오이어받기 의심: 이어받은 ID 의 첫 자기 관측 회차에서 덮인 텍셀 비율과 색 차이(로그 `inherited` 감소량), 화면에서 옷 색이 바뀐 사례.
