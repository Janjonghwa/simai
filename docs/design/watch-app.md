# 워치 앱 뼈대와 개발 환경 (S15P31A101-335)

갤럭시워치(Wear OS) 전용 최소 앱(기획서 부록 C.6, FR-43~47, NFR-12)의 첫 단계. 저장소 최상위 `watch/` 에 Kotlin·Gradle
프로젝트를 두고, EC2 주소·기기 토큰을 넣고 상태를 보는 화면까지 만든다. 위험 알림 화면·등급별 진동·확인 단추는 S15P31A101-390
(아래 "알림 화면"). EC2 연결(I4)·ACK 전송은 S15P31A101-337, 걸음 특징은 -339.
빌드·설치 절차는 `watch/README.md`.

## 구성

| 위치 | 하는 일 |
|---|---|
| `watch/gradle/libs.versions.toml` | 판 고정(아래 표) |
| `watch/app/src/main/AndroidManifest.xml` | 워치 전용(`android.hardware.type.watch`), 휴대폰 없이 혼자 동작(`wearable.standalone`), 백업 끔 |
| `config/WatchConfig.kt` | EC2 주소·기기 토큰 검증. 토큰을 `toString`·예외 문장에 넣지 않음 |
| `config/WatchConfigStore.kt` | 앱 전용 SharedPreferences 에 저장·읽기·지우기 |
| `ConfigActivity.kt` | adb `am start` 로 설정을 넣는 화면 없는 입구 |
| `MainActivity.kt` | 기본(대기) 화면(Wear Compose Material 3). 손목을 내리면 어둡게 켜져 있는 화면(앰비언트 모드)이 된다 |
| `app/src/test/.../WatchConfigTest.kt` | 주소·토큰 검증 단위 시험(JVM) |

## 명세가 비워 둔 곳에서 정한 것

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 위치 | 저장소 최상위 `watch/`, Android Studio 는 이 폴더를 프로젝트로 연다 | 파트별 최상위 폴더 관례(`server/`·`front/`·`gateway/`). 서버 Gradle 과 빌드를 섞지 않는다 |
| 패키지 | `com.ssafy.simai.watch` | 서버 `com.ssafy.simai` 아래 |
| minSdk / targetSdk / compileSdk | 30 / 36 / 37 | Wear OS 3 = API 30(워치4 이상). Wear Compose 1.7.1 이 compileSdk 37 이상을 요구한다(AAR 메타데이터 검사). 실행 동작은 targetSdk 36 으로 둔다 |
| 판 | AGP 9.4.1(2026-09-18), Kotlin 2.4.21(10-08), Wear Compose 1.7.1(10-07), activity-compose 1.13.0, androidx.wear 1.3.0(2023-08, 앰비언트 모드용), JUnit 4.13.2, Gradle 9.8.1(서버와 같음) | 나온 지 2주 넘은 안정판. AGP 9.5.0(10-28)·Gradle 9.8.2(10-19)는 2주가 안 돼 뺐다. AGP 9 는 Kotlin 을 내장해 `kotlin-android` 플러그인을 쓰지 않고 Compose 컴파일러 플러그인만 단다 |
| 설정 넣는 방법 | adb `am start` 로 `ConfigActivity` 에 `ec2_base_url`·`device_token` 을 함께 넘긴다 | 워치 키보드로 긴 토큰을 칠 수 없다. 이 단계의 "설정 화면(최소)" 은 상태 표시 + adb 입력으로 한다 |
| 설정 입구 보호 | `ConfigActivity` 에 `android:permission="android.permission.DUMP"` | adb 가 부르려면 exported 여야 해 다른 앱도 부를 수 있다. DUMP 는 adb shell 이 갖고 일반 앱은 받을 수 없어, 다른 앱이 주소를 바꾸거나 설정을 지우지 못한다 |
| 주소·토큰을 함께만 바꿈 | 둘 중 하나만 오면 거부, `clear` 와 새 값을 같이 주면 거부 | 주소만 바꿀 수 있으면 저장된 토큰이 다른 서버로 간다. 지우기와 새 값이 같이 오면 의도를 알 수 없다 |
| 저장 실패 | `commit()` 이 false 면 "저장하지 못했다" 로 알린다 | 저장이 안 됐는데 성공으로 보이면 시연 워치가 연결되지 않는 까닭을 찾기 어렵다 |
| 규칙에 안 맞는 저장값 | 읽을 때 지운다 | 규칙이 강해져 저장값이 무효가 되면 화면은 "설정 안 됨" 인데 토큰만 남는다 |
| 주소 규칙 | https·호스트 필수, 계정·query·fragment·토큰 불가, 루프백 http 도 불가 | 노트북 게이트웨이 `validate_base_url`(gateway/site_alert heartbeat.py)과 같게 해 기기 토큰 다루는 규칙을 하나로 둔다 |
| 숨긴 토큰 찾기 | 주소 원문·unquote·unquote_plus 세 형태에서 토큰 원문·quote 형태를 찾는다. unquote 는 Python 과 같이 깨진 `%` 를 그대로 둔다 | 게이트웨이와 같은 형태들. `java.net.URLDecoder` 는 깨진 `%` 하나에 예외를 내고 `+` 를 공백으로만 풀어 숨긴 토큰을 놓친다(리뷰 지적) |
| 토큰 저장 | 앱 전용 SharedPreferences(MODE_PRIVATE), `allowBackup=false` | 다른 앱이 읽을 수 없고 백업으로 밖에 나가지 않는다. Jetpack Security(EncryptedSharedPreferences)는 지원 종료라 쓰지 않는다. 기기 분실 대비는 토큰 폐기(NFR-12)로 한다 |
| 화면 문구 | 호스트만 보이고 토큰 값은 보이지 않는다 | 화면 촬영·어깨 너머로 토큰이 새지 않게 |

## 알림 화면 (S15P31A101-390)

팀이 반장 휴대폰 PWA 를 버리고(2026-10-31) 위험 알림을 워치로만 보내기로 해서, 알림이 왔을 때 보이는 화면·진동·확인을 만들었다.
서버(I4: -334 계약, -336 연결, -338 발송)가 아직 없어 앱 안에서만 도는 알림으로 만들고, I4 가 오면 알림이 들어오는 곳만 바꾼다.

| 위치 | 하는 일 |
|---|---|
| `alert/WatchAlert.kt` | 알림 한 건(watch_alert)의 값과 검사. 칸 이름은 [AlertFields]. 잘못된 값은 IllegalArgumentException |
| `alert/AlertBoard.kt` | 받은 알림의 상태(ACTIVE·EXPIRED·ACKED)를 들고 있는 순수한 값. 시각을 받아서 JVM 에서 시험한다 |
| `alert/VibrationPattern.kt` | 진동 패턴 표와 등급별 기본값 |
| `alert/AlertVibrator.kt` | 패턴을 워치 진동기로 낸다(API 30 은 `Vibrator`, 31+ 는 `VibratorManager`) |
| `alert/AlertAcker.kt` | 확인을 EC2 로 보내는 인터페이스. 지금은 logcat 에만 남긴다(-337 이 실제 전송으로 바꾼다) |
| `alert/LastAlertStore.kt` | 마지막 알림 시각만 저장(상태 화면용). 알림 내용은 저장하지 않는다 |
| `AlertActivity.kt` | 알림 화면 입구. 잠금 화면 위에 띄우고 화면을 켠다. 앱 안에서만 부른다(exported 아님) |
| `ui/AlertScreen.kt` | 검정 바탕 알림 화면: 남은 시간 링, 등급 아이콘, 큰 한 단어, 방향, 아래쪽 큰 확인 단추. 확인함 화면도 여기 |
| `ui/AlertIcon.kt`, `ui/SeverityStyle.kt` | 등급 아이콘 그리기(위험 채운 팔각형, 경고 삼각형 윤곽, 주의 원 윤곽, 확인 체크), 등급 글자·색·모양 표 |
| `ui/WordSize.kt`, `ui/ClockText.kt` | 한 단어 글자 크기(화면 폭과 글자 수로 정함), 시각·기한 경과 글자 |
| `ui/StatusScreen.kt` | 기본(대기) 화면: 큰 시계와 이름·구역, 연결 상태·마지막 알림·개발용 값은 아래로 스크롤. 손목을 내리면 시계와 이름·구역만 어둡게 보인다 |
| `ui/AmbientState.kt` | 어둡게 켜져 있는 화면의 상태(흑백 두 색 화면 여부, 번인 방지 필요 여부)와 번인 방지로 분마다 옮길 위치 |
| `config/WorkerLabel.kt`, `config/WorkerLabelStore.kt` | 기본 화면의 착용자 이름·구역(각 12자 이하)과 저장소. 값을 줄 계약(-334)이 없어 지금은 debug 입구로만 넣는다 |
| `src/debug/.../DebugAlertActivity.kt` | 가짜 알림 입구(debug 빌드 전용, adb). 사용법은 `watch/README.md` |
| `src/debug/.../DebugWorkerActivity.kt` | 이름·구역 입구(debug 빌드 전용, adb). 사용법은 `watch/README.md` |

### 명세가 비워 둔 곳에서 정한 것

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 등급 | CRITICAL 위험 / HIGH 경고 / CAUTION 주의. INFO 는 받지 않는다 | 7.3 채널 표: CRITICAL·HIGH 는 경보, CAUTION 은 약한 진동(FR-45). 관제 앱 배지와 같은 이름(▲▲ 위험, ▲ 경고, ! 주의) |
| 진동 패턴 | 위험 `DANGER_LONG` 0.8초 켜고 0.2초 끄기를 되풀이 / 경고 `CAUTION_DOUBLE` 0.15초씩 두 번 / 주의 `CAUTION_WEAK` 0.12초 약하게 한 번 | FR-45 "주의 짧게 두 번, 위험 길게 연속, CAUTION 은 약한 진동". DB 의 vibration_pattern 값(`CAUTION_DOUBLE`·`DANGER_LONG`)을 그대로 쓰고, 약한 진동은 앱 안의 값이다(-334 에서 맞춘다). 서버가 패턴을 주면 그것이 우선이고 없으면 등급으로 정한다 |

| 기한이 지난 뒤 | 진동만 멈추고 화면과 확인 단추는 남긴다 | 격상 뒤에도 작업자는 확인할 수 있어야 한다. 확인은 해소가 아니다(FR-9) |
| 알림이 여러 개 | 급한 등급이 먼저, 같으면 나중에 받은 것이 먼저. 나머지는 "+N" | 작은 화면에는 하나만 보인다 |
| 같은 event_id 가 다시 옴 | 확인 대기 중이면 내용만 바꾸고 기한 기준은 지킨다 / 기한이 지났으면 새로 받은 것 / 확인한 것은 내용만 바꾸고 다시 울리지 않는다 | 서버가 되풀이해 보내도 기한이 밀려 격상이 늦어지지 않게 한다 |
| 한 단어 | 1~8자. 글자 크기는 화면 폭 × 0.7 ÷ 글자 수(36~20sp) | 작은 화면에서 잘리지 않게(FR-45 "한 단어"). 20sp 이상은 사용자 글꼴 설정으로 커지지 않는 Wear 규칙을 따른다 |
| 방향 | FRONT·BACK·LEFT·RIGHT(↑ ↓ ← →), 없을 수 있다 | FR-45 "방향". 어느 쪽이 기준인지(작업자가 보는 쪽인지)는 -334 계약에서 정한다 |

| 알림 보관 | 연결 서비스 `I4Service` 가 들고 있고 화면은 `AlertCenter.board` 를 관찰한다(-337 에서 옮김) | 화면이 없어도 진동·기한·확인이 돌아야 한다 |

### 화면 디자인 (안 A 큰 아이콘형, 한눈에 읽기)

디자인 조사(Wear OS 공식 가이드, 안전 경보·진동 연구, 워치 경고 화면 사례)를 바탕으로 정했다. 위에서 아래로 읽는 순서는 큰 아이콘 → 등급 글자 → 큰 한 단어(방향 화살표가 붙는다)다.

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 바탕 | 순수 검정. 등급색은 링·아이콘·등급 글자에만 쓴다 | Wear OS 는 검정 바탕이 필수이고, 큰 단색 면은 상시표시·OLED 번인 규칙과 어긋난다 |
| 등급색 | 위험 `#FF4245`(검정 위 6.1:1), 경고 `#FF9230`(9.4:1), 주의 `#FFD600`(14.9:1) | 검정 위 대비가 모두 4.5:1 이상. Apple 다크 시스템색 |
| 아이콘 | 화면 폭의 34% 크기. 위험 채운 팔각형, 경고 삼각형 윤곽, 주의 원 윤곽, 모두 느낌표. 옅은 원 바탕 | 남성 약 8% 가 적록색약이라 색만으로 구분하지 않는다. 모양과 글자(위험·경고·주의), 진동 패턴을 함께 쓴다 |
| 남은 시간 링 | 가장자리 링이 확인 기한까지 줄어든다. 12시 방향 왼쪽 아래(7시)에서 시계 방향 300도, 아래 60도는 비워 확인 단추 자리를 둔다 | 기한을 눈으로 보이게 한다. 기한이 지나면 링이 한 바퀴 차고 "기한 지남 +0:12" 로 바뀐다 |
| 글자 | 등급 글자(위험·경고·주의)와 "확인 필요" 는 등급색 한 줄(화면 폭의 6.5%), 한 단어는 흰색 굵게(36~20sp, 작은 화면은 상한이 화면 폭 × 0.16) | 한 화면에 정보 4개 이하, 1~2초 안에 읽히게 |
| 방향 화살표 | 서버가 방향을 줄 때만 한 단어 줄에 붙는다(오른쪽은 단어 뒤 "멈춤 →", 나머지는 단어 앞 "← 멈춤"). 방향이 없으면 단어만 나온다. 글자 크기는 화살표를 포함한 줄 길이로 정한다 | 명세 FR-45 "방향·한 단어" 와 -334 필드에 있어 넣었다. 방향의 기준(피할 쪽인지 위험 쪽인지)은 -334 에서 정해야 한다. 따로 줄을 쓰지 않아 화면이 단순하다 |
| 크기 | 모든 크기는 화면 폭 대비 비율이다(192dp ~ 227dp 둥근 화면에서 같은 모양) | 둥근 화면 크기가 기기마다 다르다 |
| "+N" | 아이콘 오른쪽 위의 흰 원에 숫자 | 다른 확인 대기 알림이 있다는 것만 알린다 |
| 움직임 | 위험 아이콘만 1.0 ~ 1.06 배로 1.2초 주기 맥박. 글자는 깜빡이지 않는다. 사용자가 애니메이션을 껐으면(동작 줄이기) 멈춘다 | 초당 3회 미만. 깜빡임은 미확인 경보에만 쓴다 |
| 상단 시계 | 알림 화면에는 두지 않는다 | 링과 겹치고 알림 판독을 방해한다. 기본 화면은 큰 시계가 있어 위쪽 기본 시계를 끈다 |
| 기본 화면 | 첫 화면은 큰 시계(화면 폭의 25%, 흰색 굵게, 워치의 12·24시간 설정을 따르고 분이 바뀔 때만 갱신)와 그 아래 이름(흰색 굵게)·구역(회색). 이름·구역은 값이 있을 때만 나온다. 연결 상태("연결 안 됨", 설정이 없으면 노랑 "설정 안 됨")·마지막 알림 시각·EC2 주소·토큰 설정 여부·버전은 아래로 스크롤해야 나온다 | 삼성 스마트싱스 프로·위드세이프 같은 시장 제품의 기본 화면이 시계와 이름·구역을 첫 화면에 둔다(사진·기사 확인). 이름·구역을 계속 둘지는 팀과 이야기해 정한다. 연결은 -337 이 붙이기 전이라 연결 상태는 아직 실제 상태가 아니다 |
| 어둡게 켜져 있는 화면(앰비언트 모드, 상시표시) | 손목을 내리면 큰 시계(얇은 회색, 흑백 두 색 화면은 흰색)와 이름·구역(회색)만 남기고 스크롤 줄은 감춘다. 분마다 시스템이 알려 주는 때(`onUpdateAmbient`) 시계를 다시 읽는다. 번인 방지가 필요한 화면은 분마다 ±3dp 안에서 네 곳을 돌며 위치를 옮긴다. `androidx.wear` 의 `AmbientLifecycleObserver` 와 `WAKE_LOCK` 권한을 쓴다 | 켜진 픽셀을 줄여 배터리와 번인을 지킨다(에뮬레이터 측정 약 3.5%, 손목을 든 화면 5.3%). 처음에는 큰 시계를 글자 윤곽선으로 그렸는데 가변 글꼴의 겹친 획이 6·8·9·4 에서 비쳐 보여 얇은 회색 채움으로 바꿨다. Wear Compose 1.7.1 에도 앰비언트 API 가 있으나 새 Wear 서비스 SDK 에 기대 구형 워치에서 동작하지 않을 수 있어 널리 쓰이는 `androidx.wear` 로 했다. 알림 화면(`AlertActivity`)은 아직 앰비언트를 처리하지 않는다 |

## EC2 연결·확인 전송 (S15P31A101-337)

I4 계약(-334, `docs/design/watch-i4-contract.md`)대로 EC2 와 wss 지속 연결을 맺고, `watch_alert` 를 받아 울리고 `watch_ack` 를 보내며,
하트비트로 연결을 지킨다. EC2 쪽(-336 연결·등록, -338 발송·격상)이 아직 없어 PC 의 가짜 EC2(`watch/tools/fake_ec2.py`)로 시험한다.

| 위치 | 하는 일 |
|---|---|
| `service/I4Service.kt` | 포그라운드 서비스(connectedDevice 유형). 연결 루프·하트비트·알림 보관(`AlertBoard`)·진동·확인 전송·확인 보류. 모든 상태는 메인 스레드 |
| `service/AlertCenter.kt` | 화면이 관찰하는 보드·연결 상태 흐름(StateFlow)과 확인 입구. 서비스가 없으면 빈 값 |
| `service/AlertNotifier.kt` | 상시 알림(연결 상태)과 전체 화면 인텐트 알림(화면이 꺼진 채 알림 화면 띄우기) |
| `service/DeviceStatus.kt`, `service/BootReceiver.kt` | 배터리·전송 경로 읽기, 부팅 뒤 재연결 |
| `i4/I4Codec.kt` | I4 JSON 읽기·만들기(org.json, 의존성 없음). 잘못된 메시지는 버린다 |
| `i4/HeartbeatState.kt`, `i4/Backoff.kt`, `i4/PendingAcks.kt` | 하트비트 seq·echo·시계 차이·끊김 판정, 재연결 대기, 보류 확인. 순수한 값이라 JVM 시험 |
| `i4/I4Connection.kt` | OkHttp WebSocket 하나(Authorization: Bearer 기기 토큰, ping 30초) |
| `config/WatchConfig.kt` | 기기 ID(봉투 `source_id`) 추가, `wsUrl`, debug 전용 평문 http |
| `AlertActivity.kt`, `MainActivity.kt`, `ui/StatusScreen.kt` | 화면은 `AlertCenter` 를 관찰만 한다. 상태 화면에 연결·하트비트·시계 차이·배터리 |
| `watch/tools/fake_ec2.py` | PC 용 가짜 EC2: 토큰 검사, 계약 검사, 하트비트 답, 표준 입력으로 알림 발송, 확인 지연 출력 |

흐름: 설정 저장(ConfigActivity) 또는 앱 열기(MainActivity)·부팅 → `I4Service` 시작 → `wss://EC2/ws/watch` 연결 → 하트비트(기본 10초, EC2 가
`interval_ms` 로 바꿈) → `watch_alert` 수신 → 보드에 넣고 진동 → `watch_ack` VIBRATED 전송 → 알림 화면(앞에 있으면 바로, 아니면 전체 화면
인텐트) → 작업자 확인 → `watch_ack` CONFIRMED. 끊기면 1·2·4…30초 간격으로 다시 잇고, 그동안의 확인은 보류했다가 보낸다.

### 명세가 비워 둔 곳에서 정한 것

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 연결 경로·인증 | `wss://<EC2>/ws/watch`, `Authorization: Bearer <기기 토큰>` | I1 Tier 0(`/ws/tier0`)·I6 워커와 같은 방식(`Tier0TokenAuthenticationFilter`). -336 이 같은 경로를 쓴다 |
| 기기 ID | adb 로 주소·토큰과 함께 넣는 `device_id`(`instance_id` 패턴, `ec2` 불가) | 봉투 `source_id` 는 EC2 의 `device.device_id` 여야 한다(계약). 토큰에서 끌어낼 수 없다 |
| 연결 유지 | 포그라운드 서비스 `connectedDevice` 유형 + `requestNetwork(INTERNET)` + OkHttp ping 30초. 연결 중 wake lock 은 쥐지 않는다(처음에는 쥐었다가 2026-11-03 측정 뒤 뺐다) | dataSync 유형은 Android 15 부터 시간 상한이 있다. connectedDevice 는 "망으로 외부 기기와 상호작용" 에 쓰고 상한이 없다(전제 권한 CHANGE_WIFI_STATE). 망 요청은 화면이 꺼져도 Wi-Fi·휴대폰 경유 망을 내리지 않게 한다. 연결 중 부분 wake lock 은 실기기에서 CPU 수면(약 20초 주기)을 막지 못했고(시스템이 대부분 `DISABLED` 로 둔다) 배터리 통계에서 앱 소모의 90% 로 집계됐다(아래 착용 측정, CPU 가 깬 시간을 보유자에게 귀속한 값). 하트비트가 밀리는 것은 EC2 가 `interval_ms` 를 20초로 주어 계약의 3회 규칙(60초)으로 견디게 한다(-336, 계약 설계 문서) |
| 끊김 판정·재연결 | 내 하트비트 3회에 EC2 echo 가 없으면 끊고(기본 30초) 1·2·4·8·16·30초 지수 대기. 대기는 첫 echo 를 받아야 처음으로 돌아간다. 내가 보낸 범위 밖의 echo 는 무시, EC2 가 준 주기는 1~60초로 끌어온다 | 계약 설계 문서의 규칙. EC2 하트비트에 echo 가 필수라 echo 로 생존을 본다. 핸드셰이크 뒤 바로 닫는 서버에 1초마다 붙지 않게 |
| 시계 차이 | echo 로 ((t1 − t2) + (t4 − t3)) / 2, 상태 화면에 표시. 기한 판정에는 쓰지 않는다 | 계약 watch_heartbeat. 기한은 단조 시계로 재므로 시계 차이와 무관(-390). gait_features(-339)가 이 값을 싣는다 |
| 확인 전송 | VIBRATED 는 그 이벤트가 울리는 상태일 때 받는 즉시(acked_at = received_at = 받은 시각), CONFIRMED 는 확인 단추. 끊겨 있으면 (alert_msg_id, kind) 별로 64건까지 보류하고, 다시 이어지면 보류분과 최근 10분 안에 보낸 확인을 다시 보낸다 | 계약 watch_ack. `ws.send` 의 true 는 큐에 넣었다는 뜻이라 끊기기 직전 확인이 사라질 수 있다. EC2 가 중복을 뺀다. 확인한 이벤트의 같은 알림이 되풀이되면 VIBRATED 를 보내지 않는다(격상을 풀면 안 된다) |
| 같은 알림 다시 옴 | `alert_msg_id` 가 같으면 울리지 않고 보낸 VIBRATED 확인을 다시 보낸다(64건 기억). 확인한 이벤트에 다른 `alert_msg_id`(등급 상향·재발송)가 오면 다시 울린다 | 계약 watch_alert "같은 msg_id 를 다시 받으면 한 번만 진동", "확인 뒤 등급이 오른 경보는 그 확인으로 확인된 것이 아니다" |
| 알림 보관 위치 | 서비스(`AlertBoard`). 화면은 `AlertCenter.board` 를 관찰 | 화면이 없어도(꺼짐·닫힘) 진동·기한·확인이 돌아야 한다. -390 의 "서비스로 옮긴다" 이행 |
| 화면 띄우기 | 앱이 앞에 있으면 `startActivity`, 아니면 전체 화면 인텐트 알림(`USE_FULL_SCREEN_INTENT`, 채널 HIGH) | Android 10 이상 백그라운드 화면 시작 제한. Android 14 이상에서 권한이 꺼져 있으면 logcat 에 알리고 README 에 켜는 법 |
| 깨어 있기 | 알림을 받으면 부분 wake lock 10초 | 진동 시작·확인 전송·화면 띄우기가 잠들기 전에 끝나게 |
| 평문 http | debug 빌드에서만 허용(`BuildConfig.DEBUG`), release 는 저장된 http 설정도 지운다 | PC 의 가짜 EC2 는 TLS 가 없다. 운영 앱에는 남지 않는다 |
| 수신 너그러움 | 모르는 msg_type 무시, 한 단어 앞뒤 공백은 지움, 정수 자리의 소수·문자열은 거부 | 명세 12.1 "모르는 필드 무시". 계약 반례 `word_padded` 는 송신 측 규칙이라 워치 시험에서 뺐다 |
| 알림 권한 | 첫 실행에 POST_NOTIFICATIONS 요청. 거부해도 연결·진동은 된다 | 상시 알림·전체 화면 인텐트 알림이 보이려면 필요 |

    시스템 알림 팝업으로 떴고, `appops set … USE_FULL_SCREEN_INTENT allow` 뒤에는 Asleep 상태에서도 알림이 올라가 손목을 들자 알림 화면이 떴다
    (Wear 는 꺼진 화면을 알림이 직접 켜지 않고 손목 들기·탭으로 연다). 앱이 앞에 있거나 방금 만졌으면 `startActivity` 로 바로 뜬다
  - 같은 알림 재전송: 울리지 않고 VIBRATED 확인만 다시 보냄

  - 화면 꺼진 채 30분 대기(13:03~13:33, Asleep → Dozing): 연결이 한 번도 끊기지 않았고, 알림이 Dozing 상태에서 즉시 DANGER_LONG 진동·VIBRATED 확인(전달 지연은 시계차 안).

  - 착용 배터리(2026-11-03 10:36~11:05, 29분, 충전 안 함, 대부분 착용, Wi-Fi 직접, 걸음 창 전송 중): 72% → 68%, **시간당 약 8%**(책상 위 7%).

## 걸음 특징 전송 (S15P31A101-339)

## 배정 안내 (S15P31A101-510)

시연 체크인 장면의 워치 쪽. EC2 가 `watch_binding_notice` 를 보내면(계약 1.0.0, `docs/design/server-watch-alert.md` 배정 알림 절):

- **UNBOUND**(연결됨·배정 없음): 기본 화면 첫 칸이 "워치 찬 손을 3초 흔들어 주세요" 안내(손을 좌우로 흔드는 그림, `ui/WaveGuide.kt`)로 바뀐다. 연결 상태가 CONNECTED 가 아니거나 확인 대기 알림이 있으면 보이지 않는다(경보 우선. 알림 화면은 별도 Activity 라 가려지지도 않는다). 상태 알림 줄도 같은 문장으로 바꾼다.
- **BOUND**: UNBOUND 였다가 BOUND 가 됐을 때만 짧게 한 번 진동한다(`VibrationPattern.BOUND_CONFIRM`: 400 ms 한 번, 세기 중간). 경보 패턴(DANGER_LONG 800 ms 반복, CAUTION_DOUBLE 짧게 두 번, CAUTION_WEAK 120 ms 약하게 한 번)과 길이·횟수가 달라 구별된다. "연결됨" 표시는 3초 보이고 평소 화면으로 돌아간다. 처음 받는 상태가 BOUND(앱 재시작·재연결 동기화)면 표시만 하고 울리지 않는다. 같은 BOUND 가 되풀이돼도 반복하지 않는다.
- 확인 대기 알림이 있으면 BOUND 진동·표시는 건너뛴다(알림의 진동을 끊지 않는다).
- 구현: 순수 값 `binding/BindingNotice.kt`(파싱 결과)·`BindingView`·`BindingTracker`(상태 전이와 진동 여부, JVM 시험), `I4Codec` 가 `Incoming.Binding` 으로 파싱(모르는 값은 버린다), `I4Service.onBinding` 이 진동·`AlertCenter.binding` 발행, `StatusScreen` 이 구독. 시험: `BindingTrackerTest`·`I4CodecTest` 의 배정 알림 항목(계약 예시 파일을 읽는다).
- **빌드 미검증**: 이 PC 에 Android SDK 가 없어 `testDebugUnitTest`·`assembleDebug` 를 돌리지 못했다. 기존 코드 패턴만 썼지만 Android SDK 가 있는 PC 에서 먼저 돌린다. 실기기 확인은 하지 않았다.
