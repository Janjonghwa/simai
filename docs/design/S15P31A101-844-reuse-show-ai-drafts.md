# 이전 맵 재사용에서도 AI 구역 초안 보이기 (S15P31A101-844)

-714(이전 맵 재사용 = 고른 맵의 세팅 묶음 그대로)와 -758(새 맵은 AI 초안만으로 시작)의 후속이다.
관련 명세: 5.3(VLM 현장 세팅 위험구역 초안), 8.2(F-06 구역, 게시 전 초안·이관 구역), 4.3·13.4(현장 세팅·세팅 화면), 12.6(세팅 REST).
앞선 약속: `S15P31A101-714-reuse-chosen-map.md`, `S15P31A101-758-new-map-opening-only.md`, `setup-session-zones.md`(-612), `vlm-zone-draft.md`(-455·-479).

## 왜(2026-11-23 시연 리허설, 사용자 A안 확정)

운영에서 「이전 맵 재사용」 세팅의 구역 단계에 들어가니, 11-17 새 맵 세팅 때 AI 초안을 수락해 만든 「단상 개구부 1」이 오른쪽 「사용자 추가
구역」에 「이전 맵」 꼬리표로 미리 채워졌고, 위 「AI 위험 구역 초안」 칸은 비어 있었다. 재사용 세션은 워커 작업이 없어(-714, V78 짝 검사) 초안
작업(`vlm_zone_draft`)이 돌지 않기 때문이다. 시연의 「AI 추천 → 사람 수락」 장면이 사라진다.

## 정한 규칙

### 1. 초안 조회: 재사용 세션은 그 맵을 만든 세팅의 초안을 돌려준다

`GET /api/setup-sessions/{id}/zone-drafts`(`SetupService.getZoneDrafts`)

- 세션에 `reuse_source_session_id` 가 있으면(고른 맵을 그대로 쓰는 재사용) 그 원 세션의 **가장 최근 초안 작업**을 돌려준다. 없으면 지금처럼 자기
  세션의 것.
- 응답 `setup_session_id` 는 요청한 세션 그대로, 새 칸 `draft_source_setup_session_id` 는 초안을 만든 세션이다(보통은 같은 값). 상태·초안 목록·
  `calibration_version`·`preview_scene_version` 은 원 세션 초안 작업의 값이다.
- 원 세션에도 초안 작업이 없으면 `NOT_REQUESTED`(빈 목록, 보정·미리보기 버전은 원 세션 값)다. 재사용 세션에서는 앞으로도 초안 작업이 생기지
  않으므로 화면은 이 경우 기다리지 않는다(아래 3).
- 원 세션의 초안 행은 읽기만 한다(덮어쓰지 않음, 규칙 6). 재사용 세션에 초안 작업을 새로 만들지 않는다.

**좌표가 그대로 맞는 근거**: 재사용 세션은 원 세션 S 의 맵(`reuse_scene_version` = S 의 정밀 맵)·보정(`S.calibration_version`)·높이를 그대로
쓴다(-714). 완료 때 Tier 0 계보 때문에 보정을 다시 내더라도(`X-reuse-<세션>`) 계보 키만 바꾸고 content_hash 가 같을 때만 낸다
(`CalibrationService.reissueForReuse`) — 카메라 K·R·t·World 가 한 글자도 다르지 않다. 초안 다각형(`polygon_xy`·`z_min_m`·`z_max_m`)은 그 보정의
World(미터, +Z 위) 좌표라 재사용 세션 구역 단계 3D 와 같은 자리에 놓인다. S 자신의 구역 단계가 같은 초안을 같은 맵 위에 보였던 것과 같다. 초안은
`safety_use: false` 이고 사람이 수락해 세팅 완료로 구성 묶음에 실릴 때까지 Tier 0 판정에 들어가지 않는다(규칙 1·4 그대로).

`reuse_source_session_id` 는 늘 걷기 확인을 한 NEW 세션을 가리킨다(-714 재사용 후보는 NEW·COMPLETED 만, `ConfigBundleService` 주석의
「재사용은 한 단계만」 불변식). 그래서 원 세션을 한 번만 따라가면 되고 재사용의 재사용을 거슬러 올라갈 일이 없다.

### 2. 수락: 바꾸지 않는다

화면의 수락(`useAcceptZoneDraft`)은 세팅 구역 단계에서 세션 구역 목록(-612)에 `{zone_id: null, source: "AI", candidate_id, zone: 초안으로 만든
본문}` 을 더해 PUT 한다. 서버(`SetupZonePlanService.put`)는 candidate_id 를 초안 표와 대조하지 않고 모양·값만 검사한다. 초안 본문은 화면이
초안에서 만든다(`draftCreateRequest`). 그래서 재사용 세션도 원 세션 초안 ID 로 **이 세션** 목록에 그대로 들어가고, 세팅 완료가 그 항목으로 새 구역을
만들어 이 세션에 잇는다(`setup_session_zone`). 서버 수락 로직에 원 세션 조회를 더할 필요가 없었다(통합 시험으로 확인).

### 3. 화면 문구·기다림

- 재사용 세션(응답의 `draft_source_setup_session_id` ≠ `setup_session_id`, `setupUx.draftsFromReuseSource`)의 `NOT_REQUESTED` 는 끝난 상태로 본다:
  2초 다시 묻기를 멈추고(`useSetupZoneDrafts`), 「AI 구역 초안 분석 중」 대신 빈 문구를 보인다.
- 재사용 세션에서 초안이 0건이면(원 세션 작업이 없음·실패·0건) 「이전 맵 세팅 때도 AI 초안이 없었어요 — 직접 그려 주세요」. 새 맵은 -758 문구 그대로.
- `QUEUED` 는 재사용이어도 기다린다(원 세션 작업이 아직 끝나지 않았을 수 있다).
- 시연 계정(`features/demo`)은 서버 초안을 부르지 않고 `demoZoneDrafts` 를 그대로 쓴다(응답에 출처 칸이 없어 문구도 그대로).

### 4. 재사용 구역 채우기(seed)에서 AI 초안으로 만든 구역 빼기

`POST .../zones/seed` → `SetupZoneReuseSeed.items`. 그 맵의 마지막 묶음 구역 중 **지금 다시 보일 초안을 수락해 만든 구역**은 싣지 않는다.

**판정 근거 찾기**: 구역(`zone`)에는 출처 칸이 없다(`layout_item_id`·`work_id` 만 있음, V46). 세팅이 만든 구역은 `setup_session_zone`(V47)이 만든
세션과 잇지만 사람이 그린 것과 AI 초안 것을 가르지 않는다. 출처는 그 세션의 구역 목록(`setup_session_zone_plan.items`, -612)에만 있다: AI 초안을
수락한 항목은 `source: "AI"`·`candidate_id` 와 본문을 갖는다. 목록 행은 세팅 완료 뒤에도 지우지 않는다. 다만 완료가 만든 zone_id 를 목록에
되써 두지 않아 항목 ↔ 구역은 모양으로 짝짓는다.

**규칙(모두 맞을 때만 뺀다)** — `SetupZoneReuseSeed.fromShownDraft`

1. 그 구역을 만든 세팅 세션 X 가 있다(`setup_session_zone`).
2. X 의 구역 목록에 AI 수락 항목(source AI, candidate_id 있음, zone_id 없음, 본문 있음)이 있고, 그 candidate_id 가 **지금 재사용 세션에 다시 보일
   초안**(원 세션의 가장 최근 초안 작업 — 1 의 조회와 같은 작업)에 있다.
3. 그 항목 본문이 그 초안과 같은 자리이고, 구역의 지금(묶음) 모양도 그 본문과 같은 자리다. 같은 자리 기준은 -758 의 `SetupZoneOverlap.sameSpot`
   (높이 겹침, 교집합 ≥ 작은 쪽의 0.5, 크기 비 ≥ 0.25)이다.

하나라도 아니면 사람 구역으로 보고 싣는다. 그래서

- 다시 보일 초안이 없으면(원 세션 작업 없음·0건) 아무것도 빼지 않는다(빼면 되살릴 길이 없다).
- 시연 계정 초안처럼 DB 초안에 없는 후보(`demo-opening-stage`)로 만든 구역은 빼지 않는다(시연 계정 동작 그대로).
- 사람이 다른 자리로 옮긴 AI 구역은 남는다(사람이 고친 것).
- 재사용 세션에서 수락해 만든 구역(X = 재사용 세션)도 같은 규칙이라 다음 재사용 때도 다시 초안으로 보인다.

뺀 구역은 목록에 없으므로 세팅 완료 때 보관된다(기존 적용 규칙). 사람이 초안을 수락하면 같은 자리에 새 구역이 하나 생긴다 — 같은 개구부가 초안과
채운 구역으로 둘 생기지 않는다.

## 버린 대안

- **재사용 때 초안 작업을 새로 돌리기**: 재사용은 워커 작업이 없는 세션이다(V78 `reuse_source_session_id` ⇔ `job_id IS NULL` 짝 검사, -714 「GPU
  필요 없음·1~2분」). 초안 작업은 미리보기 맵·세팅 배경 프레임(-479)을 입력으로 하는데 재사용은 배경을 찍지 않는다. 같은 맵·같은 보정이면 결과도
  원 세션 것과 같아야 하므로 GPU 를 다시 쓸 까닭이 없다.
- **문구만 바꾸기**(「이전 맵에서 가져온 구역이에요」 등): 시연 장면(AI 추천 → 사람 수락)이 돌아오지 않는다. 사용자가 A안을 골랐다.
- **구역에 출처 칸 더하기(마이그레이션)**: 앞으로는 깔끔하지만 11-17 세팅 같은 기존 기록에는 값이 없어 어차피 수락 기록 대조가 필요하다. 지금 규칙은
  마이그레이션 없이 기존 기록에서도 동작한다.
- **같은 자리의 모든 묶음 구역 빼기(기하만)**: 사람이 같은 자리에 직접 그린 구역까지 지운다. 수락 기록이 있는 것만 뺀다.
- **완료 순서로 항목 ↔ 구역 짝짓기**: 구역 ID 는 무작위이고 한 트랜잭션에서 만든 구역은 `created_at` 이 같아 순서를 알 수 없다.

## 계약·REST·DB

- 계약(`contracts/`) 변경 없음: 초안 조회 응답은 계약 스키마 밖 REST 다(`vlm_zone_draft` 계약은 I5 작업 결과). 마이그레이션 없음.
- `GET /api/setup-sessions/{id}/zone-drafts` 응답에 `draft_source_setup_session_id`(문자열) 추가. 옛 화면은 모르는 칸을 무시한다(zod 기본 strip).

## 남은 위험

- **사람이 수락하지 않으면 그 구역이 없어진다**: AI 초안에서 온 구역은 채우지 않으므로, 초안을 수락하지 않고 세팅을 완료하면 옛 구역은 보관된다.
  초안 칸 맨 위에 보이므로 시연·운영에서 놓치기 어렵지만 경고는 따로 없다.
- **사건 기록의 구역 ID 가 바뀐다**: 수락하면 새 구역(새 zone_id)이 생기고 옛 구역은 보관된다. 그 구역의 과거 사건은 옛 ID 로 남는다.
- **이름·심각도만 고친 AI 구역**도 같은 자리라 빠지고, 초안을 수락하면 AI 이름·심각도로 돌아간다.
- **사람이 같은 자리에 직접 그린 구역**(수락 기록 없음)은 남고 초안도 보여, 사람이 초안까지 수락하면 같은 자리 구역이 둘 생길 수 있다(재사용에는
  -758 의 「이어 쓴 구역 확인」 묶음이 없다). 지금 운영 데이터에는 해당 없음.
- **원 세션 초안이 오래됐을 수 있다**: 그 맵을 만든 날의 현장 기준이다. 맵·보정이 같으니 좌표는 맞지만 그 뒤 현장이 바뀌었으면 초안이 낡았다. 맵을
  다시 쓰기로 한 결정(-714)과 같은 전제다.
- 개발 목업(`mocks/setup.ts`)은 재사용 세션 초안을 원 세션 것으로 돌려준다. 목업의 세팅 완료는 구역을 만들지 않아 목업 채우기에 AI 구역이 생기지
  않으므로 채우기 빼기는 흉내 내지 않았다.
