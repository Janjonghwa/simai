# S15P31A101-810 Tier 0 곁가지 부하

관련 명세 3.2·3.12·5.2·13.2: Tier 0 우선과 얼굴 처리 관문은 그대로 둔다. I1 계약은 바꾸지 않는다.

- 아바타 입력 쓰기 분리(`SIMAI_TIER0_OFFLOAD_SIDE_WORK`)는 **기본으로 켜지 않는다**(Lead 결정 2026-11-19). -727 이 17차 실측(판정 안 `avatar_share` p95 0.07 ms, `avatar-ipc` 스레드 3.7%, 분리로 옮겨지는 것은 NPZ·파일 쓰기뿐)으로 기본 끔을 정했고, 11-19 분석의 "원본 프레임 초당 350 MB" 전제도 틀렸다(실제는 사람 주변 크롭 5 Hz·1~3 MB). 켰을 때 자식을 사이드카 CPU(`SIMAI_SIDE_WORK_CPUS`)에 두는 부분만 남긴다. A/B(-662 기준: 3~5명 judge p95 5% 이상 감소)를 잰 뒤 켠다.
- 이벤트 사진 준비·업로드 풀은 각각 최대 4개에서 2개로 줄인다. 카메라 선택 상한이 2개인 점을 고려한 초기 절충이며 지연 실측은 아직 없다. 큐 상한과 전송 규칙은 유지한다.
- 워커의 `SIMAI_WORKER_FACE_POSE_WEIGHTS`로 얼굴 처리용 모델을 별도로 선택한다. 미지정 시 기존 가중치다. 포즈 누락 시 프레임 제외 관문과 외부 LLM 텍스트 전용 규칙을 바꾸지 않는다. 경량 모델을 기본으로 채택하는 대안은 누락률 근거가 없어 보류한다.
- CPU 점수 1,000 미만은 로그에 경고만 한다. 기존 GPU 화면의 초기 기준과 같으며 근거와 한계는 `S15P31A101-740-gpu-host-cpu-check.md`에 있다. 점수를 못 재면 경고하지 않는다. 상태 보고에 측정값을 그대로 싣고 부팅을 막지 않는다.

검증 위치는 `ai/tests/deploy`, `ai/tests/services/tier0/test_event_frames.py`, `ai/tests/services/worker/test_incident_summary.py`, `ai/tests/vlm`이다. GPU에서 분리 전후 Tier 0 p95·공유 파일 누락·이벤트 사진 처리 지연, 실제 후보 모델의 얼굴 누락률과 GPU 메모리·지연, CPU 점수와 실제 지연의 관계를 측정해야 한다. 경량 모델 경로는 운영자가 미리 준비해야 한다.
