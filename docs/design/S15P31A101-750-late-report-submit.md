# S15P31A101-750 지난 날 미제출 보고서를 뒤늦게 제출하기

관련 명세: 13장(관리자 화면, 작업 관리), 3.9(보고서 잠금·해시). 근거: UX 재점검 2026-11-16 N2(11-15 작업 57 이 보고서를 안 냈는데 자정 뒤 날짜 화면이 지난 날 다시 보기로 바뀌어 「보고서 제출」 길이 사라지고, 달력은 「작업 1건 완료」로 보임). 설계 이력: -696(실행 여러 번, 보고서는 하루 한 번), -734(종료 화면).

## 바꾼 것(front 만)
- 지난 날짜 화면(`PastDayPage`)에서 고른 작업의 진행이 ENDED(보고서 미제출)이면 위쪽에 「보고서 미제출」 띠(`past/LateSubmitBand.tsx`)와 「보고서 제출」 단추를 둔다. 확인 창·꺼진 이유 글·AI 초안 경고는 오늘 종료 화면과 같은 부품(`useSendReport`·`submitBlockReason`·`ConfirmDialog`·`draftWarning`)을 재사용한다. 「한 번 더 실행」은 두지 않는다(관제는 오늘만).
- 제출하면 `WorkPage` 가 오늘 흐름과 같이 알림(보고서를 보냈습니다)을 띄우고 달력으로 나간다(`PastDayPage` 의 `onSubmitted`). 제출한 작업은 SUBMITTED 라 띠가 사라진다.
- 달력 칸(`DayMark` 에 `unsubmitted` 추가): 지난 날에 ENDED 작업이 하나라도 있으면 완료 아이콘 대신 경고색 파일경고 아이콘과 「보고서 미제출」 글, 주의색 테두리. aria-label 은 「… 경고 n건, 보고서 미제출 n건」. 모두 제출한 날만 이전과 같은 완료 아이콘이다. `DaySummary.unsubmitted` 는 있을 때만 싣는다.

## 서버
바꾸지 않았다. `TbmReportRepository.submit` 은 날짜를 검사하지 않고(작업 DONE·최신 판·생성 중 아님·미제출만 본다) 지난 날짜 제출을 이미 받는다. 제출 1회(REPORT_LOCKED)·잠금·`content_sha256` 규칙은 그대로이고, 제출은 새 값을 추가해 잠그기만 하므로 규칙 6(덮어쓰지 않음)을 건드리지 않는다. `WORK_DATE_PAST` 는 새 작업을 만들 때만 막는다.

## 버린 대안
- 지난 날 화면에도 `WorkActionLayer`(하단 단추 줄)를 씌우기: 지난 날은 단추가 하나뿐이고 단계 줄이 없어 띠 안 단추가 더 눈에 띈다.
- 달력 칸에 미제출 건수 숫자: 하루에 보고서가 하나라 「미제출」 글과 아이콘이면 충분하다.

## 잔여·넘긴 일
- 달력 칸에서 직접 제출하는 단추는 없다(날짜를 열어 제출).
- -749(지난 날 3D 영역)·-751(이벤트 로그·달력 요약 숫자)와 같은 파일(`PastDayPage`, 달력 칸)을 건드릴 수 있어 합칠 때 확인이 필요하다.
