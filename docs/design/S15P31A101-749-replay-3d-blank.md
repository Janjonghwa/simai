# S15P31A101-749 지난 날 다시 보기: 3D 기록이 있는데 큰 영역이 빈 화면

관련 명세: 13장(최소 리플레이·작업 다시 보기 M3: 녹화가 없거나 만료된 구간은 3D 관제 모의 시점 폴백, 기록 없는 구간은 “데이터 없음”).
근거: UX 재점검 2026-11-16(저장소 밖 `simai-local/ux-audit/2026-11-16/findings.md` N1·N6). front 만 바꿨다(서버·계약 그대로).

## 원인

### N1 — 11-15 실행 3: 이벤트 390건·타임라인은 있는데 왼쪽이 빈 화면

서버 응답·조건 분기 문제가 아니었다. 운영 화면(`/work?date=2026-11-15`, 실행 3)을 GET 만으로 열어 요소 크기를 재 보니
기록은 받았고 목 화면(카메라 1~4 SVG 4장)도 그려져 있었는데, 칸 배치의 높이가 0이었다.

```
section(CCTV 다시 보기)            811x520
  ReplayStage                     811x520
    ReplayCctv                    811x484
      div.min-h-0.flex-1          811x484   ← flex 열이 아님
        CctvWall 바깥 (flex-1)     811x0     ← 부모가 flex 가 아니라 flex-1 이 먹지 않음
          [container-type:size]   811x0     ← size 격리라 내용 높이 0
            grid(칸 4개)          0x0       ← 100cqh = 0
```

`CctvWall` 은 남은 높이를 `flex-1` 로 받고 그 높이(cqh)로 16:9 칸을 잰다. `ReplayCctv` 가 벽을 감싼 칸을 flex 열로 두지 않아
벽의 높이가 내용 높이(=size 격리라 0)로 접혔다. 녹화 영상 벽(`ReplayVideoWall`)도 같은 칸에 들어가므로 같은 문제다.
실시간 CCTV 화면(`CctvPage`)은 부모가 flex 열이라 문제가 없었다. 운영 화면에서 그 칸에 `flex flex-col` 만 붙이자
목 화면이 811×456 으로 보였고, 재생을 누르면 칸의 시각 배지가 22:03:07 → 22:03:10 으로 타임라인과 함께 움직였다.

canvas 0개는 정상이다. 지난 날 화면의 「3D 다시 보기」는 명세 13장의 「3D 관제 모의 시점 폴백」(카메라 4대 시점에 World 의 사람을 SVG 로 그린 목 화면)이고 Three.js 캔버스가 아니다.

### N6 — 11-12: 같은 문구가 위 띠와 가운데에 두 번

-735 가 빈 기록이면 타임라인 자리에 사유 띠(`emptyReplayReason`)를 넣었는데, 가운데 `ReplayStage` 도 같은 사유(`stageNotice`)를 보여 두 번 나왔다.
0초 작업(`ZERO_SPAN_REASON`)도 위 띠와 가운데에 두 번 나왔다. 시작하지 않아 구간이 없을 때는 위에만 한 줄이 있고 가운데가 비어 있었다.

## 수정

| 화면 | 전 | 후 |
|---|---|---|
| 3D 기록이 있고 녹화 영상이 없는 실행 | 큰 영역 빈 화면(칸 높이 0) | 카메라 1~4 목 화면이 남은 높이에 맞춰 보이고 재생 시각을 따라 움직인다 |
| 녹화 영상이 있는 실행 | (같은 칸이라 같은 위험) | 영상 벽도 남은 높이를 받는다 |
| 빈 기록(1초 미만·데이터 없음·잡힌 사람 없음) | 위 띠 + 가운데 같은 문구 | 타임라인·위 띠 없음, 가운데 한 번(`ReplayStage`) |

| 시작하지 않아 구간 없음 | 위 한 줄 + 가운데 빈 칸 | 가운데 한 번(「아직 다시 볼 구간이 없습니다.」) |

- `PastDayPage.tsx`: 위에는 타임라인만(기록이 있을 때). 사유는 모두 가운데 칸에 한 곳.

## 버린 대안

- `CctvWall` 바깥을 `h-full` 로 바꿔 부모 모양과 상관없이 높이를 받게 하기: 실시간 CCTV 화면·영상 벽이 같이 쓰는 배치라 영향이 넓다. 문제는 다시 보기의 감싸는 칸 하나다.
- 빈 기록이면 `PastDayPage` 가 `ReplayStage` 대신 사유 상자를 직접 그리기: 사유 문구가 두 파일에 남는다. 사유는 `ReplayStage` 한 곳에 둔다.

## 한계·잔여 위험

- jsdom 은 배치를 재지 못해, 시험은 벽의 부모가 flex 열인지(클래스)만 본다. 실제 높이는 운영 화면에서 같은 클래스를 붙여 확인했다(배포 뒤 다시 확인 필요).
- 빈 기록이면서 녹화 영상만 있는 경우(Tier 0 기록 없음 + 업로드 성공)는 전처럼 영상을 틀지 않고 사유만 보인다(바꾸지 않음).
