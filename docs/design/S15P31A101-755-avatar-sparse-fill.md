# 아바타 외형 점묘·검정 점 (S15P31A101-755)

19차 GPU 세션(2026-11-16, 녹화 재생 시험)에서 -742 배포 뒤에도 실제 아바타(작업자 #56)가 회색 바탕에 검은 점이 흩뿌려진 점묘로 보였다.
다른 사람(#60)은 조끼 무늬가 보이다가 몇 초 뒤 검은 점묘로 바뀌었다. -742 는 합성 fixture 로만 확인했었다.
이 티켓은 실제 자산으로 원인을 확인하고 워커(원인)와 뷰어(이미 쌓인 자산 표시)를 함께 고친다. 계약·서버는 바꾸지 않는다.

EC2 DB 의 `avatar_asset` 행에서 객체 키를 찾고, 서버 컨테이너의 저장소 설정으로 S3 서명 GET 을 만들어 받았다(비밀 값은 출력·저장하지 않음).
대상은 `w-mwi7t59c-0056`(v2·v10·v18·v19·v23)과 `w-mwi7t59c-0060`(v3·v9·v10·v14), 공통 메시 `v1/mesh.glb`(정점 19,455·삼각형 36,874).
파일과 렌더는 노트북 스크래치에만 두었다. 녹화 속 사람이라 저장소에 넣지 않는다.

## 원인

`LatestChannelReader`(-650)는 카메라마다 3칸 고리 버퍼에 크롭을 복원해 돌려준다. 같은 칸을 다시 쓸 때 **이전 크롭 영역을 0 으로 지우고** 새 크롭을 덮는다.
외형 작업자(-498)는 포즈 루프와 따로 도는데, `AppearanceWorker.offer` 가 "영상은 생산 뒤 불변" 이라는 옛 가정으로 그 배열의 참조만 쥐었다.
포즈 루프가 5 Hz 로 세 번 더 읽으면(약 0.6 s) 같은 칸이 지워지고 덮인다. 분할·4대 z-buffer 를 도는 외형 회차는 그보다 길어서,
누적 도중 검정(0)이나 다른 시각의 크롭 픽셀을 관측으로 적었다. 움직이는 사람(#60)은 크롭 위치가 바뀌어 지워진 영역이 넓고, 거의 서 있던 #56 은 적다.

한번 0 이 쌓인 텍셀은 뒤의 바른 관측이 `outlier_rgb`(채널 차 >80)로 거절되어 검정이 굳는다(설계 문서 hmr-appearance-texture.md 의 잔여 위험 "첫 관측이 잘못되면 고착"이 실제로 났다).

## 전후 비교 (실자산, 오프스크린)

뷰어 채움 코드(전·후)를 Node 로 실자산에 돌리고, 실제 MHR 메시(바인드 자세)를 소프트웨어 래스터로 앞·뒤에서 그렸다(셰이더 규칙 그대로, 쌍선형·밉맵 흉내).
그림은 스크래치에만 있다(녹화 속 사람). 행: 전(밉맵 없음) / 후(밉맵 없음) / 후(밉맵 1단계).

- #60 v10: 전에는 앞판 노랑 조끼 위로 검은 점, 뒤판·다리가 거의 검정 점묘. 후에는 검은 점이 사라지고 뒤판은 남은 관측 색(어두운 조끼·회색)으로 이어진다. 다리에는 0 과 섞여 어두워진 관측(RGB 4~30) 줄무늬가 조금 남고, 밉맵에서 옅어진다.
- #56 v18: 빈 픽셀이 적어(관측·보간·얼굴 관측의 0.3%) 전후 차이는 작다. 소매의 밝고 어두운 섞임(다른 시각 크롭 픽셀이 섞인 관측)은 데이터라 남고, 밉맵에서 점묘가 부드러워진다.

뷰어 수정은 이미 오염된 관측을 지울 수 없다. 남은 줄무늬·섞임은 워커 수정 뒤 새 누적(새 세션·새 World ID)에서 사라진다.

## 명세에 없어 정한 수치

| 항목 | 값 | 근거 |
|---|---|---|
| 빈 픽셀 상한 | RGB 모두 ≤ 3 | 실자산에서 빈 픽셀은 정확히 0 이 대부분(#60 v10 관측 0: 136,980 / 1~3: 5,443). 1~3 은 0 과 어두운 관측의 가중 평균. #56 의 검정 상의는 채널 최댓값 대부분 16 이상 |
| 빈 얼굴 이웃 반경 | 1칸(1024 기준 ±4 텍셀) | 철망 무늬 간격(삼각형 크기 수 텍셀)을 덮고, 얼굴 안 먼 색을 끌어오지 않는다 |
| 섬 밖 번짐 | 8칸(32 텍셀) | 1024 텍스처 밉맵 5단계(32×32 묶음)까지 섬 가장자리 표본에 빈칸 검정이 섞이지 않는다. 격자 8회 훑기라 비용은 수 ms |
| 워커 0 판정 | 세 채널 모두 0 | 크롭 밖·지운 칸·왜곡 제거 밖이 정확히 0 이다. 실제 영상에서 세 채널이 모두 0 인 픽셀은 드물어 버려도 잃는 관측이 거의 없다 |

## 성능 (노트북, Node 26 V8)

실자산 1024²: 부위 지도 33~93 ms(메시당 한 번, 캐시), 채우기 92~128 ms(전 106~192 ms, 첫 호출은 JIT 포함). 밉맵 생성은 GPU 에서 버전마다 한 번이다.

## 버린 대안

- **뷰어에서만 고치기**: 이미 쌓인 자산은 가릴 수 있지만 0 이 계속 들어오고, 고착 때문에 바른 관측도 버려진다. 원인(작업자 참조 보관)을 고쳤다.
- **읽기 고리 버퍼를 늘리거나 없애기**: 칸 수를 늘려도 외형 회차가 더 길면 같은 경합이 난다. 매번 새 배열은 Tier 0 경량화(-650)의 목적과 어긋난다. 비동기 소비자만 사본을 쥔다.
- **어두운 텍셀 국소 이상치 제거(despeckle)**: 검정 옷·무늬 경계를 지울 수 있고, 0 과 섞인 값과 실제 어두운 관측을 텍셀만 보고 가를 수 없다. 정확히 0(≤3)만 빈 픽셀로 본다.
- **outlier 고착 규칙 바꾸기**: 입력 0 이 없어지면 고착 원인이 사라진다. 이상치 기준은 다른 오염(다른 사람 색)을 막는 역할이라 그대로 둔다.

## 남은 위험

- 이미 오염된 세션 자산(19차)의 0 과 섞인 어두운 관측·다른 시각 크롭 픽셀은 뷰어가 가리지 못한다. 워커 배포 뒤 새 누적부터 깨끗해진다.
- 밉맵은 섬 경계를 넘어 섞이므로 아주 먼 거리(32× 이상 축소)에서는 섬 가장자리 색이 조금 번진다. 사람 크기에서는 보이지 않는 수준으로 본다.
- 채우기는 실자산에서 100 ms 안팎으로 메인 스레드를 막는다. 여러 사람이 같은 순간 새 버전을 받으면 한 번 끊길 수 있다(-742 와 같음, Web Worker 는 넘긴 일).
