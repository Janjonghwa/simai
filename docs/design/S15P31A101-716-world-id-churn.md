## 원인

1. **(재생 전용, 주원인) 카메라 간 촬영 시각 어긋남 188~342 ms.** 재생 파일이 카메라별 실제 촬영 간격을 버리고 25 fps 로 고르게
   내보내 카메라끼리 어긋나는데, 헤더는 20 ms 로 보낸다. Cross-view 가 한 사람을 두 묶음으로 가르거나(그림자·분할 나머지)
   묶지 못해(1대 클러스터) 새 ID 가 4분에 42개(확정 25개) 생기고 동시 확정이 사람 수보다 많아진다. 소실 13회 중 되찾음 0회.
   라이브 RTSP 는 프레임마다 수신 시각 추정(PTS 있으면 그 간격)을 써서 이 어긋남이 생기지 않는다.
2. **(라이브에도 있음) 새 ID 마다 사람 대상 이벤트가 새로 열린다.** 이벤트 키는 (규칙, World ID, 구역)이고 재개도 같은 사람에게만
   된다(6.4). ID 가 바뀐 같은 사람은 병합 ID 교정이 오기 전까지 다른 사람이다. 병합되면 `IDENTITY_MERGED` 가 중복을 닫지만 발생·경보
   뒤다. 병합 없이 소실→새 ID 면 묶을 근거가 없다(위치만으로 잇지 않는 5.2 원칙).
3. **(라이브에도 있음) 새 ID 는 접지점이 없어 R2·R3 가 '그 위에 있을 수 있음'으로 난다.** 7.2 접지 모름 정책대로 범위가 0.40 m
   작업면 footprint 에 걸치고 가장자리 1.0 m 안이면 `Z_UNKNOWN` 으로 R2(CRITICAL)·R3(HIGH)가 함께 열린다. 17차는 27건 모두 이
   경로였고 대부분 PREDICTED·SINGLE_VIEW 위치였다. 1번 때문에 접지가 거의 나오지 않아 단상 근처를 지나는 새 ID 마다 R2+R3 가 났다.
4. **(라이브에도 있음, 고침) R7 이 한두 tick 늦은 카메라마다 즉시 열렸다.** R7 은 지속 조건이 없다(6.4, 카메라 장애는
   `camera_stall_ms` 500 ms 로 이미 걸렀다는 전제). 그런데 -219 가 더한 '늦어서 융합에서 뺀 카메라'는 한 tick(100 ms)만 빠져도
   R7 정상 카메라에서 빠져 이 전제를 거치지 않았다. tier0-fusion-time 설계 문서가 잔여 위험(깜빡임)으로 적은 그대로다.
   라이브도 늦은 카메라 비율이 있다(15차 cam_C 10.9 %).

- **R7 에 일반 지속 조건(3프레임 중 2)**: 늦은 카메라가 1·2 tick 씩 반복되면 그대로 통과하고, 카메라 끊김(NO_SIGNAL)의 G3 예산까지
  늦춘다. 원인 쪽(늦은 카메라 표시)에서 정지 판정과 같은 500 ms 를 쓰는 편이 6.4 와 맞다.

## 제안 (고치지 않음)

1. **재생 입력 정렬(다음 GPU 세션 전 필수).** 재생 파일을 사이드카 촬영 시각으로 공통 40 ms 격자에 맞춰 다시 자른다(카메라마다 각
   격자 시각에 가장 가까운 프레임을 고르고 모자라면 앞 프레임 반복, 남으면 버림). 또는 중계 파일 입력이 녹화 세션 폴더의
   `frames.jsonl` 촬영 시각으로 페이싱하게 한다(gateway, 별도 티켓). 그 전 재생 결과는 ID·이벤트 수 판단에 쓰지 않는다.
2. **R2·R3 발생 근거 강화(명세 판단 필요).** 17차 R2 발생 27건 모두 `Z_UNKNOWN` 이고 21건이 PREDICTED 였다. 예: `Z_UNKNOWN` 이면서
   위치가 PREDICTED(또는 SINGLE_VIEW)면 새 발생은 하지 않고 활성 이벤트 유지(holding)만 한다. 또는 R5 처럼 CONFIRMED 만 발생.
   어느 쪽이든 7.1 'R2~R5 발생은 범위가 조금이라도 걸리면'을 바꾸는 일이라 Lead·명세 결정이 먼저다.
3. **같은 위험의 현장 경보 합치기(명세 3.10 판단 필요).** 흡수 마감이 경보 뒤라 ID 가 갈라질 때마다 R2 CRITICAL 이 한 번 더 운다.
   이벤트는 그대로 열고(규칙 6), 현장 소리만 '같은 규칙의 경보 중 이벤트 대상이 그림자 반경(1.35 m) 안에 있으면 새로 울리지 않음'
   같은 방식으로 묶는 안. 신원을 잇는 것이 아니라 소리만 묶으므로 5.2 와 부딪히지 않지만 3.10 재경보 규칙과 맞춰야 한다.

## 잔여 위험

- 늦은 카메라가 500 ms 안쪽으로 짧게 반복해 빠지면(예: 한 tick 걸러 빠짐) 그동안 그 카메라는 반쯤만 융합에 쓰이는데 R7 로 드러나지
  않는다. 카메라 정지(500 ms)와 같은 눈높이로 본 것이다. 30초 줄의 `늦은 카메라 비율` 로 계속 본다.
- 늦은 카메라가 이어 빠지기 시작한 처음 500 ms 동안 그 카메라에 기대는 구역은 R1 도(2대 미만) R7 도 나지 않는다. 카메라 정지 첫
  500 ms 와 같다.
- 원인 2·3 은 그대로라 라이브에서도 ID 가 갈라지는 만큼 R2·R3 중복 경보가 난다. 라이브 갈라짐 빈도는 -657 뒤로 잰 적이 없다.
