# simai 요구사항 명세서 v1.3

2026-10-17 · A101 · 기준: 기획서 v1.3 (`docs/spec/`)

simai는 고정 카메라 4대로 작업 공간의 사람·장비·정적 구조를 하나의 미터 좌표 3D 디지털 트윈에 올리고, 위험을 근거와 함께 판정해 현장 담당자에게 전달하는 예방형 안전 관제 플랫폼이다.

**이 문서의 규칙**

- 기획서(`docs/spec/`)에서 파생한 요구사항 표다. 세부 기준·근거는 기획서가 정본이다.
- **ID 는 고정한다.** 기능 요구사항 `FR-n`, 비기능 요구사항 `NFR-n`. 삭제한 번호는 다시 쓰지 않고 행을 "폐기(버전)"로 남긴다. 새 요구사항은 끝 번호 다음에 붙인다.
- **진행 상태는 적지 않는다.** 진행은 Jira 에서 본다. Jira 스토리 본문에 관련 ID(`요구사항: FR-60, FR-61`)를 적어 추적한다.
- **갱신 시점:** 기획서가 바뀔 때마다가 아니라 마일스톤(M1·M2·M3)과 제출 전에 몰아서 맞춘다. 기획서 MR 이 요구사항에 영향을 주면 MR 본문에 `요구사항 FR-n 갱신 필요` 를 적어 둔다.

**사용 대상**

- 관리자: 관제 화면(Three.js 뷰어)으로 현장을 감시하고 구역·레이아웃·보고서를 관리
- 열람: 관제 화면 조회만(구역·규칙·레이아웃 수정 불가)
- 반장: 휴대폰 PWA로 위험 알림을 받고 조치를 보고
- 작업자: 카메라에 잡히는 모든 사람. 워치를 차면 개인 진동 알림을 받음(확장)
- 현장 노트북: 카메라 영상 중계와 현장 경보 단말
- 시스템: RunPod GPU Pod 하나(일본 AP-JP-1 H100)의 Tier 0 프로세스(실시간 판정)와 분석 워커 프로세스(VLM·3D, Tier 0 자원 우선), EC2 서버(저장·전달), 외부 LLM API(텍스트 생성)

**비고 표기**: [MVP] MVP 범위, [M1]\~[M3] MVP 통합 단계, [확장] 확장 트랙(번호는 확장 순서, 기획서 부록 C), [보류] 결정 보류, (G0)\~(G8) 시연 합격 게이트(기획서 15.1), 부록 D-Gx-nn 회귀 시험, [실험] 대형 Experiment(EXP-01·EXP-02·INT-01, 기획서 20장; EXP-02·INT-01 아바타 스트림은 [시연 범위]), (E-GATE) 실험 검증·채택 게이트 E-GATE-0\~4. 비고 끝의 "기획서 x.y"는 근거 절

**수치 기준**: 표의 임계값·목표 수치는 초기값·예시값이며 실제 안전 기준이 아니다. 위험 규칙 임계값은 시나리오 데이터셋으로 조정하고, 그 밖의 수치는 검증 게이트(MVP G0\~G8, 확장 트랙 게이트) 실측 후 다시 정한다. G0\~G8 수치를 바꿀 때는 실측·결정 기록과 함께 기획서를 명시적으로 개정한다. EXP 게이트의 수치 합격 기준은 RunPod 실제 Baseline 보고서 이후 정한다.
