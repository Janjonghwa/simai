## 1. 프로젝트 개요 및 시스템 아키텍처

simai 는 교실(공사 현장 테스트베드)에 설치한 고정 카메라 4대의 영상으로 사람을 미터 좌표 3D 디지털 트윈에 올리고,
고소·낙상·보호구(PPE)·위험구역 접근 위험을 판정해 관제 화면·현장 경보·갤럭시워치로 알리는 안전 관제 플랫폼이다.

### 구성 요소

| 구분 | 위치 | 스택 | 실행 위치 |
|---|---|---|---|
| FE 관제 앱 | `front/apps/admin` | React 19 + Vite 8 + Three.js (pnpm/turbo 모노레포) | 빌드 산출물을 EC2 Nginx 가 정적 서빙 |
| BE 관제 서버 | `server/` | Spring Boot 4.1.1 (Java 21, Gradle) REST + STOMP(WebSocket) | EC2 Docker `server` |
| DB | — | PostgreSQL 17 + TimescaleDB + PostGIS + pgvector (`timescale/timescaledb-ha:pg17-all`) | EC2 Docker `db` |
| Risk Engine | `ai/services/risk_engine` | Python 3.11 + FastAPI/uvicorn (CPU) | EC2 Docker `risk-engine` (내부망) |
| 웹서버 | `deploy/web` | Nginx 1.30.6 (HTTPS 종료, 리버스 프록시) | EC2 Docker `web` |
| CI | `Jenkinsfile`, `deploy/jenkins` | Jenkins 2.580.1 LTS (JDK 21) | EC2 Docker `jenkins` + `ci-db` |
| AI Tier 0 / 분석 워커 | `ai/src/simai_ai`, `deploy/tier0` | Python 3.11, PyTorch 2.11 (CUDA 13.0), TensorRT, vLLM 0.21 | GPU 인스턴스(RunPod 등, 필요할 때만 켬) |
| 현장 게이트웨이 | `gateway/` (relay, site_alert, recorder 등) | Python 3.11 (uv) | 카메라 옆 Windows 노트북 |
| 워치 앱 | `watch/` | Kotlin 2.4.21, Wear OS (minSdk 30) | 갤럭시워치 (ADB 설치) |

### 서비스 구성도

```
                         ┌──────────────────────── EC2 (Ubuntu 24.04, Docker Compose) ───────────────────────┐
 관리자 브라우저 ─HTTPS──▶│ web(Nginx :80/:443) ── /api/, /ws ──▶ server(Spring :8080) ──▶ db(PostgreSQL :5432) │
                         │      │  └─ /jenkins/ ──▶ jenkins(:8080) ── ci-db               │                       │
 갤럭시워치 ──wss /ws/watch▶│      └─ / (관제 앱 정적 파일)            server ──▶ risk-engine(FastAPI :8080)       │
                         └──────────────────────────────────────────────────┬───────────────────────────────────┘
                                                                            │ wss /ws/tier0 (I1: 위치·이벤트·상태), REST(GPU 등록)
 카메라 4대 ─RTSP─▶ gateway 노트북 ──── I0 영상·제어 (TLS, 17000/17001) ────▶ RunPod GPU Pod (Tier 0 + 분석 워커 + vLLM)
                    (영상 중계 relay,    SSAFY 망: 노트북 → EC2 SSH 포워드 → Pod 공개 포트
                     경보 단말 site_alert)

 외부: AWS S3(영상·장면·사진), RunPod API(GPU 켜기/끄기), SSAFY GMS(LLM), 국가법령정보 Open API, Hugging Face(가중치),
       Let's Encrypt(인증서), Cloudflare DNS
```

### 데이터 흐름

1. 카메라 4대의 RTSP 영상은 **gateway 노트북**의 영상 중계(`gateway/relay`)만 받는다.
2. gateway 노트북이 영상을 **RunPod GPU Pod 의 Tier 0** 에 I0(TLS, 제어 17000 / 영상 17001)로 보낸다. SSAFY 망에서는 노트북 → EC2(`simai.live:22`) SSH 로컬 포워드 → Pod 공개 포트 순서로 간다. RunPod 은 카메라나 EC2 에서 영상을 직접 받지 않는다.
3. Tier 0 가 위치·위험 이벤트를 판정해 EC2 서버에 I1(`wss://<도메인>/ws/tier0`)으로 올린다.
4. EC2 서버는 관제 화면(STOMP `/ws`), 갤럭시워치(I4 `/ws/watch`)로 알림을 보내고, gateway 노트북의 경보 단말(`gateway/site_alert`)이 현장 경보음을 낸다.
5. CCTV 원격 시청은 gateway 노트북이 EC2 로 올린 영상을 관리자 브라우저에 나눠 준다(저장 없음).

- 공개 포트는 Nginx 의 80·443 뿐이다. `db`·`risk-engine` 은 `ec2-internal`(internal) 망에만 붙어 외부로 나가지 못한다 (근거: `deploy/ec2/compose.yaml`).
- 관제 앱·REST·STOMP 는 `simai.live` 한 출처로 묶는다. 갱신 토큰 쿠키가 `SameSite=Strict; Path=/api/auth` 라 CORS 를 쓰지 않는다 (근거: `docs/design/ec2-deploy.md`).

### 3.5 프로파일 구분

- Spring 은 별도 `application-{profile}` 을 두지 않고 **환경 변수 하나의 기본값 방식**이다. `application.yaml`(운영·로컬 공통) + `src/test/resources/application-test.yaml`(시험) 뿐이다.
  `application-local.yml` 은 `.gitignore` 대상이라 개인용으로 만들 수 있다.
- 로컬과 운영의 차이는 위 표의 값(DB 주소, `SIMAI_REFRESH_COOKIE_SECURE=false`, `SIMAI_CORS_ALLOWED_ORIGINS`)과 FE 빌드 변수(`VITE_*`)뿐이다.
- CI 는 `SPRING_DATASOURCE_*` 를 써서 `ci-db` 로 붙는다(`Jenkinsfile` `server` 단계).

## 4. 빌드 및 실행 방법

### 4.0 공통 준비

```sh
git clone https://lab.ssafy.com/s15-final/S15P31A101.git
cd S15P31A101
git checkout dev
cp .env.example .env                                   # 값 채우기(3.4 절)
cp front/apps/admin/.env.example front/apps/admin/.env.local
sh deploy/scripts/check_versions.sh                    # 판 점검
```

필요 도구: JDK 21, Node 24.19.0 + `corepack enable`, uv 0.11.x(+ Python 3.11), Docker(+ buildx, compose v2).

### 4.1 로컬 실행

**① DB (PostgreSQL + TimescaleDB + PostGIS)**

```sh
docker run -d --name simai-db -p 5432:5432 \
  -e POSTGRES_PASSWORD=<DB_PASSWORD> -e POSTGRES_DB=simai \
  timescale/timescaledb-ha:pg17-all
```

스키마는 서버 기동 시 Flyway(`server/src/main/resources/db/migration`)가 만든다. 따로 DDL 을 돌리지 않는다.

**② BE 서버**

```sh
cd server
export DB_PASSWORD=<DB_PASSWORD>
export SIMAI_JWT_SECRET=$(openssl rand -base64 32)
export SIMAI_REFRESH_COOKIE_SECURE=false
export SIMAI_CORS_ALLOWED_ORIGINS=http://localhost:5173
```

### 4.4 RunPod GPU 서버 실행 (웹 콘솔)

EC2 서버가 먼저 떠 있어야 한다(Pod 가 EC2 에 스스로 등록한다).

1. https://www.runpod.io 에 로그인한 뒤 **Pods → Deploy** 로 이동한다.
2. GPU 를 고른다.

   템플릿에 이미 설정된 값(**수정하지 않고 그대로 사용**):

   | 항목 | 값 |
   |---|---|
   | 이미지 | `docker.io/jonghwa1492/tier0:unified-181732c464ec@sha256:17fc29e55247ab1433b76f3dd1c35789007e5609c0f8cdecc9a6a80e39c0971d` (다이제스트로 고정. Docker Hub 무료 플랜은 비공개 저장소가 1개라 `jonghwa1492/tier0` 저장소 안에 `unified-<커밋 12자리>` 태그로 올린다. 비공개 저장소라 Container Registry Auth(Docker Hub 읽기 토큰) 필요) |
   | Container Disk | 150 GB 이상 |
   | Volume | 없음 |
   | 공개 포트 | TCP 22·17000·17001, HTTP 8080 |
   | 시작 명령 | 비움 (이미지 기본 `simai-bootstrap auto` = 자동 부팅) |

4. **Deploy On-Demand** 를 클릭한다.
5. 자동 준비가 끝날 때까지 기다린다.

수동 경로·장애 대응(시작 명령 `sleep infinity` + SSH 로 `simai-bootstrap lobby`)과 부팅 직후 체크리스트는 `deploy/README.md` 「RunPod 템플릿」「GPU 자동 부팅」 절.

## 5. 배포 절차 및 특이사항

### 5.1 EC2 최초 1회 준비 (근거: `docs/design/ec2-deploy.md`, `docs/design/ci-pipeline.md`)

1. DNS: Cloudflare 에서 `@`·`www` A 레코드 → EC2 공인 IP, **프록시 끔(DNS only)**.
2. Docker Engine + compose 플러그인(공식 apt), `ubuntu` 를 docker 그룹에 추가, `sudo ufw allow 22,80,443/tcp`, `sudo mkdir -p /opt/simai`.
3. `/opt/simai/.env` 생성(6절 템플릿), `chmod 600 /opt/simai/.env`.
4. 소스 올리기(개발 PC, 저장소 최상위):
   ```sh
   git -c core.autocrlf=false archive HEAD | ssh -i <EC2_PEM_PATH> ubuntu@<EC2_HOST> \
     "rm -rf /opt/simai/repo && mkdir -p /opt/simai/repo && tar -x -C /opt/simai/repo"
   ssh -i <EC2_PEM_PATH> ubuntu@<EC2_HOST> "echo $(git rev-parse --short=12 HEAD) > /opt/simai/repo/REVISION"
   ```
5. 인증서 처음 발급(80 포트가 비어 있을 때, web 기동 전):
   ```sh
   cd /opt/simai/repo && set -a && . /opt/simai/.env && set +a
   C="docker compose --env-file /opt/simai/.env -f deploy/ec2/compose.yaml"
   ARGS="certonly --standalone -d $SIMAI_DOMAIN -d www.$SIMAI_DOMAIN --email $CERTBOT_EMAIL --agree-tos --no-eff-email --non-interactive"
   $C run --rm -p 80:80 --entrypoint certbot certbot $ARGS --dry-run   # 성공했을 때만 다음 줄
   $C run --rm -p 80:80 --entrypoint certbot certbot $ARGS
   ```
6. 빌드·기동(4.2), 관리자 계정 생성:
   ```sh
   docker compose --env-file /opt/simai/.env -f deploy/ec2/compose.yaml run --rm server admin create-user --login <ADMIN_ID> --role ADMIN
   ```
7. 자동 배포 준비: `sudo sh /opt/simai/repo/deploy/ec2/install-host.sh` 후 Jenkins 키·known_hosts 등록(`docs/design/ec2-deploy.md` 「자동 배포 → 준비」).
8. Jenkins 초기 설정·GitLab 연결·Webhook(`docs/design/ci-pipeline.md` 「Jenkins 준비 (EC2)」 1~8).

관리 명령(`server` 이미지 진입점, `server/src/main/java/com/ssafy/simai/global/command/`):
`admin create-user | disable-user | set-password | set-profile | device register --kind LAPTOP|WATCH | worker register | gpu-boot register | scene … | job … | floorplan …`

### 5.2 CI/CD 파이프라인 (Jenkins, 근거: `Jenkinsfile`)

GitLab Webhook(`https://<도메인>/jenkins/project/simai`) → Jenkins 작업 `simai`.

| 순서 | 단계 | 내용 | 조건 |
|---|---|---|---|
| 1 | 변경 경로 | `git clean`, MR 이면 바뀐 경로로 돌 파트 결정 | 항상 |
| 2 | 판 점검 | `sh deploy/scripts/check_versions.sh` | 항상 |
| 3 | contracts | `uv run contracts/scripts/validate_examples.py` | `contracts/` 변경 |
| 4 | server | `ci-db` 에 빈 DB 생성 → `sh gradlew build --no-daemon` | `server/`·`contracts/` |
| 5 | front | `pnpm install --frozen-lockfile` → `format:check` → `lint` → `typecheck` → `test` → `build` | `front/`·`contracts/` |
| 6 | gateway | 패키지별 `uv sync --frozen && uv run pytest` | `gateway/`·`contracts/` |
| 7 | watch | `gradlew assembleDebug testDebugUnitTest` | `watch/`·`contracts/` |

`deploy.sh` 흐름: 진행 중 작업·세팅·Tier 0 연결·녹화 업로드가 있으면 보류(`pending/`) → tar 풀기 → `bake ec2` → 마이그레이션이 바뀌었으면 `pg_dump -Fc` 백업 → `SIMAI_TAG` 교체 → `up -d --wait` → `https://<도메인>/` 2xx 확인 → 오래된 이미지 정리. 실패하면 이전 판으로 자동 복구.

### 5.3 Nginx 설정 (근거: `deploy/web/templates/simai.conf.template`, `deploy/web/Dockerfile`)

- 이미지 진입점이 템플릿의 `${SIMAI_DOMAIN}` 을 채워 `/etc/nginx/conf.d/simai.conf` 로 쓴다.
- `:80` — `/.well-known/acme-challenge/` (certbot webroot) 외에는 `https://<도메인>` 으로 301.
- `:443 www.<도메인>` → 맨 도메인으로 301.
- `:443 <도메인>`: TLS 1.2/1.3, HSTS 1년, gzip(JSON·JS·CSS·wasm), `client_max_body_size 10m`.

| location | 대상 | 비고 |
|---|---|---|
| `/api/` | `http://server:8080` | X-Forwarded-* 전달 |
| `/ws` | `http://server:8080` | WebSocket Upgrade, `proxy_read/send_timeout 1h` (STOMP·Tier 0 I1·워치 I4·CCTV) |
| `/jenkins/` | `http://jenkins:8080` | `proxy_buffering off`, gzip off |
| `/assets/` | 정적 파일 | 1년 immutable 캐시 |
| `/` | SPA `index.html` | `no-cache` |

- upstream 은 `resolver 127.0.0.11` + 변수로 둬서 server 가 재생성돼도 Nginx 가 뜬다.
- SSL: Let's Encrypt. 갱신은 `certbot` 서비스가 12시간마다 webroot 로, web 은 6시간마다 `nginx -s reload`.

### 5.5 배포 시 주의사항

- **빌드 순서**: `contracts/` 스키마 → server(`contracts.gradle` 이 JSON Schema 로 Java 클래스 생성) / front(`check:generated`). server 이미지는 `contracts/` 를 함께 복사한다.
- **볼륨**: `db-data`(DB), `letsencrypt`·`certbot-www`(인증서), `jenkins-home`(Jenkins 자격 증명·작업). `docker compose down -v` 금지.
- **메모리**: server 2 GB(힙 `-XX:MaxRAMPercentage=75`), db 4 GB, jenkins 6 GB(`oom_score_adj 800`, 먼저 종료), ci-db 1 GB. 호스트 스왑 없음.
- **자동 배포는 jenkins·ci-db 를 재시작하지 않는다.** compose 의 jenkins 설정을 바꿨으면 빌드가 없을 때 `up -d jenkins`.
- **Flyway 는 앞으로만 간다.** 판을 되돌려도 스키마는 돌아오지 않으므로 `/opt/simai/backups/*.dump` 로 복구한다.
- **CORS**: 운영은 같은 출처라 `SIMAI_CORS_ALLOWED_ORIGINS` 를 비운다. 로컬 Vite 에서 서버를 직접 부를 때만 설정.
- **FE 주소는 빌드에 박힌다.** 도메인을 바꾸면 bake `SIMAI_DOMAIN` 과 `.env` 의 `SIMAI_DOMAIN` 을 함께 바꾸고 web 이미지를 다시 빌드한다.
- **타임존**: 시각은 UTC int64 ms 로 저장·전송한다(AGENTS.md 좌표 규약). 컨테이너 시계는 UTC, 화면 표시만 KST. Jenkins 주기 빌드는 `TZ=Asia/Seoul` 을 명시한다.
- **Windows 에서 소스를 보낼 때** `git -c core.autocrlf=false archive` 로 셸 스크립트 LF 를 지킨다.
- **시연 전**: `SIMAI_REPLAY_TEST_ALERTS=false`, `SIMAI_REPLAY_TEST_SKIP_CAMERA_CHECK=false` 확인 후 `up -d server`. 배포 동결은 `deploy/README.md` 「EC2 배포 동결」.
- **GPU**: 한 시점에 GPU 인스턴스는 하나. 검증·시연 때만 켠다.
- **RunPod 는 On-Demand 로 띄우고, 사용 후 반드시 Terminate 한다(과금).**
- **Pod 가 EC2 에 스스로 등록하므로 EC2 서버가 먼저 떠 있어야 한다.**

### 6.4 RunPod 템플릿 환경 변수·Secret (근거: `deploy/README.md` 「RunPod 템플릿」「GPU 자동 부팅」)

값은 템플릿에 직접 쓰지 않고 비밀은 RunPod **Secrets** 에 두고 `{{ RUNPOD_SECRET_<이름> }}` 으로 참조한다.

| 환경 변수 | 템플릿 값 | RunPod Secret 이름 | 내용 |
|---|---|---|---|
| `HF_TOKEN` | `{{ RUNPOD_SECRET_hf_token }}` | `hf_token` | Hugging Face 읽기 토큰 |
| `SIMAI_GPU_BOOT_SECRET` | `{{ RUNPOD_SECRET_simai_gpu_boot_secret }}` | `simai_gpu_boot_secret` | 부팅 비밀값. EC2 `admin gpu-boot register --id <BOOT_ID> --worker-id <WORKER_ID>` 가 한 번 보여 준 값 |
| `SIMAI_TIER0_TLS_PRIVATE_KEY` | `{{ RUNPOD_SECRET_simai_tier0_tls_key }}` | `simai_tier0_tls_key` | Tier 0 TLS 비밀 키(PEM 또는 base64 한 줄) |
| `SIMAI_TIER0_TLS_CERT_PEM` | `<TLS_CERT_PEM>` | (공개, 선택) | 위 키의 인증서 |
| `SIMAI_TUNNEL_PREFIX` | `{{ RUNPOD_SECRET_simai_tunnel_prefix }}` | `simai_tunnel_prefix` | 막힌 망 최후 예비 443 터널 경로(선택) |
| `SIMAI_GPU_BOOT_ID` | `gpu-boot-runpod` | — | 부팅 비밀값 ID(비밀 아님, EC2 `.env` 와 같게) |
| `SIMAI_EC2_BASE_URL` | `https://<DOMAIN>` | — | 등록할 EC2 주소 |
| `SIMAI_TIER0_PINNED_SPKI_SHA256` | `sha256:<hex>` | — | gateway 노트북과 같은 TLS 지문(선택, 공개) |
| `SIMAI_IMAGE_DIGEST` | `sha256:17fc29e55247ab1433b76f3dd1c35789007e5609c0f8cdecc9a6a80e39c0971d` | — | 이미지 다이제스트(4.4 표의 이미지와 같은 값) |
| `SIMAI_TIER0_GPU_RESERVE_MB` | `8192` | — | Tier 0 GPU 선확보 |
| `PUBLIC_KEY` | `<SSH 공개키 한 줄>` | — | Pod SSH 키(비밀 아님). 비워 두면 sshd 가 뜨지 않는다 |
